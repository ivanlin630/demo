# 09 長考閘：驗收考的開考前置閘（用戶立法 2026-08-21）

owner: systems（流程本體）。機制面不入意圖帳（blueprint 裁：**流程非機制**）。

## §0 法條（含 2026-08-21 補立法：**一道閘、兩種模式**）
**半成品禁跑驗收考。**
★**兩種考都要過同一張「已知結構缺件清單」**，**判準不同**：
- **驗收考 ＝ 清單清零**：每項**已修** or **明列豁免（該科結果標記無效）**。
- **診斷考 ＝ 對齊審查**：逐科目問「**這個目標科目會不會被已知缺件蓋掉**」——
  - **會** → **先修**，或**該科降級**標「**已知污染、不讀結論**」；
  - **不會** → **照考**。
- **判準示例**：**生育壞 → 人口科必修才考**；**生育壞不礙 k 值 → 效能科照考**。
★**本閘只管「已知」缺件**；**未知缺件正是診斷考要去找的**——本閘**不是**「必須先知道所有問題才能開跑」。

## §1 兩種考的分辨（先分類，再決定要不要過閘）
| | 診斷考 | 驗收考 |
|---|---|---|
| 目的 | **找斷點在哪** | **宣稱某批修好、或世界達到某狀態** |
| 結果的用法 | 產生工單 | **背書**（餵 blueprint／用戶做取捨） |
| **已知**缺件時 | **對齊審查**：蓋得住目標科目 → 先修／該科標「已知污染、不讀結論」；蓋不住 → 照考 | **不准開**：清單須清零（已修 or 明列豁免＋該科無效） |
| **未知**缺件時 | **正是要找的東西**（診斷考的產出） | — |
| 例 | 2026-08-13 與 2026-08-20 兩次 12mo（blueprint 定調「**大考是診斷器不是及格考**」） | 下輪**新基線考**（要背書效能 arc + 時間包 + 生育） |

★**分類錯的代價是不對稱的**：把驗收考誤當診斷考 → **拿半成品的數字去背書**；反之只是多做一次檢查。**不確定時當驗收考辦**。

### §1b 對齊審查怎麼做（診斷考模式的操作）
逐**科目**（不是逐缺件）問三個問題：
1. **這科的結論依賴哪些機制鏈？**（例：人口科 ← 生育 → 成年 → cap）
2. **鏈上有沒有已知缺件？**（例：生育整 12mo 零 fire）
3. **若有，缺件會讓這科的結論「錯」還是只是「弱」？**
   - **會錯**（結論方向被反轉／數字被系統性偏置）→ **先修，或標「已知污染、不讀結論」**。
   - **只是弱**（樣本少、雜訊大，但方向可信）→ **照考、在 verdict 標注侷限**。
★**輸出**：這張對齊表**也要進 verdict**——讀報告的人要看得到**哪幾科是在已知污染下跑的**。

## §2 開考前置閘（逐項勾、缺一不可）
**★閘 ＝「已知結構缺件清單」逐項審**，每項只能是兩種狀態之一：
1. **已修**（merged + 閘綠 + 在考卷 build 內、**可證**）
2. **明列豁免** → **該科目結果標記無效**（不是「先跑再說」，是**事前就寫死這科不算數**）

**★證明「在考卷 build 內」的方法**（不是憑印象）：
- **線性歷史推論**：若 probe 顯示某更晚 merge 的機制在跑，則它**之前**的 merge 必在 build 內。
- **probe 直證**：該機制的 tap 在考卷資料裡有非零計數。
- ★**反例警告**：`death.starve_minor > 0` 曾被 systems 當成「生育有 fire」的證據，**實為 world-gen 存量出清** → **證據要對準機制本身**（`reaction.breed`），不是對準它的下游。

## §3 血訓：本閘防的正型
**2026-08-20 12mo 大考**：「**繼承-lite 有沒有進考卷 build**」是**開考之後**才被 blueprint 列為 CHECK 項、由 systems 事後補證。
→ 那次僥倖（線性歷史可推、確實在 build 內），但**流程上是開考後才驗**。本閘把它移到**開考前**。
同輪另一個實例：**政治質地欄全 0** ＝ **量測 artifact**（床的 `watch_prefixes` 對不上 production key 名），**開考前對帳就能發現**。

## §4 與現有清單的關係
`progress.md`〈12mo 大考 啟動閘〉的 **A 開考 blocker 五項 ＝ 本清單的一部分**，非全部。
**下輪新基線考**的清單至少還要含：
- 效能 arc 各刀（已 merge 者逐項可證在 build 內；未 merge 者明列豁免並標哪科無效）
- 時間重錨包（**S1–S7 哪些進、哪些沒進**；沒進的要說**哪科因此無效**）
- 生育連續速率（已 merged）、觀察者永不凍結（已 merged）、命令戳記誠實化（已 merged）
- **儀器面**：`watch_prefixes` 對帳（`envoy.`/`g3.`/`g2.`/`cohesion.`/`trade.`/`order.`）＋ **結尾全量 `Probe.counts` dump** 必開
- **已知結構缺件**：GATE-B（貨到不了）／設施鏈（沒人蓋 workshop → tools=0）／失敗反饋鐵律尚未納管的族群 → **每項標「修了」或「這科不算」**

## §5 執行方式
1. 開考前，systems 產出**本次考卷的清單快照**（貼進該次考的 dispatch 信與 verdict 檔）。
2. 逐項標 **已修／豁免（+ 失效科目）**。
3. ★**清單本身進 verdict**——讓讀報告的人**看得到哪幾科的結論是被豁免掉的**，而不是只看到分數。
4. ★★**「報不修」讀數**（blueprint 裁 2026-09-03）：有些數字是**世界性質的溫度計**，**不產生工單**，但**每次考都要報**——
   ⇒ 現有一項：**施主可及率 ／ 深帶「找得到施主」比例**（＝世界薄不薄）。★量法：`_find_aid_target` 五道濾網 × band 交叉。
   ★★★**報它是為了看趨勢，不是為了修它**——**沒有它的話，「世界變薄了」只會以別的症狀現形，而那時已經歸錯因。**
   ★**第二項（blueprint 2026-09-03，不開線）**：**`peaceful_economy` 裡【承諾紮根的隊數】** —— 2026-09-03 實測 **0／0**（兩 seed）。
   ★★可能是**和平世界早就定居完了**的預期行為，也可能另有故事；★★★**長考會免費照到它，所以現在不開線，只報。**

## §6 地基保鮮期（R6 接線，2026-08-21）

開考前置閘除了「已知缺件清零」，**還要問清單上每一項的地基是不是還活著**。

```bash
bash .claude/hooks/stale-claims.sh docs/process/<考卷清單>.md
```

| 結果 | 處置 |
|---|---|
| exit 0 | 照常開考 |
| exit 1 | **該項標「地基待重驗」**——不是自動退考：地基過期只代表「這個數字不能再當事實用」，
由派考的人裁「重跑」還是「本科目改列診斷目的」 |
| **exit 2** | **★停**——母體塌陷＝ regex／路徑壞了，**不可讀成「零過期＝綠」** |

★ **地板要自己宣告**：對指定檔案掃時預設地板 = 0，因為「不溯改」讓**舊檔本來就該是 0 筆**。
要斷言「這份清單應該有 R6 標記」，呼叫端自己給：`EXPECT_MIN=1 bash .claude/hooks/stale-claims.sh <清單>`。
（**母體地板只能對「你確知該有標記」的母體宣告**，否則地板自己就在製造假警報——
這條是寫這支腳本時被自己的自測抓到的。）

★ 特別盯 **「裁定建立在量測上」**：裁定本身不過期，但地基會，而**檔面上看不出來**。
`地基＝… @<commit>` 這個標記就是把那條隱形的繼承關係寫到檔面上。

血證：D1「它是長桿」這個排程裁定，繼承了 `統領 0.08` 的保鮮期而不自知（見 `03b_measurer §R6`）。
