## ★`LOCKED` 的界線：**鎖的是【裁決】，不是【事實】**（systems 立 ／ blueprint WHAT 側背書 2026-08-27）
> ★**「LOCKED 鎖的是裁決，事實歸量測管。訂正事實不碰設計 ＝ 不算解鎖；碰設計才回 blueprint ＋ 用戶。」**（blueprint 原話）

### ⇒ 訂正 LOCKED spec 裡的【事實】：准，但四件必須齊備

(a) 保留原文刪節線            (b) 指出推翻它的證據（哪一天、哪張床、什麼數字）

| **6** | ★**用 cherry-pick 搬東西進 main ⇒ 只信樹比對**（`git diff main <branch> -- <路徑>`），commit 層工具兩方向都會騙；對帳範圍要涵蓋所有會被引用的路徑。〔詳 detail#arch-6〕 |
| **5** | ★**dump／量測票必須指定母體**（team＋tick 窗）。〔詳 detail#arch-5〕 | 窗要同時寫 tick 數與遊戲天，並寫世界規模（config）——窗長與規模是兩個獨立的軸。 |
| **4** | ★**A 級條目開票前一律先 code 複驗**：符號在不在／錨對不對／斷言成不成立／分清靜態可驗與要跑才知道。〔詳 detail#arch-4〕 | 行號錨可在同一顆 commit 內失效 ⇒ 錨一律用 `檔::符號`。 |
| **9** | ★**收到 ruling 而手上有反證：先跑出「照做會怎樣」再回信**，附實跑輸出不是推論（會蓋章的閘比做錯的標記貴得多）。〔詳 detail#arch-9〕 |
| **10** | ★**「不動的東西」清單只承諾不改、不承諾安全**：列進「不動」的每一項仍要問「它會不會被新路徑用到」。〔詳 detail#arch-10〕 |
| **11** | ★**拆票前先問：後半靠什麼被想起來？** 有會自動重複曝光的機制才拆；答不出來就不要拆。〔詳 detail#arch-11〕 |
| **12** | ★**名字出現過≠被讀過**：用「提及」當證據的檢查會被提及它的文件自己滿足 | 判準改成「有沒有真的讀它」（`state.<欄位>`） | R² CLEAN 保證的是兩人都想不出反例，不是判準對。〔詳 detail#arch-12〕 |
| **13** | ★**風險也要被量，不只被列** | 描述母體時把結構性 gate 與行內 gate 分開列 | 沒量的風險會變成為空集合設計的工作項。〔詳 detail#arch-13〕 |
| **14** | ★**「安不安全」不可判 ⇒ 拆成可判的問題再量** | 例：持久參照／快照消費者／整 tick 跑完 | 抽象形容詞寫進 code 就永遠沒人驗；推翻的是理由不是機制。〔詳 detail#arch-14〕 |

| ★**驗 merge 候選的刪除那一半要用看的**（`git diff main...<branch>` 篩出 `^-` 行），不是看數字：誤刪只會變成一個數字。〔詳 detail#arch-deletions〕 | systems 2026-09-22 |

## ★未驗的合併【不得】放在共用 main dir（systems 立 2026-09-25；血證 → `detail/01_architect-cases.md`）

★**合併在臨時分支或專用 worktree 裡做**，在那裡跑完電池，綠了再把 main fast-forward 上去。
★理由：「這段時間別 push main」是一條靠【所有人記得】的紀律，而它的失效方式是
**某個角色照平常流程推了【與它無關的】一顆** ⇒ 你的合併跟著公開，★**而他不會知道自己做了這件事**。
⇒ 放在別人推不到的地方 ⇒ **不需要任何人配合**。
★已發生時：**往前補驗**（新頂端跑一輪完整電池），**不往後改歷史**（revert／force-push 共用 main 是破壞性的）。

## ★預註冊實驗要【同句指定跑的人】（implementer 提、systems 立 2026-09-23）

★**規矩**：預註冊那一段要寫「**我跑**」或「**你跑**」，不要留給機器誰空誰跑。
★而重複發生了的時候，**不要丟掉任何一份** —— **兩人跑同一實驗結果不一致【本身就是讀數】**。
★目的不是省機器時間，是**讓「誰的數字算數」在看到數字之前就定下來** —— 否則挑哪一份會變成【事後的選擇】。
