# 規則退役程序（blueprint 立 2026-09-10，systems 落 doc）

## 為什麼需要它

一條規則的生命週期到目前為止是：**出事 → 寫成規則 → 進必讀區 → 永遠留著**。
★**沒有任何程序會讓它出去** ⇒ 必讀區單向長大 ⇒ ★★**超限＝開場讀不完＝規則存在但不會被用到**。
（`01_architect` 2026-09-10 實測：血證全搬走之後仍 207 行，**因為剩下的每一節已經是一條規則一行**
⇒「搬到按需讀」這條處置對它**已經用盡**。）

## ★★★出口只有三個。「很久沒事」不是出口。

| 出口 | 判準 | 動作 |
|---|---|---|
| ①**機械化** | ★有 hook／gate **實際擋得住**這條規則要防的事 —— ★★**必須附【陽性對照】**：造一次違規，看它真的紅／真的擋。★★★**沒跑過對照的「已機械化」不算數**（「裝好了」與「接上電了」長得一樣） | 文字版縮成**一行指標**（或整條刪，由閘的訊息承擔說明）；★同時更新 **P7 三態表** 的態 |
| ②**前提消滅** | 它要防的**結構已經不存在**（模組刪了／欄位沒了／那條路徑被改掉了） | 退役，**帶墓誌銘**（何時立／為何立／為何退） |
| ③**併吞** | 有一條**新的通則**已經涵蓋這個舊特例 | 合併進通則，舊條目留一行「已併入 X」 |

## ★★★出口①的兩條附加條件（systems 提，blueprint 2026-09-10 核定升入正文）

```
①【必附陽性對照】：造一次違規，看閘真的紅／真的擋。
  ★沒跑過對照的「已機械化」不算數 —— ★★「裝好了」與「接上電了」長得一樣，
    而報告上讀不出差別。
②★★★【對照本身要先驗它成立了沒】：先印出「違規條件已經造出來了」的那個數字，
  再去看閘的反應。
  ★血證（首輪試點當場）：我第一次搭的 rebase 場景【沒有真的產生 merge commit】
  ⇒ `git rebase` 回「up to date」⇒ 看起來像【閘沒擋】。
  ★★而「閘沒擋」與「我沒造出違規」長得一樣，
  ★★★前者會讓人把一條【活閘】判死，然後退役一條【還在守著】的規則。
```

★**明文禁止的判準：「好久沒咬了」**（blueprint 2026-09-10）。
★★理由：**安靜分不出【威懾生效】與【規則無用】** —— 這是**恆綠問題的鏡像**
（恆綠的閘與「世界真的沒問題」長得一樣；沒再現形的規則與「規則沒用」長得一樣）。

# 首輪試點（2026-09-10，blueprint 指定：挑 2-3 條走一遍校準）

## 候選① `git pull --rebase` 護欄 ⇒ ★**退役**（出口①機械化）

```
規則原文位置：01_architect 觸發式必讀表「★要 git pull --rebase」列
閘：.git/hooks/pre-rebase（systems 立 2026-08-27）
★陽性對照（今天真的跑了，不是宣稱）：
  scratch repo：main/side 分岔 → side merge main → main 再前進一顆
  ⇒ `git rev-list --merges --count side ^main` = 1（★先確認條件真的成立
     —— 我第一次搭的測試場景【沒有真的產生 merge commit】，得到假的「沒擋」）
  A) git rebase main          ⇒ ⛔ 擋下（印出完整理由與逃生門）
  B) git pull --rebase . main ⇒ ⛔ 擋下  ★★兩條路徑都擋
⇒ 覆蓋完整（★它擋的正是規則描述的危險：重放 merge commit），且逃生門具名
   （ALLOW_REBASE_WITH_MERGES=1）。
★★★退役理由：閘在【你伸手的那一刻】印出比那一列更完整的說明，
   而那一列要求你【事先記得去讀】——後者嚴格弱於前者。
```
