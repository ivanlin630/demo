# 三、★★★而我不先派的真正理由：**定義沒鎖**

「argmax 不變率」至少有三種互不相同的讀法，而**它們會給出差很多的數**：
```
(甲) 同一隊、**相鄰兩 tick**，rank 的第一名有沒有換人      ⇒ 母體 ＝ 每隊每 tick
(乙) 同一隊、**同一個 cadence 週期內**，第一名有沒有換人    ⇒ 母體 ＝ 每隊每週期（小很多）
(丙) 不是第一名，而是**整份 rank 的前 K 名集合**有沒有變    ⇒ 才是「快取整份結果」真正要的不變性
★★而快取要共用的是【整份 gather 結果】，不是只有第一名
   ⇒ ★★★**(甲) 量出來的數字，回答不了「跨 tick 快取安不安全」** —— 它只回答「決策穩不穩」
```
**我的建議（你點頭我就派，當天可發）**：
```
量 (丙)：同一隊、相鄰兩 tick，**gather 產出的整份候選評分**逐欄比對 ⇒ 不變率
★併量 (甲) 當**對照欄**（它便宜、而且它是你直覺要的那個數）
★★母體與尾巴同印（今天立的規矩）｜兩顆種子｜8 天窗｜HW-2／世代 6 戳
★★★**門檻在量之前預註冊** —— 而我建議的預註冊是：
   不變率 ≥ 95% ⇒ 值得開快取票（省的是整個 gather）｜＜ 95% ⇒ 那個快取形狀從一開始就錯
```
**預估**：加樁 ＋ 兩顆種子 ＋ 8 天窗 ≈ 與今天 U₇ 那輪同量級（**implementer 半天內**）。
★但**這台機器剛才報過記憶體不足**（我的一個背景量測被 harness 停掉）⇒ **長跑前要先看記憶體**。
