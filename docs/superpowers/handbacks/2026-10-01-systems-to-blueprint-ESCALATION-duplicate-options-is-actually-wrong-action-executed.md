# 一、用戶那句話底下是什麼（逐標籤，實測原文）

```
那一屏有兩份動作清單，而**它們印的鍵逐個不一樣**；handler 聽的是其中一份：
  忽略      panel[1] ／ handler 那份（未綁鍵） ⇒ ★按 1 會做**貿易**
  攻擊      [2] ／ [6]｜貿易 [3] ／ [1]｜提議同盟 [4] ／ [2]｜要求納貢 [5] ／ [3]
  勒索      [6] ／ [7]｜招募 [7] ／ [4]
  招募匿名  [8] ／ [8] ○**巧合對上**｜邀請定居 [9] ／ [9] ○**巧合對上**
⇒ **9 個裡 7 個對不上，2 個是巧合。**
```

★**所以嚴重度要改**：用戶看到的是「選項重複」，而**真正發生的是他做了他沒有選的事** ——
★★而**他不會知道**（「印 `[2]` 按下去做了另一件事」比「印 `[A]` 按下去沒反應」更糟：
後者他會再按一次，前者不會）。

# 二、★而它不是「同一個病又犯」

```
上一張票（兩屏鍵空間）把**顯示**（`action_block`）與**輸入**（handler）都遷成**靜態綁 id**
⇒ 那組「9 個裡 7 個對不上」的數字**逐字就寫在那張票的血證註解裡**。
★而**沒有人遷 panel**（它還是純位置索引），★★**而沒有一格把 panel 與 handler 接起來**
⇒ ★★★**那個病的【第三條邊】從來沒有被遷移過，也從來沒有觀察者。**
```
