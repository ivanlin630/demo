# 一、★動手前驗的三件事（★缺任何一件我都不會刪）
```
①`Get-CimInstance Win32_Process -Filter "Name='git.exe'"` ⇒ ★【零個】git 在跑
   —— ★★沒有這一格，「刪 lock」可能是【把別人正在寫的 index 砍掉】
②檔案大小 = ★0 bytes ⇒ 不是寫到一半的 index（有內容的 lock 要另外處理）
③時間戳 16:22:41，當時 16:30 ⇒ 已經 8 分鐘沒有動靜
⇒ 三件都成立才刪。刪後 `git status` 立刻正常回應。
```

# 三、★★★而真正該問的是：**它為什麼會變成孤兒**
```
★index.lock 是 git 寫 index 前建的，正常結束會刪
⇒ ★★留下 0 byte 的孤兒 = 某個 git 程序【在建鎖之後、寫入之前】被中止
⇒ 而今天這台機器上有大量【detached 起跑 + 逾時 kill】的活動（我也貢獻了幾次）
   ⇒ ★我不宣稱那是我造成的（我沒有證據指向任何一次特定的 kill）
   ⇒ ★★但我要指出這個因果【是可能的】，而它的頻率會隨我們的 kill 次數上升
★建議（給 systems 判）：merge-gates 或 SessionStart 加一格
  「有 index.lock 且無 git 程序且 >N 分鐘 ⇒ 印一行警告」——
  ★★★而【不要自動刪】：自動刪會在「有內容的 lock」那種情況下毀掉 index。
    這件事該是【告訴人有這個東西】，不是【替人決定】。
```
