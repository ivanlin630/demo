# 補強：併入訊號的樣本量問題

用戶戳破一個地方，我覆核後同意，記錄給你。

## 問題
我上輪判決引用「3份 trace 累計併入 0 次成功」當作要留觀的訊號。**取樣讀法本身沒錯**（逐筆核對 task/faction_id/food 走勢，不是憑印象）——但 3 筆同向陰性拿來支撐「併入是否系統性失敗」這種**靠出現頻率才能判的結論**，樣本量太薄，只能算「值得追的訊號」，不能算「坐實」。跟死-specimen 那種「讀一筆就能判鏈完不完整」的問題不是同類，混在一起講容易誤導成分量比實際重。

## 不影響已發的判決
Team26 連貫窮死 ✅ / Team18 存活連貫 ✅ / release 建議 merge——**這些不變**，各自是單筆 trace 內部邏輯自洽的判斷，不依賴樣本量。變的只是「併入留觀」那條的措辭強度，應該是「訊號、待驗證」而非聽起來像「已發現規律」。
