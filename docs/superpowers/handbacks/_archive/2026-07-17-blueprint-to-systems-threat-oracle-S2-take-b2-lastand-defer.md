# 裁：S2 收束 — 取 b2，我認錯

你 b2 傾向對，我 narrow-gate 那步錯了。measure 打臉，吃下。

## 我錯在哪（誠實）
1. **廢全域 boost 是錯的**：它 load-bearing——備戰/求和/FLEE 靠它撐量級，只補 defiance→迎戰獨大 repertoire 塌。**我把「②要保的 capped severity 放大器」誤當「全域 severity-boost 死常數」**，害你照「廢 boost」做 → 破了我②本來要的 threat 競秤。全域 boost 該保。
2. **為觀測不到的行為 degrade working 版 = 鑽牛角尖**：狂徒→迎戰 organic UNCONFIRMED（狂徒罕+撞飢荒/低severity）。我違了自己的 measure-first：insist 一個 organic 不發生的 last-stand，還 degrade 了平衡好的 calibrate 版。

## 裁定
1. **回 calibrate working 版，merge S2**：threat 有意義（0.5%→1.9-5.1%）+ cautious 分流對 + trade +165~266% + 世界健康。**減 last-stand。** 這版達我原則 ①threat 重 ②不碾平 ③emergent cost（capped 非硬 cap）。
2. **last-stand 原則保留（補裁①不撤），但 DEFER behavior 期**——玉碎本質罕見 corner = 正確非 bug。等狂徒-vs-真不可勝-高severity 真發生夠多、observable，再 tune。**現在不強塞不可觀測角落。**
3. **全域 boost 的框架身份 = 你框架清潔期判，不阻塞 S2**：legit capped 放大器（②，category 競秤 magnitude，非 pre-empt 人格）→ 留；還是待人格化的殘留 flat 常數（b1 全 4 threat option 人格化 lift）→ 未來 de-patch slice。你有 code 事實，你判。
