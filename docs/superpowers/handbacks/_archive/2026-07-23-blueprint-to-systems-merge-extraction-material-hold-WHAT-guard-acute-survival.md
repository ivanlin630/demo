# 裁：merge extraction + material-hold-protection（WHAT 精修 + acute-survival 守護）

## ① merge extraction 認可
機制真生效（fire 66%、中位人格取回 152-169 coin、無新餓死、necessary、無迴歸）→ **merge**。

## ② 認三腿 reframe
脫貧 = **食 + coin liquidity + material HOLD-protection**。reserve_factor-suppression 是**同一個 villain 三度出現**（coin 被它鎖、material 被它賣光）——patch-gate-first 每次都挖到它在下游的下一個化身。

## ★③ material-hold-protection：方向認可，但 WHAT 精修 + 守護
認可方向（patch-gate-first、連 material means-end、同 idiom），**但別直接「當 survival floor 一樣全保護」**——那生**新失敗模式**：
- construction-material 若 need_keep 完全不乘 factor = survival 級保護 → **餓隊會抱著「自己規則說要留」的 material 餓死**（material 不能吃、又不肯賣去買糧）。這是加保護會引入的迴歸，不能不防。

**★真 WHAT = decouple 兩種 urgency**：
- construction-committed material 對 **【coin-urgency】免疫**——coin 焦慮但食物 OK 的隊，賣掉自己要蓋的料 = **incoherent**（這正是本 case 的病）。
- 但對 **【acute food-survival】仍釋放**——真餓的隊賣光一切求生 = **coherent**（survival first 不變）。
- ∴ **不是 ranking material = food**，是 ranking **material > coin-anxiety-selling 但 < acute-food-survival**。
- **behavioral intent**：隊 committed 要蓋 X 且買了料 → 守住料熬過 coin 焦慮 + 中度壓力，但**真餓還是賣掉先活**。HOW（哪個 urgency 項驅動 reserve、閾值）你 scope。

## ④ coin_need 對齊 afford×1.5 認可
coin_need 估 material 缺口對齊 `cost×1.5`（extraction 才拉夠 coin 去買足量 material）。認可。

## ★⑤ QA 判準更新（重要）
**這次三腿都閉 → facility-rise NOW 才是端到端成功信號**——**不同**上次食安單獨那次（我說「別預期 facility 升，coin 鎖還在」）。現在全鏈通了：
- **成功 = facility count 真升**（端到端閉了）。**不升 = 還有漏**（要繼續挖）。
- **★守護必查**：加了 material 保護 → QA 故事稽核必查「**有沒有隊抱著 protected material 餓死**」（加保護引入的新失敗模式，這是硬迴歸檢查）。
- 兩個一起綠才 release-pass：facility 升 **且** 無抱料餓死。

## ⑥ 可能 generalize（標記，先別做）
真原則可能是：**means-end committed 資源（任何隊為 goal 買的、means-end 抬高 need_keep 的）都該 hold-protect** 像這樣（守committed投資不panic賣）。但**先 scoped 做 material 別 over-reach**（本場我已數次被 measure 校正過度下注），generalize 標記留著，material 這腿驗證有效後再看要不要推廣。

## 序
1. **merge extraction**。
2. **疊 material-hold spec**（帶 ★acute-food-survival 守護：對 coin-urgency 免疫、acute-food 釋放）+ coin_need 對齊 afford×1.5。
3. **三腿齊 → remeasure**：facility 端到端升否 + QA 故事稽核（facility 升 **且** 無抱料餓死）。
4. 後續：queue-limit 次要、GATE-B 排後、bootstrap 遷徙逃生閥。
