# ★用戶拉高標準：真統一（非「已統一」）

用戶定調:**重點是真統一。** 我太快接受 R① 的「已統一（同池/canonical 單源）」就降級 dispatch cleanup——**標準拉高了。**

## 「已統一」≠「真統一」
- R① 證 4 rank_* **同 applicable() 池、非繞過引擎** → 對，**排序沒繞過**。
- **但真統一更高**：還有 **4 個入口 + 手派 `return`-gate**（`if uses_unified(team): return` 按隊型手動路由誰走哪條）。**那些 return-gate ＝殘留非框架控制流**（手動路由焊 code，即使排序共用）。
- **按用戶零殘留原則：它們是殘留閘;按真統一：4 入口手派 ≠ 一條。**
- **∴ 我收回「dispatch cleanup ＝ cosmetic、降級」。真統一 ＝ 收斂成一入口、零手派路由。這是真工作,不是幻影 cleanup。**

## 「已統一」判決要重驗真統一
`threat「已統一(ThreatAssessment 單源)」`等 R① 判決——**真統一要問更深**:
- 呼叫端是否還在 canonical 函式**外**各自做（不同 filter / 各自門檻 / 近似重複）?
- **有 canonical 函式 ≠ 真統一**——若 4 呼叫端還各自繞、各套門檻,就不是真的一條。
- **重驗每個「已統一」判決:是真的一條路,還是「有個共用核心但周邊還散著」。**

## 真統一的驗收定義（兩原則合一）
```
零殘留閘 + 真統一 = 每個決策「真的只走一條統一路」：
  零手派 return-gate 路由
  零散落入口（一個 decision 一個入口）
  零 canonical 外繞道 / 各自門檻
  零近似重複邏輯
  零框架外硬門檻 / override / RNG 閘
```
**不是「有引擎、大致走它」,是「真的一條,無任何殘留繞道/路由/重複/門檻」。**

## R①-verify 剩項改問法
剩項（valuation/emotion/prisoner/死常數/內政 + dispatch + 重驗 threat）→ **R① factcheck 問「真統一否」**（真的一條路?）**非只問「有沒有繞過引擎」**（那太寬鬆,放過手派路由/散落入口/近似重複）。
