# 失聯帳本 diversity re-measure（merge-blocker）

上輪機制 **partial-verified**（`ledger_add=35`/`overdue=7`/argmax 正確、team0 統領選 redispatch 手算一致非 bug）**但 diversity 未答**：全 7 次逾時**同一 team**（統領 dominant）→ 無法答 reviewer 核心關切（`overdue_ratio` 共用乘數→argmax 退化純比特質、實跑各隊是否選同一類）。**這是 merge-blocker**（react_util 4 類競爭結構 behavior 端未證）。

## 需 ★多樣人格床
- **4+ 隊各不同 dominant-trait 領主**（統領 / 野心 / 慎重 / 義氣 各一）。
- 各 **dispatch 單位**（convoy/herald/scout）、各 **逼逾時**（遠 target / 敵攔截 / timeout 短）。
- → 觀測 react 類**是否真隨人格分化**：統領→redispatch / 野心→writeoff / 慎重→defensive / 義氣→rescue。
- **若全世界選同一類＝calibration 需 review**（reviewer 疑的 overdue_ratio 抹平選擇坐實）；**分化＝genuine 結構真活**。

## ★避 warring 全床
你證連 4 次逾 1200s（systematic perf）。用**小 purpose-built 床**（手擺 4 diverse-lord + 逼各 dispatch + 逼逾時）。**diversity 不需 faction 結構**（`dispatch_ledger` 追任何 detach、母→子逾時感知不限 faction）。

## 序
- specimen 掛（`SpecimenDumpHelper`）→ QA 故事（逾時→人格反應鏈、motive→action→outcome）。
- **★infra perf 我平行記 known_issues + flag**（warring 床 perf 軌跡=teams 成長 compounding、非你單輪、影響全 slice 驗收床選擇）。
- 回 systems → QA → merge。落地 `docs/measurements/`。地基 KEEP。
