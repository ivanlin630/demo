# 接受「真統一」標準 + 修正我的過寬判決 + 擴 gate scope

用戶標準**收下並修正自己**：**真統一 = 每決策真只走一條**（零手派 return-gate 路由 / 零散落入口 / 零 canonical 外繞道 / 零近似重複）。**canonical 單源存在 ≠ 真統一**（若呼叫端還各自繞/各門檻/手派路由）。

## ★我修正過寬判決（誠實）
- 我把 dispatch「4 rank_* 同 applicable 池」判「已統一 cosmetic→skip」**太寬鬆**：4 個入口 + **手派 return-gate 按隊型路由**（哪隊走哪 rank_* 是焊 code 的控制流）= **殘留控制流閘 = 非真統一**。**收回 skip，收斂是真工作。**
- threat「ThreatAssessment.score canonical」**要重驗真統一**：4 呼叫點是否還**各自加 margin/繞道/各門檻**（canonical 存在但呼叫端不一致=非真統一）。
- ∴ R① 的「已統一」判決在**新標準下部分翻案**——canonical 源 ≠ 一條路。

## ★constitution_gate 強化 scope 擴大（兩類閘都抓）
1. **值閘**（原計畫）：硬門檻 / override early-return / RNG-in-decision。
2. **★控制流閘**（新加）：**手派 return-gate 路由**（按隊型/tag/context 手動選 decision 路徑）、**散落入口**（同決策多入口非單一 dispatch）、**近似重複公式**（canonical 外手刻版，如 R①-batch 抓的估值 `faction_ai:2092-2096` belief 版）。
- **綠 = 每決策一條統一路可證 = 零殘留閘 + 真統一合一**（用戶要的硬驗收）。歧義（好/壞）仍 baseline-freeze + de-patch 進度處理。

## 收斂後 map（R①-batch + 真統一標準）

- **值閘（de-patch）**：②`_threat_recent` + ③`FEUD_ATTACK_MIN`/`VIABLE_ARMED_RATIO` + section-A（你的清單）。
