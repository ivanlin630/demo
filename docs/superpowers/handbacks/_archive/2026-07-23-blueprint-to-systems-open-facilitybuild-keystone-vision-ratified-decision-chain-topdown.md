# 裁：開 facility-build keystone NOW + vision 認可 + top-down 決策鏈序

## ① vision 認可：poverty-trap 逃生 = 發展層願景本體
**認可**。poverty-trap 逃生（求生高壓的隊掙脫、爬升去建設/專精/繁榮）**就是發展層願景本體**，不是附帶——它是**綜合發展模型（用戶 2026-07-15/16 定：商隊追財/軍閥追武/工匠追建設）的前置地基**：
- **全隊卡 subsistence → 沒有任何多元 archetype 分化的戲**（大家都在求生，誰都沒餘裕走自己的路）。
- ∴ **脫貧 = 那整套多元發展願景能不能長出來的地基**。食安→脫貧→發展是一條線，這條線通了，merchant/warlord/craftsman 的分化才有舞台。
- 符合沙盒「自己說故事」尺（窮部落掙扎翻身 = 強戲）。**folds game-design 已有的食安 arc『為何重要』，一致。**

## ② coin 升 keystone-level 確認，但 folds 非獨立
- coin poverty = **keystone-level 確認**（91% 廣布、mil+civ 皆是、結構性非 transient）——從「窄 mil defer」正式升格。
- **但 necessary-not-sufficient**（facility 近零 regardless of coin）→ **folds facility-build 當三根之一，不開獨立 coin arc**。倒著先修 coin 會白做（已證）。
- **★scope-measure 紀律回本**：若當初信 3 隊就開 coin 專屬修 = 失敗（necessary-not-sufficient 那時看不到）。先量 scope 擋掉一個註定失敗的修法——這是「別過度概括、先量分布」直接省一刀。

## ★③ 開 keystone：measure-first，但硬要求 top-down 決策鏈序（別倒修）
認可 measure-first 開場，但**序要 top-down**（facility 近零 regardless coin = binding 在決策端非資源端 → 先查決策）：

1. **先量 build-decision fire 率 + 誰 preempt**——**★patch-gate-first！** survival-override preempt 是**已知 prior**（早先 workshop-build 終閘 = farming survival-override 碾 specialization = **同一個 trap**）。**優先查是不是又一個 survival-override 硬閘 pre-empt 建造決策**，別先猜 tuning。這是本場「補丁閘優先查」通則的正面應用——behavior 近零 = 先找 override 閘。
2. **decision 若 fire 但選錯** → 查 means-end want 生成（target = flat cap 100 非 goal-derived 那條）。
3. **want 對但湊不到** → 才輪 accumulation locks（coin/food/reserve）。

**不准倒著先修 accumulation**——coin necessary-not-sufficient 已證倒修白做。

## ★④ binding-hypothesis 本身要 measure 坐實（新 R① 第 3 案例，事前套）
「binding 是 build-DECISION 非 accumulation」是你 scope 判斷的 **causal claim**——照剛 ratify 的新 R①，**要 measure 坐實（build-decision fire 率 + preempt 源）再 spec，別假設**。你已經提 measure-first 開場，方向對，這裡只是明文標記：這是新 R① 的**第 3 個事前套用案例**（cost70 事後、③ movement pre-spec、這個 keystone-open pre-spec）。連著三次照新規矩走 = governance 修在工作流裡站穩了。
