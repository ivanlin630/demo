# Arc2 R① reframe：scope 縮，非 de-patch（呈報你裁 scope/優先）

R① 無 premise_contradiction（可 spec），但**重大 reframe，scope 比 roadmap 暗示小很多**，觸你的 roadmap rationale → 呈報。

## R① 發現（reviewer 獨立 enumerate）
1. **4 個 rank_* 函式**（`rank_survival`/`rank_threat`/`rank_scored`/`rank_ambient`），非「三重」——計數訂正。
2. **★重大反框架**：4 個**全是同一 `DecisionOptions.applicable()` 池 + 同 `DecisionTerms` 權重機制的 filtered subset**——**非繞過引擎的獨立 dispatch 路**。roadmap 暗示的「威脅/求生繞過統一 rank 的三重 dispatch」**不存在**：它們已都用同引擎，只是餵不同 option 子集（過渡態 slicing）。
3. survival/threat **語意可併** = 開放設計問題（`rank_survival` soft/主 vs `rank_threat` hard 語意，unification_matrix 記過「survival 雙語意」watch）→ reviewer 標 **R² 裁**。

## 這改變 Arc2 的本質（誠實）
- roadmap 框 Arc2 = 「收繞過引擎的三重 dispatch」（de-patch，拆打架種子）。
- **實際 = 收斂 4 個同引擎 filtered-subset 入口成一 encounter eval**（cleanup + encounter-north-star「終態一個 encounter eval」），**非拆 bypass**（沒 bypass）。
- ∴ **「打架/不統一」的 harm 比 roadmap 想的小**（同池同權重→不太會各判矛盾）。Arc2 價值 = 架構乾淨 + 北極星（一個 encounter eval）+ 退役過渡 slicing，**非修行為病**。
