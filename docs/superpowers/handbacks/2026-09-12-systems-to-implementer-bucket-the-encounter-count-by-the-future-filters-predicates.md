# ① 原本要的（不變）

```
**相遇一天幾次｜一個 tick 幾次（p50／p95／max）**
```

# ② ★★★順便要的分桶（★一趟答兩個問題）

```
同一次量測，把相遇數**依【未來過濾器會用的謂詞】分桶**：
  ①**敵對與否**（★★注意：這一格**可能違反外觀層限制** ——
     若「敵對」要讀 faction 關係／意圖 ⇒ **它不能當過濾器的判準**，
     ★但它**可以當量測的分析欄**（我們是觀察者，過濾器才受鐵律限制）
     ⇒ ★★★**兩者要分開寫**，別讓分析欄偷偷變成設計。
  ②**可見武裝**（有沒有帶武器／戰力外顯）
  ③**規模差**（人數比）
  ④**逼近**（是不是朝我來，而不是路過）
⇒ ★於是「相遇總數」與「**這幾個謂詞各自能篩掉多少**」**同一趟就有答案**。
★★而若最後發現「怎麼篩都篩不掉多少」⇒ **那本身就是結論**：相遇不是海量，直接全醒。
```

# ③ 過濾器的硬條件（★blueprint 給的，我逐字轉）

```
①**只准外觀層便宜謂詞**（可見武裝／規模／逼近）——**禁讀 tag／意圖**
  ⇒ ★理由是感知鐵律：**決策只能吃 belief，不能吃 god-view 真值**
②★★★**預設醒、具名靜** —— 過濾器是**具名的靜音清單**，不是**具名的喚醒清單**
  ⇒ ★理由是我們的不變量原句：**沉默的預設要落在安全側**
  ⇒ ★★所以實作出來的形狀必然是「**這幾種相遇不喚醒**」，
    **不會**是「**這幾種相遇才喚醒**」—— 兩者在 code 上差一個 `not`，在世界上差很多。
```
