# 一、★★★我錯在哪

```
我昨天才寫過「先問母體再問比率」，★而我鎖定義的時候**沒有對自己套用它**。
算式（用 U₇ 同一個 8 天窗的卷面）：
  gather 呼叫 9237｜tick 11520｜隊數 ~103
  ⇒ 每隊平均 gather 89.7 次 ⇒ **平均每 128.5 tick 才輪到同一隊**（cadence，本來就該這樣）
  ⇒ ★「相鄰兩 tick 都有同一隊的 gather」**幾乎不存在** ⇒ **母體 ≈ 0**
⇒ ★★而 0/0 在卷面上會長成「100%」或「—」，**兩種都會被讀成「快取很安全」**
```
★**這是我今天第 N 次的同一個病，而這次它發生在【我自己剛立的規矩】上**
（我今天在別人身上抓了「驗收假設不存在的開關」，而我自己 spec 出了一個**量不到的量**）。

# 二、★訂正（已同步 HOLD implementer）

```
【主量 (丙′)】同一隊的**相鄰兩次 `gather`**（不論隔幾 tick）逐欄比對 ⇒ 不變率
   母體 ＝ **≈ 9134**（9237 − 103）★真的有母體
【必印】★**tick 間距分佈**（median／p90／max）——
   ★★★**跨 tick 快取要重用的就是【跨過那個間距】的結果**
   ⇒ 「隔 1 tick 不變」與「隔 128 tick 不變」是**兩個強度完全不同的主張**
```

# 三、★★要你裁的一件：**門檻不能照抄**

```
95% 是對著「相鄰兩 tick」預註冊的；現在的量是「相鄰兩次 gather（平均隔 128 tick）」
⇒ ★**referent 換了** ⇒ 照抄 ＝ **「把門檻指向另一個量，然後說它通過了」**
   —— 而那正是預註冊本來要防的事
⇒ ★★我**不自己改**。三個選項，你裁：
   (甲) 95% 照舊（★而它現在是一個**更難**的門檻：要跨 128 tick 還不變）
   (乙) 依間距重新定（例如：**按間距分桶**，各桶各自報不變率，門檻只對「快取真的會跨過的那個桶」）
   (丙) 先看數字再定門檻 ⇒ ★**我不建議**（那就不是預註冊了）
★★★我的建議是 (乙)：**它讓門檻對著【快取真正要跨過的那段距離】**，
   而 (甲) 的風險是「一個過嚴的門檻把一個其實可行的窄形狀誤殺」。
```
