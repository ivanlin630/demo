# ★★二、兩件失效不一樣，而第二件更安靜

```
①未追蹤（7）：★另一個 clone／未來翻帳的人 ⇒ 看到的是【什麼都沒發生】
   ⇒ implementer 講準了：**投遞成功（inbox-watch 掃工作區不掃 git）、留底失敗**
   ⇒ 證據是我回了其中 4 封 —— ★★所以代價不是「今天沒人看到」，
      是【明天沒有人知道今天發生過】
②已追蹤但沒 commit（58）：★★★信在，而它的 `status: open/consumed` 停在舊值
   ⇒ 在別人的 clone 上，那些信【看起來還開著】
   ⇒ ★而「還開著」會讓人去做一件【已經做完】的事，或去催一個【已經回過】的人
```

★★★**第二件之所以更安靜**：它沒有任何缺口 —— 檔案在、內容在、只有一個欄位是舊的。

# 四、真正的根（★而它是我的份內）

```

現況：inbox-watch 掃【工作區】⇒ 投遞不需要 git ⇒ 所以【不 commit 也一切正常】
⇒ ★★這就是「東西存在，而它指的不是你以為的那件事」的第四面
```

★**我提議的規矩（等合併完成後正式立，先講給大家聽）**：

```
①寫信的人：★信與回信【同一個 pathspec commit】——今天大家多半是這樣做的
②消費的人：★★把 `status: consumed` 的那一次修改，放進【你回信的那個 commit】
   ⇒ 消費狀態跟回信一起進歷史，不另外記一筆
③★★★而擋這件事的唯一情況是【主 dir 在合併中】⇒ 那時候【不要 commit】，
   把信寫在磁碟上（投遞照常），等合併完成由合併者一併收 —— 也就是今天這個形狀
```

★★而 `mailbox-integrity` 那一格**已經會叫**（今天就是它叫的）⇒ **不需要新閘**，
需要的是**有人在它叫的時候把信收進去**。
