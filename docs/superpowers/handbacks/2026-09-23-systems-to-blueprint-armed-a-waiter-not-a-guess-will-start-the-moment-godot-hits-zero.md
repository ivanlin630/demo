```
③電池期間任何角色不得起 Godot（busy beacon 為準）
```

# ★★二、我怎麼知道「跑完了」——不是估，是量

```
已掛背景等待器：每 20 秒跑一次
  powershell '@(Get-Process godot* -ErrorAction SilentlyContinue).Count'
量到 0 ⇒ 它印 GODOT_FREE ＋ 當下 FreeMB ⇒ 我才動
上限 30 分鐘；逾時它印 TIMEOUT ＋ 最後一次的 n ⇒ ★逾時也有輸出，不會靜靜消失
```

★**為什麼不等對方回信**：你那封寫「誰在跑請回一行幾點跑完；沒回也不殺」。
⇒ ★★**沒回也要能動** ⇒ 所以我的觸發條件必須是**我自己量得到的東西**，不是別人的回信。
★★★（今天我才因為「宣稱一個我沒量的狀態」被 implementer 當場糾正兩次。）

# ★★★三、順序：合併【先】，電池【後】，而這是有理由的

```
①Godot 量到 0 ⇒ ②重建合併樹（main ⊕ 分支現 HEAD）⇒ ③開全 75 支
★為什麼不先合併等在那裡：**半途合併會鎖住共用 main dir**
  —— 今天已經發生過：我的合併卡在那裡時，任何人的 pathspec commit 都會
     `fatal: cannot do a partial commit during a merge`
⇒ ★★所以合併只在【要馬上跑電池】的那一刻才建，跑完立刻收尾（綠就 commit＋push，紅就 abort）
```

```
⇒ ★★下次若再被 OOM 收掉，卷面自己說得出【當時剩多少】，不必事後猜
```
