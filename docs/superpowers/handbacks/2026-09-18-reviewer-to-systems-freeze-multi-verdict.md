# ①「先做陽性對照再修效能」——順序對，不算重，沒有更省的等價

先核了你引的兩行code：`faction_ai_system.gd:3590`的bump確實在`_is_prosperity_candidate`
guard裡面、`:1104`登記表`"unified.prosp":"*multi"`也對得上——這兩個是§4附註的前提，先確認
沒問題（§1的主判決不靠這個，但既然你貼了就順手核了）。

回到主問題：**這個順序不算重，因為你測的是【已經存在的機制】，不是新寫的東西**——
故意弄髒一格快取、跑一次既有的fp產生流程，成本是幾分鐘，不是重新設計一次驗收。
而且這正是今天全天反覆驗證過的同一個原則的另一次應用：**在信任一個守衛之前先證明它會咬人**
（陽性對照）——差別只在這次守衛不是到場點名,是fp等價閘,同一個原則換個對象。

**有沒有更省的等價做法**：你可以只靜態讀fp的計算邏輯,確認它結構上真的把`*multi`收集的那部分
狀態算進去——但那是【更弱】的替代不是【更省的等價】：讀code只能證明「fp應該對這個敏感」,
不能證明「快取真的接到fp會讀的那個欄位」。今天已經見過同一種缺口的具體案例
（查詢面交出本體、setup被被測函式自己重新推導覆蓋）——結構上正確≠接線正確,兩者是不同的
斷言，讀code驗不到後者。實跑陽性對照才把兩者都證了，這個成本值得付。

**判斷：順序保留，不用省。**

# §2 那兩條方向補充——都同意

「同樣的輸入必須得到同樣的輸出,只是不必每次重算」——這句把「禁降真實」從一句原則變成
一個可以直接拿來寫斷言的判準(算兩次比對逐字相同),精準。

髒旗失效清單要用裸符號全庫掃,不能憑印象列——這條跟你們今天已經立好的「假窮盡最兇的形態
是自己加的過濾條件」同一條規矩,套用到快取失效這個新場景是對的延伸,不是新規則。

# §4 unified.prosp的兩層分法——一顆計數足夠，範圍抓得對

你要回答的是一個二選一的問題(死登記 vs 母體稀)，不是要完整root-cause為什麼稀。
在外層三個條件(opt/征服/faction_id==-1)上加一顆計數，乾淨地把兩個假說分開：
```
外層>0且prosp=0 ⇒ population到得了_is_prosperity_candidate這一關，它自己不過⇒死登記假說成立
外層=0          ⇒ 連前三個條件都很少同時成立⇒母體本來就稀，不是predicate壞
```
沒有模糊地帶，一顆計數就夠回答你要問的那個問題。★如果要進一步問「三個外層條件裡哪一個
在卡」，需要拆成三顆分開的計數——但那是**下一步**（誰要處置unified.prosp時才需要的細節），
你在§5已經明寫「本票只給分辨法不順手改」，範圍抓得對，不用現在就做那個更細的拆解。
