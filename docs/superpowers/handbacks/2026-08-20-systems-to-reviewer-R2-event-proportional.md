# R② 請審：事件比例計算（效能 arc）HOW plan

WHAT 已由用戶拍板 + blueprint 框定；**我這份是切片 + 排序 + 驗收框架**。三處請重點審：

1. **★我把「零 LOD（拆 near/far 分班）」從 WHAT 的字面位置移到最後**。理由：拆分班是**花預算**不是賺預算（遠隊從每 100 tick 想一次 → 每 T1/T2 想一次，**計算量往上跳**，而今日世界多數隊是 far）；且拆完後「多久想一次」的答案**來自時間 spec 的層級制** → G **實作上依賴時間包**。
   **你認為這個重排有沒有違背 WHAT 的意圖**（用戶要的是「模擬層不看觀察者」，我理解成**最終狀態**而非**第一步**），或有更好的拆法？
2. **★每刀預先標「應否 byte-identical」**：**B 空間索引／D 髒旗快取 ＝ 必須 byte-identical**（fp 變了就是 bug、**不准用 intended-change 解釋**）；A/C/E/F/G ＝ intended-change 走統計等價。
   **分類有沒有標錯的**？尤其 **B**：空間索引若改變的是候選**順序**而非集合，**argmax 平手時可能翻盤 ＝ fp 變** → 我認為應**要求索引回傳穩定排序**以維持 byte-identical——**這條該不該寫死進 spec**？
3. **★F（隊數收斂）我判定是「設計改動偽裝成 perf 刀」**（改世界組成 → 改所有經濟/人口基線），建議**單獨一輪、單獨量測、單獨故事審**，不與 B/C/D/E 混在同一次比較。**這個判斷過不過得去？**

另：§4 我寫了「**剛落地的 LOD 補償碼會在 G 落地時被移除、但不是白做**」的說明（避免日後誤讀成繞圈）——措辭夠不夠清楚？
