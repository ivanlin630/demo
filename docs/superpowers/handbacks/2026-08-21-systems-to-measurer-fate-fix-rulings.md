# 三題全裁

## ① 多趟追蹤修法 → **提交進床本體，不 revert**
**它不是 temp tap，是真的儀器修。**

★ 而且我把它**升成 `invariants`**〈**以 id 為鍵的量測記錄，必問「同一個 id 會不會有第二次」**〉：
- 容器要是 **`id → Array[事件]`**
- 開新事件的條件是「**無記錄 or 最新一筆已終局**」，**不是「這個 id 沒出現過」**
- **報「追蹤了 N 個」時要同時報「共 M 個事件」——`N ≠ M` 就是警訊**

★ **這是同一天第三次同族**：
① specimen 選樣清單**凍結** ② fate 分類器**以「隊伍消失」推論** ③ trip 記錄**以 id 為鍵**。
**共同形狀 ＝ 儀器悄悄少算，而少算出來的數字看起來完全正常。**

## ② porter_22 的 ghost → **要看，而且它比表面重要**
它 `dispatch@16900` ＝ **day 70.4**，而我設的**防呆絕對上限是 60 日**
⇒ **把窗拉到 150 天**：
- 若它在 **day 130 前後被 `by_abs_cap` 收掉** ⇒ **gate 9／gate 10 第一次拿到真樣本**
  （gate 9 ＝ `stranded` 當下距母隊 ≤2 格的比例，**證偽誤殺**）
- 若到 150 天**還是 ghost** ⇒ **連絕對上限都沒生效**，那要查（我設的兜底沒作用 ＝ 又一個 inert 機制）

★ 這比「單純好奇它去哪」值錢得多——**它是目前唯一有機會驗到 T3 的自然情境**。

## ④ 你那句自評我同意
「**本身沒錯但不完整**」—— **不是誤讀已有數據，是儀器結構性只追第一趟**。
**這種區分要繼續這樣寫**：它讓帳目能分辨「判讀錯」與「看不到」，那是兩種完全不同的問題。
