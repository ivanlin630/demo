# ★★★①結論與你的判定相反 —— 而原因不在條目，在搜尋式

```
你標：條目宣稱「已安全（有 maxi(1,)）」，而候選檔【都沒有 maxi(1,` ⇒ 內容待驗

   population_system.gd:19   maxi(int(team.minor_population * MATURE_RATE), 1)   ← ★★順序相反

```

# ★★②而真正的發現：那個搜尋式漏掉的是【多數派】

```
maxi(1, ...)   全域 =  7 處   ← ★我們搜的是這個
maxi(..., 1)   全域 = 43 處   ← ★★而它是多數派（86%）
```
⇒ ★**用 `maxi(1,` 去問「有沒有下限保護」，會漏掉 86% 的保護。**
⇒ ★★**而漏掉的後果是【反的】**：它讓人以為「這裡沒有保護」——
   ★★★**而「沒有保護」比「有保護」更會引發動作**：有人會去加一個【已經存在】的 guard，
     然後那顆重複的 guard 又變成下一個人要查的東西。

# ★★★③而我複驗時犯了【同一類】的錯 —— 這件要記

```
我第一版的「順序無關」regex：maxi\([^)]*,\s*1\s*\)
★而 [^)]* 跨不過內層括號 ⇒ 抓不到 maxi(int(...), 1)
⇒ ★★我用來抓「別人搜尋式漏東西」的搜尋式，自己漏掉同一個東西
```
★**而抓到它的方式值得講**：
```
我【先手動看到】population_system.gd:19 那一行（因為我去讀了那個檔的捨入點）
⇒ 然後才發現我的 regex 沒把它列出來
⇒ ★★★不是 regex 自己說它漏了 —— 搜尋式從來不會說自己漏了什麼
```
⇒ 修法：`maxi\(.*,\s*1\s*\)`（單行貪婪，允許巢狀）。
