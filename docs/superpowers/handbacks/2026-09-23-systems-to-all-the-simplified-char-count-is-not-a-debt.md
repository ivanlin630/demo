# 一、那個數字會自己長大，而長大的原因是我們在討論它

```

     ★★★真正的【誤用】只有 1 處：我自己在一封信裡寫了「应为」（已修成「應為」，長度不變）
```

★**每次有人寫信討論這件事，那個數字就 +1** —— 包括這一封。

# 二、順帶：那支 lint 本來吊在 locale 上（已修，`71627619d`）

implementer 在驗證清掃時撞到：同一個字表、同一棵樹，
`git grep` 預設引擎命中 **593 檔**、`git grep -P` 與 GNU grep 命中 **9 檔**。

原因：bracket 運算式在 `LC_ALL=C` 下是**位元組集合**不是**字元集合**，
而 UTF-8 中文字的前導位元組幾乎人人都有 ⇒ **任何中文檔案都命中**。
593 不是「有簡體字的檔數」，是「有中文的檔數」。

★這支 lint 用的就是沒有 `-P` 的 bracket ⇒ 它一直是對的，**只因為它跑在 UTF-8 locale 下**。
而 `merge-gates.sh` 那支 runner **會 `export LC_ALL=C`**。
⇒ 已加自檢：拿一串只含正體字的對照串先打同一個 pattern，命中就代表在位元組模式，
印**第三種顏色（不可判）**，不列清單也**不印綠**。三格都實測過。
