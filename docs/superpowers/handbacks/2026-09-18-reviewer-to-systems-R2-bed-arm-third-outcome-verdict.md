# 誠實限的三個子問題——我自己動手核了20支，不是純推理回答

## ①保守方向(任何字面Probe⇒判適用)對不對——對，但我找到一個會被誤傷的真實案例

我逐支grep了implementer列的20支,結果：
```
19支：字面Probe出現次數=0
1支(fp_behavior_coverage_bed)：出現2次
```
開檔看那2次是什麼——**不是這支床自己讀寫Probe**，是一句斷言在檢查【另一個檔案的原始碼】
裡沒有殘留`Probe.bump(`（`_ok(not src.contains("Probe.bump("), ...)`）。這支床本身完全不碰Probe,
implementer原本的窄判準(限定`.counts/.bump(`等具體API)正確排除了它;你提的寬判準(任何字面
Probe⇒判適用)會誤傷這一支，把它錯誤地推回「適用」那一堆。

**判斷**：方向仍然對(寧可多抓幾個假警報,不要漏一個真的)，但**不是零成本**——會多出至少1支
需要人工說「這支是誤傷」。給你一個真實數字讓你評估這個代價：20支裡1支誤傷，比例可接受，
方向維持。

## ②有沒有更好的判準(掃helper)——不建議，會製造它自己要防的那種債

我檢查了這20支有沒有呼叫任何`XxxHelper.method()`型的共用helper——**全部0個**，
這20支都是自建`WorldState`的獨立fixture,不走任何共用setup路徑。這代表**目前**沒有間接
Probe usage的實際案例(我查得到的範圍內)，但這個乾淨結果本身就是理由：**若要「掃helper」
變成判準，你需要維護一份「哪些helper會touch Probe」的清單**——那份清單本身會腐爛,
跟你正在逃離的白名單債是同一種形狀。目前這20支不需要它(查證下沒人走helper)，
不建議現在就加這層複雜度。
