# 一、★掃描結果（★判別句：「這兩份 drift 時，我會說【壞了】還是【抓到了】？」）

```
①相位床用 `FactionAISystem.PHASE_PARENT`（**沒複製**）
   ⇒ 若複製，drift ＝ **床過期** ＝ 壞了 ⇒ **不該複製** ✔
②普查床從原始碼推導週期值（**沒手抄清單**）
   ⇒ 若手抄，drift ＝ **掃描器過期** ＝ 壞了 ⇒ **不該複製** ✔
③方向守衛複製威脅判準（**複製了**）
   ⇒ drift ＝ **實作漂離意圖** ＝ **抓到了** ⇒ **該複製** ✔
④★★★**註冊表 `expect` 複製床的橫幅** ⇒ **兩格都不是**
```

# 二、★★★第四種：耦合（★而它有成本，已經收過兩次）

```
`expect` 是【床輸出的一份副本】，而它住在**另一個檔**。
⇒ drift 時：**不是床壞了**（床是對的）、**也不是抓到了**（沒有任何缺陷被揭露）
   ⇒ **是註冊表過期** ⇒ ★**而後果是【靜默不命中】＝ 那支閘不再守任何東西**
★血證（今天，兩次）：
   ・`intel-wake-godview` 點名 5／5 → **6／6**（加正向錨）⇒ 我手動改了 `expect`
   ・同一支 6／6 → **7／7**（加 B6）⇒ 我又手動改了一次
   ⇒ ★★**兩次我都記得了，而「我記得」不是機制。**
★★★而這個耦合**不是可以消掉的**：`expect` 的存在理由正是「不讓床自己說自己過了」
   ⇒ 它**必須**在床外面 ⇒ ★**耦合是這個設計的代價，不是它的 bug。**
```

# 三、★我不提議改它（★★但有一個便宜的觀察）

```
✘ 不提議把 `expect` 自動化（那等於讓床自己宣告通過 —— **把它的存在理由拆掉**）
★**而有一個便宜的縮小**：**expect 盡量釘【語意行】而不是【點名行】**
  ・`world-fp` 我釘的是**指紋行** ⇒ ★**加一格不會動到它**
  ・`intel-wake-godview` 我釘的是**橫幅（含點名數）** ⇒ ★★**每加一格都要改**
  ⇒ ★★★**同一支閘的兩種釘法，維護成本差很多** —— 而我今天兩次改的都是後者。
⇒ **要不要把它改成釘語意行，是你的欄**（★我不自己動註冊表的既有語意）。
```
