# ★乙 boost 查真面目：真實價值計算 vs 硬加常數（用戶命門）

## 用戶核心擔心（決策引擎命門）
**腳本化 OR 無意義分數競爭。** 決策引擎能成立的前提：**分數 = 真實價值**（共同尺度）。一旦「因某行為不發生就 crank 它分數到會贏」→ **分數變旋鈕、競爭變假數字比大小、廢掉引擎意義。** 這是根本原則，非小事。

## ★求你查（讀你自己 code，非破壞）
乙 merged 的整併 util boost（`ce369dca`）到底哪種：
- **(a) 真實價值計算**：吸併 util 算「**我真正得到什麼**」（target 的 pop / 資源 / 地盤 / 軍力 − 成本/風險），人格 weigh 那份**真 value** → **合法、保留**。
- **(b) 硬加 drive 常數 / tuned 讓 absorb 贏 argmax** → **就是用戶怕的無意義分數競爭 → revert、改 (a)。**

## 原則（守憲法決策模型）
**util = 真實期望價值（共同尺度）；人格 MODULATE 那份真 value（野心更看重擴張回報），非另加一個 arbitrary boost 常數把它推到贏。**

## ★若 genuine-value 算出來仍低 = finding，非 paper over
若吸併一個 **3 人小團**的真實價值本來就低（+3 人、邊際小 → 該低、隊不該吸是理性的）→ **那是真發現，根在上游**：
- **「變大」有沒有真好處**（規模經濟 / 大勢力更強/更富/更穩）？沒有 → 「有大有小」缺真動力、得先讓變大值得（世界設計，回我拍板）。
- 或**為何碎成 3 人**（不值得被吸）。
- **boost 只是遮這個上游問題。**

## 序
你查回：**boost = (a) 還 (b)** + 若 (b) 改 genuine-value 的 HOW + 若 genuine-value 算出仍低 = 上游 finding。**HOLD §5 待此釐清**（若 boost 是 b 要 revert，§5 基礎變）。**revert/keep 用戶最終裁**，我要你先給真面目 + 若需 revert 的 genuine-value 方向。
