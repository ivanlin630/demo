# ★澄清原則：框架只管規則，不管驅動與思考（治商業+生產兩 arc）

用戶點出核心,修正我前幾封措辭糊（「掛單層進框架+人格化」易誤讀成把邏輯搬進框架 code）。**這是沙盒憲法（作者寫世界不寫決策）的精準版,治商業（in-flight）+ 生產（new）兩 arc。**

## 兩層分明
- **框架＝世界規則/機制**（中性世界物理，不做決定）：
  - 商業：成交怎麼結算、賣單/買單結構、market-as-place 怎麼撮合、accessor 讀持有、守恆。
  - 生產：設施怎麼蓋（成本/時間/產出）、goods 怎麼產、資源怎麼轉。
  - **框架只回答「規則允許什麼、機制怎麼運作」,不回答「該不該做」。**
- **思考＝DecisionEngine + 人格**（NPC 自己想，驅動）：
  - 要不要貿易、跟誰、什麼價、掛不掛單、掛什麼單。
  - 建什麼設施（工坊/農田/軍事）、食安後追哪維、發展節奏。
  - **所有「要不要/選哪個」＝思考層,人格秤,非框架。**

## 補丁閘為何是病（精準診斷）
補丁閘＝**把決策焊進機制層**（`恆-hungry→強制建農`、`SURVIVAL→不掛賣單`、facility 硬優先序）→ **硬決定 pre-empt 掉本該思考層做的秤。** 這違「框架只管規則」。

## ∴「融入框架」的正確意思（別誤做）
- **✗ 錯**：把 `恆-hungry→建農`、掛單 if/else 硬邏輯**搬進** order_system/facility code「整理乾淨」——那只是**換地方藏補丁**,決策還在機制層。
- **✓ 對**：**決策從機制抽出來 → 交思考層（DecisionEngine + 人格秤）**；機制層只留**純規則**（設施建造機制、賣單結算），無任何「該建什麼/該不該賣」的判斷。
- **檢驗**：改完後,order_system / facility 機制 code **應讀不到「決定要不要/選哪個」的邏輯**（那些都在 DecisionEngine + 人格）。機制 code 只有「怎麼執行規則」。

## 套兩 arc
- **商業（in-flight）**：掛單「要不要掛/掛什麼/什麼價」＝思考（引擎+人格）;order_system 只留「賣單結構+結算規則」。成交條件（流動偏摩擦 tolerance）＝人格秤,非 order_system flat 常數。
- **生產（new）**：「建什麼設施/食安後追哪維」＝思考（引擎+人格）;facility code 只留「建造機制（成本/時間/產出）」。恆-hungry 等閘＝決策焊進機制 → 抽出交思考。

## 不變
- 全程人格化、無殘補釘、新決策路接 tap（守全量暫態可觀測）。
- HOW（怎麼把決策接進 DecisionEngine、機制怎麼留純規則、切幾 slice）＝你。我只定「框架＝規則、思考＝引擎+人格,兩層分明,決策不焊機制」。
