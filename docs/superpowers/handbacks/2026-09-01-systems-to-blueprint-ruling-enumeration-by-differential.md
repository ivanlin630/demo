# ★①先講為什麼**不能只用命名軸**（這是整個裁定的支點）
最直覺的枚舉是掃 `*_PER_TICK` / `*_RATE` / `ALPHA` / `DECAY` 這種名字。
★★**而這一類裡就包含【病6 命名說謊】**：`HP_REGEN_PER_TICK` 的名字說它是 per-tick，**真語意是 per-cadence**。
⇒ ★★★**用【名字】去枚舉一個【名字會說謊】的類 —— 說謊最兇的那幾顆會正好落在網外。**
★**那跟我們今天已經數過兩次的形狀是同一個**：檢查用的軸，跟失效用的軸，不是同一根。

# ★★②裁定：**枚舉用三刀取聯集**（★三刀不同軸，故意的）
```
刀① 用法軸（★機械，不看名字）：源碼中 `x += C` / `x -= C` / `x *= C`
     且 C 是 module-level 常數、該函式在 cadence pass 內
     ⇒ ★★這一刀補的正是命名軸的漏：它問「它每次呼叫做了什麼」,不問它叫什麼
刀② 命名軸（★heuristic，補網）：PER_TICK|PER_DAY|_RATE|ALPHA|DECAY|REGEN|CADENCE
刀③ 鏡像對帳（★exact，非啟發）：scripts/debug 內與 production 同名 const 而【值不同】者
     ⇒ ui_logic_test:77 那顆會被這一刀精確抓到，而它是唯一不靠猜的一刀
```
★**取聯集當候選。★★交集【不是】判準**——
★★★**並且要報「只被一把刀抓到」的那幾顆：那一格告訴我們哪把刀真的在做事**（三刀若高度重疊，等於只有一刀）。

# ★★★③而【判定】不用讀 code —— 用**換根微分試驗**
★**候選出來之後，「這顆會不會隨根漂」不要靠讀理由文字判**（那是詮釋，兩個人會讀出兩個答案）。
```
把 TICKS_PER_HOUR 從 60 調成 120，同 seed 各跑一輪，
★比對【每人日】的率：每人日回復 HP／每人日增飢餓／每人日平滑窗長 …
⇒ ★★正確導出的量【應該維持不變】；漂移的那顆會直接 ×2 露出來
```
★**這把「詮釋」變成「量測」，而且【一次跑同時判所有候選】** —— 不需要名字、不需要人讀理由。
★★**而這把尺已經證明能用**：S5c 就是用它量出疲勞 `0.50–0.52×` 的乾淨減半。

## ★★★誠實限（★必須跟數字一起出現）
```
①換根會讓世界軌跡分岔(不同 RNG 序列) ⇒ ★比的必須是【率】不是總量,且兩床都看
②★解析度下限:×2 的漂移在雜訊裡藏不住,×1.05 的藏得住
   ⇒ ★★這把尺答的是「有沒有整數倍漂移」,不是「有沒有任何偏差」
③★★★三刀都抓不到「時間語意藏在演算法結構裡而【沒有常數】」(如迭代次數)
   ⇒ 不宣稱窮盡;而那一格要靠 review,不是靠掃描
```
