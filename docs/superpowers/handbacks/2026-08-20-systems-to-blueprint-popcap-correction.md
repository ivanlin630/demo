# ★更正：我上一封的「領導天花板」診斷被 measurer 反駁

**REFUTED**：統領實測**全部 0.600**（非我推的 0.08）、`effective_pop_cap` **76–99**、population **3–6**、**AT_CAP=0.0%** → **cap 根本沒在綁**。
我的錯誤：把「統領 0.08 → cap 6」這個**算術巧合**（恰好等於量到的 median 6）當成坐實。公式是真的，「這條在綁」是我腦補的。

**★你那三項裁定不受影響、仍成立**（領導綁帽＝意圖 CONFIRMED 是意圖帳的事實；飽和剎車走 (乙)+(丙)；科目 A ＝診斷器、判準不改）——但**「村莊小」的原因換人了**。

**新診斷方向（這次標明：待測，非結論）**：人口成長引擎可能是**結構性關閉**而非速率慢——
1. 生育迴圈只跑 **named**（`reaction_system:21-36` 迭代 `state.persons`）＝ **anon cohort 完全不生**，而村人口主體是 anon。
2. `_breed_balance` 要求該隊 **named 中兩性皆有**（單性→0→直接不生）；小村 named 才 1–3 人 → 單性機率極高。
3. 還要 `food_flow_avg > 1.2` **持續淨盈餘**（而 labor-v2 那輪量測顯示多數隊 **chronic ≤ 0**）。

已派 measurer 用**既有 `reaction.breed` tap** 分解哪道門在綁（便宜）。

**★對你的意義**：若坐實「breed 全期零次 fire」，則「村莊小」**不是平衡問題、是成長機制沒接上 anon 模型＝機制缺口**；那 12mo 科目 A 的答案會是「**正循環斷在人口引擎、不在經濟**」——這跟你定的「大考是診斷器」完全一致，只是**斷點位置從領導換成生育**。

我不改 `game-design.md`，等 measurer 數字回來再呈。
