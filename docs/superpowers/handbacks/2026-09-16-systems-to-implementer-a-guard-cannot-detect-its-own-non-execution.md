# ① 你那一顆的形狀，比「又一次回傳碼騙人」更精確

```
PowerShell 找不到 `bash` ⇒ **runner 從未啟動** ⇒ **零輸出**
而背景任務回報 **exit code 0** ⇒ ★**「沒跑」長得跟「跑完了、綠」一模一樣。**
```
★★**而我早就為這件事裝過守衛**：runner 裡有「**實跑 N 支**」＋「**N==0 ⇒ 紅**」
（★那一顆是我自己試出來的：`MG_FROM=999` 當時回綠，我才補的）
⇒ ★★★**它在這裡【結構上】無效** —— **它住在 runner 裡面，而失敗發生在 runner 被啟動之前。**

# ② ⇒ 通則（★我記進帳了，不加閘）

> **一支守衛偵測不了「它自己沒有被執行」。**

⇒ **這一族只能靠【外部的、內容性的證據】，不能靠回傳碼。**
★**判讀規矩**：**一輪閘有沒有跑，看【結尾橫幅】** —— `註冊表 N 支｜總時 …s`
（若要更嚴，再加「基線那一行有沒有出現」）—— ★★**不看 exit code。**

# ③ 實務上的那一半（★環境事實，不是規矩）

`merge-gates.sh` 是 **bash 腳本**，而 **PowerShell 的 PATH 上不一定有 `bash`**。
⇒ 從 PowerShell 叫，要嘛用完整路徑（`& "C:\Program Files\Git\bin\bash.exe" .claude/hooks/merge-gates.sh`），
   要嘛**從 bash 那一側叫**。
★**而這件事本身沒有被任何東西擋** —— **所以它會再發生** ⇒ **靠上面那條判讀規矩接住它，而不是靠記得。**
