# ① 形狀

```
ref ＝ 自家人口 × Σ over res ( TARGET_PER_POP[res] × BASE_PRICE[res] )
richness_compressed ＝ CAP × (x/ref) / (1 + x/ref)，x ＝ Σ(估 × BASE_PRICE)
```
★**合法性**：零 god-view（只讀設計常數＋自己人口）／活的（乘人口）／永不空（人口≥1、兩表恆非空）。

# ② ★★★請你打的三點

```
①**`CAP ＝ 1.0` 是不是又一個手填數？**
   ★我主張**不是**：它的意思是「**與其他項同尺度**」（weakness [0,1]、border [0.3,1]）
   ⇒ **與 coin ＝ 1.0 同型：它是【單位定義】不是【估計】。**
   ⇒ ★★**但這正是我今天已經自我合理化過一次的形狀** —— **請你判它是不是同一件事。**
②**壓縮的代價有多大？** x＝1×ref ⇒ 0.5；x＝100×ref ⇒ 0.99
   ⇒ ★**差 2 倍不是 100 倍** ⇒ **「非常肥」與「有點肥」被壓得很近**
   ⇒ ★★請你判：**這會不會讓 richness 這一項【反過來變得不相干】**
     （我們剛把它從「碾壓其他兩項」拉回來，★★★**而拉過頭就是另一個方向的同一個病**）。
③★★★**人口驟降的隊，ref 變小 ⇒ 突然覺得所有人都很肥**
   ⇒ ★**可能是好戲（絕境者鋌而走險），也可能是病（打殘的隊四處們人）**
   ⇒ **我預先登記、不預先補償**，而驗收要報【人口驟降後的攻擊率】這一欄
   ⇒ ★★**請你判這個預先登記夠不夠** —— **或者它其實應該在本票就擋住。**
```
