# 一、★撤回

```
我上一封寫：「若掉的全部來自 intel ⇒ intel 佔修前喚醒 40.6%（s1337）／54.7%（s77）」
★**撤回**：那個算式的前提是【一支隊只被一個事件叫醒】。
⇒ 有重疊時，抑制 intel 不會讓那支隊少醒一次（別的事件仍然點到它）
⇒ ★★所以 40.6%／54.7% **既不是 intel 的佔比，也不是任何有意義的量** ——
   它是「無重疊世界」裡的一個影子。
★★★而我當時已經標了「分不出來、不下判」—— ★**但標了不確定仍然把兩個數字送了出去**，
   而數字比警語更容易被引用。**下次這種情況不要印數字，只印「切不出來」。**
```

# 二、★★★重疊為什麼量不到（★這一格是從 code 讀出來的，不是推測）

```
`world_events.gd:71`：`state.pending_rethink[id] = true`
⇒ ★**存的是布林，不是計數** ⇒ 同一 tick 第二個事件點到同一隊，**寫入的是同一個 true**
⇒ ★★**「這一隊本 tick 被幾個事件叫醒」在資料結構層就被丟掉了**
⇒ ★★★所以：**你的模型不是算錯，是【它要的那個數字從來沒有被存下來】。**
★而這也解釋了我上一封那個「兩顆種子差 14 個百分點」的怪事：
  ★★重疊率本身會隨世界密度變化 ⇒ 不同種子、不同密度 ⇒ 不同重疊 ⇒ 我那個影子數字自然亂跳。
```

# 三、★我不提議去量它

```
要量重疊，得把 `pending_rethink` 從布林換成計數（或存 kind 集合）
⇒ ★**那會動到通道本身** —— 而通道正是這張票宣稱【沒有動】的東西
⇒ ★★而你已經說了：**B3 會直接量到，再推一個估值只是多造一個會被引用的數字**
⇒ ★★★**所以我的回報到此為止：重疊不可量，原因在通道；不要為它開工。**
★若未來真要，它屬於「per-actor 消費」那張既有的 defer（`world_events.gd:1-20` 的註解裡就寫著）。
```
