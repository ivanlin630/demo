# 生產 merge 批 + emergence WHAT 裁

**供給側大成功,恭喜**——facilities 恆1→31.3%(含獨立隊 27.3%)、goods 18x、Manufacture 700x、no-op=0、餓隊沒餓死(食安地基靠軟急迫守住)、守恆 PASS、無殘補釘。**這是 R① 訂正後的設計成功**(urgency 真 fire、獨立隊真發展兩項坐實)——R① 那道閘沒白過。

## WHAT 裁:merge 不卡 multi-seed；emergence-confirm 走 fast-follow
**merge 依據＝框架 correct + safe + 主目標達成（全強證），非弱 emergence：**
- **主目標供給牆破**（facilities 建、18x goods、no-op 0）＝achieved。
- **safe**（餓隊沒餓死、守恆 PASS、無殘補釘）＝強證。
- **兩誠實項坐實**（urgency fire、獨立隊發展）。
→ **這些足以 merge 一個正確安全的框架。人格分化 emergence 是 richness 質量問題,mechanism 已在（leader_pref+_facility_personality）,弱證據（n=8）不 contradiction（team12 好戰沒建工坊＝忙軍事＝反而合願景）,且 tunable。**

**∴ 裁：**
1. **觀測閘綠即 merge**（不加 multi-seed 當 merge-block）。
2. **誠實 merge 標**：「供給牆破 + surplus 存在 + 食安無回歸;**人格分化 mechanism-present,emergence 待 multi-seed confirm**」——**別在 n=8 上 claim「人格化多路 emergence 已交付」**（守「measure 前不宣 victory」,這 arc 教訓）。
3. **emergence-confirm ＝ merge 後即刻 fast-follow multi-seed**（measurer 多 seed 聚合,看工匠→工坊/農夫→農/好戰→軍事乾淨分化）→ **弱則 tune 人格權重**（小 follow-up,非 merge block;架構對、權重可調）。

## 理由（為何不 block）
- 供給是**整條經濟下游 arc（deal 側）的前置**——surplus 存在了,死法②成交牆才有東西可流通。卡 merge 於 emergence-measurement 延誤下游。
- 架構正確（facility 決策走引擎+人格）＝對的骨;emergence 弱只是權重可能要調,不是骨錯。merge 骨、調權重。

## 剩餘（follow-up，非本輪，確認你分類對）
1. **deal 側仍低（sell_no_surplus 仍最大 bail）＝死法②同款成交牆**：供給「量」有了但**流通到 visitor 隨身可交易貨**未打通 → **下個 arc**。經濟全景:水管通（商業）+ 水有了（供給）→ 但**水流到買家手上（deal-flow）仍塞**。
2. A3 utility 化、GOVERN const 孤兒＝低優先 de-patch follow-up。
