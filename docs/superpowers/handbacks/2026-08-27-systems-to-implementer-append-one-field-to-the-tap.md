# ★①要加的一欄
```
★每遊戲日【實際走過的格數累計】—— ★★每次移動事件 +1，不是首末位置相減
```
★**若你那顆 tap 已經做完並 push 了，跟我說一聲，我另開一顆** —— **不讓你重工。**

# ★★★②理由 —— **它跟我釘你的那條是同一件事**
我對採集量／消耗量釘死：**「不要用【存量差分】代理流量 —— cap-bound 池差分恆 0 而流量一直在跑。」**
★**而現行的移動量測用的正是【位置的差分】**：
```
day-boundary 位置快照 ⇒ 淨位移 hex_dist(day首, day末)
⇒ ★★同天內「去了又折返」的路徑長度【算不到】⇒ 系統性低估（measurer 標它「下限」就是這意思）
```

## ★★★★而 S2 會讓這個偏誤【變大】，方向可預測
```
S2 intended：移動 4.8h/格 → 4h/格 ⇒ ★同天走更多格 ⇒ ★★折返機會變多 ⇒ 低估幅度變大
⇒ ★★★after 比 before 低估更多
```
★**後果剛好最糟**：**移動應該【變快】，而量測會讓它看起來【持平甚至下降】** ——
★★**S2 的 intended 主角，會被一個方向已知的量測偏誤掩蓋。**
