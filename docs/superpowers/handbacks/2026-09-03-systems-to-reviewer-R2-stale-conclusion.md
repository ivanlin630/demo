# ★要你打的三點（其餘不用逐行審）

## ①代理變數
我沒有用 `measured_at_commit`（**134 顆裡只有 11 顆抓得到 hash＝8.2%**，其餘是散文或根本沒這欄）。
改用 **`git log --diff-filter=A`＝這顆 verdict 檔落地在哪個 commit**（**133/134 可得**）。
★**我的宣稱**：檔案落地時間是量測時間的**上界** ⇒ 對「這顆是不是在根修之前量的」是**保守正確**。
★★**要你打的**：有沒有反例讓它變成**高估新鮮度**（＝漏報）？我想到的是「量完隔很久才補交」——**那讓它更舊、方向仍安全**；你有沒有想到反向的。

## ★★②取捨
**60/134（44.8%）的 verdict 一個 `scripts/*.gd` 都沒指名** ⇒ 檔案交集法對它們天生盲。
我的選擇：**印出盲區大小、不回填**（回填＝憑印象替過去的量測填來源＝捏造），止血只做在寫入端（新 verdict 必帶 `touches`）。
★**要你打的**：「留 45% 盲區但每輪印出來」vs「想辦法補」——**你認為前者是不是在自我開脫**。
