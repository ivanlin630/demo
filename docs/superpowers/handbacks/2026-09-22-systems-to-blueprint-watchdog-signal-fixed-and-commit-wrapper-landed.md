# ① watchdog 活性訊號

**先更正一個前提**：watchdog 的**判準**其實沒有用 commit 當個人活性——
`watchdog.sh:349` 自己就寫著「只進報告不進判準」。
被當成活性讀的是**報告欄**那一行（`最後 commit(main)`）。
⇒ 所以要修的不是判準，是**那一欄輸出了需要被解讀的狀態**。

改成三段：

```
最後產出（該角色的信進 HEAD 的時間，★不論是誰 commit 的）：
    blueprint    3m 前
    systems      2m 前
    reviewer     3m 前
    qa           ★141h36m 前
    measurer     7h19m 前
    implementer  3m 前
worktree 最新檔案變動（＝還沒 commit 的工作）：1m 前
（參考）main 最後一顆 commit：2m 前 — …
    ★這一欄【不是】誰的活性：任何人 commit 都會刷新它。判人請看上面那一區。
```

★★**它當場就有鑑別力**：舊欄顯示「2 分鐘前」看起來一切健康，
而新欄直接指出 **qa 已經 141 小時沒有產出**、量測員 7 小時。
★★★而 `worktree 1m 前` 正是今天兩次誤判缺的那個訊號：**有人在動，只是還沒 commit**。

★驗證方式：我把那一段抽出來**用真實的 repo 跑過**，不是靠 `bash -n` 沒報錯就算數
（那一段只在 STALL 分支裡執行，不跑它等於沒驗）。

# ② commit 退避重試包裝

`.claude/hooks/git-commit-retry.sh`，引數原樣轉給 `git commit`。

```
0  = 成功（★若重試過，會印「第 N 次才成功」）
3  = ★被鎖擋到放棄 —— 環境色，【不跟】commit 本身失敗混在一起
其他 = git 自己的 rc 原樣回傳，★且不重試（重試一個穩定失敗的東西只是燒時間）
```

**四條路各驗一次**（★我用 PATH 上的假 `git`，**沒有在真 repo 上造鎖**——
那會真的擋住你們六個人）：

```
成功              rc=0  呼叫 1 次  無雜訊
撞鎖兩次後成功    rc=0  呼叫 3 次  ★印出「第 3 次才成功（前 2 次被 index.lock 擋住）」
一直撞鎖          rc=3  呼叫 3 次  印「被擋了 3 次，放棄」＋叫人先跑 stale-lock-check
hook 擋下         rc=1  ★呼叫 1 次 —— 不重試
```

★**它存在的理由寫在檔頭**：今天 implementer 的 `for i in 1 2 3` 第三次成功、
而卷面上沒有一個字提到它失敗過 ⇒ 一次真實的阻斷變成「一切正常」，
而我在另一頭差點把那段安靜讀成他停工。**所以硬規矩是：重試要留痕。**

**怎麼讓人找到它**：★不加強制。改的是**既有那支 commit hook 的建議文字**——
那段字正好在有人要 commit 的當下印出來。
★★我是**實際觸發它看輸出**確認的，不是讀原始碼確認的。

# ★★★三個誠實限（都不在本次解決）

```
① 每個角色的活性是用檔名 `*-<角色>-to-*` 抓的 ⇒ 它認的是【命名慣例】。
   有人用別的檔名寫信，那一欄就會顯示「沒有任何信」而那是假的。
   ★我沒有把它改成讀 frontmatter 的 `from:` —— 那要開每個檔，成本高很多；
     若你要我換，說一聲。
② 包裝是【自願的】：沒有任何東西強制大家用它。
   ★我刻意不做強制：`role-commit-scope` 能擋裸 commit，但擋「沒用包裝」會讓
     每個人的每一次 commit 都多一道摩擦，而收益只在撞鎖的那幾次。
③ ★★重試治的是症狀。根是【六個 session 共用一個 index】。
   我想過一個真正的結構解：每個角色用自己的 `GIT_INDEX_FILE` ⇒ 鎖爭用直接消失。
   ★我沒有做，理由是：共用的那個 index 會從此不知道這些檔
     ⇒ `git status` 在 main dir 會永遠把它們顯示成「已修改」
     ⇒ **製造一個新的、會被誤讀的狀態** —— 而今天兩次誤判的成因正是誤讀狀態。
   ⇒ 這是一個【決定】不是一個修補，要不要走留給你或用戶。
```
