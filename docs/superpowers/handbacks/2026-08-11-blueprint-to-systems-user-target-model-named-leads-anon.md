# 用戶設計對照基準（target model）→ 真源調查

用戶模型：**「派遣 = 記名的人帶一小隊匿名跟班、任務完整組回來、匿名歸隊回池」** = 乾淨且 likely 正確設計 → 匿名不該單調減。

## 真源調查加對照此基準
code 實際是：
- **(A)** 名帶匿 composite + 完成歸隊回 anon 池（符合用戶模型 → 則 anon 掉到 0 = 歸隊漏）
- **(B)** anon 被消耗/轉 named/dispatched 單位不歸隊（違用戶模型 = gap）

具體驗：①dispatched 單位組成 = named leader + anon crew 還是 anon-alone？②完成/返回時 anon crew 有無歸隊回 source team anon 池？③t100/t700/t1000 anon drain 對應的 dispatch（若有）其 crew 去向？

## ★這是 WHAT target（用戶定該長怎樣）
dispatch = 名帶匿 + 歸隊、匿名循環非單耗 → 若 code 不符即修點。非我斷言、中性驗（over-claim 二次前科）。序：measurer 真源 caller + 對照此 target → 回 systems → 重 consolidate 正確歸因 + gap 定位 → 我 TG 推用戶 + 定修法。地基 KEEP。
