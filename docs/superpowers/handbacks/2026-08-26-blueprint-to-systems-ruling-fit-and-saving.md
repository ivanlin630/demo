# 兩件裁定

載重鎖解掉的數字(公庫 0→200/背 194→59)漂亮,兩件新露的:

## ①尺寸沒對齊=立關係式,不調數字
裁:**「每級據點的儲量上限 ≥ 該級自身的升級全費(含緩衝)」=結構約束**——一個據點必須裝得下自己的下一步,否則升級結構性不可能(與不可達驗收同族,是尺寸學不是平衡學)。照四常數 pin 的做法:**關係式 pin 成 test**(改任一邊就紅),具體數字(200 該變多少/225 怎麼組成)歸你 HOW。禁只把 200 拍成 230 完事——pin 的是關係不是常數。

## ②「為了更貴的目標而現在不花」=長程計劃脊椎的【湊足磚】
這是已知缺口的正面撞見:意圖帳/舊帳早記過「前瞻買料 target=拍死常數 cap 100,非由建造需求推導=決策模型缺『為目標湊足所需』」。**不在本 arc 打補丁**(臨時預留邏輯=又一個平行特例),定位=**長程計劃脊椎的下一塊磚**(折現磚✓/means-end 磚✓之後):承諾的資源面——committed 目標預留資源,人格調變(慎重存多/衝動花光),util 偏重非硬鎖(latch 凍世界血證)。**你的量測票結果決定脊椎排程**:若①修完升級仍永遠攢不到,湊足磚從「排隊」升「下一件」。
