# ① 事實

implementer 做 BED_DAYS 陰性對照時順手量到（1/2/3 天窗**都一樣**）：

```
BED_DAYS=1/2/3  ⇒  母體 15/16/17 隊｜_msf 相異 12/14/14｜★分母 need_keep 相異 2/2/2
```

⇒ **`need_keep(state, team, "material", lv)` 在整個世界只取兩個相異值。**

# ② 這對批一② 的意思

我報給你的是「17 隊有缺口、`_msf` min .125／median .730／max 1.000、相異 14」。
★**那句話是對的，而我沒有分辨那些變異來自哪裡。**

現在知道：**固定分母 80 之下 `_msf` 照樣有 12 個相異值**（因為分子＝缺口本來就跨隊變異）
⇒ ★★**②那張票實際多出來的差異化是「兩檔」，不是「逐隊」。**

★★★**我不撤回那張票**：把分母從「對所有隊都一樣的 80」換成「那支隊自己的需求」
在**語意上**仍然是對的（而且 `_msf > 1` 的病沒了）。
**我撤回的是我隱含給你的印象——它讓 drive 變成逐隊的。它讓 drive 變成兩檔的。**

# ③ ★★★而這可能是下一批普查的判準

你上次裁「下批普查判準＝【同一個量在兩層各有一份】優先」。我建議**再加一條**：

> ★**【一個看起來逐隊的量，實際上只有 N 檔】**（N 很小）。
> ★★它與「死常數」是**同一個病的下一層**：死常數是 1 檔，這個是 2 檔，
> 而**兩者在 code 上長得完全不同** —— 前者是 `const`，後者是一個**看起來很認真的函式**。
> ★★★**它只有在你去量【那個量本身】的時候才會現形**：
> 量它的**下游**（這裡是 `_msf`）永遠看不到，因為下游的變異來自別處。

★而這條判準**沒有辦法靜態查** —— 它要跑。⇒ 若你要開，形狀是
「挑 N 個決策路徑上的導出量，各 dump 一次它自己的跨隊相異數」，而**不是**讀 code。

# ④ 順帶：床成本那條線的結論

`BED_DAYS=1` 准了（陰性對照在 1 天窗紅、且紅在該紅那格）。
★而 implementer 量到**世界窗床約 40s 是 Godot 啟動＋GameSetup** ⇒ 降窗砍不到那一半，
再省的路是**多支床共用一次 setup**，不是繼續砍天數。**已記待辦，不是這輪的票。**

# ⑤ 我對這件事的自評

★我今天兩次把「有變異」讀成「機制有效」：
①材料那張（`_msf` 相異 14 ⇒ 我以為逐隊）
②我擋 implementer 降窗時，他拿的也是同一種代理量（母體、`_msf` 相異）而我擋對了——
**但我擋對的理由，正好是我自己那張票上犯過的錯。**
⇒ ★★判準寫成一句：**「有變異」要問【變異來自哪一項】** —— 分子、分母、還是機制。
