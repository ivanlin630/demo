# 上游供給：逐層剝，**每一層都窮盡對帳**

## §1 第 3 層（最上游）：資源前置的出口表 —— ★**完全窮盡**

```
goal.res_prereq.entry      = 6293
  ├ satisfied              = 1166   （持有 ≥ need_keep：不缺，本來就不該產）
  ├ no_specie              =  459   （沒錢 → 跳過買）
  ├ buy_wins               = 3038   ★買得到 ⇒ 直接 return，永遠走不到採@地形
  └ no_market              = 1630   （買不到 → 才往下走）
1166 + 459 + 3038 + 1630 = 6293 ✓
```
★**逐項加總等於母體，零殘差** —— **這代表出口列全了，沒有我沒看到的路。**
（★**我先驗這個等式再讀內容**：**不對帳的分佈不能拿來推論，因為漏掉的那條可能才是主因。**）

## §2 ★★收斂點確立：**不是 argmax、不是採@地形分支**

| 層 | 數字 | 判 |
|---|---|---|
| ②argmax | 28 個候選**全部贏** | ⛔ **不是瓶頸** |
| ①採@地形分支 | `emitted 28`／其餘出口**全 0** | ⛔ **零過濾**（28 進 28 出）|
| ★①上游 | 落到「取得手段 2」＝ `459 + 1630 = 2089` 次，**但只有 28 次進得了採@地形分支** | ★**2061 次消失在 `RES_HARVEST_TERRAIN.has(res)` 這一行** |

⇒ ★**真正的收斂點是【缺的那個資源不是「可從地形採」的那一類】。**

★**這也解釋了 day 0 集中**：★**待驗，但形狀吻合** ——
若 day 0 缺的是 `material`（可採），之後缺的多半是別的（不可採）⇒ **build 候選只在 day 0 出現。**
★**我不宣稱，因為現在的證據是【分類維度】而 day 0 是【時間維度】** ——
**用分類數字去斷時間，就是我上一封剛犯過的錯。要斷得同時有兩維，或直接看下一輪的資源分佈。**

## §3 跑中：分類維度再切一刀
`goal.res_fall.<res>`（落下來的缺的是什麼）／`goal.res_nonharvest.<res>`（其中不可採的是什麼）
⇒ ★**這會直接指出「缺的到底是哪種東西」，而那才是供給問題的真正描述。**

## §4 ★方法紀律（這一輪我自己在守的）
1. ★**每層出口表都要對帳**（`Σ 出口 == 母體`）—— 不對帳就不推論
2. ★**先剝層、再歸因**：三層各自的 0 意思完全不同（沒產生／被過濾／輸掉）
3. ★**證據維度要對上主張維度** —— 分類數字不回答時間問題（你上一封那條，我這封還在守）
4. ⛔ **不開藥**：目前為止一行 production 邏輯都沒改，★**全部是 tap**
