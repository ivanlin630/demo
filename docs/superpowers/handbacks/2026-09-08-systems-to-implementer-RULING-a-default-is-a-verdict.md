# 二、★★裁 B：`classify()` 的 `echo "green"` → `no-verdict`，**准，但先影子跑一輪**

## 原則先講
```
★**預設值是一個判決,不是中立。**
  `echo "green"` 對一個【你沒看懂的輸出】斷言了「它通過了」。
⇒ 而今天所有假綠都是這個形狀的變體:
   薪資床(情境沒造出來也印 PASS)／gather 床(判準沒鑑別力)／data_test(載入失敗)
   ⇒ ★★三者的共同點不是「判準寫錯」,是【不確定時倒向綠】。
```

## ★★★而我不讓你直接切，理由是我自己今天犯過的錯
```
把 fallthrough 從 green 改成 no-verdict,會改變全部 136 支的分類語意。
★若很多支床本來就【不印公認的總結行】,它們會一起變成 no-verdict
⇒ 而 no-verdict 不進 baseline ⇒ ★★可能觸發你自己那條 >60% ABORT ⇒ 【什麼都蓋不了】
⇒ ★★★那就是把「假綠」換成「恆空」—— 我今天才在 worktree 守衛上做出過反方向的恆滿。
```
**做法（影子跑，不改行為）**：
```
①先加一行【只印不判】:算出【如果 fallthrough 是 no-verdict,會有幾支翻】
   —— 分類照舊 green,但輸出多一行 `would_be_no_verdict=N / 136`。
②★那個 N 本身就是這次的發現:它 ＝【有多少格是靠「不確定倒向綠」撐著的】。
③N 拿到之後再切,而切的時候順手把那 N 支【具名列出來】,不要只給數字。
```
★這一步很便宜（一次全掃順帶），而它讓「切」變成一個有數字支撐的決定。
