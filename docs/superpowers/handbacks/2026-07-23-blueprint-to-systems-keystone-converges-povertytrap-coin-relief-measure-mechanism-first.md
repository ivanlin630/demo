# 認匯流 framing + means-end 我押錯位階 + coin relief 先 measure 機制

## ① 認可匯流 framing
**facility-build keystone = poverty-trap 逃生匯流**（食安 GATE-A + coin relief），**非新 investigation、非新 fix，是本場所有線的匯合點**——食+coin urgency 壓 reserve_factor → 隊守不住投資本 → afford 過不了。這場從 117 誤植一路挖，最後全匯進同一個根。優雅。

## ★② 我自認：means-end 押錯位階
我這場一直把 **means-end（cap-100 非 goal-derived）捧成「頭號 exhibit」**，measure 證 **demand/argmax 健康、means-end 非 binding**——它是**潛在的第二序**（poverty-trap 解、reserve 升近 100 之後才會 bind），我押錯了位階。收（同我上封剛認的「別把 pet-hypothesis 當已驗」教訓，這次換 means-end 被 measure 校正）。means-end 標記留著（latent，poverty-trap 解後回看），但**不當現在的 binding 修**。

## ★③ coin relief = 下個 live，但先 measure 機制再 spec（別假設）
coin relief 是 keystone 的下個 live step，但**硬要求先 measure 機制、別直接挑 fix**：
- coin poverty 91% 廣布 **mil + civ 都是**，但**兩族群很可能不同源**：
  - **mil**：loot → anon_treasury 不流 team.coin（已知機制）。
  - **civ 不搶掠 = 另一源、未量**。★hypothesis：civ 靠**賣**賺 coin → deal-flow 壞（`sell_no_surplus`/GATE-B）→ 賣不出 → 賺不到 coin → **civ coin poverty 是 deal-flow 下游**。
- ∴ **coin-poverty-cause 是 causal claim**——照新 R① **先 measure 機制 split（mil routing vs civ trade-income vs salary-drain）再選 fix**。別直接挑「mil loot→team.coin」就做（那只修 mil 半邊，civ 90% 不解）。

### ★這 hypothesis 若坐實 = GATE-B 重框
若 civ coin poverty 真是 deal-flow 下游 → **GATE-B 從「排後面的獨立 deal-flow arc」重框成「coin relief 的引擎」**，pull 進 poverty-trap 匯流、而非排其後。**但別假設**——measure civ coin 源才定。這是本場「經濟全景」的可能收官：水管通（商業）→ 水有了（供給）→ deal-flow（GATE-B）不只是死法②，是**讓隊賺到 coin 脫貧的引擎**。

## ④ 序
1. **二刀 merge 續**（QA 綠已 green-light）。
2. **coin 機制 split measure（live next）** + 食安 GATE-A 續跑 = **afford 兩腿**（食 + coin）。
3. **queue-limit（INFRA_INTERVAL 50h 節流）= 次要**——afford 解後才 bite（現在 afford 就過不了，節流還沒輪到），排 afford 後。
4. **bootstrap survival-blood（立新據點建設 option 42-47% 被 survival 血洗）= 遷徙/分家逃生閥**——★patch-gate/survival-override 我上封押對但**錯族群**（走 decision.rank 的是「立新據點」非「既有加設施」）。這是 **carrying-cap 逃生閥（遷徙/分家）被 survival 堵的實例**，排 afford 後但**別丟**（它是 poverty-trap 的另一條逃生環）。
