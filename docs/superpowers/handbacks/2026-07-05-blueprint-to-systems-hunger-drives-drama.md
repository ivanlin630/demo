# ④ 承載力裁：餓是引擎，先量「餓的隊在幹嘛」再定

回 `food-ledger`。收支表揭深層：**承載力現在（×5、速度無關）就已邊緣**——60% 負流、20% 斷糧、中位打平=既有苟活平衡，非 ×1 才出現。

## 核心裁：別灌糧解決，餓是戲的燃料
- **最懶解=調高糧產→20% 斷糧歸零**——但這**拔掉稀缺引擎**：沒人餓→沒人被逼去搶/崛起/投靠→回 turtle-world 死水。**禁**。
- **稀缺是驅動戲的引擎**（匱乏→搶/投靠/崛起=已建機制）。20% 在餓可能=20% 在搏命=戲在 churn。

## ★ 補一刀（便宜，bed 現成）：量那 20% 斷糧隊「在幹嘛」
```
好的餓（保留）：餓→raid 搶糧/投靠強鄰/搏命移動 = 匱乏驅動行動 = 崛起/興衰戲
壞的餓（修）：  餓→靜默死在原地,無行動 = 匱乏→搶 沒觸發到他 = 機制斷(response gap)
```
量斷糧隊的**行為分布**（dispatch: raid/投靠/移動 vs idle-死）→ 決定：
- **多數搏命** → 好的餓 → **保留稀缺，A2 承載力只 recalibrate ×1**（不升糧產）。
- **多數靜默死** → 壞的餓 → **修「餓了會行動」trigger**（讓匱乏→搶真觸發到他們），非灌糧遮蓋。

## A2 拆兩波
```
A2a = 承載力/FOOD 校 —— 等上面那刀:
       好的餓→只 recalibrate ×1（speed-independent，B 前可備）
       壞的餓→修 trigger（餓→行動）+ 適度校，非灌糧
A2b = ×5→1 + 沿途補給 —— B merge 後行軍斷糧率量準才定值
       （現 29-37% 是 far 稀釋低估地板，B 後 journey 變長會升）
```

## 序
1. **斷糧行為那刀 = 現量**（速度無關）→ 回我裁 A2a 方向（recalibrate vs 修 trigger）。
2. **行軍補給等 B merge 後重量**（真斷糧率）→ 定 A2b 補給值。
3. B（far elapsed）繼續解物流三病、平行。

## 藍圖自檢
- 差點又「灌糧解決」——那會拔稀缺引擎。抓住：**先問飢餓有沒有驅動戲，再決定升不升糧**。同一路原則「稀缺給野心牙、匱乏是侵略驅力」。
- 承載力「現在就邊緣」是 measure 揭的（非 ×1 問題）——好在量了，否則 A2 會把它跟移動混一起校錯。**這條升紀律：measure 揭的「既有問題」別跟當前 wave 的問題混校。**

## 待
斷糧隊行為量（現）+ B 續跑 + B 後行軍重量。三者回來 → A2a/A2b 定值。
