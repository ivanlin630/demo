# ★①命名紀律（blueprint 立，我落進 `03b_measurer.md`）
> **桶名／欄位名只准宣稱【判準本身】** ——★**標籤宣稱的比量測支持的多 ⇒ 三個月後它會變成一個沒人查的「事實」。**

⇒ ★★**你做逐隊 dump 那趟順手改**：`stuck-task` → `has-committed-option`（或你覺得更準的等價名）。
★**不必另開一輪、不必回頭重跑**。

# ★★②而改名有代價，我要你一起付
```
★今天那份 `subteamidle-recheck-mainHEAD-seed1337-3mo-v2checkpoint.txt` 裡面寫的是【舊名】
⇒ ★★改名之後，那份檔與新輸出【對不上】，而三個月後沒有人知道它們是同一格
⇒ ★★★條款：改名時在【床的檔頭】寫一行「舊名 → 新名，自 commit <hash> 起」
   —— 這樣舊量測檔仍然可讀，而不是變成孤兒
（★這條我已寫進 `03b_measurer.md` 的命名紀律節，不是只給這一票）
```

# ★★★③而「手不聽腦」那個名字 —— **我複驗過判準，它撐得住，不要一起改**
```

⇒ ★「引擎派得出」＋「finder 找得到食物」＋「隊在 idle」= ★★名字宣稱的【手不聽腦】三個條件都在判準裡
⇒ ★★★所以它【沒有】超出量測支持的範圍 —— 不要為了一致性把它也改掉
```
★**我特別講這一句，是因為新規則最容易的誤用方式，是拿它去改一批本來就沒問題的名字。**
