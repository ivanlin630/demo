# 一、★關鍵事實（我查的）

```
`SimRunner.advance_tick(state, player_pos) -> String`
  ・`current_tick += 1` 在它**內部**（`_step1_advance_time`）
  ・★**呼叫端 263 個**（扣掉定義本身）—— 幾乎全是床與工具
⇒ ★★**改它的契約 ＝ 動 263 個地方** ⇒ **不可行，也不必要**
```

# 二、★★形狀：**第二個 driver，而不是改舊的**

```
①**保留 `advance_tick`**（跑完整顆 tick）⇒ ★**263 個呼叫端一個都不動**
②**新增一個分片 driver**：同一批內部步驟 ＋ **一個游標**（跑到哪一隊）
   ・★**它不推進 `current_tick`，直到整顆 tick 的工作做完**
   ・★★**分片之間不得有任何其他系統改世界** —— 否則就是**交錯**，那會改變世界
③**只給互動迴圈用**；床／量測**繼續走舊入口**
⇒ ★★★**而這正好讓驗收變得天生可驗**：**兩個 driver 跑同一顆種子 ⇒ 指紋必須逐字相同**
   —— ★若不同，就是②的條件被破壞了，而**那一格會自己紅**
```

# 三、★★★一個【不是 fp】的風險，我要單獨標出來

```
分片之後，**世界在 tick 中途是可以被看見的**（渲染發生在分片之間）
⇒ ★**指紋會是對的，而畫面可能是半更新的**：
   例如「A 隊已經移動、B 隊還沒」在同一幀被畫出來
⇒ ★★**這是【一致性／觀感】問題，不是【正確性】問題** —— 而 fp 驗收**抓不到它**
⇒ ★★★所以若要做，**驗收要多一格「玩家看到的東西不會前後矛盾」**，
   而那一格**不是指紋能回答的** —— 它要截圖／或明確規定「只在 tick 邊界渲染」
★**而「只在 tick 邊界渲染」會讓分片失去意義**（畫面照樣卡在那一顆 tick 上）
   ⇒ ★★**這是這個形狀真正的張力，我把它擺在你面前，不替你裁。**
```

# 四、★我的判斷（供你裁）

```
★**技術上可行**（第二 driver ＋ 游標），**而且 fp 驗收天生存在**
★★**但 §三那個張力沒有免費的解**：要嘛畫面可能半更新，要嘛分片沒有意義
⇒ ★★★**所以我建議：先答「天然叢集 vs 排程對齊」那一格**（已派，讀既有 raw）

   ⇒ ★而「錯開」確實改變世界 ⇒ 要進世界改變窗 —— **但它不需要動主迴圈架構**
   ⇒ ★★**兩條路的成本差一個數量級，而那一格【今天就能答】。**
```
