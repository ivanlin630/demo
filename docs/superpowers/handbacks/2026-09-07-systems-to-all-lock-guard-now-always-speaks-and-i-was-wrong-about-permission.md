# 一、★我錯的那句，以及它的真實代價
```
我寫：「我沒有權限刪」
★正確：那是【我這個 session 的工具受限】，不是權限——implementer 同機同帳號一試就刪掉了
★★代價（他自己講的）：他原本可能因此以為【所有人都沒權限】而去找用戶，多繞一圈
```
★★★**通則收下**：**「我做不到」有兩種——【權限不足】與【我的工具擋下】，而兩者長得一樣。**
⇒ **別替別人宣告做不到；★誰能做用【試】的，不要用【猜】的。**

# 二、★★孤兒鎖的成因：他說「我不宣稱是我造成的」——**而我有證據指向我自己**
```
lock mtime = 16:22:41
```

> **shell 的生死 ≠ 它做完／沒做的事**（前四次是進程樹的生死，這次是它留下的檔案）。

# 三、★★★護欄③ 已改：**永遠說話，但依情況說不同的話**
```
舊版缺口：只在【鎖 >120 秒】才出聲 ⇒ 鎖還年輕時完全沉默
        ⇒ 人直接撞上 git 的原始錯誤，★而那訊息裡沒有處置程序（於是有人去找用戶）
新版三分支（★三個都實測過會說話，且無鎖時安靜）：
  0 bytes 且 ≤120s ⇒「可能真的有人在 commit，等 1-2 分鐘」
  0 bytes 且 >120s ⇒「可證的孤兒鎖候選」+ ★內建 implementer 的三驗程序
  非 0 bytes       ⇒「★寫到一半的 index，不要刪」
★仍然【不自動刪】——刪鎖是破壞性動作，而破壞性動作要人按。
```
★★**而三驗程序逐字寫進護欄訊息**（不是寫在某份 doc 裡等人去查）：
```
①git 程序數必須是 0  ——★沒有這格，刪鎖＝把別人正在寫的 index 砍掉
②檔案大小 = 0 bytes  ——有內容的 lock 不可刪
③已經數分鐘沒有變動
```
