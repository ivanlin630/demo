# 判決：`issues`（小），`premise_contradiction: false`

## ①分組地理切法——**用遊戲實際的 hex distance 重算過，整體站得住，但兩處要明講**

你寫的距離（例如「3 到 B 最近≈5.7」）用的是歐氏距離，但這個引擎的移動/可達性一律用 hex distance（`_hex_dist`）。我用 hex distance 重算了全部 12 隊的最近鄰：

```
0(7,6)  最近三: 5(3) 8(3) 9(3)   ★三方同距(A的5/9 vs 獨立的8)
10(6,10) 最近三: 8(2) 0(4) 6(5)   ★★★10 的單一最近鄰是 8(獨立)，離自己 B 組的 leader 6 反而是第三近，距離多一倍以上
3(10,14) 最近三: 2(8) 8(8) 10(8)  ★★換 hex distance 後是三方【等距】，不是「離 B 較近」
8(8,8)  最近三: 10(2) 0(3) 9(4)   ★8 的單一最近鄰是 10(B組)——這是整份資料裡最近的一對
```

**(a) 8↔10 是全資料集裡距離最近的一對（hex=2），卻被拆到獨立／B 兩邊**——你用商隊 tag 蓋過地理這個判斷本身沒問題（跟你自己的原則②③一致：獨立看的是「不是這一帶的人」不是純距離），★**但 spec 目前寫「3 為什麼獨立」寫了理由，沒有把「8/10 是最近對卻被拆開」這個最顯眼的張力寫出來**——下一個對著座標核對的人第一眼會看到這對，若沒有先講清楚，會誤以為是算錯。建議補一句：「8↔10 是最近對，8 仍獨立是因為 tag 判準優先於距離，這是刻意的，不是漏看」。

**(b) 「3 離兩圈都遠」的支持數字用錯了度量**——換成 hex distance，3 到 A（team2）／獨立（team8）／B（team10）三者【剛好等距，都是 8】，不是「離 B 較近、離 A 較遠」（你原文的 Euclidean ≈5.7/≈8 那組數字給人這個印象）。**結論（3 保持獨立）不受影響**——三方等距本身就是「流民」最乾淨的證據，比你原本寫的「離兩圈都遠但比較靠 B」更站得住——但支持它的數字本身要換成正確的度量，不然下一個人拿 hex distance 去複驗會對不上。

**其餘分組（A 的 7/5/9/11/2，B 的 1/6/4）沒有發現類似張力**——最近鄰查詢都落在同組或獨立那兩隊身上，沒有第三個藏著的錯位。

## ★★②重心代理——**查過了，這是永久性承諾，不是會自我修正的種子值**

grep 了全部 `.leader_team_id = ` 賦值點：**只有 `game_setup.gd:412`（worldgen 內）寫這個欄位，`scripts/simulation/` 裡沒有第二個賦值點**——**沒有任何 runtime 繼承/篡奪/選舉機制讓 leadership 在遊戲過程中改變**。這代表你這次用「距重心最近」選出來的 leader，會是**這個世界從第一個 tick 到結束的唯一 leader**，不會因為某隊後來蓋出更高等級的據點而自動換手。

⇒ **這不影響你「用代理」這個決定本身**（config 裡真的沒有據點等級可用，代理是唯一可行的選擇），★**但要把這件事的份量講清楚**：你信裡寫「它是代理不是準則本身」聽起來像「先湊合，以後會自己校正」，**實際上它不會自己校正——若日後 config 真的補上據點等級且跟這次的代理選擇不一致，需要的是【手動重新編輯這個 config】，不是等遊戲自然收斂**。建議 spec 把這句加重：「此選擇無 runtime 修正機制，一旦定案即為永久，若未來 config 引入據點等級且與此不符，需手動更新此 config，不會自動生效」。

## ③連帶——**同意你列的，但範圍比你寫的更寬**

你抓到的（`09_exam_gate §5.4`的「不修讀數②」／今天那筆「紮根0/0」）是對的，但這兩個都是**政權相關**的統計。★**真正會被影響的範圍更大**：**任何在 `peaceful_economy.json` 上量過「哪個 option 贏了 argmax／被 rank 選中幾次」的既有量測或 known_issues 條目，都可能受影響**——因為「徵收」「歸建」從「applicable 母體恆 0（從不參賽）」變成「applicable 母體 >0（真的加入 rank_scored 競爭）」，這會**改變同一個 argmax 池裡所有其他選項的相對勝率**，不限於政權相關的統計本身（例如今天 `lod-production-neutrality` 那票量的「camp.won_argmax」「覓食/紮營」勝率，都是在這個 config 的舊世界上量的）。

⇒ **建議**：不用現在窮舉每一份受影響的文件（那是另一次掃描的規模），但 spec 補一句誠實限：「本刀改變 `peaceful_economy.json` 的 argmax 競爭池，任何既有『某 option 在此 config 上的勝率/母體』量測都可能過期，不限於政權相關統計；建議下次要引用這些舊數字時，先確認是量在改動前還是改動後的世界」——跟你自己已經在別票立過的「舊結論會默默過期」（`stale-conclusion-expiry`）同一個問題，這裡先手記一筆，免得將來又要靠那道閘去偵測。
