# 裁定：經濟怎麼真正活起來（回應 economy-architecture A/B/C）

長討論收斂。先講**主從**，這是整個取向的魂——別把僕人當目的。

## 主角：NPC 經濟決策（最重要，其餘都服務它）

真正要做的 = **讓 NPC 真的會用經濟**。一條 load-bearing 決策：
- 讀自己「**我滿了 / 我缺**」（自知，可靠）+ 讀外面「市集在哪、誰要啥」（情報，殘缺，G3）。
- 滿 → 去市集賣；缺 → 去市集買。

**現在就壞在這**：你診斷的縫#1——商業隊全被卡在不貿易的角色（leader 跑勢力 AI / 獨立隊覓食分數蓋過 / 子團不派 / member 被 SETTLE + faction goal 攔截）= **決策根本沒 fire**。
→ **核心工作 = 解角色卡死 + 讓貿易決策真觸發 + 讀對信號。複用既有 `_can_trade`/`_find_trade_target`/派工，非造新系統。**

**鐵則：上限/市集/糧倉都是為了讓這條 NPC 決策「簡單到做得到」。若它們不改變某個 NPC 局部決策 = 死概念，砍。**

## 僕人 1：上限（給 NPC 一個「該賣」的簡單觸發）

「我滿了」= 最 trivial 的局部信號。上限存在就為製造這觸發。

- **移動隊**：carry cap = base(pop) + **馬車 + 獸**。
  - ⚠ 現 `get_carry_capacity` 有，但超載只是**速度懲罰（軟）**，定居隊不動 → 無感 → 照囤。要讓上限**真硬**（超額存不下，不是只變慢）。
  - **救活馬車**：現馬車只少吃點速度懲罰、對囤貨零約束。硬上限後馬車 = 「商隊能多搬多少貨去市集」→ 馬車終於有正經工作。
- **定居隊**：食物進**據點糧倉**（`tile.public_storage`），cap 複用 `_get_storage_cap`（已綁 outpost_level）。
  - ⚠ **食物現在繞過糧倉**：`_collect_from_tile` food 走 `else` 直接塞 `team.resources` uncapped（= 4-5萬 幽靈囤的真因）。**改成 route 進 capped 糧倉**（像礦）。
  - 消耗端要改從糧倉提領吃（既有 withdrawal 流）。

## 糧倉容量（用戶定 A + 加糧倉設施）

- 食物用**自己的 per-level 容量陣列**（**非**通用 `[100,300,800]`——那對主糧太小，L3 800 ≈ 50人村 6 天，會餓死）。專屬放大到「合理糧儲」。
- **加「糧倉」設施**（farming 線或獨立 facility）：蓋/升糧倉 → 拉高食物上限 = 玩家/經濟投資點。
- 效果：**據點尺寸 = 經濟容量** → 大據點囤更多、更值得搶/圍 → 糧倉變戰略資產（接 G2 控據點=經濟力）。
- 數字全 TEST VALUE，平衡 pass 調。

## 僕人 2：集中市場（選 B，給 NPC 一個「簡單目標」）

A/B/C 用「NPC 怎麼理解」這把尺裁：
- **A 漫遊商隊**：NPC 要用舊情報追會動的目標 → 正是 2 年 5 次成交的失敗主因。否決為**主**機制。
- **B 固定市集**：NPC 決策 = 「去已知據點市集」= trivial + 可靠，固定會合點 → 成交必發生。**選 B。**
- **C 抽象撮合**：無 NPC 決策、無 emergent、無玩家干預。否決。

- **路上順路交易保留，不取代**：兩隊碰到照樣換（= 用戶原本「與 team 交易順路才做」）。保住「商隊路上被攔截/打劫」的 emergent 戲（A 的好處疊在 B 上）。市集 = 可靠主場，路上 = 順路。

## 腐壞：砍

上限已結構封頂囤貨，腐壞只剩「沒滿也慢慢壞」的 realism 點綴 = YAGNI，不做。（先前 spoilage-feel ruling 作廢，以本檔為準。）

## 驗收方向（重量看）

- **履約率 / [Market] 成交 大幅 > 0**（從 2 年 5 次 → 常態成交）。
- **囤糧峰值崩**（4-5萬 → 受糧倉 cap 封頂）。
- 商業隊**真的被派去貿易**（不再卡覓食/faction goal）。
- 馬車對商隊載量有感。
- 路上順路交易仍偶發（未被市集滅掉）。
