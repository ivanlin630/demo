# ①計時器：**收**（★兩條證據的性質不同，這點值得說）
```
★對照探針那條是【直接測那一層】—— 不吃 CPU、不跑 godot,兩臂都活滿 90 分
   ⇒ ★★它不是「warring 活久了所以大概沒計時器」這種推論,是直接證據
★★而你自己把「59.5 ≈ 60 的巧合」標成【看起來有意義的巧合】並且去打它 —— 對
   ⇒ ★★★數字上的巧合是最會騙人的線索:它自帶一個現成的故事
```

# ②★★而「day 53／59.5 分」是**兩道牆**，你只越過一道
```
★前次:day 53 ／ 59.5 分   ←★★這是【兩個】獨立的量,不是一件事
★本輪:day 47 ／ 61 分
⇒ ★越過的是【wall-clock 那道】(61 > 59.5)✅
⇒ ★★【day 53 那道】仍未受測 —— 本輪還沒跑到 day 53
⇒ ★★★所以「死在固定天數」現在【既沒被證實也沒被否證】,不要寫成已排除
```
★**真正的檢定點還在前面**：**本輪跑過 day 53 的那一刻。**

# ③★而有一個會污染比較的因素（★你自己降 EXCLUSIVE 時就預見了）
```
★本輪速率比前次慢約 23%（day 47@61 分 vs day 53@59.5 分）
★★而同機還有 30 日 unit-overlap 在跑 ⇒ EXCLUSIVE=unknown
⇒ ★★★時間類讀數在並跑下【不可比】—— 這【不】推翻計時器否證(活得更久仍是有效證據),
   但它讓 day 53 的檢定點落在【更晚的 wall-clock】
⇒ ★所以別把「過了 70 分還活著」讀成「又多排除了一點」——★★分母(進度)不同
```

# ④緩衝說：**收，而且這一半已經定案**
```
輸出從 day 1 起持續落地(61 分 482 KB)⇒ 就算被砍也留得下段落
⇒ ★第二次那份 0 bytes 不是「跑太久被砍」的必然結果,是【舊的非串流 wrapper + 被砍】
⇒ ★★儀器失效,不是世界失效 —— 已上帳
```

# ⑤記憶體那條：**斜率收斂這個觀察比絕對值有用**
```
+60.7 → +24.1 → +16.6 MB／10 日 ⇒ ★收斂 ⇒ 外推 day 90 約 250 MB
⇒ ★★而若它照樣跑完 ⇒ 【三個候選全被排除】—— ★★★那不是「白跑」,那是乾淨的結果
   ⇒ 而那時該問的不是「還有什麼候選」,是【前兩次到底有沒有共同成因】
```
