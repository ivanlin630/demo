# HOW 認同：pivot 到 deal-flow/分配 keystone

## 你 meta-pattern 對且關鍵
今日 economy 四層診斷全同形狀：
- food（76k 豐產但 starve）/ goods（91% bail 是 goods）/ weapons（civ 有 material 軍事沒有）/ material（全域 3587、mil 隊 54-80）
- = **世界層級夠、個體/子群體層級不夠 = 分配/物流，非產量**。

根 = **貿易撮合層沒讓 surplus-holder 真的賣/送給 shortage-holder**（最初 2026-07-16 death② 0.06% 撮合率，一路被 food/goods/weapon reframe 繞開）。

## ★code 判斷：同意 pivot
- **bespoke 每資源運送機制 = whack-a-mole**（修完 material，下個資源缺口重演同款「夠但送不到」）。你警告對。
- **deal-flow/liquidity = 真 keystone**：一修全解——food-short 隊買 food、mil 隊買 material+tools、goods demand 遇 supply。

## HOW plan
1. **immediate cheap = (a) `_pick_facility` afford 預檢**：停 weaponsmith 空轉「選中-不-建」（decision-quality 修，**非分配修**）。cheap 獨立值得，但**不假裝解分配**（只停空轉噪音）。
2. **★真工 = deal-flow 診斷**：為何 surplus 不流到 shortage？市場撮合 **SELL 側**——surplus-holder 不賣 / 不到市場 / co-location 限制（原 `sell_no_surplus 100%` + `order_placed 9450/fulfilled 6`）= **patch-gate-first**。
3. **weaponsmith material/tools = deal-flow 解**（mil 隊經市場買），**非 bespoke 運送**。
4. `market-liquidize` branch（降 goods reserve）仍**錯層**（reserve~0）——deal-flow 真根**另診斷**，非那 branch。

## 開始 + 一個 WHAT 邊界問
我開始 **deal-flow SELL-側診斷**（patch-gate-first：surplus 為何不成交）。
- **★WHAT 問（可能需你先 frame）**：deal-flow arc 的**市場物理願景邊界**——資源分配靠 **co-location 市場**（隊帶貨到市集賣，物理移動）還是允**遠距/物流**（跨距調度）？這決定 fix 是「讓隊帶 surplus 去市集賣得掉」(co-location 撮合修) vs「建物流層」(大)。你 frame or 我診斷完提選項?
