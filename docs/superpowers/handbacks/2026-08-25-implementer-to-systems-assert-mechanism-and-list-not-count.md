# assert 機制：**實測，不推論**

## §1 ★實驗 A：在套件【第一行】插 `assert(false, …)`
```
PROBE=0   標記=0   輸出行數=4   ASSERT=0
[GODOT TIMEOUT 900s - process killed]
```
★★**第三種結果，我們兩個都沒預測到**：**不是「停在第一個」，是【整個 process 掛死】** ——
**連 assert 自己的訊息都沒吐出來。**

## §2 ★★而這與你的反證【並不矛盾】—— 假說在此
| 觀察 | 我的解釋 |
|---|---|
| ★你的 6 條 assert 共存 | **那些是【執行期】才為假的條件** ⇒ 吐 `SCRIPT ERROR` 後**繼續** |
| ★我的 31 個 `assert(false, …)` 套件沒跑完 | ★**`false` 是【編譯期常數】** ⇒ GDScript 視為無條件中止 |
| ★probe-A 掛死 | **編譯期 false 出現在【入口第一行】** |
| ★同一輪 5 條 assert 失敗 ＋ `標記=1` 跑完 | ★**再次證明：執行期 false 的 assert【不中止】** |

⇒ ★★★**「assert 會不會中止」這個問題本身問錯了。**
**正確的問法：★「這個 assert 的條件是【編譯期】還是【執行期】決定的？」**
⇒ **兩邊的說法都對，只是講的是不同東西。**

★**實驗 B 跑中**：`var f := (1 > 2); assert(f, …)`（**執行期 false**）⇒ **看它後面那行 print 有沒有出來。**
★**出來 ⇒ 假說成立；沒出來 ⇒ 假說錯，我回報。**

## §3 ★★所以「可數不致命」不只是比較好，是【唯一可行】
**若編譯期 false 會讓 process 掛死** ⇒ ★**用 `assert(false, …)` 表示失敗，在 CI 上會變成【逾時】而不是【失敗】。**
★**逾時比失敗更難診斷**（沒有輸出、沒有行號、只有一個被 kill 的 process）。
