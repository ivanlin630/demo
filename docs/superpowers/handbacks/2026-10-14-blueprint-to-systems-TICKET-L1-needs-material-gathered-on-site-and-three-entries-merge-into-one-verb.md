# WHAT
1. **L1 要材料**：民用／軍用各一筆（值＝HOW，測試值；現表 50／80 可沿用），寫在**唯一一張成本表**，紮根與派子隊與玩家建設同讀。
2. **就地採，不是備料**：開工不查「手上有沒有料」。工期分兩段：先採腳下格的材料直到夠數，再築。採的速度讀既有採集物理（腳下 tile 材存量、人數、技能）；材料不夠＝工期變長，不是門。有料的隊帶料來就跳過採段（帶多少抵多少）。腳下格材料採空＝蓋不成，隊自己會知道（估算器讀同一份物理，禁手抄）。
3. **估算器同源**：紮根／派子隊的「付不付得起」估算改讀「工期＋採料時間」一份算法；派子隊那道材料硬閘退場（它現在是 100% 的死門），改成估算進秤：料遠／地禿⇒成本高⇒自然不選。糧橋照舊（它算的是人會不會餓死，是物理）。
4. **三入口併一個動詞**：「建點」一個身體（開工＋採段＋築段＋完工），紮根＝自己站上去呼叫它，派子隊＝子隊到場呼叫它，玩家建設＝同一個呼叫。禁止保留第二張表或第二支開工函式「然後讓它等於第一支」（S6 那條禁令同形）。驗收：三個入口開同一座 L1 的工期與扣料逐數相同；grep 全庫只有一處寫 `construction_target` 的 build 分支。
5. **玩家面**：紮根／建設的結果句印「需材 N，腳下可採約 M 天／帶料抵 K」；採段與築段在頂列進度分得開。
6. **可觀測**：採段／築段各自 tap；`funnel.build_gate.cost` 退場要在量測對照裡看得到（修前 81 死／修後 0 死，而派出數要 >0 才算活）。
