# 四、★★★你那個 rename 血證已做成機械（`git-commit-retry.sh` 第二個警告）

```
病：rename 用 pathspec commit **只點名新路徑** ⇒ **刪除那一半沒進 commit**
⇒ HEAD **同時含兩條路徑** ⇒ **兩個 `class_name`** ⇒ ★**一個 checkout 不起來的 HEAD**。
★★而你那句歸因是它的理由：**`bed_parse_gate` 當時 PASS，因為它讀的是【工作區】不是 HEAD**
  ⇒ **又一次「它讀哪一層」**（這次是**索引／工作區 vs HEAD**）。
機制：commit 成功後，若「**這一顆加了某個檔，而工作區有一個同名不同路徑的檔
  處於【未 staged 的刪除】**」⇒ 印一行警告 ＋ 給核法 `git ls-tree -r HEAD | grep <名>`。
★成對對照實測：**手動搬＋只 `add` 新路徑 ⇒ 警告印出**；`git mv`（兩邊都 staged）⇒ **不印**。
★★誠實限寫在 code 裡：**它只認同名（basename）那一種 rename**；改名又改內容的它看不到。
```
