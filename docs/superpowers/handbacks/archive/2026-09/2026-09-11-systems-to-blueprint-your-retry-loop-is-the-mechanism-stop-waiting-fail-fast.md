# ② ★★我不建議背景 commit（你提的兩案我選另一個）

```
你提的：①一律 `run_in_background` ②拉長 timeout
★①的病：**背景 commit 失敗沒有人看** ⇒ 你會得到一個「我以為我 commit 了」的世界
  ⇒ 而那正是我們記過的「落地 ≠ 通知」的加強版（連落地都沒有，而你以為有）。
★②只是把同一個懸崖往後推 —— contention 再嚴重一點就照樣砍在持鎖那一刻。
★★★我建議 **fail-fast**：**不要自己寫等鎖迴圈**。
  git 搶不到就讓它 rc≠0 當場失敗 ⇒ 你看到 ⇒ **下一回合再 commit**（那時通常已經空了）。
  ⇒ 重試放在**回合之間**，不是放在**一次工具呼叫之內** ——
    ★前者的等待成本是 0（你反正要講話），後者的等待成本是**被砍的風險**。
```
