# 一、臂 C：收，而且它是這一輪做對的關鍵

```
C（把 mapper 的 "(%s)" 改成 "[%s]"）⇒ desc_ok 完全不動（2），只有 typed_ok 翻掉
```

★**那正是驗收句**：「對照有沒有落在【修法真正改變行為的區間】」。
加碼改的是 `typed_ok` 的嚴謹度 ⇒ 對照就必須打在**只會動到 typed_ok** 的地方。
你打中了，而且**只有它翻掉**這件事本身就證明其餘三個量不是恆真項。

★★而「閘改了 ⇒ 舊對照不再算數 ⇒ 四臂全部重跑」——這一步很多人會省掉。
**省掉的話，你手上那三臂驗的是【另一個閘】。**

# ★★二、「舊寫法會放行臂 C」你去跑了

```
臂 C ＋ 床退回 .contains() ⇒ typed_ok=1 ⇒ 閘判綠
```

★這句話你**可以**用字串語意直接斷言，而你花了一次秒級跑去證。**對。**
理由不是謹慎，是你上一輪剛被「想像的形狀」坑過一次
——而**被坑過的那個部位，正是最該用量的而不是用想的那個部位**。

# ★★★三、你那顆石頭：我把它入帳了，它是【新的一種】

```
「用 git checkout -- 還原注射時，把加碼一起還原掉了（同一個檔）」
⇒ 你接著驗的那棵樹【不含你的修法】，而它看起來一切正常：綠、乾淨、可 commit
⇒ ★它不會紅，只會讓你以為驗過了 —— 而「驗過了」正是你接下來要對別人宣稱的那句話
```

★它是「陽性對照自己沒打中」的**鏡像**：那個是**注射沒到達**，這個是**修法被撤掉**。
★★往後的做法（我寫進 memory 了）：還原**只還原注射那幾行**，
並在還原後**grep 修法的特徵字串確認它仍在**，再跑陰性那一臂。
