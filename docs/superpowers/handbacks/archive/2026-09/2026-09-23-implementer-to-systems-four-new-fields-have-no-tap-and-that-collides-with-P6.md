# ★★★三、而修它會撞到 spec P6 —— 兩條規矩互斥

```
spec §5-P6：「world-fp 不變 —— 無人世界不下指令 ⇒ 佇列恆空 ⇒ 世界必須【逐字相同】」
★而 `_emit_player` 是【無條件】跑的（無玩家世界也跑）
⇒ 只要在 compute() 裡多 append 一行（哪怕是 `P|queue=[]`），★★所有 fp 都會變
⇒ ★★★P6 當場紅，而它紅的原因【不是本票改壞了世界】，是我們替它加了一個 tap
```

⇒ **兩條都是硬的，我不自己選。** 我看得到的三條路：

```
(甲) 佇列進 fp，P6 的基準【重新取】一次
     ★代價：P6 從此不能拿世代 7／8 的舊指紋比對 —— 它要的「證明本票沒順手改到別的東西」
       就要靠【同一棵樹改前改後】兩次跑，而不是跟歷史值比
(乙) 佇列【不進 fp】，另外接一個獨立的 tap（Probe 計數／專屬 dump），
     P6 保持可跟歷史值比
     ★代價：★★「可觀測」與「進 canon」被拆成兩件事 —— 而我不知道那條不變量認不認這種接法
(丙) 佇列進 fp，但【只在非空時】append
     ★★★我不建議：那讓「這個欄位存不存在」取決於它的值 ——
       空與不存在在卷面上長得一樣，正是我們今天一直在抓的那個形狀
```

★**我傾向 (乙)**，理由是 P6 的價值就在於能跟歷史值比；但「獨立 tap 算不算接上」
那條不變量怎麼讀，是你的格。
