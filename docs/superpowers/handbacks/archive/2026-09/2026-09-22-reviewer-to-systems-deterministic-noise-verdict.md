# 你問的第(2)題：便宜擋週期性——不用統計檢定，用「短 lag 精確不重複」

```
建議加一格 2-d'：
  取樣窗內任兩個「不同 tick、其他都一樣」的組 (tick, observer, target)、(tick+k, observer, target)，
  k ∈ {1,2,3,5,8}（幾個互質小步長，非等差),★斷言 value(tick) != value(tick+k)
  ——★不是機率檢定，是逐點【不等於】斷言，跟你現有 2-a 的「逐字相同」同一種寫法（相等 vs 不相等）
⇒ 抓得到「雜湊對相鄰 tick 產生近似/重複值」這種週期
⇒ 成本=幾次額外呼叫比較，不需要引進分佈檢定
```
這個做法跟你 2-a 是同一個模具（都是「兩個輸入 → 值該相等還是該不等」的逐點斷言），
只是方向相反，寫起來應該不貴。

# ★我自己順手抓到的一個洞（不是你問的,但同一族，順便講）

```
2-a 只斷言「同 tick 同對 ⇒ 同值」，★★而它對「雜訊公式根本沒吃 observer/target，
只吃 tick」這種退化實作【沒有鑑別力】——因為「同對」永遠會給「同值」，不管公式有沒有真的用到 pair。
2-d 現在只禁「隨 team_id 單調」，★★不禁「同一 tick 內所有 pair 都拿到同一個值」（那不是單調,
是常數,常數技術上不違反「不得單調」）。
⇒ 這是跟你(2)同一族但不同方向的洞:(2)防「跨tick週期」,這個防「同tick內塌成常數」。
```
**建議**：2-d 加一句「同一 tick 內，取所有 (observer,target) pair 的值 ⇒ 不得全部相同（除非母體只有 1 對）」。
便宜（同一批取樣多印一個 unique-count），跟你現有 2-d 是同一次掃描，不用加新機制。
