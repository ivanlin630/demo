# 為什麼開這張（一句）

批二① 順手量到：**最遠的「最近同地形目標」只有 2-3 格**（三個世界，穿透 0/204、0/18、0/42）
⇒ ★**「去哪裡採」不是一個決策**：任何隊、任何時候、任何地形，**答案都在隔壁**。

blueprint 裁「開」，理由是它是**地基題**：
> 它回答「**這個世界存不存在值得跨越的距離**」——
> 而今天所有距離相關的接線（移速逐隊化／搜尋半徑／convoy）**舞台大小繫於此**。

# ★★★方法上最重要的一句（請先讀這段再設計床）

```
terrain 直方圖  答的是【組成】：這張圖有多少 plains / forest / mountain
距離分布        答的是【排列】：★兩張直方圖完全相同的圖,可以一張成簇、一張散佈
⇒ ★★而 arc 的問題（「位置該不該是一種資產」）問的是【排列】
⇒ ★★★所以直方圖【單獨】答不了這張票 —— 它是背景,不是答案。
```

# 要的格子

```
①terrain 直方圖（各 terrain 的格數與佔比）        ← 背景
②★到最近【各 terrain】的距離分布，兩種母體【都要】,而且【分開報】：
   (a) 從【每一格】起算  ⇒ 世界的結構性質
   (b) 從【每支隊當下位置】起算 ⇒ ★決策實際面對的東西
   ★★兩者會不同（隊不是均勻散佈的）,而★★★把它們混成一個平均值會答錯這張票。
   報 min / median / p90 / max ＋【> 5 格的比例】（★那是「值得跨越」的操作定義）
③★逐資源拆（blueprint 加）：食物 / 礦 / 林 各自的「到最近產地」距離分布
   ★★真相源用 code 不要手抄：`ResourceSystem.REGEN_RATE`（食物/材料逐 terrain）
     ＋ 礦（`ore_gold`）的產出條件請【自己去 code 查它綁哪個 terrain】並在卷面寫出 file:line
   ★★★預期是「礦該最稀」—— ⇒ ★若它【不是】最稀,那本身就是發現,請直接標出來
④★對照（blueprint 加）：從 17 個 `radius >= 16` 的 config 抽 2-3 張跑同一份格子
   ⇒ 問【密度隨圖變大怎麼變】：是【同密度鋪更大】(距離不變) 還是【同數量攤更開】(距離變遠)?
   ★這一格決定「把圖畫大」是不是一條可用的旋鈕。
   ★★建議抽：`infonet_recovery_r2_invest`(40)、`perf_scale`(24)、`infonet_established_fragility`(16)
     —— 三個量級各一，理由寫進卷面（若你有更好的抽法，自己換並說明）。
```
