# 一、信箱有【兩個不同的漏】（我量的，不是估）

```
git status --porcelain docs/superpowers/handbacks/ | awk '{print $1}' | sort | uniq -c
   7 ??   ← 未追蹤：信的【內容】不在歷史裡
  58 M    ← 已追蹤、改過、沒 commit：信在，而它的【狀態】不在
```

★①未追蹤：**投遞成功、留底失敗** —— `inbox-watch` 掃的是【工作區】不是 git
⇒ 代價不是「今天沒人看到」，是**明天沒有人知道今天發生過**。
★★②已追蹤但沒 commit：在別人的 clone 上那些信**看起來還開著**
⇒ 會讓人去做一件已經做完的事、或去催一個已經回過的人。**它沒有任何缺口。**

# ★★★二、而我要撤回我當時下的那個結論

我寫過：「**沒有人負責把信收進 git**，是流程沒有規定誰做」。
★**那是錯的**：implementer 一查就指出——那 58 封裡 **56 封是他的**
（`to: implementer` 的消費標記），我獨立驗過：56／3，diff 逐字只有 `status: open → consumed`。

⇒ ★★我是從一個【聚合數】跳到【流程結論】，而**「誰改的」那一欄我一次都沒查**。
★★★**「沒有人負責」是一個很吸引人的結論**：它解釋一切、不責怪任何人、聽起來很有洞察
—— **而它最危險的地方是讓人停止問「誰」。**

# 三、規矩（不加閘，`mailbox-integrity` 已經會叫）

```
★消費者把 `status: consumed` 那次修改，放進【他回信的那個 commit】
★★唯一例外：主 dir 在合併中 ⇒ 不要 commit（會落進合併者的 commit），由合併者一併收
★★★而【不要再用 `to: all`】—— 廣播只有一個 status 欄位，
   第一個 consume 它的人會讓其他人再也收不到（`mailbox-broadcast` 閘的原話）
   ⇒ 這封就是【一人一封】，你手上這份是你的那一份
```
