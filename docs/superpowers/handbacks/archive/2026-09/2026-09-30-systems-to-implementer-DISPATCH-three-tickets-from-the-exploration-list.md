# 派工三張，而分票的理由要講清楚

**分票判準（藍圖今天定的）**：**兩件事該不該同一張票，看它們的母體是不是同一個掃描**，
不是看主題像不像。照這條分：

```
①遭遇戰進行中 → 拒絕＋原因        母體＝床的 (c) 必有回饋      ⇒ 一張
②玩家面字串零英文識別字（70＋2）  母體＝床的 (d) 同一個掃描    ⇒ **合成一張**
③接受卻回被拒                     母體＝床的 (b) 回應↔結果一致 ⇒ 一張
```

## ★★★一、遭遇戰進行中：拒絕＋原因（41 筆，藍圖裁 (a)）

**spec** `docs/superpowers/specs/2026-09-30-during-encounter-refuse-with-reason-HOW.md`
```
藍圖逐字：非戰鬥指令一律 ok=false ＋「遭遇戰進行中，先處理戰鬥」，走結果句與事件流；
         戰鬥本身的鍵由 encounter_view 管，不在此列。**按鍵三態②的執法，零新機制。**
★那 41 筆不是 41 件事：三個條件裡【玩家在／隊在】是常態 ⇒ 唯一變數是「遭遇戰進行中」
  ⇒ 修一處，41 筆一起走
★★「哪些是戰鬥內動作」**不准手抄清單** ⇒ 母體＝`encounter_view` 處理的那些，機械抽
  ⇒ ★抽不出來（它不是可列舉集合）⇒ **回報，不要自己編一份**
★★★P3：那一句要 `ok=false` ＋原因，**不是 `ok=true` 配一句安慰**
  —— `ok=true` 會讓佇列／事件流以為事情發生了（＝今天「按接受卻說被拒」的鏡像）
★P4 成因要從 5 降到 4，而卷面要說出那 41 筆是【消失】還是【改分類到「設計上的靜默」】
  —— 那是兩件事
```

## ★★二、玩家面字串（70＋2 ＝ 兩個修點）

**spec** `docs/superpowers/specs/2026-09-30-player-facing-strings-no-raw-identifiers-HOW.md`
```
70 筆全部出自一處（`player_command_api.gd:237 describe()` 原樣印參數）
⇒ ★**70 筆但只有一個修點** —— 這是「症狀數 ≠ 工作量」最清楚的例子
★★中文表要與既有那份**同源**（`_forced_label` 那一系）⇒ 不另開第二張表
  ＋不認得的 id 印「（未知動作：<id>）」**不得吞掉**（同 #7 那條）
★P3 有一格守「一個真相只存一份」：玩家面那條路**不得出現第二張表**
★不動白名單（白名單變寬＝判準變鬆；要加就就地具名寫理由）
```

## ★★★三、接受卻回被拒（1 筆，而重點是【還有第三個嗎】）

**spec** `docs/superpowers/specs/2026-09-30-join-request-accept-says-rejected-HOW.md`
```
★這與用戶那句「我按 T 跳出表單後 還是寫我拒絕事件」**同族**，而那一族今天已經修過一次
  ⇒ **這是第二個實例，所以本票的重點是母體不是那一筆**
★★真因不是句子寫錯：**兩件事都真**（他接受了、隊伍滿了），
  而那一句把【我的決定】與【世界的結果】混成一句 ⇒ 玩家讀成「我按的沒生效」
  ⇒ 修法是**分開講**：「你接受了他的請求，但你的隊伍已滿 ⇒ 沒有加入」
★★★母體：`_forced_responses()` × forced_event 的**全部組合**逐一問
  「它的結果句會不會把我的決定說成別的決定」⇒ 三數相加＝總組合數
  ⇒ ★若「要修」那一欄 > 1 ⇒ **那不是本票失敗，是本票找到第三個**
```
