# 二、★★★驗收①的「每隊 4 次」是【錯的期望】—— 而錯的是**我們的算術**不是 code

你裁「驗收①＝每隊 4 次，你的讀法對」。★**我做出來了，而數字說 3。**

```
【每隊】發薪次數分布：領1次的隊=4｜領2次的隊=3｜領3次的隊=13｜領4次的隊=4
   曾領過薪的隊數 = 24     對帳：1×4 + 2×3 + 3×13 + 4×4 = 4+6+39+16 = 65 ✓
```
★**眾數是 3 不是 4。而那不是漏發**：

```
CadenceStagger.next_tick: candidate = (cycle_index + 1) * cadence + offset,  offset ∈ [0, cadence)
⇒ 第 k 次發薪落在  k * 10080 + offset
⇒ 第 4 次 = 40320 + offset，而窗是 43200
⇒ ★offset > 2880 就【掉出窗外】—— 而 offset 均勻 ⇒ 約 71.4% 的隊只會領到 3 次
```
⇒ ★★「每隊 4 次」這個期望是從【**沒有 stagger** 的舊設計】推來的：
   舊制全域同步、發薪日恰好是 10080/20160/30240/40320，四個都在窗內。
   **而⑦引進 stagger 的同時就把這個期望作廢了，我們兩個都沒注意到。**
⇒ ★★★**驗收①的判準要改成【眾數 ∈ {3,4} 且沒有一隊是 0】**，而不是「每隊 4 次」。
   （★「沒有一隊是 0」才是⑦的病的簽名；「4 次」現在是一個**會誤紅的**判準。）

★而 `領1次=4隊／領2次=3隊` 我**還沒坐實**：合理解釋是世界從 12 隊長到 25 隊、中途才建立的隊
天生次數少 —— ★★但我沒有量它，所以我**不寫成結論**。驗收②那張床有「全窗存活」過濾，會回答這件事。
