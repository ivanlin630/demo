# 一、你抓到的鏈我確認（★而它比「可砍項變承重」更難看一點）
```
⑩ 拆閥 ⇒ `local_value` 可以【正好 0】（深過剩）
⇒ 待領【貨】折值 = 0 ⇒ `pending_claim_amt` = 0 ⇒ `claim_value` term 直接 return 0
⇒ ★【自己的貨永遠沒有人去領】
⇒ ★★而那正是我自己在 `audit_escrow()` 裡命名的 `orphan_escrow`（「貨永遠沒有人來領」）
   —— ★★★我命名了那個失效模式，然後【自己造了一條通往它的路】。
```

# 二、★★而我要往下挖一層：**這不只是「到期退貨變承重」**

```
★`local_value(team, res)` 回答的是：【我還缺不缺這個】（target − stock 的缺口）
★★而「要不要去把【已經是我的、只是躺在別處】的東西拿回來」問的是【別的問題】：
   它問的是【放棄它的損失】—— 而那與【我現在缺不缺】無關
⇒ ★★★用錯的價值函數，答案會是 0，而它【看起來像一個正常的秤】
   —— 不是 bug、不是門檻、不是缺資料，就是【問錯問題】
```
★**所以「到期退貨」是兜底，而不是修法**：
   ★★就算有到期退貨，**在到期之前那批貨仍然是【沒有人想去領的】** ——
   ★★★而如果 `claim_value` 永遠是 0，**「領取」這個念頭在深過剩品上【從來沒有被想起過】**，
   那三件套的第③（行為級驗收）**會量到一個結構性的 0**。

## ⇒ 兩條路，而**我不自己選**
```
(a) 到期退貨兜底：貨標到期、由另一個機制歸還 —— ★它治的是【結果】不是【念頭】
(b) 換尺：待領【貨】的折值不用 `local_value`，改用一個【不問「我還缺不缺」】的尺
    （例如 `BASE_PRICE` ＝ 這東西一般值多少，而不是【對我現在的邊際值】）
    ⇒ ★★它治的是【念頭】，而且它讓「去拿回自己的東西」不再與【當下缺口】綁死
★★★而 (b) 有一個我看得到的副作用：`BASE_PRICE` 不隨世界變 ⇒ 它是【死尺】
   —— 而「死常數 vs 人格化/情境化」是這個專案有前科的那一族 ⇒ ★所以我不自己決定。
```

# 三、★而在裁定之前，我做的是【讓那個 0 被看見】
```gdscript
if Probe.enabled and v <= 0.0 and amt > 0.0:
    Probe.bump("claim.goods_value_zero")
    Probe.bump("claim.goods_value_zero." + res)
    Probe.add_amount("claim.goods_stuck_qty", amt)
```
★**它不改行為**（純觀測），★★而它把「有貨卡著、而折值是 0」這件事**變成一個數字** ——
   ★★★否則那批貨會**靜靜地留在 escrow 裡，而 `audit_escrow` 要等到存根消失才會叫**。
   （**存根還在的時候，它是「合法的未成交單」，不是分歧。**）

# 四、★而我要指出這一格的來源：**它是兩張票的交互作用，不是任一張的 bug**
```
⑩ 單獨看：拆閥、深過剩品價格 0 —— blueprint 裁過，是經濟真相
B-v0 單獨看：待領貨折成 local_value —— 在【有 clamp 的世界】它永遠 > 0，沒問題
⇒ ★★★兩張票【各自都對】，而合起來造出一條【貨卡死】的路
⇒ ★而它是在【B-v0 從 ⑩ 開分支】之後才存在的 —— 在 main 上它不存在
```
★★**所以它不會被任何一張票自己的驗收抓到** —— 這是你堅持 merge 序（每票的對照組＝前一票 merge 後的狀態）**買到的東西**。
