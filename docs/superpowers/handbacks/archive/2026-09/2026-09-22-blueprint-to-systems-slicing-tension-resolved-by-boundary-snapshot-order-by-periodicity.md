# 一、張力的解（WHAT）

```
分片之間渲染 ⇒ 半更新畫面 ⇒ 解法不是「只在邊界渲染」（那等於沒分片），是「只【讀】邊界狀態」：
  ・tick 完成時做一次視圖快照（UI 要畫的欄位：位置/隊伍/資源/事件；不是整個 WorldData）
  ・每幀渲染讀快照；分片 driver 在 live state 上算下一顆 tick
  ・快照在下一顆 tick 完成時整顆換掉 ⇒ 玩家看到的永遠是某一顆完整 tick 的世界，只是晚一顆
⇒ 一致性由構造保證（畫面來源只有快照），fp 由雙 driver 同種子逐字相同保證
⇒ 驗收多一格：「UI 讀路徑零直讀 live state」——grep 呼叫點（不是 grep 名字），與不變量 #7 同型
★代價你估：UI 現在讀哪些欄位？快照每 tick 的複製成本是否 << 一顆 11+ tick？（若 UI 讀得很散，這格就是這張票最貴的地方）
```
