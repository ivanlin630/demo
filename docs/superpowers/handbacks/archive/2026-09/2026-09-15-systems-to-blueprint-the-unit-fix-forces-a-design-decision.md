# ① 先講清楚這張票原本要修什麼

估敵方「有多肥」的那支函式，**有兩條回傳路徑、兩種單位**：
- **有分項情報時**：把幣、糧、建材**直接相加**，再除一個**手填的 100**
- **只有粗略印象時**：**直接回那個 0..3 的等級編號**

⇒ ★**而 72% 撞頂的真因是「等級編號剛好等於除數」**（3 ÷ 3 ＝ 1.000，實測逐字吻合）。

# ② ★審查打掉我推薦的那個選項

我原本推薦「**承認估不出 ⇒ 那一層不參與**」，理由是不要造假數字。
★**而他指出**：那支公式是**加總**，`A ＝ X ＋ Y`（X 缺席）與 `A ＝ 0 ＋ Y`（X＝0）
**印出來的分數逐位元相同** ⇒ ★★**「不參與」是語意上的區分，不是行為上的區分** ——
**對排序而言，低情報目標與一個「真的被估成一毛不值」的目標完全無法分辨。**
⇒ ★★★**而那正是我今天早上抓到的同一個病**：**「表裡沒有這一格」被當成「這一格是 0」** ——
**病灶換了位置，形狀沒變。**

# ③ ★★★而我順著他的推論再走一步：**只修一半也不安全**

```
今天：有情報那條 ＝ (幣＋糧＋建材) ÷ 100   ⇒ 例：600 ÷ 100 ＝ **6**
      只有印象那條 ＝ 等級編號            ⇒ **0～3**
      ★兩條【量級剛好差不多】—— 而那是巧合，不是設計
修好有情報那條（改成 Σ 數量 × 單價）      ⇒ 例：600 × 2 ＝ **1200**
⇒ ★★**量級從「差不多」變成「差幾百倍」** ⇒ **低情報目標永遠排在最後**
⇒ ★★★**那不是「修好單位」，那是【把一群目標靜默地判死】。**
```
★**這是算術不是量測**（我用的是表上的單價與桶的邊界），**而它的方向不會因為量測而反轉。**

# ④ ⇒ 三條路，**都不是純接線**（★我推薦第一條）

| | 做法 | 代價 |
|---|---|---|
| **A（我推薦）** | **分池**：有情報的目標彼此比；**情報不足的不進攻擊排序，改去偵查** | 行為改變（要你點頭）。★**但它是唯一不造假數字、也不判死任何人的** |
| **B** | 用**本隊自己已知的其他目標**的平均值當基準（審查找到的非 god-view 變體） | ★**是新機制不是接現成線**，工程量大一截 |
| **C** | 只修有情報那條、另一條維持現狀 | ★★**上面③證明它不安全** —— 我不推薦 |

★★**我推 A 的理由是語意**：**「我不知道它有多肥」的正確反應是【去看】，不是【假設它一文不值】。**
★★★**而它順帶解釋了一件事**：那個 0..3 的等級，**本來就比較像「我對它了解多少」而不是「它值多少」** ——
**把這兩件事塞進同一個欄位，是這個 bug 的根源。**（★審查也獨立指出同一點。）
