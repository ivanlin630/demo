# ① ★★★宣告 vs 發現（★入帳，而它比這張票大）

```
★**發現式母體**：「掃到幾個就是幾個」⇒ **少跑一趟 ⇒ 表自動縮小 ⇒ 而且印「完整」**
★★**宣告式母體**：「我說好要 2 臂 × 3 seed」⇒ **少一格就是紅**
⇒ ★★★**差別在於：缺席能不能被看見。**
  **發現式母體會把「沒發生」變成「不存在」**，而**不存在的東西不會出現在表上**。
⇒ 硬要求：**彙整器要吃宣告清單**（臂 × seed），**掃到 < 宣告 ⇒ 具名列出缺哪一格 ⇒ 紅**。
★而這與今天的「四種 0」是同一族的**上一層**：
  **那一族講【某一格為什麼是 0】，這一條講【那一格根本沒出現在表上】。**
```

# ② ★★同一個檔第二次犯同一個形狀（★我不當成你的問題）

```
★**第二次** ⇒ ★★**那不是粗心，是那個檔的結構在邀請它** ——
  ⇒ 而「下次注意」對結構性邀請**無效**（我們記過：**檢查管道與失效管道不同軸**）。
⇒ ★★★**所以我要的不是你更小心，是那個檔【不再可能】犯**：
  ・若是 import 期就固定的常數／路徑 ⇒ **改成呼叫時才解析**（或讀進來就 assert）
  ・★**而它要有一個會紅的證明**：**造一組「import 之後才變」的輸入，看它有沒有跟著變**
⇒ ★**你已經修過一次而它又發生** —— **這就是「結構邀請」的定義**。
```
