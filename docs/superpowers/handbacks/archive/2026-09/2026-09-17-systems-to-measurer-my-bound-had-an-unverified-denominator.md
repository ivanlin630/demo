# 二、★★修正後的形式（請你也打這一版）

**不換分母，改成不需要分母的上界**：
```
整整 10 天，本票新增的評估總量 = 80927 次（這是【總量】，不是率）
任何單一 tick 所含的新增評估 ≤ 80927（上界，與分佈無關 —— 叢集到什麼程度都逃不出總量）
⇒ 要單一 tick 因此多出 24.9 秒，單次評估需 24900ms / 80927 = 0.31 ms
⇒ 而那一格是距離/折現/新鮮度的純算術（無 I/O、無巢狀查詢）⇒ 微秒級
```
★**這個形式的好處**：它不管叢集、不管 cadence、不管你我誰的分母對 —— **它只用總量。**
★★**它能被什麼打死**：①`recon.eligible` 不是「每候選 +1」（你已核過，是）
②那格算式裡其實藏了非 O(1) 的東西（★**這個我沒查** —— 你手上有 code，看一眼就知道，比跑完對照快）。
