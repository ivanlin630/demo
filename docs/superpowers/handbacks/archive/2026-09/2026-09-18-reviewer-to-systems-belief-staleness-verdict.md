# ①供給端不判斷之後的安全預設——建議把「沒有預設值」變成語言強制，不是純規矩

你自己抓到的風險是對的：拆掉硬切之後,忘記定容忍度的讀者會拿到一個看起來正常但可能過期
很久的位置,不會紅。你的處置(遷移時在呼叫點明寫容忍度)目前是**寫在信裡的規矩**——
規矩要靠人記得執行，跟這行整條線今天在打的東西不同方向。

**建議**：讓容忍度變成**必填、無預設值**的參數,而不是留給呼叫端「自己記得檢查`age_ticks`」。
不是回到供給端硬切(那是你正確否決的舊模式)，是這兩者中間的第三種形狀：
```
現在的設計(供給端全域硬切)：一個常數，所有讀者共用，讀者無從置喙
你提的設計(供給端只回事實)：讀者自己看age_ticks/drift_tiles，但看不看是讀者的良心
建議的形狀：position_estimate()的容忍度是一個【必填參數】(沒有預設值)，
  函式內部用它算出blind，讀者拿到的還是一次判斷完的結果——
  但「有沒有定容忍度」這件事，忘記寫就是GDScript層級的缺參數錯誤，不是靜默通過
```
這仍然是「讀者自己秤」(容忍度由呼叫端決定，不是全域死常數)，只是把「有沒有秤」這個動作
從「靠記得」換成「沒有就跑不動」——跟你們今天全天在做的事(把規矩變成會紅的斷言)是同一個
方向，只是這次紅的形式是「執行期缺參數」而不是「閘紅」。

這是建議不是硬性要求——如果Slice 2遷移本身逐個都走R②審查(而它應該會)，人工審查也能擋住
這個風險，只是構造式的形狀會讓它連審查漏看都擋得住。

# ②Slice 1邊界(1-d+1-e)夠不夠——夠，而且你已經有的是比清單更強的形狀

你擔心「兩格擋不擋得住我順手改了某個讀者」，答案是：**1-e本身就是你要的那個構造式保證**，
不需要再加一份讀者清單。

理由：Slice 1明講「不改任何既有讀者」，也就是全庫目前沒有任何呼叫點呼叫新的
`position_estimate()`。在這個前提下，**fp與逐tick行為軌跡逐字相同**這件事，不是靠列舉
「這些讀者我核過了」湊出來的——它是**整個世界的輸出**在觀察，任何一個讀者被意外改動，
都會反映在某一tick的某個決策差異上，而fp/軌跡比對會抓到，不需要事先知道是哪一個讀者。
這正是「構造保證」vs「清單保證」的分野：清單會漏(遺忘、新增的讀者沒補進清單)，
而fp+軌跡是**觀察結果**不是**觀察清單**，結構上不可能漏掉任何有真實行為後果的改動。

1-d(belief_pos()內容錨)不是用來扛「所有讀者」這件事的，它只是額外釘住最可能犯的那個
具體錯誤(順手改了既有函式本體)——兩格分工是對的，不用再加第三格清單式的東西，
加了反而是退步(回到你們今天正好在避免的那個形狀)。

# ③「距離」的更正——對，而且你新公式本身已經印證了

漂移是「情報有多舊、目標多會動」的函數,跟「我現在離那裡多遠」無關——兩個不同的觀察者
站在不同位置,對同一則「三天前見過某城在(x,y)」的belief，漂移風險應該完全相同，因為
決定漂移的是「這三天目標可能移動的範圍」，不是「我現在站在哪裡」。你的修法(§3:
`drift_tiles = age_ticks × baseline_tiles_per_day() ÷ TICKS_PER_DAY`)本身就沒有任何距離項——
公式已經印證了這個判斷，不是另外需要驗證的事。「該不該為此出動」才是距離該登場的地方，
而那正確地被你排到決策層(§7排除清單)。這個更正對，不需要再打。
