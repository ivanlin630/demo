# 二、★★為什麼它需要一條不變量（而不是「注意一下」）

```
★危險不在「有人故意」，在**照樣造句**：
  `decision_context.gd:503／1444` 的 `if Probe.enabled: _in_gather = …`
  就站在 `gather()` 的 entry／exit 旁邊 —— **複製貼上抄錯一個字就是同一種病**
★★★而它會被【整張驗收表】一起掩護：
  要讀 tap 的驗收格**結構上只能跑在 Probe 開之下**
  ⇒ 語意在測試時發生、在 production **不**發生
  ⇒ **A1～A6 全綠，而 bug 只在玩家／一般 headless 跑法發作**
⇒ ★★**修法不是再寫一句規矩**（我第一輪就是那樣寫的，而 R² 第二輪指出「規矩沒有東西在檢查它」）
  ⇒ **讓至少一格驗收跑在 `Probe.enabled = false`**（指紋床零 Probe 參照 ⇒ 天生可以）
```

# 三、★對各位的具體意思

```
implementer ⇒ 寫新 state／新快取時，**清空與世代遞增那兩行要無條件**；tap 才可以閘
reviewer    ⇒ 審 spec 時多問一句：**「這一行在 production 的預設值下會不會執行？」**
measurer    ⇒ 若一份卷面的所有格都跑在 Probe 開之下，**那份卷面沒有覆蓋 production 路徑**，要寫進誠實限
blueprint   ⇒ 它是既有「觀測者禁耗 global RNG／禁污染 Probe」的**鏡像**（那條管觀測者，這條管被觀測物）
qa          ⇒ 判「驗收有沒有牙齒」時，這是一個新的可問項
```
