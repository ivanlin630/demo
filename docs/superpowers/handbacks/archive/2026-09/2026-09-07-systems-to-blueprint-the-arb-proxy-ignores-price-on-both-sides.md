# ★一、implementer 找到的（★我自己驗過）
```gdscript
order_system.gd:349  買邊:gain  = local_value(merchant, res) × qty              ←★自評值高＝該買,方向對
order_system.gd:362  賣邊:gain2 = local_value(merchant, res) × min(stock, qty)  ←★★而自評值【低】才是想賣的理由
```
★**場景**：merchant 自己該 res 過剩 ⇒ ⑩ 之後 `local_value = 0` ⇒ `gain2 = 0` ⇒ **不進候選**。
★★**而「我不需要這批貨」正是【我想賣掉它】的理由** ⇒ **方向是反的。**

# ★★二、而我往外再看一格：**兩邊都不看價格**
```
買邊 gain  = local_value × qty        ⇒ ★它【沒有減掉要付的錢】
賣邊 gain2 = local_value × qty        ⇒ ★★它【用自己的估值當收入】,而收入其實是【對方出的價】
⇒ ★★★所以這不是「賣邊寫反了」,是【這個 proxy 從來沒有把價格放進去】
   —— 買邊少一項、賣邊用錯量,而兩者是同一個缺口的兩半
```

## ★而一筆交易的真實期望價值是【捕獲的剩餘】（★由既有量導得出，零新常數）
```
買:gain = (local_value − ask)  × qty     ←★我得到的價值 減 我付的價
賣:gain = (bid − local_value)  × qty     ←★★我收到的價 減 我放棄的價值
⇒ 兩式都只用【已經存在】的量(local_value／ask_price／bid_price)
⇒ ★★★合「估算器禁手抄物理」那條:物理同源推導,不是新常數
```
★**而它自帶正確的邊界行為**：
```
自評 0 的貨賣掉 ⇒ gain = bid × qty > 0  ⇒ ★★該賣,而且【越沒用越該賣】——方向對了
自評 0 的貨買進 ⇒ gain = (0 − ask) ≤ 0  ⇒ ★★★不該買 —— 而那正是 zero-gain 該擋的那種
   ⇒ ★所以你先前裁的【嚴格 > 留著】在【算對的收益】上是對的,只是它現在架在一個算錯的量上面
```

# ★★★三、時序：**⑩ 之前這件事被 clamp 藏著**
```
有 clamp:local_value 最低 = BASE_PRICE × (1 − 0.5) ⇒ ★永遠 > 0
⇒ 賣邊 gain2 【永遠是正數】⇒ 方向錯只表現成【排序偏差】,不表現成【排除】
⇒ ★★⑩ 拆掉下限之後,它從【排序偏差】變成【完全排除】
```
