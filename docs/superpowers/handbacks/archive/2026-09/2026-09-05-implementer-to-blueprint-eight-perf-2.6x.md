# 一、數字（★動刀【前】量的，不是投影推算）

做法：`lod_perf_bed` 同一顆 seed 同一個 config 跑兩趟 ——
**pass A = 現行 LOD（＝before）／pass B = 全高清（★而 ⑧ 之後的世界【就是】pass B）**
⇒ 不必等改完才知道代價。

```
config   regime    teams  mean_us   p99_us    max_us    tps
default  LOD          15     3649    94879   2449012    274
default  full-HD      15     9642   466372   2559119    104
```

| 指標 | LOD（現行） | full-HD（⑧ 之後） | 倍率 |
|---|---|---|---|
| **mean**（攤銷吞吐，決定 tps） | 3649 us | 9642 us | **2.64×** |
| **p99**（worst-tick hitch） | 94879 us | 466372 us | **4.92×** |
| max（單 tick 最壞） | 2449012 us | 2559119 us | 1.04× |
| 可達 tps | 274 | 104 | **0.38×** |

## ★怎麼讀這三個數字（它們說的不是同一件事）
```
★mean 2.64×  = 平均每 tick 的成本 ⇒ ★★這是【能不能跑滿】的那個數
★★p99 4.92× = 最糟的那 1% 變【將近 5 倍】⇒ ★★★卡頓感比平均值難看得多
★max 1.04×  = 最壞單 tick 幾乎沒變 ⇒ ★那顆 hitch 【不是 LOD 造成的】，
              它在兩邊都在 —— ⇒ ★★拆分班【不會】讓最壞情況變糟，變糟的是【常態】
```
★★★而 **tps 104 vs playback 參考（1×=240tps／4×=960tps）** ⇒ **連 1× 播放都跑不到**。
   —— ★這是我看到最該給你的一行，而我**不替你判它可不可接受**。

## ★誠實限（三條，寫在數字旁邊不寫在腳注）
```
①`default` config 15 隊；★而 `warring_states`（重的那個）【上一跑被 3000s timeout 砍掉】
   ⇒ ★★我【沒有】拿 default 的比值代表全部 —— 已用 5400s 重跑，數字到了補給你
②bed 自帶 caveat：full-HD 會改行為（移速/思考頻率恢復全速）⇒ 兩趟世界 tick1 後發散
   ⇒ ★量的是「~15 隊規模下該 regime 一個 tick 值多少」的分佈 envelope，★★不是同一世界狀態雙跑
③這是【投影】：⑧ 真的落地後【我會再跑一次真的】對帳 —— ★★★不拿投影交差
```

# 補：**重的那個 config 量到了，而它把結論翻了一半**

```
config          teams  LOD_mean_us  HD_mean_us  HD/LOD  HD_tps   窗
default            15         3649        9642   2.64×     104   1 個月
warring_states     49        21887       40967   ★1.87×      24   3 日
```

## ★①**倍率隨負載【下降】**，不是上升
```
15 隊 ⇒ 2.64×   ｜   49 隊 ⇒ 1.87×
★★解讀：隊數越多，【跟隊數無關的固定成本】(日邊界／harvest／訊息／encounter…)佔比越大
   ⇒ 拿掉 LOD 多出來的那份【被稀釋】
⇒ ★★★所以「2.64×」是【小世界的上界】，不是代表值 —— 我上一封只有 default 時
   把它當成【the 代價】報給你，★而那是【拿最輕的 config 代表全部】。這裡訂正。
```
⇒ **實際落在 1.9×~2.6× 之間，隨規模往 1.9× 靠。**

## ★★②而**真正該看的那一行不是倍率**
```
warring_states 在【現行 LOD 下】就已經是 46 tps（HD 之後 24 tps）
                                    ↑★★★而 1× 播放要 240 tps
⇒ ★也就是說：★★【49 隊的戰國世界在拆分班【之前】就已經跑不動了】
⇒ ★★★⑧ 不是「把可玩的東西弄成不可玩」，是「把已經不可玩的東西再慢 1.9 倍」
```
★而被砍掉的長跑留下的部分資料同向：**85 隊時 LOD 已 20ms/tick（50 tps）、99 隊時 40ms/tick（25 tps）**。

## ★★★③誠實限（★寫在數字旁邊）
```
①`warring` 是【3 日窗】不是 1 個月 —— ★背景長跑被砍三次（>10 分鐘就會被砍，
   而【砍它的不是 GODOT_TIMEOUT】—— 我調大那個調了兩次都沒用，第三次才看出來）
   ⇒ ★★窗短 ⇒ 隊數只長到 49（不是 99）⇒ 【倍率可比，絕對值不可外推】
②兩個 config 的窗不同（1 個月 vs 3 日）⇒ ★★★兩列的【絕對值不可互比】，只有各自的倍率可比
```
