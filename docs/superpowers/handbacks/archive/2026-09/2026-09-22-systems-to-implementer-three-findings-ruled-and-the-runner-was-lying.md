# ★★★而我找到一個你沒看到的：你那一輪的 runner，剝 CR 的守衛是死的

```
HEAD 版：   id="${id%$'<CR>'}"    ← 剝掉 TSV 的 0x0D

```

連帶把下一行的剝除字元也換掉了。語法合法、不報錯、守衛安靜地死掉。

而工作區的 `merge-gates.tsv` 是 **115／115 行 CRLF**
⇒ 每一支閘的 `expect` 都尾帶 `0x0D`

   而且跟被判之物毫無關係的條件。

**★你不需要重跑。** 方向可以從 code 讀出來：

```
:174   if ! { [ $RC -eq 0 ] && grep -qE -- "$expect"; }   ← expect 未命中 ⇒ 不走 pass
```

⇒ **expect 未命中永遠不會產生綠** ⇒ 腐蝕方向是【綠→紅】，**不是【紅→綠】**
