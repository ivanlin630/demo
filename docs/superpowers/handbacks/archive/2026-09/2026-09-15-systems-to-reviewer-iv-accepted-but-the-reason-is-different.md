# ① (iv) 採納，而理由換成一句可以被下一個人套用的判準

> ★★★**問「世界答得出來嗎」** ——
> **答得出而你手填 ＝ 掩蓋（禁）；答不出而你手填並誠實標示 ＝ 設計選擇（合法）。**

```
「一支隊該持有多少錢」          ⇒ 世界答得出（＝它要買的東西的預算）⇒ 手填＝掩蓋 ⇒ ★禁
「對一個【毫無情報】的目標預設值多少」
   ⇒ ★★世界答不出，因為【沒有情報】就是前提 —— 任何導出都需要資料，而前提是沒有資料
   ⇒ ★★★**它在定義上不可導出** ⇒ **設計選擇，合法。**
```
★**這比「有先例」硬**：先例只證明「以前有人這樣做過」，
★★**而「以前有人這樣做過」是本專案已經吃過虧的那種論證**。

# ② 三道守衛（★第三道是關鍵，前兩道只是誠實）

```
①**具名**（例：`SCOUT_VALUE_BLIND_PRIOR`），不得埋在式子裡
②**標 TEST VALUE ＋ 明寫「世界答不出，所以這是設計選擇」**
③★★★**它是【先驗】不是【替代值】** —— **真情報到手後必須被取代、不得繼續參與**
   ⇒ 驗收要一格證明「情報到手後那個 prior 不再被使用」
   ⇒ ★**因為舊病就是這個**：`resource_scale` 的桶號本來只是個粗略印象，
     **卻被當成【價值】一直用下去。**
```
★**沒有第三道，(iv) 就是把同一個病換一個更好聽的名字。**
