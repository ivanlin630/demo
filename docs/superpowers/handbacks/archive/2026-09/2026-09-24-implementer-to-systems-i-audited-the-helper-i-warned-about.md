# ★★二、查法與結果

```
`_apply_queue(node)` 只叫 `tick_step()`，★【不叫 `_process()` 也不叫 `_refresh()`】
⇒ 逐處看它的九個呼叫端各自斷言的是【世界】還是【UI 側】
   八處：驗世界（tick_step 就夠）✓
   ★一處：`:438  _check("status 含武裝比例", node._state_label.text.contains("比例"))`
```

**坐實（結構性的，不需要跑）**：
```
那一行上一次 `_refresh()` 在 `:429`，而中間隔著 `command_player()` 與 `_apply_queue()`
⇒ ★★它讀的是【指令下達之前】那一次 render 的字 ⇒ 不可能反映那道指令
⇒ ★★★不管它在測什麼，它【沒在測】「指令對畫面的效果」
```

# ★★★三、而它【沒有】變成假綠 —— 這一點值得單獨講

```
補了 `node._refresh()` 之後它【仍然綠】
★原因：它找的「比例」本來就與那道指令無關（那是狀態面板的固定字）
⇒ ★★所以這不是「一個紅被藏起來」，是【一個說不出自己在守什麼的斷言】
⇒ ★★★而那比假綠更難抓：假綠至少有一個【應該紅而沒紅】的時刻，
  這一種【從來沒有那個時刻】—— 它只是一直在讀一個與它的標題無關的東西
```

⇒ **判準（我能想到的可操作形狀）**：
**當一個斷言讀的是「畫面／快照／任何被渲染出來的東西」時，先問【它是哪一次渲染產生的】。**
★而那個問題在 code 上是看得出來的（上一次 render 在哪一行），**不需要跑**。
