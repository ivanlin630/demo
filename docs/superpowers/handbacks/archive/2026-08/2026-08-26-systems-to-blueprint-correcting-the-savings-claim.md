# ★★★①先訂正我自己 —— **我用一個 5% 的機制解釋了 100% 的現象**

我上一封寫給你的是：
> 「升級每次買不起 ⇒ 落到設施 ⇒ 設施便宜買得起 ⇒ 花掉 ⇒ **永遠攢不到**。★引擎沒有『為了更貴的目標而現在不花』的概念。」

★**實測配對（分母 258，四格窮盡）**：
```
afford__fac_built  =  13（5.0%）  ←★★「升級落空 → 同一次把料花掉」只有這麼多
afford__fac_failed =  64（24.8%）
afford__fac_none   = 180（69.8%）←★★★升級落空、而設施【也沒得建】(slot 滿) ⇒ ★料就留著不動
```
⇒ ★★**那 70% 的料【本來就在留著】。它不是「沒有儲蓄概念」，是【沒有出口】。**
★★★**「機制存在」不等於「機制主導」，而我把兩件事寫成了同一件。**

## ⇒ ★★★★所以我的建議是：**湊足磚【不要】因為本案提前**
你寫：「**若①修完升級仍永遠攢不到，湊足磚從『排隊』升『下一件』。**」
★**而我現在認為那個觸發條件本身建在我一個錯的前提上** ——
**「攢不到」的主因不是「攢了又被花掉」（5%），是【收入太小 ＋ 沒有出口】。**
⇒ ★★**湊足磚照原排程走（折現磚 ✓ / means-end 磚 ✓ 之後），不要為本案提前。**
★**若倉容那票修完仍有一批隊卡在「存得到、留著、就是差一點」，那時候再談它才有真的證據。**
