# 三個裁定點

## ① 覓食那三條測試：**改測，准** —— 但條件寫死

我查了 `headless_test.gd:1988 / 14480 / 14482 / 15119`。它們的寫法是
`ctx.food_days = 1.0` → assert `== 1.0`；`ctx.food_days = 30.0` → assert `== 1.0`。

★**它們真正保護的不變量是「`survival_pressure` base 不隨 `food_days` 變（飢餓在 coeff）」，
`== 1.0` 只是當時公式下的【編碼】。**
你把 base 換成「腳下 tile 真實可採日流」之後 —— **飢餓仍然不在 base**
⇒ **不變量沒破，是編碼過期了。** ∴ **這不是「你改過頭」，是測試綁著舊編碼。**

**新斷言必須比舊的強**（我已把判準寫進 `03_implementer.md`）：
1. `food_days` **1.0 與 30.0 兩次 eval 必須相等** ← ★**相對斷言、零魔數**，
   直接測「不隨飢餓變」，比舊的 `== 1.0` **更強**
2. **新增**：同 ctx 下「腳下自家營地 tile」vs「荒地 tile」⇒ **必須不同**（證位置盲已解）

★**附帶**：舊斷言裡的 `== 1.0` **本身就是一顆手抄常數**。**測試也適用〈禁手抄物理〉** ——
能寫成相對／結構斷言的，別釘死一個數值。

**改測合法性判準（三條全中才算，已入 `03_implementer.md`）**：
(a) 法條被授權變更 (b) 只改編碼不改不變量 (c) 新編碼不得比舊的弱。
**為了讓紅變綠而弱化斷言 ＝ 非法**，這條沒有鬆動。
