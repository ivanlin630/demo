## ★T3 預算錨定：我的判斷——錨死跟重置兩極都不對，提第三案
你問「錨在進入 RETURN 那一刻、rehome 不重置」會不會誤殺健康長追逐——**會**，你自己的算術已經證明了（初始 ETA 可能很小、`3×小ETA` 可能小於一趟正常尾隨總耗時)。這不是猜測風險,是你舉的例子本身就踩得到。你否決的三個替代錨（max=沒錨／距離比值=尾隨時失效／rehome次數上限=偽裝常數)我覆核過,否決理由都對,這三個真的都不行。

**第三案（你沒列出的選項）：預算隨 rehome 累加、不重置也不凍結**——
```
每次 _stamp_return_eta 被呼（真 rehome，非首次）:
    xd["return_budget"] = xd.get("return_budget", 0) + RETURN_ABANDON_ETA_MULT × new_eta
    # 首次進 RETURN：return_budget = RETURN_ABANDON_ETA_MULT × new_eta（等同你原案的錨）
放棄判準：elapsed(from return_start_tick,首次不變) > return_budget
```
**跟你已否決的方案的差別**：
- 跟「錨死不重置」的差別：目標**真的**變遠了（新 ETA 明顯大於前一次)，預算會**跟著長**，不會拿「進RETURN那刻恰好很近」的小預算去審一整趟後來變長的追逐——直接解決你舉的誤殺案例。
- 跟「重置(現況bug)」的差別：**預算不是被换成新 ETA、是累加**——純尾隨（每次 rehome 的新 ETA 都跟上次差不多小）時,預算增長速度跟 elapsed 增長速度同量級,不會出現「只要一直動就永遠不判定」的無限縱容;而如果母隊持續**加速遠離**（每次 rehome ETA 越滾越大),elapsed 終究會追上累加預算的增速（因為每段 elapsed 實際發生的時間通常比對應那段的 `k×eta_i` 更接近 1 倍而非 k 倍,除非追逐效率剛好卡在臨界)——**多數持續發散的追逐仍會被判定**,只是不像原案那樣一開始就用一個可能過小的數字砍掉一切。
- **殘留的邊角**：若母隊**真的**永遠不停但每段 rehome 的相對距離增量剛好穩定不變（教科書式的等速平行移動),這個累加預算理論上會跟 elapsed 同步成長、永不觸發——這跟「健康的無限尾隨」在直覺上其實是同一件事（porter 確實一直追得上,只是永遠追不到終點)。**這個殘留邊角要不要單獨管一個外層絕對上限**（例如整趟 RETURN 累積 elapsed 超過某個很寬鬆的絕對天數才強制砍,純粹防資源永久卡死,非追逐品質判準)——**這條我沒有預設答案,理由對稱於你自己在 §3 T3 那句「不新增絕對天數常數」的規約顧慮,你來定要不要開這個例外**（我傾向：這個例外的定位是「防呆的資源回收上限」不是「追逐品質判準」,性質類似`erase_teams`那種系統健康維護,不算違反時間包§2「找不到自然錨才准絕對」的精神——因為它本來就找不到自然錨,是故意的最後防線)。

## ★不管選哪個方案，2格內證偽稽核要升級成硬性 gate，非「傾向」
你自己提的「`stranded(timeout)`事件裡有多少筆當時porter其實距母隊≤2格」這條**證偽誤殺**的量測——**這條不該是你信裡寫的「我傾向做」,該直接寫進 spec 的 gate,不分方案都要**。理由：這題你自己講「沒有預設答案」,代表無論選錨死、選我這個累加案、或選你原本想放寬倍率那條,**紙上推導都無法保證涵蓋所有情境**（你我剛剛的討論已經證明這題比表面複雜)——既然理論分析靠不住,唯一可信的收斂點就是實測資料。這條要求跟你自己這輪從 T1 學到的教訓（先看tap再談門檻）是同一個精神的延伸應用：**T3 這題也不該只靠公式推理過關,要有一條硬性的『timeout 觸發時真的是沒救了、非誤殺』的實測 gate**。
