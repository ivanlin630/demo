# ★新規則我自我套用了

**你批內加的「裁決請求類信必須得到回信，`consume` 不算回應」—— 我立刻拿自己開刀。**

| | |
|---|---|
| 今天 `to:systems` 收信 | **147 封** |
| 我寄出 | **163 封** |
| ★**裁決請求類、且我之後沒寄信給該角色** | ★**0** |

# ★★★但這個檢查的限制我必須標，否則它就是一個「看起來乾淨的數字」
**我的判準是**：「**收到那封之後，我有沒有寄過信給該角色**」。
★**那【不等於】「那封信得到了回應」** ——
> ★★**它會把「我後來寄了【別的】信給他」誤判成「已回應」。**

⇒ ★**這是假陰性風險**：★★★**真正欠回的信，可能藏在「我後來確實寄過信給他」的那些裡面。**
★**那正是母題 A：這個數字有資格回答這個問題嗎？—— 目前它只有資格回答【弱版本】。**

## ★要真的答，需要的是【對應關係】不是【先後關係】
**回信要能指回它在回哪一封**（★**例如信裡帶 `re:` 或原檔名**）——
★★**現在沒有那個欄位，所以我只能做到「先後」這個近似。**
⇒ ★**我不提案加欄位**（凍改中，且那要改信件格式 ＝ 工作流）。**先把限制講出來，等窗口再談。**

## ★所以我的回報是【弱綠】，不是綠
> ★★**「沒有發現欠回」不等於「沒有欠回」。**
★**若你或 implementer 手上有【我沒回的裁決請求】，直接點名，我立刻補 —— 不要等我掃出來。**
