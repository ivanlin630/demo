# ★★★★★訂正我自己：**「世界結束」不是文明崩潰，是【玩家隊絕後】——H 不變量 by design**

我上一輪把它框成「**試跑的質地訊號：七支放慢到 3 天 ⇒ 世界 5.7 天內結束**」。
★**那個框架過強，我撤回。** 逐層查完是這樣：
```
sim_runner.gd:81-82   state.game_over ⇒ advance_tick 回 "game_over"（凍結）
game_over 全庫只有兩個 production 賦值點,★兩個都只為一件事:
   event_system.gd:80            「玩家絕後（TeamN 無繼承人）」
   player_command_system.gd:926  「玩家絕後（隊已滅,無繼承人）」
★★兩處都有 player_id == -1 守衛（觀察者世界永不凍結,註解還帶血證「大考 warring leg day70 凍死」）
★★★而 config/warring_states.json 有 "player" 區塊 ⇒ 這張床【有玩家】⇒ 守衛不適用,凍結是 by design（H 不變量）
```
★**而那個玩家隊長這樣**：`join_mode: independent`／`population: 10`／★★**`starting_named_count: 1`**
⇒ ★★★**「世界結束」的真相 ＝【一支 10 人、只有 1 個 named member 的獨立隊，其唯一 named 成員死了】。**
★**那不是「決策太慢導致廣泛崩潰」，也不是「殲滅 cascade」** —— **它是單點故障。**

# ★★而 A/B 那兩個 `teams` 數字【不可直接比】—— 它們不同刻
```
T3    ：teams 69  ← ★量在 tick 8160（凍結當下）
閥回滾：teams 89  ← ★量在 tick 17280（跑滿 12 天）
```
★★**兩個不同時刻的數放在同一欄比較，是我們自己記過的那條**：
**「比率的分子分母不同時刻／不同母體 ＝ 沒有意義」** —— ★★★**這裡是它的變體：不同【終點】的兩個絕對數。**
⇒ ★**要比就比【同一刻】**：**兩條都取 `tick 8160` 的 `teams`。** ★★**在那之前，「69 vs 89」不支持任何結論。**

# ★★★還站得住的事實（★這條沒有被訂正掉）
> ★**T3 條件下，玩家隊在 tick 8160 絕後；閥回滾條件下，到 17280 都沒有。同 seed 同床，唯一差異＝七支 cadence。**
★★**這仍然是真差異，值得查** —— **只是它的名字是「一支脆弱的獨立隊活不活得下來」，不是「世界崩潰」。**

# ★★★★★你的③正中，而答案就是上面那段
> **你問：「什麼算世界結束；殲滅 cascade ＝ 絕境老家族？」**
★**答**：**在這個 code base，「世界結束」只有一個意思 ＝【玩家絕後】**（H 不變量，兩個賦值點都是它，且都有無玩家守衛）。
★★**跟殲滅 cascade / 絕境家族【無關】** —— **它甚至不看世界狀態，只看一支隊有沒有繼承人。**

★★**因為那支隊 `starting_named_count = 1`。** ★**S2 那兩份 30 日終量沒凍是運氣好，不是結構保證。**
