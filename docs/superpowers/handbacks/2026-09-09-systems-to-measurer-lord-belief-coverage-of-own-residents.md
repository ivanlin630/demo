# 為什麼要這個數字

批一④（`DISTRIB_RELIEF_REF_POP = 5.0`）我本來以為是「死常數沒接真值」，**撤回了**：
`goal_resolver.gd:373-374` 的註解寫著資訊網 arc 已**移除 god-view live-read**
⇒ 那個 5.0 是「**領主不被允許知道真值**」的結果，不是漏接。

blueprint 已裁 WHAT 方向：**他要 relief 隨【領主相信的】聚落規模變**（誤判成戲＝沙盒正味），
★**但硬前提是 belief 覆蓋率** —— 覆蓋率低時**禁止**做 fallback-常數的假接線
（那會做出「看起來接了線、實際大多數情況沒接」的東西，**比不接更糟**）。

# 要的數字（★母體先報，再報比例）

```
母體（★這格要先講清楚,不是先給比例）：
  配對 = (領主隊, 自家居民隊)
  領主  = team.parent_team_id == -1 且 faction_id != -1 且該 faction 的 leader_team_id == 自己
  居民  = FactionAISystem.is_resident_static(state, resident) 且 resident.faction_id == 領主的 faction_id
  ⇒ ★分母是【配對數】不是隊數。★★覆蓋率的分母搞錯會做出一個看起來很高的假數字。

①覆蓋率   有 belief 記錄的配對數 / 配對總數
②新鮮度   有記錄的那些,belief 的 age 分布（min/median/max）
   ★因為「有一筆三十天前的記錄」與「有一筆昨天的記錄」對接線的意義完全不同
③偏差     population_est vs 真 population 的相對誤差分布（★量測讀真值是可以的,
   ★★但要在卷面寫明【決策端不准這樣讀】,免得下游把這份卷當成「真值可用」的證據）
④★★★分佈不是平均：逐 faction 報,而不是全世界一個數
   —— 一個 faction 覆蓋 100%、其他四個 0%,平均會說「20%」而那是三個不同的世界
```

# ★★一魚兩吃（blueprint 加的那一問）

**若覆蓋率低，那本身可能是資訊網的縫**：共位裁定說**自家 resident 理應最常被看見**
（同勢力、常共位、有 convoy 往來）。
⇒ 所以請在卷面直接回答：**低覆蓋是「belief 通道沒接到自家居民」還是「接了但過期被清掉」？**
   ★這兩者的修法完全不同（前者是缺一條產生路徑，後者是 TTL/prune 太兇）。
   ⇒ 判別法建議：看 ②的 age 分布 —— 若**有記錄的都很新**而**覆蓋率低**，
     那比較像「只有少數配對曾經產生過 belief」；若**age 普遍很老**，比較像 prune 沒發生但也沒更新。
