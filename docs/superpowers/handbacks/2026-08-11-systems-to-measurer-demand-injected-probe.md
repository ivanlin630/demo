# 派量測員：demand-injected measure probe（size-production conditional）

用戶拍 A。既有 concentrated/dispersed fixture、main 含 iii。★★**probe 非 shipped 機制**：demand 注入 = test-only bed harness 只為答 conditional、確認 payoff 存在才決定建 genuine demand 機制（B）。

## ★demand 注入法（感知鐵律-honest）
test-only harness 每 cadence 注入 **synthetic 製造品買單**（tools/weapons/goods）進核心村 team_known（如外部 export 買家親聞單；`NeedOracle.demand` 讀 team_known 親聞買單 → facility need `_construction_facility_need` / `_facility_deficit` → build → manufacture fire）= 解 no_facility precondition。
- ★**先驗注入生效**：`manufacture.fired` > 0（前=0）+ `manufacture.noop_no_facility` 大降 + facility level>0 真蓋。

## ★conditional 量（注入後、生產淨值帳）
concentration（1 大隊+共享勞力池+多設施）vs dispersion（多小）：好處側（`LaborSystem.pool_of` 利用 + facility `worker_rate` + output 量 + 貿易 throughput）vs 成本側（維護/消耗）、核心村（濾 spinoff）長期 gradient（~4-6mo、**compound 否** = 領導軸 1 大隊短期 capped 0.38-0.45 → 注入 demand 後長期追平/超越 vs 仍 capped）。

## ★方法
核心村 focus 濾 spinoff、spinoff 率對稱、3seed determinism、★relief 殘餘 confound 分清（核心村 production 純內生 labor pool 非 relief-fed、relief_dispatched 仍 false）。★★命門 measure-first：**dump 真生產數字禁 pre-assume**（乙+3 層 premature 燒過）。

## 序
★用戶要求「好了先回報」= 結果鎖後直接回 systems → 我推用戶（非等下站）。★長跑附 specimen（核心村逐月 demand→facility build→manufacture→output 發展 conc vs disp）送 QA。output → conditional 結果（size given manufacturing 有無優勢）→ systems 推用戶 + consolidate（正 payoff→B 樞紐 arc / 零 payoff→size 生產真不 matter 收）。地基 KEEP。
