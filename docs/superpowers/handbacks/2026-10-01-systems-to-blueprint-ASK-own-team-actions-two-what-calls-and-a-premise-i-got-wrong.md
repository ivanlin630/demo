# 兩個待裁 ＋ 一條前提訂正

**票**：自家隊／無目標動作的全列＋原因（＝你 2026-09-30 裁定②「動作全列拆成**三個具名母體**」的**第二個**）。
第一個母體（團隊目標）已竣工並進主線。spec 草稿已寫好、待 R²，而**這兩個問題是 WHAT，我不自己定**。

## ★★★一、要你裁的第一件：情境動作不可做的時候，**列不列**

```
四支動作只在「剛打完一場」的狀態下存在：
  take_loot（收取戰利品）／leave_loot（放棄戰利品）／subjugate_enemy（收編敗者）
  ／confirm_gather_intel（確認打聽）
沒有那個狀態時，它們現在【整列消失】。兩個選項：
  (a) 列出來 ＋ 原因「你沒有剛結束的戰鬥」⇒ 玩家永遠看得到完整的動詞表
  (b) 不列                                ⇒ 清單短，但玩家不知道有這個動作存在
```

★**我傾向 (a)**，理由是本票的整個動機就是「不可做也要說得出為什麼」；而 (b) 會讓這四個名字回到「只有懂的人才知道」。
★★**但這是 WHAT**：它直接決定**畫面上永遠有幾列**（而版面 v2 的區塊高度吃這個數）⇒ 你裁。
★★★**而 (a)／(b) 不是只有美感差別**：選 (a) 之後，「灰掉的列」在畫面上會**常駐**四列，那是你在版面稿裡要留的空間。

## ★二、要你裁的第二件：`offer_surrender` 算第二母體還是第三母體

```
它宣告 `allowed_kinds = ["team"]`（要選一個目標），★而它被寫在「無目標動作」那個區塊裡
（`player_query_api.gd:463` 附近），條件是 `state.encounter_active and focus_team_id != -1`。
⇒ 它是【戰鬥中對當前對手】的動作。
```
★我傾向**照宣告走**（`target=="team"` ⇒ 不在本票的母體），並把「它放錯區塊」就地具名登記。
★★要你裁的是語意：**投降請和在玩家心裡是「對某一隊做的事」還是「在戰鬥中做的事」** —— 前者歸第一母體（團隊目標），後者需要第四類（戰鬥中）。
★★★**而我不建議現在開第四類**（一個母體只有一個成員 ＝ 一份長度 1 的手抄名單，那是我們正在治的病）。

## ★★三、前提訂正（我自己寫錯的，而它擋了這張票一輪）

```
`defers.tsv:305` 我寫過：「自家隊那一類**沒有任何來源常數**」⇒ 因此第一張票只做了第一個母體。
★而那句話是錯的：`player_command_system.gd` 的 `_action_registry` 有 **51 個 key**，
  那一類的 11 個裡 **10 個在裡面**（只有 `cancel_move` 不在，它跟 `move_to` 一樣是另一套 dispatch 的自己一格）。
⇒ 正確的句子是【**沒有一個剛好等於這一類的常數**】：registry 是超集，缺的是**邊界的宣告**。
⇒ ★★我的錯法：我查了「有沒有一個叫 `OWN_TEAM_ACTIONS` 的常數」（沒有），就寫成「沒有任何來源」。
  implementer 用不同工具異源重數確認了 51／10-in-11，並多驗一件我沒查的：
  ★★★GDScript 的 dict 字面**重複 key 會靜默覆蓋** ⇒ 若 51 行裡有重複，那個 51 會比實際大而**不會紅**；
    實測 51 ＝ 51、無重複 ⇒ 引用它是安全的。
```

★**為什麼要告訴你**：你裁定②把它拆成三個母體，而**第二個母體被一條假前提擋了一輪** ——
那一輪的成本是真的（第一張票的卷面上寫著「本票因此只做團隊目標那一類」）。
★★而它現在解開了：本票的母體**不是一份新清單**，是從 registry ＋ 一張 `target` 宣告表**機械導出**。

## 四、不需要你裁的（我已定，列出來讓你能否決）

```
·母體形狀：`ACTION_SHAPE`（key ⊆ registry，宣告每個動作的 `target`），母體 ＝ `target=="none"` 的那些
  ⇒ 完整性靠**反向掃**（registry 每個 key 都要有一列，漏一個紅並指名），不靠紀律
·不把既有的 `TEAM_TARGET_ACTIONS` 收成衍生檢視（兩支床＋同格閘在逐字引用那個符號名
  ⇒ 一起改會讓三支守衛同時失去主詞）⇒ 改成**異源交叉斷言**＋登一列 defer 分兩票走
·`defers.tsv:306`（格動作的界線不可機械讀）**不宣稱解除**：它的解除條件是「宣告與**行為**對齊」，
  而 hunt／camp 讀不讀腳下那格是行為問題，本票不動行為 ⇒ 第三個母體仍然要等它
```
