# 判決：`issues`（小），`premise_contradiction: false`

## ①代理變數——**方向對，但找到一個真的會造成 false freshness 的反例，而且不是冷門邊角**

你想到的「量完隔很久才補交」是安全方向（讓它更舊），我認同。★**要找的是反方向——讓 add-commit 看起來比實際量測時間更新**，我找到一個：

**worktree 分支延遲 merge**。這個專案的既有工作流（`CLAUDE.md`）明寫：implementer 在 `.worktrees/<feature>/` 上做事，code 寫 worktree，最後才 merge 回 main。★**若一顆 verdict.json 在 worktree 分支上早就寫好（針對當時的舊 code 分析完成），但那個 slice 隔了一段時間才真正 merge 回 main**——`git log --diff-filter=A` 在 main 分支上看到的「add」commit，是【merge 落地那天】，不是【verdict 實際被寫下、依據哪個版本的 code 分析】那天。★★**這代表：一顆對著舊 code 下的結論，會因為它的 worktree 遲遲沒合併，而在合併那天被系統誤判成「剛量的、很新鮮」**——這正是 false freshness，會讓真正該被標記過期的結論被漏掉。

★**這不是邊角案例**——這個專案的整個多終端工作流【本來就】是 worktree-then-merge 為常態（`docs/process/00_roles.md`/`07_mailbox_trigger.md` 描述的就是這個模型），不是罕見分支操作。

⇒ **建議**：三行誠實限加一句，明講「worktree 延遲 merge 會讓 add-commit 時間晚於實際量測時間，此代理對這類情況會誤判為新鮮（唯一已知的高估新鮮度反例）」——不用現在修（要修需要讀 verdict 內文找有沒有更早的時間戳，成本高，不建議現在做），但要誠實列出來，跟你自己已經列的「保守正確」那句話放在一起，不能只講安全方向不講風險方向。

## ②取捨——**同意，不是自我開脫**

backfill 才是真正的自欺——用印象重建一個當時沒記下來的來源，等於用現在的記憶去回填過去的事實，跟你們今天已經反覆抓到的「negative assertion 沒有窮盡證據」「引用坍縮成沒人查證的斷言」同一族問題。**印出盲區大小，止血在寫入端**是唯一誠實的做法：60 顆的盲區是真的存在，承認它比假裝補上它更安全。這個取捨不需要重新考慮。

## ★★★③會不會變第二個沒人看的 tree-div——**不會，但要做一件事才能守住這個判斷**

我認為它跟 tree-div 結構上不同，理由是**觸發條件的窄度**：tree-div 印的是一個**永遠存在、單調成長、跟任何具體事件都無關**的數字（純粹背景噪音，沒有人有理由在特定時刻去看它）；這道閘只在**「根修 merge」這個罕見、具體的事件**發生、且**剛好**命中某顆已具名的舊結論時才印出東西——它的預設狀態是【空】，不是【一個持續變大的數字】。**空輸出不會累積成噪音疲勞，只有在真的有東西要說的時候才說話**，這跟 tree-div 的失效形狀不一樣。

★**但這個判斷成立有一個前提**：它印出來的東西要**真的被看到**。你自己引的「`bed_arm_gate` 教訓（人讀的是 print，不是檔頭註解）」提醒了格式問題，但沒解決**位置**問題——若這道閘的輸出被埋在 13 道閘的一大堆輸出中間，即使它本身夠稀有夠具體，人眼掃過一整面 merge log 時還是可能滑過去（尤其如果它平常大多數時候印的是「本次無候選過期」這種空結果，人會養成「這道閘習慣性看不出東西」的預期，等它真的有內容時反而最容易被跳過）。

⇒ **建議**：不是重新設計判準，是**輸出位置/格式的一個小要求**——當候選清單非空時，讓它的輸出跟其餘 12 道閘的例行輸出**視覺上分開**（例如放在整份 merge-gate 輸出的最後，前後加明顯分隔線，或用不同前綴），不要跟其他閘的例行綠燈輸出混在一起捲動過去。這個成本很低（純格式），但直接針對「會不會被看到」這個真正決定它有沒有用的變數。

## ⇒ 要你補的
1. ①：三行誠實限加一句 worktree 延遲 merge 的 false-freshness 反例，不用現在修，誠實列出。
2. ②：不用補，判斷正確。
3. ③：做（不要因為跟 tree-div 都是 warn-only 就放棄），但輸出非空時要視覺上跟其他 12 道閘分開，不要混在一起捲動過去。

**premise_contradiction: false，①③處理過即可整票 CLEAN。**
