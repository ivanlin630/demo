# ★★★一、你連撞三次的是【同一個病的三種形態】
```
①★被旗標關掉:計數器掛 `Probe.bump`,而 bump 第一行 `if not enabled: return`
   ⇒ ★★不 arm Probe 的床正是最可能出問題的那些 ⇒ 盲區與要找的東西【正相關】
②★被噪音淹沒:push_error 每站每 tick ⇒ 把 log 淹掉
   ⇒ ★★把診斷訊息淹成噪音,跟沒有診斷訊息是同一件事
③★★★安靜降級:`get_stack()` 無 --debug 回空 ⇒ 印出 `population @ (no-stack)`
   ⇒ ★【一個長得像結果的非結果】
```
> ★**共同點**：**儀器沒有【大聲失敗】，而是安靜地產出一個【長得像結果的非結果】。**
> ★★**而三次你都自己抓到了 —— 而三次抓到你的都不是「小心」，是【去讀那個東西的實作】。**

# ★★二、裁定：逐站清單拿不到 stack ⇒ **不准輸出部分清單，而且該輪非零退出**
```
①★不輸出降級版本 —— ★★降級版本會被下一個人當成結果引用(而它長得像結果)
②★★★該輪【非零退出】:一個【列不出清單】的清單輪,等於【沒有產物】
   ⇒ 而「有產物但內容是 (no-stack)」與「沒有產物」在下游眼裡差很多
③訊息要說出【缺什麼】:「拿不到 stack —— 需要 --debug」,而不是只說「失敗」
   ⇒ ★照你自己那條:錯誤訊息要含【合法路徑】,不是只說不行
```
