# 判決：`issues`，`premise_contradiction: false`

## ①「初始值＝再生上限」——**(a) 設計，不是巧合，而且有直接 precedent**
`world_generator.gd:95`（herb 那段）**自己的註解就寫**：
> 「herb：森林 30% 帶 2-6；藥草林（高產點）5% 帶 10-20。**計入 resource_cap（月再生上限＝初始值）**」

★**這句話早就把「初始值＝再生上限」當成 rich-point 機制的一部分明講出來，不是事後才發現的巧合。**
更硬的證據在旁邊：`:106-108` 野馬富點——`rng.randf()<WILD_HORSE_RICH_CHANCE` 命中後，**顯式覆寫** `tile.resource_cap["wild_horses"]=8`（不管初始滾到 4-8 哪個值，cap 都釘死 8）——**這行只在「作者不想要 duplicate() 的預設行為」時才需要存在**，證明作者清楚知道 `resource_cap=resources.duplicate()` 這條預設規則，且在需要時主動繞過它。**兩個獨立證據都指向同一件事：這是被理解、被使用的既有設計，不是巧合。**

⇒ **處置**：你 spec 原本打算寫「警告未來別拆開」的防禦性註解——**改個框架寫**：不是「警告一個脆弱巧合」，是「延續 herb 已建立的慣例，比照 `:95` 的註解風格寫一句」（內容可以一樣，但定性是「遵循既有規範」不是「補救巧合」）。**不需要更大的結構改動**（例如拆成獨立具名欄位）——herb/wild_horses 都沒那樣做，老熟林比照現況即可。

## ②對照組——**你的風險成立，而且比你想的更具體：是 RNG 消耗次序，不是邏輯結構**
你擔心「一般那支也被改動」；我查出一個更precise、你還沒點名的機制性風險：

現有 herb 兩層 roll 用 `if/elif`：
```gdscript
if rng.randf() < HERB_RICH_CHANCE: ...
elif rng.randf() < HERB_FOREST_CHANCE: ...
```
★**這是 short-circuit：第二個 `rng.randf()` 只在第一個評估為 false 時才呼叫**——**呼叫次數本來就隨機不固定**（1 或 2 次，取決於第一輪骰的結果）。

**老熟林若照同一形狀寫**（`if rng.randf()<OLD_GROWTH_CHANCE: ... elif ...`），★★**即使 `OLD_GROWTH_CHANCE=0`，`rng.randf()<0.0` 仍然是一次真實的 RNG 呼叫**（只是恆假）——**這次呼叫在【改動前的舊 code 裡根本不存在**（forest 的 material 舊路徑只有 `:78-80` 的 profile roll，沒有這道額外的骰）。
⇒ ★★★**「比例設 0」會比「沒有這張票」多消耗一次 `rng.randf()`，seeded RNG 往後的呼叫序列全部平移一格** ——**下游所有 tile 的資源/單位/床位生成都會跟著變，不會是同一個世界。**
⇒ **你想強化成的「`fp` 必須逐位元等於改床基線」——在現在這個寫法下，這條驗收永遠不會綠，即使程式邏輯完全正確。**（跟今天在 D/A 票踩過的「驗收本身不可達」是同一種病，只是這次是你自己在寫下一張票時才要犯。）

⇒ **修法（便宜、寫進 spec 即可）**：guard 成 `if OLD_GROWTH_CHANCE > 0.0 and rng.randf() < OLD_GROWTH_CHANCE: ...`——**比例＝0 時整個條件短路，連一次 `rng.randf()` 都不呼叫**，這樣「比例設 0」才能真的跟「沒有這張票」在 RNG 消耗次序上一致，你想要的「`fp` 逐位元等於改床基線」才是【可達】的驗收，不是又一個死水。

## ③比例與量級「刻意不定」——**誠實留白的方向對，但目前的判準句太軟，建議收緊**
「不手抄數字」是對的紀律；但「能被 organic 分布或既有稀有度慣例支撐」這句**沒有給 implementer 一個可以自己驗證「我選的數字對不對」的機械判準**——沒有 falsifier，等於還是implementer自己感覺對就好，跟「我挑一個好看的數字」在【可檢驗性】上沒有差很多，只是換了誰來挑。

★**你自己提的「量級要讓一座老熟林單獨足以支撐一次 cost 50 的建設」我查過：forest 一般 profile 就是 `[80,220]`（spec 自己引的數字）——上限 220 早就遠超 cost 50，就連【一般】森林頂端都已經滿足這條，不需要老熟林機制就達標，這條門檻定得太低，測不出「老熟林比一般森林特別在哪」。**

★★**建議改錨在 herb 自己的 rich/normal 比例**（既然這票明講「形狀抄同檔既有高產點模式」，量級也該抄同一個 precedent，不是另開一個跟 cost 掛勾的門檻）：herb rich `[10,20]`（中值 15）vs normal `[2,6]`（中值 4）≈ **3.75×**。老熟林量級可要求「rich 值域中值／forest normal 值域中值 的比例，落在 herb 建立的既有比例量級附近（例如同數量級，不用剛好一樣）」——**這是可從既有數字推、implementer 自己能算的判準，不是我或你手抄一個新數字，也不是空泛的「organic 分布支撐」。**

## ⇒ 要你補的
1. ①改框架（設計非巧合），內容可留，動作小。
2. ②guard 成 `chance>0.0 and rng.randf()<chance`，讓「比例設0」真的等於「沒有這票」——這是**必須**，否則驗收③(或你想強化的fp版)是不可達驗收。
3. ③把「organic分布支撐」換成「rich/normal中值比例錨在herb既有比例量級」這種可算判準——**建議**，你裁要不要收緊。

**premise_contradiction: false，但②是硬傷需要補（跟前兩票同型：驗收設計本身不可達），①③調整方向即可，不用重寫。**
