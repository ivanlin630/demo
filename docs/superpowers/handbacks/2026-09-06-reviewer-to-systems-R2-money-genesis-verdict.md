## ★★你自己標「未窮盡」的那格——我補完了，結論成立
```
grep -rn "ore_gold|ore_silver" scripts/simulation/*.gd
```
逐條看過全部命中：`world_generator.gd:78/94/96` 是**世界生成時一次性播種**（`_ensure_min_ore`／`randi_range` 直接賦值，只在建世界那一刻跑一次）；`world_generator.gd:117` 的 `tile.resource_cap = tile.resources.duplicate()` 也是**只在世界生成時賦值一次**（後面沒有任何 production code 再寫 `resource_cap["ore_gold"]`／`["ore_silver"]`，其餘所有命中都在 `scripts/debug/*_test.gd` 的測試 fixture 裡，不是遊玩期間會跑的路徑）；`resource_system.gd:396` 的 `"ore_gold","ore_silver":` 是**採集函式**（`gain = tile.productivity * current * COLLECT_RATE * ...`，從有限池裡扣，不是補）；`faction_ai_system.gd:4460-4463` 是**滅團時把未分配的礦歸還地面**（資源守恆搬移，不是新生成）；`outpost_system.gd:318-334` 是**鑄幣消耗**。**全部路徑逐一看過，沒有一條會增加 `ore_gold`／`ore_silver` 的總量。** ⇒ 「沒有任何 ore 會再生，通縮是結構事實」這句話，在窮盡搜索後**確認成立**，不是只看了 `REGEN_RATE` 一處就下的結論。

## ★★★主判斷「讓 k 吸收交易佔消費的比例」——這是誠實做法，不是把兩個未知塞進同一個旋鈕

判準是：**這個複合常數能不能被拿去跟「真實世界會發生什麼」對照校準，而不是被調到「看起來平衡」為止。** 讀 §5 驗收 #3/#4，你要求的是**拿 k 的推導值去跟前 90 日「真的量到的」市場成交額＋隊間交易成交額比**——這**不是**「經濟感覺對不對」那種主觀判準，是跟今天已經判過好幾次的「genuine value 不是 crank 出來的分數」同一套測試：**只要校準的錨點是【真實量到的量】，這個常數即使內部吸收了兩件事，也不算手抄——它是【讀自身狀態】校準，不是憑感覺挑數字**。而且你要求把「k 的意義變了」這件事寫進 **code 註解**（不只 spec）——這個透明揭露正是把「合法複合常數」跟「拿一個好聽名字包裝任意數字」區分開的那條線，你已經站在對的那一邊。

**但要補一條護欄，把「萬用旋鈕」的退路堵掉**：驗收裡要明寫——**如果之後要重新校準 k，唯一合法理由是【推導值跟真測量交易量對不上】，不能是「物價漂移看起來太誇張」或「經濟感覺不平衡」這種下游感受倒推回來調 k**。如果 k 因為「漂移不好看」被動了，那就是 crank 從後門溜回來——跟你自己在③一開始拒絕的「硬選一個交易佔比係數」是同一種病，只是換了個時間點發作。這句話請跟「k 的意義變了」那句一起寫進 code 註解。

## ★④角色加權「逐個寫理由」——你的懷疑是對的，建議換一個可證偽的判準

「逐個寫理由」確實擋不住「理由是編的」——寫一段聽起來合理的散文不能證明權重不是拍出來的。**但 pilot 漂移驗證要驗什麼，spec 目前沒有講清楚**，如果只是「跑一輪看整體有沒有明顯跑偏」，那個判準太軟，跟「經濟感覺對不對」一樣主觀。

**建議換成一個可證偽的具體判準**：**每個角色類別，用它分到的初始資金，能不能執行【它自己該做的第一個經濟動作】而不會立刻撞上資金不足的擋因**——商隊（`TAG_TRADE`）分到的本錢夠不夠付第一趟已知規模的交易；國庫（統領）分到的大頭夠不夠支付前幾輪已知的固定支出（發薪／基建）；生產隊 ≈0 是不是真的不會因為缺 0 而卡在某個需要 coin 的動作上。**這跟 k 的校準是同一種紀律**：不是看「權重寫的理由聽起來合不合理」，是看「照這個權重分出去的錢，能不能讓每個角色真的做到它該做的事」——一個可以被撞出紅燈的具體斷言，比「逐個寫理由」更擋得住編造。
