# 2 你問的第 2 點:威脅句截斷——成因核實;『多一行』不是最好的修法
## 2.1 成因(✓)
```
text_ui_view.gd:151-175:威脅欄是頂列唯一被 clip 的欄（注釋自己寫『唯一長度無界』）,budget = COLS(120) − (head 四欄+sep+tail+label) ;
  clip_to（text_ui_layout.gd:84-93）靜默截斷不加記號 ⇒ 『Team6 敵對，最後所知 』（player_api_mapper.gd:965 句子）半句。
  第一個證據點:head 的 team_name／home 是【不 clip 的無界字串】:它們一長,budget 就≤0（maxi(budget,0)）⇒ 威脅欄變空『威脅：』且整列超寬——
  你的 P3 佈置要含 budget≤0 的格,不只是『剩一點』。
威脅句本身有界:兩種模板（敵對 `Team%d 敵對，最後所知 %d 格`、野獸 `<方位>有<名>`）,最長約 28 欄——不是無界。
```
## 2.2 『放不下就多一行』的代價
```
·版面跳動:威脅【出現的那一刻】整屏下移一行——那正是玩家視線最需要穩定的時候（不變量『可慢不可卡／畫面節奏均勻』的精神;至少與『畫面不跳』的既有設計相衝）;
·引用頂列的床:至少 scripts/debug/{f8_camp_settle_bed,terminal_e2e_bed,terminal_selfcheck_bed,text_ui_layout_bed,threat_column_bed}.gd(grep top_row／威脅：)——
  行數固定的斷言會全動,你已預告要逐行列差異,數字是 ≥5 檔。
·『頂列本身印「威脅：見下行」』又引入一個新的欄內容,與意圖帳『玩家頂列威脅』的三態（尚未提供／（無）／整句）之間要多一態『見下行』。
更小的做法(建議,systems 定):
   【預留寬度給有界的那一欄,截無界的那兩欄】
   ·威脅欄寬度預留 = 兩個模板最長 render 的寬度（由模板算,不手寫常數）;
   ·剩餘預算給 team_name／home,用既有 `clip_mark`（text_ui_layout.gd:79-82,『…』）截,而不是 clip_to;
   ·威脅句【從不】被截;被截的是隊名／家名,且帶『…』讓人看得出被截。
   單列、無跳動、床只動頂列字面那幾格;P3 的『句子∈模板集合』斷言原樣成立。
   取捨要明說:長隊名在窄屏被截成『…』是新的可見變化——但它截的是玩家已知的名字,不是安全資訊。
若仍選『多一行』:至少要『行恆在』（無威脅時印空行或（無）,不隨有無出現）,否則上述跳動成立。
另:map_pages_box（text_ui_view.gd:~140）對每一列也用 clip_to 靜默截;你的『其他欄列出』要含它,別只看頂列。
```

# 3 你問的第 3 點:派遣子隊按即做——與既有鍵有三處撞,第二刀擋在這裡
```
①『先 WASD 移游標再按 N』:子隊面板開著時 WASD 【未綁定】——_subteam_mode_binds_key（text_ui_main.gd:~3003-3009）只綁 Esc/U、A/B/N、1-9;
   按 W/A/S/D 走 _refuse_unbound_key（『此鍵在此模式無作用（子隊）』）;而面板內的 A 還被占用成『下令移動』（已選子隊時）。
   ⇒ 順序變成:先關面板移游標、再按 U 開面板、再按 N——spec 沒寫,玩家照字面做不到。
   選擇:(a) 面板開著也允許 WASD 移游標（要改 binds_key 與 unbound_key_bed P2 的機械抽取,並解 A 的衝突）;(b) 明寫『先在主畫面定游標,再開 U,再按 N』並把游標格顯示在子隊面板上(玩家看得到目標)。
   不論哪個,面板要顯示『目標＝(q,r)』。_cursor(text_ui_main.gd:33)在面板開著時不變——這是可用的事實。
②字母選隊長 vs 既有字母:同面板已綁 U(關)、N(派遣)、A(下令移動,已選子隊時)、B(召回)。隊長清單若用 a、b、c… 會撞 a/b/n/u。
   要嘛隊長選擇做成【獨立的子狀態】（進入後字母歸隊長、鍵列換成該子狀態的鍵表、Esc 退回）,要嘛字母集跳過保留鍵;
   而且 unbound_key_bed 的 P2 是從 KEY_ 分支機械抽取比對,新增的字母分支必須被它看到。
   ★另:現狀 selection==-1 時 A/B 是『綁了但沒作用』（binds_key 回真,handler 落到 _refresh(); return,靜默）——這是既有的灰區,別讓新字母疊在它上面。
③數字鍵:同面板 [1-9] 在 selection==-1 時是『選子隊』(:~3085-3090),新設計『人數用數字或 ±』與它同屏——P5『同屏不再有兩組數字鍵指不同東西』要明寫:
   人數輸入走輸入模式（modal,數字進緩衝,與選隊的 1-9 不同時存在）。
④『游標格不可達 ⇒ 下令當下拒、說原因』:重用多格移動票已做的『下令時算路徑／無法抵達』那支（同一個函式,不要寫第二份可達判斷）;子隊的移動成本與玩家隊不同（可能超載/車輛）,請寫明可達性判斷只問『路徑存在』不問時間。
```
