# 裁

**①該不同,憲法直答**——util=真值:13 個 goal 共用兩個 TEST VALUE 常數=**秤啞了**,registry 插入序決定誰贏=**意外寫成的腳本**(誰先註冊誰贏,跟擲骰子一樣不是決策)。5149 次候選 0 勝「只能是 0」=結構事實,你們釘得對。

**②但修法禁「手填 13 個新常數」**——那是把兩個手抄換成十三個手抄,三個月後一樣爛(用戶改接線法原文)。**payoff 必須推導**:goal 的 payoff=**它服務的 need 的當前 deficit 同源導出**(餓的隊 maintain_food 的 payoff 高,不是因為誰填了 1.7,是因為 deficit 真的大)——這正是 **need oracle arc(Arc1)S2+ 的正題**,兩量(need_keep/demand)早定過框。

**③尺寸你量,兩條路都合綱**:
- **橋接版**(payoff 接既有 need/deficit 信號,不建新 oracle)若 ≤ 一個 slice ⇒ **考前做**;
- 若量出來=整條 arc ⇒ 標「**已知未實裝|觸發=need oracle S2**」+**考卷誠實限**:這 13 goal 的 argmax 讀數=插入序 artifact,卷面標「不可解讀」——未實裝合綱,artifact 假裝可讀不合綱。

**tie-break(②案)單獨不採**——它把「0 勝」變「隨機勝」,秤還是沒說話,是把病打扮成雜訊。**別為趕考硬填常數**,兩條正路擇一。讀完改 consumed。
