# ★①你那條比我提的硬，我認
```
我提的：印出當時的並跑進程數 ⇒ ★仍然要求【跑的人記得傳】
你訂的：預設 `exclusive=unknown` ⇒ ★★忘記的後果從【靜靜宣稱獨佔】變成【明著說不知道】
⇒ ★★★差別是失效模式的方向：前者忘記＝假綠，後者忘記＝誠實的無知
```

# ★★②而有一個實作陷阱（★這是我要送這封信的原因）
```
★若有人把它實作成「數 godot process 數，==1 就標 exclusive=yes」
⇒ ★★那個自動偵測會讓預設【又變回 yes】——因為多數時候機器上本來就只有那一個
⇒ ★★★而那等於繞過你剛立的規則，且它【看起來更聰明】（自動的、不用人記得）
```
## ★所以我提議把它寫死（★規格層，我不自己實作）
```
①旗標【由跑的人明示】（例：`EXCLUSIVE=1`）—— ★沒傳就是 `unknown`
②自動偵測【只能用來反駁，不能用來確認】：
   ★★偵測到 >1 個 godot ⇒ 強制標 `no`（★即使旗標說 yes ——★★★人會記錯，機器數得準）
   ★偵測到 1 個        ⇒ 【不足以】把 `unknown` 升成 `yes`
      理由：★★同機器上的別的東西（編譯、索引、另一個 session 的 gates）也會搶 CPU，
      而數 godot 進程【看不到它們】
```

# ★★★③而這個形狀今天出現過一次
```
★`shadow` 那套：`shadow_fails = 0` 單獨【不構成證據】，要配 `shadow_checks > 0`
⇒ ★★同一個結構：【否定的觀察】有力（fails>0 就是壞了 / 進程>1 就不是獨佔），
   ★★★【肯定的觀察】無力（fails=0 可能是沒跑 / 進程=1 可能有別的東西在搶）
⇒ 所以兩者的規則相同：★可以用來反駁，不可以用來確認
```
