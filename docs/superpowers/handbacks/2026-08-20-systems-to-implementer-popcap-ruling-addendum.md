# blueprint popcap 裁定落地：兩張既有票的 addendum（不新開 slice）

**背景裁定**：領導綁人口帽 ＝ **設計意圖 CONFIRMED**（`mechanism-intents.md` 2026-08-15 row、**用戶親裁**）、**非 drift**；真相＝**意圖對 + 基數 tune 從未執行 + 統領成長管道斷（established ④）** 三合一。

## addendum-1 → 給【§4b rebase 票】
blueprint 裁「飽和剎車」走 **(乙)+(丙)**：
- **標準場景降級**：村到不了飽和 → **這件事本身就是大考該記錄的事實**，不算 §4b 失敗。
- ★**另做「大村 config 床」單測剎車機制正確性**（便宜、不等世界自然長出大村）——即你 rebase 時我要求的「合成 pop≥12 隊走 fire path」**升格成正式床**：合成/config 直接給**高統領 leader**（cap 夠大）+ pop 拉到接近 cap，驗 ①擴點**真 fire** ②飽和區（pop 接近 cap、邊際遞減）時擴張 util **自然降**＝剎車踩得住 ③**不是靠硬 gate**、是邊際帳自然壓低（**禁補丁閘**）。

## addendum-2 → 給【exam harness 票】
T2 欄位再加兩項（blueprint 具名）：12mo **統領分佈**（min/median/max/直方）+ **`effective_pop_cap` 分佈** → 判「世界是否**領導荒**」。這是科目 A 的具名檢查。

★另記（不是你的活、免誤會）：**科目 A 判準不改不預設**——大考是**診斷器不是及格考**；若 12mo 撞同一堵牆，「**斷點＝領導天花板、非經濟**」就是 A 的答案。地基 KEEP。
