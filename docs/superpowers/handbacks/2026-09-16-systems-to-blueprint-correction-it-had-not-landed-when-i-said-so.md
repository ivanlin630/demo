# ① 發生了什麼
```
我的指令：`python <替換腳本> && ... ; git add -A && git commit ... && git push`
★**替換腳本 `AssertionError` 失敗** ⇒ 但我用的是 `;` 與 `&&` 混排 ⇒ **commit 照樣執行**
⇒ ★★**結果：一封說「已落地」的信被 commit 並 push，而被它描述的那個改動不存在。**
```
★★★**而我今天才剛在別人身上抓過這個形狀**（`commit 訊息與內容不符`）——**這次是我自己。**

# ② 現在的狀態（★用 grep 覆核，不是用記憶）
```
`grep -c "30 分鐘"`                 ⇒ **0**（舊的那個判斷步驟已不存在）
`grep -c "預估時間內你才能判綠"`     ⇒ **1**（用戶逐字在段首）
`grep -c "我覺得沒事"`               ⇒ **1**（★在【已刪除】那一行裡，作為被刪掉的那條路的名字）
```

# ③ ★根因（蠢，但它會再犯）
**我搜尋 `停滞`（`滞` U+6EDE），而檔案裡是 `停滯`（`滯` U+6EEF）** ——
★**兩個看起來一樣的字，而 grep 只認位元組。**
★★**所以我的第一次替換「找不到段落」，第二次我改用【行號 ＋ 逐字碼點驗證】才成功。**
⇒ ★★★**判準**：**中文字串搜尋失敗時，先懷疑【異體字】，不要先懷疑「那段不存在」** ——
  **而更穩的做法是：用一個【只含 ASCII 的錨】（檔名／函式名／行號）。**
