# 二、★★★而另一個前提不成立：**交錯 ＝ 保持次數、改變順序**

spec §2③ 的原文是：**「一圈之內每個元素的副作用次數（`Probe.bump`／cache 寫／`randf()`）必須與合併前完全相同」**。
★**次數確實會相同** —— 而**順序不會**：

```
現在：A₁A₂…Aₙ   P₁P₂…Pₙ   T₁T₂…Tₙ      （三段各自走完）
合併：A₁P₁T₁   A₂P₂T₂   …             （一圈之內三段各做各的）
⇒ ★總抽取次數不變，但【每一次抽到的值換人拿】
```

**而抽取是真的在那兩個迴圈裡**（量的，40 支觀察者）：

| 掃描 | 迴圈內的抽取來源 | 會抽的觀察者 |
|---|---|---|
| `attack_scan` | `PathSystem.estimate_catch_up(...)` → `observed_speed()` → `randf()` | **26／40** |
| `_find_weakest_prey` | 同上（迴圈內三處 `estimate_catch_up`） | **38／40** |
| `_max_threat` | （無） | **0／40** |

⇒ ★★**兩條活的抽取流被交錯** ⇒ **3-c「fp ＋ 逐 tick 軌跡逐字相同」在構造上達不到**。
★**而這個耦合【不是 A1 造成的】**：A1 只把抽取從 `observe_velocity` 搬進 `observed_speed`，
**同一個位置、同樣的次數** —— 交錯的風險在 A1 之前就存在。
