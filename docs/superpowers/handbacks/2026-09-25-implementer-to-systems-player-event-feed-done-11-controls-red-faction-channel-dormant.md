## ★★★③ 收緊之後，那條「同-faction 通道」今天是【休眠】的

```
實測：預設開局【玩家隊沒有勢力】 faction_id = -1
⇒ 同-faction 那一條對【今天的玩家】一次都不會 fire
⇒ ★收緊後的過濾器實際上等於「只放行自家隊」——而那正是用戶要的那一半，不影響交付
```
★★它**不是死 code**（玩家之後可能建國／加入），而是**第三格：條件尚未出現的分支**。
⇒ ★★★處置＝**把觸發條件做成一個會自己變的量**：母體那一行**印出 `faction_id=-1`** ⇒ **玩家哪天真的有了 faction，那一行會自己變，不需要任何人記得回來看**。
⇒ 而那一格必須**兩邊都造**（玩家隊與目標隊都設同 faction）才驗得到那條通道 —— ★**而「兩邊都造」本身就是那句休眠的證據**（是做法逼出來的，不是我寫下來的）。

## ★★★④ P2 抓到一個真的 off-by-one，而它在 spec §3 的推理裡

spec 寫「壽命一小時**剛好夠**，因為讀者每 ≤60 tick 讀一次」。★**剛好不夠，差一個 tick**：
```
一次 tick_step() 上界 ＝ STEP_TICK_BOUND ＝ TTL ＝ 60，而讀者在 step【之後】才讀
⇒ 一件在 step 開頭產生的事件，被讀到時年齡【正好 60】⇒ `< TTL` 判它過期
★血證：推進一天、逐小時各注入 1 件 ⇒ 注入 24 件、【畫面收到 0 件】
  ★★而卷面上原本看到的 9 件是世界自己產的 —— 那 9 件差點讓我以為「大致有在動」
  ⇒ ★★★部分有效的輸出，比完全沒有輸出更會讓人停止追問
```
⇒ 修剪比較改成 `<=`（兩處）。★指令結果句原本沒被咬到，是因為入列→消費只差 1 tick；**匯流排事件產生在 step 中間 ⇒ 邊界對它是致命的**。
⇒ ★★`>=` 保證的是「壽命不短於一步」，而**足夠條件是「事件必須活過【產生它的那一步】」**。
