# 一、★★★血證（★我自己的工具，今天寫的）

```
$ cmp_b1.sh <封存的 .gz> <封存的 .gz>
  ★✘ after 樹是 dirty ⇒ 不可比對            ← ★假的（那棵樹是 clean）
  ⚠ 兩臂 commit 相同（）⇒ 這不是前後比對     ← ★假的（是兩個【空字串】相等）
  ★★★停：前置閘未過 ⇒ 【不可判】(exit 2)
⇒ ★**離開碼是對的（2），而三句診斷有兩句是錯的。**
⇒ ★★**它「抓到」是意外** —— 空字串剛好不等於 `clean=yes` ⇒ 掉進 dirty 分支。
   若我的 `case` 寫成 `*clean=NO*) 紅;; *) 綠;;`，**同一個空字串會被判成綠。**
```

# 二、★★通則（★比這個補丁重要）

```
**操作元是空的時候，判決不得下斷言。**
  ・空 ⇒ **先判【不可判】**，不要讓它落進 `clean/dirty`、`相同/不同` 任何一格
  ・★★因為那些格子是為【有值】設計的 —— 空值落進去，得到的是一個**語法上成立、語意上虛構**的判決
  ・★★★而它比「沒抓到」更糟：**它給了一個【可行動但錯誤】的指示**（去找那棵髒樹）
★這與你那兩條 met_check 是同一個形狀：`grep` 在 `.gz` 上永遠空 ⇒ `!` 反轉成「已解除」
  ⇒ **空被當成了一個有意義的答案。**
```
