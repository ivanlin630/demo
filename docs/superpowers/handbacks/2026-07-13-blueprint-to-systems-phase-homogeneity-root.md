# plan_phase同質化——查是分布窄現象還是缺口偵測閘有問題

## 背景
plan-layer S2 organic驗（3seed×3mo）：「成長」phase三seed皆獨大(71-78%)，「求糧」phase幾乎不出現（月1甚至0/0/0，全隊初期都落成長）。偏置實效薄（25-33%命中）。見`2026-07-13-measurer-to-blueprint-plan-phase-probe-result.md`。

measurer判讀：可能與野心分布窄同源（已知已誠實標記的風險）。**但這只是猜測，未查code證實**——patch-gate-first紀律要求先查是否為機械閘/門檻問題，再判斷是否為預期內的分布現象。

## 待查（零跑，file:line）
1. **`derive_plan_phase`的缺口偵測邏輯**（spec§「phase選擇=缺口×個性×隊形」提到的機械偵測部分）——「缺糧」判定門檻具體是什麼？跟現在forage-floor-tune後的食物水位（急性崩已緩解，attrition降到17-31%）是否有關——**是否因為食物修得夠好，多數隊organic狀態下真的已經不缺糧**，所以「求糧」phase本來就該少見（這樣同質化=食物修成功的合理副作用，非bug）？
2. **若多數隊實際仍有一定食物壓力但仍被判定「不缺糧」**——查缺口偵測門檻是否設太寬鬆/有計算錯誤，導致該進求糧phase的隊被誤判進成長phase。
3. **「成長」phase本身的milestone判定條件**（`milestone_met`附近）——是否設得太容易滿足，導致大量隊「預設」落在這裡（類似之前B3野心門那種「門檻沒對齊」問題）。
4. **月1甚至0/0/0求糧**——特別可疑：如果急性崩緩解前的世界，月1本該是最缺糧的時候（前面經濟長程診斷查過月1-3是急性危機期）。查月1這個時間點缺口偵測邏輯有沒有跟這個已知的「月1最缺糧」現實脫節。

## 判斷請求
- 若查出是門檻/邏輯問題（同型雞生蛋/倒序）→ 這是要修的bug，非可接受的分布現象。
- 若查出純粹是野心分布窄的直接後果（且缺口偵測邏輯本身正確）→ 這是已知風險，維持誠實標記，不強行修正（避免為了製造多樣性而扭曲缺口偵測的正確性）。
