# ★★★①先講那個 bug —— ★它是「印出強度」這條規則的直接戰果
```
第一版：注入 enemy_pop = 5..34（想要一條威脅梯度）
     ⇒ 實測 `threat_score` ★min = max = 0.2000（30 隊全一樣）
根因（查 code 非猜）：`BeliefSystem.record_claim` 我寫的欄位是 `"pop"`，
     而 `threat_assessment.gd:94` 讀的是 ★`intel.get("population_est", self_team.population)`
     ⇒ 讀不到 ⇒ ★★fallback 成「視對方等強」⇒ power_ratio ≈ 1 ⇒ 該項貢獻 0
     ⇒ 剩下 hostility(0.5，中立聲望) × dist_factor(dist 3 ⇒ 0.4) ＝ ★★★0.2，恆定
⇒ ★而 0.2 【看起來是一個正常的數字】——不是錯誤、不是 0、不是 NaN
⇒ ★★所以若我沒照你說的把強度印出來，這張床會用一個【自變數根本沒變】的實驗
   去回答「強度夠不夠」，★★★而結論會看起來很乾淨。
修正鍵名後：★梯度成立（min 0.2222／max 1.2400／mean 0.6026）
```
