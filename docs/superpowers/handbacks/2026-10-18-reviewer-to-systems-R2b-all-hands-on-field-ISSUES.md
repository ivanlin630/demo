# 二、must-fix

## N1 撤退謂詞：spec 說「分母不含死者」，程式是含的；照 spec 的字面實作會改到所有遭遇戰的撤退行為，照程式的實際值則與 H7(a) 相衝
- spec §四：撤退謂詞＝tick 尾 `_calc_team_incapable_ratio(side) > RETREAT_TEAM_RATIO`，「分母＝這一方場上全部單位，含失能、**不含死者**——實作端照 `:377-385` 實際的取法寫進註解」。
- `_calc_team_incapable_ratio`（`encounter_system.gd:377-385`）：迴圈跳過 `has_exited`，其餘每個單位 `total += 1`，`not is_combat_capable` 就 `incapable += 1`。`is_combat_capable` 對**死者回 false**（`:105-107`）。⇒ 死者**在分母也在分子**，比例＝(死＋失能) ÷ 未撤出的全部（死者永遠留在表裡）。
- 兩個後果：
  1. 描述與程式不一致。實作端若照描述「不含死者」去改 `_calc_team_incapable_ratio`，會改變今天所有遭遇戰的單位撤退（`_should_retreat` 用同一個比例，`:348-350`）。要求：spec 改成「沿用 `_calc_team_incapable_ratio` 原樣（死者算在內），不改函式」。
  2. 照原樣（死者算在內），H7(a)「一方場上全死而隊列非空 ⇒ 不結束、補人」不成立：全死時比例＝1.0 ＞ 0.7，謂詞判「整隊撤退中」⇒ 不補 ⇒ 沒補進 ⇒ 照原判，直接判負。更一般地，一旦累計傷亡（含已補進又死的）超過約七成，補人就停，隊列再滿也沒用。這在語意上是一致的（單位自己這時也會集體撤退）——潰敗就是潰敗——但它和 WHAT「死了從場外補」的關係要讓人看到。
- 要求（二擇一，HOW 內寫明；若選 (a) 請交件信告知藍圖，因為它決定「有後備的一方會不會潰敗」）：
  - (a) **潰敗優先**：保持原樣（死者算在內）。H7(a) 改成「死傷比例 < 0.7 時，全部在場者倒下前的補人」，並加一格「死傷比例＞0.7 且隊列非空 ⇒ 不補、照撤退結算」。累計傷亡取決於整場補人，所以邊界格要在 0.65／0.75 兩側各一場。
  - (b) **補人不被潰敗擋**：補人的抑制謂詞改成只看「這一方有沒有單位已經在撤出」（例如這一方 `has_exited` 的單位數 ≥ 1），不用比例；那麼補進的新單位在第一次行動時會因比例仍高而立刻撤，隊列會被撤光——也要寫明。
  - 不論哪個：H7(a)(e) 各自的 fixture 要印當時的比例值；n6 另加 n6b：把謂詞改成「不含死者」的比例 ⇒ 邊界格紅（證實描述與程式的差別會被量到）。

## N2 H12 基準式漏了戰後命運欄
- H12：「戰後匿名數＝戰前匿名數 − 場上死的匿名 − 場上被俘的匿名」。但結算裡 `_aftermath_captives_fate_pursuit`（`encounter_system.gd:1324` 一帶，於 `pop1` 取值之前）在 NPC 為留場方時會再扣玩家方人口：`fate_killed`、`fate_captured`、`pursuit_killed`，與 `held_by_enemy`（被俘移走）是不同的欄（這正是我 R²b 對小修二 A3 指出的同一條，A3 已收）。⇒ 玩家方輸、NPC 贏且有傷兵處置或追擊的仗，這條式子差額非 0，H12 紅，或實作端為了讓它綠把基準式削掉。
- 要求：基準式右邊補上 `fate_killed ＋ fate_captured ＋ pursuit_killed`，或明寫 H12 只在「不進命運／追擊階段」的場上量（量測點放在 `AnonTierSystem.kill_random(... "combat")` 之後、命運階段之前）。母體地板再加一場「玩家方輸且有追擊」，印這三欄非 0 的項，避免 H12 只在最簡單的仗上綠（同小修二 C3）。
- 另：「隊列的人一個不少」本身無法在戰後直接量（隊列已清）；式子成立就是它的證明，請在 spec 寫一句這個因果，免得之後有人把式子當成多餘而刪掉。
