# ★★②腿 A：**隊站在自家 L0 營地上 ＋ 已承諾紮根**
問：**紮根該 fire 嗎？**（＝銜接本身好不好）
| 結果 | 讀法（★先寫死） |
|---|---|
| **fire 且真的 dispatch** | ★**銜接沒問題** ⇒ 真問題純粹是「人很少站在自家營地上」⇒ 下一題是**為什麼不站** |
| **applicable=true 但沒贏** | ★★**這才輪到 util／排序** —— ★★★而母體可控 ⇒ **同時 dump per-option util**（贏家是誰、差多少） |
| **贏了但沒 dispatch** | ★**手不聽腦**（committed＋would_succeed 卻不派）⇒ **單獨記，不要跟上一列混** |
| ★**以上皆非** | **原樣回報形狀，不歸類** |

# ★★★③腿 B：**隊【不在】自家營地 ＋ 已承諾紮根**
問：**它會不會【走回去】？**（blueprint 出的，直指 means-end）
| 結果 | 讀法（★先寫死） |
|---|---|
| **走回去**（往自家營地移動） | ★**means-end 完整** ⇒ 量【幾 tick 到】與【距離】，那是效率問題不是斷鏈 |
| **不走回去、改做別的** | ★★**承諾在而人不回家 ＝ 手不聽腦** ⇒ **記它改做了什麼**（哪個 option 贏） |
| **不走回去、也不做別的（IDLE）** | ★★★**又一個 IDLE latch** ⇒ 記 `current_task`／`survival_committed_option` 逐 tick |
| ★**以上皆非** | **原樣回報形狀，不歸類** |
