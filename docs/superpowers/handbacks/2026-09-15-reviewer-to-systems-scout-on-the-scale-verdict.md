# ② ★★★留白格：全盲的隊偵查價值該是多少

## 2-1. 有沒有第四種不手抄的形狀？—— **有，但要你先接受一個分類**

`belief_system.gd:35-39`：

```gdscript
# ── 戰力迷霧 fallback（未偵察武裝 → 人格化尺寸代理，非埋死「陌生=滿武裝」常數）──
# 基準武裝比＝世界參數（第三家）：村多平民 → 未偵察目標的武裝占比明顯 <1（measure 調）。
const ARMED_FRACTION_BASE := 0.35        # TEST VALUE：中性領袖對未知目標估的武裝/人口比（<1）
```

**這是同一個病的另一個部位**：不知道對方武裝多少，答案不是「讀真值」也不是「拿本隊已知
目標的中位數」——是一個**具名、承認自己是 TEST VALUE、靠 measure 調**的世界參數。
這支檔案自己已經在用這招解過同型問題。

★★但這不是「隨便填個數字」跟「手抄物理」之間沒有分別——你的 `估算器禁手抄物理` 立法
（用戶 2026-08-21）禁的是**假裝一個手填數字是從真實量推出來的**（例如 `URGENCY_COIN_COMFORT`
那種披著「已算好」外皮的猜測）；而 `ARMED_FRACTION_BASE`／`DiscountedFlow.DELTA_FLOOR`
（`discounted_flow.gd:22` 註解原文：「★真參數 — 在真實量上劃線＝設計選擇。世界答不出
『應該幾天／該折多少』——而答不出就是它該留的證明」）是**誠實承認「這是一個設計選擇，
不是量出來的」**——這是本專案已經接受、活在生產路徑上的第二種合法類別。

⇒ **候選 (iv)**：`SCOUT_VALUE_BLIND_PRIOR`（或同構命名）——一個誠實具名、標 TEST VALUE、
不偽裝來源的世界參數，代表「對一個毫無情報的目標，我們預設它可能值多少」，
跟 `ARMED_FRACTION_BASE` 同一個類別、同一種正當性。

**這條路能不能走,取決於你（或藍圖）願不願意把「誠實具名的設計參數」算進「不手抄」的範圍**——
我讀得出這個分類在本專案已有先例並被接受，但「這次也算數」不是我能單方拍板的，
這半步是 WHAT／立法解釋層的事,判準查完證據回你。
