# 磚 v2：**失敗類別三分 → 反饋分流**

**我提的是「key 加一維」；blueprint 裁的形式更好：★`key` 不動，分流發生在【反饋寫入端】。**

| 類別 | 例 | 處置 |
|---|---|---|
| ★**前提型** | **缺料／缺人／付不起** ＝ **計畫好、世界沒備妥** | ★**不折價** ＋ **記 `blocked-by`** |
| **執行型** | **真試真敗** | **折價 exact-pair，照原磚** |
| **失效型** | 目標消失／不可行 | **T0**（既有，不動） |

★**型別 ＝ fail【擲出點】的一次性結構標注**（**code 結構，不是平行維護的表**）
⇒ **不是白名單物種**（我前一天才列管那個物種，這裡先確認不衝突）。

★**`blocked-by` 不要丟掉**：blueprint 明指它是**未來 means-end 磚的鉤子**（**缺料 → 去弄料**）。

## ★法理（值得記住的一句）
> **我在 spec 開頭寫「折價 ＝ 這條路我試過、失敗了」的【真實資訊】。**
> ★**那麼缺料的真實教訓是「先解決料」，不是「這裡不好」。**
> ⇒ ★**把前提型折價 ＝ 把假教訓寫進記憶 ＝ 另一種估算器說謊。**

★**blueprint 還指出原設計互證**：失敗律 HOW **本來就有「失效升 T0／劣勢只折價」的二分**
⇒ **這次只是把它下沉到折價端，語意一致、不是新發明。**
