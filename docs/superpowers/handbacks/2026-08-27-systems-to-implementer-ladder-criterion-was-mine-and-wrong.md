# ★①先講結論：**你不用去解釋那 120 tick，因為它不是缺陷**

★**我逐行讀了 `CadenceStagger.next_tick`（不是猜）**：
```gdscript
cycle_index = current_tick / cadence                  # 整數除
offset      = _mix(team_id, cycle_index) % cadence    # ★每個 cycle 都【換一個 offset】
candidate   = (cycle_index + 1) * cadence + offset
```
⇒ 連續兩次 fire：`t1 = (k+1)C + off1`、`t2 = (k+2)C + off2`
```
★間隔 = C + (off2 − off1),而 off 均勻散在 [0, C)
★★⇒ 期望值 = C = 4320（E[off2−off1] = 0）
★★★⇒ 但【單次間隔】在 (C/2, 2C) 之間跳,下界被 min_gap = C/2 = 2160 夾住
```
★**而樣本只有 ~24 個間隔、分佈是寬度 ±C 的三角形** ⇒ ★★**中位數 4200（−2.78%）完全在它該晃的範圍內。**

# ★★②所以錯的是【我的判準】，不是你的數字
★**我在 spec 寫「per-actor 觸發間隔【中位數】＝ 3 天，容差 ±2%」** ——
★★**那是為【固定週期排程】（`next = last + C`）訂的**：**那種排程每次間隔都恰好 C，中位數就是 C，±2% 只留給取樣邊界。**
★★★**而 LADDER 走的是【錯峰】排程 —— 每次間隔【本來就不等於 C】，那正是它存在的理由**（防同批到期爆 tick）。
⇒ ★**拿固定週期的尺去量錯峰排程 ＝ 錯尺** —— **而錯的是我，不是機制。**

## ⇒ ★★★判準改成（★這是【推導】不是【放寬容差】，差別很重要）
```
★固定週期型（六支：ALLIANCE/BETRAY/FACTION_UPDATE/INFRA/STRATEGIC/GOAL 修完後）
   ⇒ 中位間隔 = C,容差 ±2%（原判準,不動）
★★錯峰型（LADDER,以及日後任何走 CadenceStagger 的）
   ⇒ ①【平均】間隔 = C,容差 ±2%   ←★★★由 E[off2−off1] = 0 推導,不是拍的
      ②最小間隔 >= min_gap = C/2  ←★驗 wrap clamp 真的有夾住
      ③★間隔分佈要【印出來】(min/median/mean/max),不要只報一個統計量
         ——★★因為「錯峰有沒有在工作」看的是【散開】,而散開只有分佈看得到
```
★**我要特別講死一件事**：★★**這不是「量不過就放寬容差」** —— **若我只是把 ±2% 放成 ±5%，那才是把判準調到數字會過。**
★★★**這次是【判準的形狀本來就不對】：它假設了一個這個機制刻意不具備的性質。**
