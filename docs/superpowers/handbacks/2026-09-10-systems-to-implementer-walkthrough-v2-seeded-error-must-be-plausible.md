# ① ★★★②：種錯機制自曝（用戶第一輪走查抓到的**對照缺陷**）

```
`scripts/debug/c1_walkthrough.gd:141`
    fields[k] = "★（本頁埋的錯：這個值是假的）"
⇒ ★正文直接宣告哪一格是假的 ⇒ **這一格的對照【恆真】** —— 它量不到「人眼能不能發現」，
  ★★它量的是「人看不看得懂中文」。
⇒ ★★★blueprint 裁：本輪簽核**不算**，修完重生 v2、換一顆錯。
```

**修法（三條，★第二條是我加的，blueprint 只講了第一條）**：

```
①答案**只在檔尾**：正文零標記；檔尾一段 `=== 埋錯答案（走查完再看）===`。
②★★★種進去的值必須與真值【同型且合理】——
   數值 ⇒ 乘個倍數／位移（★**且不得等於真值**）；布林 ⇒ 翻面；
   座標 ⇒ 換成另一個真實存在的位置；字串 ⇒ 換成另一個真的任務／隊名；
   陣列 ⇒ 少一個元素。
   ⇒ ★**任何「一看形式就知道是假的」都是同一個病換個樣子**（星號、方括號、佔位字串都算）。
③★★而我要加一條 blueprint 沒說、但決定這個練習有沒有意義的：
   **被種錯的那一格，必須是【有可能被抓到】的那一種** ——
   ⇒ 它要跟另一頁的某個值**互相矛盾**，或跟同頁的另一格**對不起來**；
   ⇒ ★★★否則你種了一顆**沒有人能發現**的錯，而「沒抓到」會被讀成「用戶不夠仔細」，
     ★實際上是**那一格本來就不可判**（同界限第九條：驗收條件要落在世界的可達區間裡）。
   ⇒ 交件時**寫出你選它的理由**：「這一格錯了會跟 X 矛盾」。
```
