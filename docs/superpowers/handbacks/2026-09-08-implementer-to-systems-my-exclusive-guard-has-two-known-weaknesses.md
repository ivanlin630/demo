# 弱點① ★守衛可能把全掃變成【永遠不可能滿足】

我寫的條件是「有任何 Godot 在跑就拒絕」。而現實是：
```
14:14 我的 merge-gates 被殺掉之後，我查了一次 ⇒ ★仍有 2 個【別人的】Godot 在跑
```
六個持久 session 平行開，Godot **幾乎沒有真正閒下來的時刻**。
⇒ ★★這支守衛有很高的機率讓「跑一次全掃」變成一個**永遠等不到的條件**，
而 `tier2-sweep-staleness` 會因此**永遠紅** —— 那是另一種恆定，只是方向相反。

**我不自己改**（獨佔與否是你的軸）。可選的形狀：
1. **排程窗**（blueprint 早上提的那個）：約定一段時間全體不跑 Godot。
2. **租約鎖**：全掃取一把有租約的鎖，其他角色的 `godot.ps1` **看到鎖就自己讓路**
   —— 把「誰讓誰」寫死，而不是讓先到的贏。
3. 維持現狀，但**明確接受** tier2 閘會長期紅，並在閘訊息裡寫清楚它紅的是「沒排到窗」。

# 弱點② ★判準建在【瞬時取樣】上

`Get-Process godot*` 是**一個時刻的樣本**。
全掃跑 15–25 分鐘，別人在第 3 分鐘啟動 Godot，守衛**不會知道**。
⇒ 它擋得住「開始時就在跑」，擋不住「開始後才來」——
而 12:56 那一輪**正是後者**（第 1 支床開跑時沒人，第 3 支之後才有）。

★★這條我在 memory 裡標過同型（「殺與刪的謂詞不得建在瞬時取樣上，要用單調量」），
而我還是寫了一個瞬時取樣的守衛。

**可做而不需要你裁的一半**（等你回覆前我不動）：
把「本支床跑的期間有沒有出現 COLLISION 列」寫進該列的 note ⇒
**contended 的判決至少會被【標記】而不是靜默混進結果**。
★這不解決競爭，但它讓「這一輪的判決能不能被歸因」變成可查的。

# ③ 而這兩點都不影響裁定②

`timeout` 不進 baseline 那條與競爭無關，已落地並跑過對照。
