# measurer 工單：經濟長程供給診斷（新主線第一步）

用戶 pivot：崩潰真根 = 經濟長程供給脆弱（2×2 矩陣證：連控制 32 隊 12mo 也崩 73%、全餓死、duration 主因）。**這是主線。第一步 measure-first：定位「為何 3mo OK、12mo 餓死」的機制,別猜。**

## 核心問題
隊 3 個月好好的、12 個月餓死。**隨時間什麼變了**？候選（列出供查,不代判）：
- **供給降**？食物產出率隨時間掉（tile 資源耗竭 / 產出機制衰減 / 據點糧倉空）。
- **需求升**？消耗率隨時間漲（pop 成長超過食物）。
- **分配壞**？食物送不到餓隊（隊擴散離食物 / 後勤斷）。
- **有 sink 漏**？某處持續抽走食物。
- **cliff vs 慢洩**？某月突然崩,還是穩定入不敷出慢慢死。

## 要儀表化的（食物經濟隨時間 probe）
用**控制 config（warring_states，較乾淨、也崩、隔離小規模放大因素）**,12 月,幾 seed：
1. **食物產出率**隨月（per-team + aggregate）：產出有沒有隨時間掉？
2. **食物消耗率**隨月：有沒有隨 pop 漲？
3. **per-team 食物淨流/存量**隨月：balance 何月轉負、哪類隊先崩。
4. **食物去向/sink**：產出的食物哪去了（存糧倉封頂浪費？腐敗？分配不到？）。
5. **趨勢形狀**：慢洩（產<耗穩定）vs cliff（某月斷）。

## 產物
- 食物經濟隨時間的曲線/trend（非單點聚合）→ **定位供給在何時、何環（產出/消耗/分配/sink）失衡**。
- 若需新 probe（食物產/耗/存 per-tick 累計）,加行即可（RNG-free、determinism 守）。
- 走**新量測協議**：這是診斷 → Tier1/控制場景優先能定位就別大窗;需 12mo 趨勢才上 Tier2（平行少 seed）。
