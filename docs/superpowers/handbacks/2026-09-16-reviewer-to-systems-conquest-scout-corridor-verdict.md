# ①「降成可行性會不會把攻擊判死」—— 母體太小，這格驗收要加防呆

你自己報的基準：**10 天窗攻擊贏 3 次**。這是個位數樣本——驗收③「攻擊仍會贏 argmax」
如果只是一個布林（這窗裡有沒有至少贏一次），在 n=3 這種量級下**雜訊跟真訊號分不開**：
運氣好抽到 1 次也會判過、真的被壓到趨近 0 也可能因為單次偶然贏而判過，兩種情況在

⇒ 建議：驗收③不要只看「贏過沒有」，**報實際勝率（贏次/候選次）並跟這次 10.8%

不管改法對不對，單看「有沒有贏過」這格通不過我的判準。

# ②「成對驗收夠不夠」—— 我看到一個第三方向可能漏的地方

你補的驗收「總量不塌＋勝率不爆」防的是**偵查整體**的塌/爆，但這個修法是「攻擊走廊 → 偵查」
的**替代**，真正要防的退化是**偵查專門在跟攻擊比的時候贏**（而不是偵查在整體的所有對戰
裡贏得比較多）——這兩者不是同一件事：

```
情境 A（你的驗收會抓到）：偵查對任何對手都變得很會贏 ⇒ 整體勝率飆高 ⇒ ②的「不爆」會紅。
情境 B（你的驗收可能漏掉）：偵查對【其他選項】（貿易/生產…）勝率正常，
   但偵查對【攻擊】這一種對手贏得異常多 ⇒ 整體聚合勝率被其他對手的正常表現稀釋，
   看起來「不爆」，但走廊換皮的病其實原封不動地搬進秤裡了。
```

★這正是我在偵查進秤那張票裡已經提過一次的量測母體問題（用「候選集裡有沒有 X」篩，
不要只看聚合率）——這次的形狀是同一根：**「偵查 vs 攻擊」這個特定對局的勝率，
跟「偵查 vs 所有對手」的聚合勝率，是兩個數字，只報後者會看不到前者出問題**。

⇒ 建議驗收②再加一格（或把現有那格拆細）：**在『攻擊與偵查同時是候選』的那些 argmax
呼叫裡，偵查贏的比例**——這個數字才是直接對應「走廊有沒有換皮」的那個問題，
總量+聚合勝率是必要但不夠。
