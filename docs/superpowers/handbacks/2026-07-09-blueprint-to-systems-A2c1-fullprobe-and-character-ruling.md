# A2c-1 裁定：Option 1 + 定性預判

## 走 Option 1：立 full_probe 三探針 + 重跑拿鐵證
**選 1 非 2**，理由：
1. **用戶明說要全探針對照數據才判**（「我不知道 要有全探針量測數據對比」）——多信號間接證雖強，但用戶要看直證，不給就是逼他盲信。
2. **順手立標準 full_probe 床**（用戶流程修）——A2c-1 當首個 customer。防未來再走這種 7 輪反應式來回（byte0→drive→artifact→phantom→drama→因果→生存，每輪缺一維）。
3. 補唯一缺的直證（merge dispatch count + option 去向），~20min 值得。

**★立成標準、非一次性**：照 full-probe 流程 handback，三探針做進可複用 `full_probe` 模式（①consolidate-merge dispatch count ②merge-applicable 隊 option 選擇分布 ③team-size 直方圖 + food-flow 分布），產標準 JSON schema baseline/fold 並排。A2c-1 用它，未來 slice 也用它。

## 定性預判（鐵證坐實則定案，我判大機率坐實——多信號已一致）
- **A2c-1 純 fold 弱化 merge-as-survival = shipping regression**，非中性 artifact 移除。**純 fold 不可 ship as-is。**
- **我先前裁定的自我修正坐實**：把「duress 下整併」劃 A2d = 錯，其**求生版本 load-bearing、不可延**，拉進 A2c-1。
- **A2c-1 升級**：從「純 FA5 fold」→「**fold + 正確 value 求生整併**」（弱/餓/小隊該併時引擎得選併）。
- **這不違用戶「別瞎調」**：非調 conquest target（那治不了、死隊不征服），是**針對 survival-consolidation 估值缺口定點補**——弱隊 merge option 的 utility 要正確反映「不併會餓死」。具體 seam/估值形狀你 spec（讀 full_probe 的 option 去向定），別在鐵證前鎖形狀。

## 定序
1. 你：立 full_probe 三探針 → baseline/fold 重跑 → 回**全探針對照**（merge count + option 去向 + team-size 分布 + food-flow）。
2. 我：讀對照 → 定案 A2c-1 定性 + **同步用戶看數據**（他等這份判世界）。
3. 坐實 → 你 spec「fold + survival-value」→ reviewer → 下游。**A2c-1 收尾/merge 續暫緩**至升級版過。
4. 若對照意外翻案（衝突降非 consolidation 下游）→ 回頭再議。
