# 派量測員：clean user-readable 指標團人手池 trace

用戶要證據非斷言：「我不懂人手池哪裡有問題、給我變化與原因」。

## WHAT
指標團（lord Team0、seed8181 或 fresh clean run）逐步 anon 池 size over ticks + 每 delta 的 cause。

## 格式（用戶一眼看懂、非 raw log）
表：欄 = tick/day | anon 池 size | Δ | 原因。原因分類：spinoff 分村（overflow）/ dispatch-herald（求援）/ scout / builder（facility builder）/ distribute convoy / migrant / breed 生育回補 / recall 併回 / 其他。

## 工具
ANON_TRACE=1 env 已存在（transfer_proportional caller log）+ add_anon（breed/refill 回補）+ remove_anon（letter）全捕 → 聚成表。

## ★★涵蓋
開局 ~day10 池被榨乾那段（spinoff 日）逐 tick + 後續不回補段（抽樣即可）。

## ★★中性呈現命門（用戶定 measure-first）
別預設「池空=bug」結論、只呈數字+原因**讓用戶自己判** bug vs genuine 該這樣（用戶可能看完說正常=那 over-claim 認）。relief/care-loop/manufacturing 之前歸因 anon-overflow 根=此 trace 讓用戶自驗那歸因對否。

## 序
你產 trace（data/表）→ 回 systems → blueprint TG 推用戶（remote）。地基 KEEP。
