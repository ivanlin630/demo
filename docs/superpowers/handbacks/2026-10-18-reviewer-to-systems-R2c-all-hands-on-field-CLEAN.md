# 二、派發前請併進 spec 的文字修補（C1–C3）
- **C1 N1 的效果描述比事實樂觀**：spec 寫「有後備的一方不會因為前排死了七成就潰退；隊列用完之後，比例照今天上升，潰退照今天發生」。這對**死亡**成立，但比例的分子是「死＋失能」（`is_combat_capable` 對兩者都回 false），而失能（活著、重傷）依 §四「佔名額、不補」。⇒ 前排**失能**七成而隊列滿著，比例照樣 > 0.7，整隊集體撤退，隊列一個都沒用上；累計死亡夠多（約 `n` 的 2.3 倍，比例 `d/(n+d)>0.7`）也會在隊列用完之前觸發。請：
  1. 把這句改成「死亡由補人稀釋；失能與累計傷亡不被稀釋，仍會觸發潰退，與隊列是否用完無關」；
  2. H7 加 (h)：前排失能七成（活著）且隊列滿 ⇒ 照今天潰退，印比例與隊列剩下數（記下它，證明這是已知後果，不是漏洞）；
  3. 誠實限加一句「重傷後個別撤出的單位佔名額、不補，隊列在傷多於死的仗裡會有大量剩下」，免得之後 QA 看到「全員在場」的仗裡隊列幾乎沒用而報成 bug。已告知藍圖的那一句請同步寫進去。
- **C2 H12 母體地板只蓋了追擊**：地板場是「玩家方輸、NPC 贏且有追擊」（`pursuit_killed ≥ 1`）。`fate_killed`／`fate_captured` 另需 NPC 為留場方且有傷兵處置（同小修二 C3）。請印三場（你贏／NPC 贏有傷兵處置／NPC 贏有追擊）各自非 0 的那一欄，當母體地板，避免式子的右邊兩項在所有場上都是 0。
- **C3 分配段的床格**：H3 的連續性掃描只固定 R_b=60。請再掃一次 R_b 取在保底邊界上（例如 R_b=10、11）與 R_a 兩者互換（對稱性：`field_allocation(a,b)` 的 a 邊結果＝`field_allocation(b,a)` 的 b 邊結果），一個一行的斷言，抓取整方向的錯誤。
