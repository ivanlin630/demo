# 一、用戶這輪說了什麼（逐字）＋我的讀法

```
「新版UI更爛 爛到沒救」          ⇒ 六區 Label 合成版面在真機上不可用（排版壞、選項重複）。
「改用終端形式的文字UI」        ⇒ 不是再排一次 Label，是換呈現媒介：終端（monospace、逐行輸出、鍵入指令／按鍵選項）。
「你們自己抓排版 重複選項等問題」⇒ 交玩前的視覺驗收是我們的義務；兩個已知病名：排版、重複選項。
★而這跟他 9/29 的原意同一句：「文字UI用終端表現 agent能自己抓錯」——終端輸出是一份文字，人讀、床讀、agent 讀的是同一份。
```

# 二、WHAT

```
①媒介：終端。Godot 以 headless 跑模擬；玩家介面＝一個讀指令、印畫面的迴圈。
   每次輸出＝固定順序的純文字區塊：狀態列（第N天 HH:MM｜隊名 人口｜家｜糧撐｜威脅｜待執行）／地圖（#9 四態字元＋圖例）／當前分頁內容／可做的事（編號清單，含灰掉＋原因）／最近事件（帶時間）／最後結果句／提示列（可按的鍵）。
   區塊順序與寬度固定；寬度上限 100 欄（HOW 可定），超寬＝紅。
②輸入：單鍵或短指令（HOW 定一套：數字選項／x 一小時／空白一天／t 互動／1-5 分頁／q 離開），每道輸入後重印整個畫面（終端捲動是玩家的歷史，不另存）。
③同一份文字三個讀者：人（終端）、床（逐區塊斷言）、agent（JSON 通道照舊，另加可讀純文字模式）。
   ⇒ 「畫面長什麼樣」第一次成為可被 diff 的東西。
④交玩前自驗（硬閘，取代用戶眼睛）：對一組腳本化走法（開場／T 互動／招募展開／強制事件到達／遭遇戰／推進一天）逐幀印出畫面並斷言：
   a 區塊齊全且順序固定  b 無重複選項標籤（同一畫面同一標籤只准一次）  c 印出的鍵＝接受的鍵（反向也成立）
   d 無英文識別字（既有 d 規則）  e 每行 ≤ 寬度上限、無空白區塊  f 同一狀態重印兩次逐字相同（確定性）
   任一紅＝不可交玩。這份走法的輸出要落檔成人可讀卷面，交玩時附給用戶（他要看什麼我們先看過）。
⑤版面 v2 停止投資；TextUiView 的區塊產生器若能直接產純文字就搬，Label／.tscn 那層退場（TextUI.tscn 不再是玩家入口；main_scene 改指終端入口或 headless）。
⑥不變的：五分頁內容、指令佇列與按了就結算、按鍵三態、地圖記憶、事件流、強制事件生命週期——全是資料層，媒介換了它們不動。
```

# 三、HOW 先查（你的格，我只列會擋路的）

```
·Windows 的 stdin：agent_repl 走 pipe://stdin 在 Windows 不可用而退到 TCP。候選：Godot 4.2 的 OS.read_string_from_stdin()（若 4.2 有且 Windows 可用）；不行就一支薄客戶端（python play.py 連 TCP、在終端印），兩者對玩家都是「開一個終端」。
·CP950：終端輸出必 UTF-8（wrapper 已做過這件事的經驗），中文寬度（全形 2 欄）要進寬度計算，否則對齊永遠歪。
·鍵入模型：逐鍵（無 Enter）需要 raw mode；逐行（按 Enter）最穩。先逐行；逐鍵列待辦。
·床：不起 transport，直接呼產生畫面的那支函式（同探索床的做法）。
```
