# 一、裁定的理由（WHAT）

```
①瞬醒的目的＝「不能等到下一次思考」；被襲是；一封每小時 pass 送來的普通情報不是——它本來就以小時為節奏產生
②現況＝全體在同一 tick 被叫醒一起想 ⇒ 這是模型的人工同步，不是世界該有的樣子；情報網 arc 的意圖是「傳播靠延遲與衰減」，瞬醒反而把延遲抹成 0
③但不可反過來讓威脅情報也等：那會讓「怕」失去出口（恐懼出口那條）。所以切在【內容】：威脅相關瞬醒，其餘排定
   ⇒ 零特例：讀情報的 salience/threat 欄（belief 已有威脅感知），不列白名單事件型別
④「反應變慢上限一小時」對非威脅情報＝可接受；對威脅情報＝0（不變）
```

# 二、驗收（數字前寫死；HW-2、12 天、兩顆種子、Probe 關為主）

```
B1【機制】pass tick 上 woke_only 次數 ⇒ 相對修前下降（方向性）；非威脅 intel 引發的 T0 瞬醒＝0（構造）；威脅 intel 引發的瞬醒次數與修前同量級（±20%）
B2【行為】威脅反應延遲（威脅情報到第一個反應動作的 tick 數）median 修前後同（±10%）；非威脅情報到動作的延遲 median ≤ 60 tick
B3【玩家尺】>2s 幀數／p99／median（同尺）；可交玩門檻不變（≤1/日 且 p99<1s）
B4【副作用】A3 同型：每隊每日決策次數 median ±5%；A6 守 extinct/starve/combat（帶主詞）
B5【fp】指紋床改變＝預期紅 ⇒ 世代 7；樁開/關 fp 同
B6【陽性對照】把「威脅也折進排定」跑一次 ⇒ B2 威脅延遲必須惡化 ⇒ 證明 B2 會紅
★「假設為假時這格長什麼樣」：若情報其實不是喚醒波的主因，B1 的 woke_only 不會降、B3 不動 ⇒ 兩格一起綠才算
```
