# 判決：`clean`

## ②預設反轉——**不是鑽字面，是真的不同東西，兩個理由**
1. **失效方向不同**：白名單漏加一條 ⇒ 新事件類型靜默【不喚醒】任何系統，正是這整個 arc 要殺的「危機時沒反應」bug；你的形狀漏寫一條例外理由 ⇒ 新事件類型預設【喚醒全部】，代價只是多評估一次（浪費，不是漏接）。WHAT 自己的優先序（「T0人人瞬醒,鐘慢不害死人」）明確站在「寧可多喚醒不可漏喚醒」這邊，你的預設方向跟這個優先序對齊，不是巧合換個說法。
2. **可稽核性不同**：白名單裡「沒被列進去」的組合，看不出是「想過但排除」還是「根本沒想到」；你的形狀強制每個排除都要一行理由，210 格逐一有處置，跟今天 `NEEDS_HUMAN=0`／`TIER_UNJUSTIFIED` 是同一種紀律。這個結構性保證是白名單天生沒有的。

★**「有些例外理由會是廢話」（例：`teams_erased`喚醒野心階梯）——這個成本我判可接受**：一行短理由的寫作成本很低，換來的是「這格被想過」的紀錄，而不是留白讓半年後的人猜。跟"逼出一堆廢話白名單"不是同一件事——那個的問題是【假裝窮盡】，你這個是【每格都真的有處置，只是有些處置很短】。**不算鑽字面，方向對。**

## ③-1 沿用既有 `reeval.event` tap——**驗過，確實存在**
`faction_ai_system.gd:3212-3213`：`if WorldEvents.is_pending(...): if Probe.enabled: Probe.bump("reeval.event")`——就是要照抄的那個形狀，不是要你相信它存在，我直接讀了。夠。

## ③-2 意圖併遷推論——**獨立確認過，推論對，而且驗收④本身就是它的安全網**
blueprint 扣住意圖的理由明確是「危機 T0 接管機制不存在」——我查了驗收④（「意圖遷 T3 後,因事件被喚醒次數必須 > 0」）：**這條要求本身就蘊含意圖也要跟七支一樣被接上 `is_pending` 短路**，不是只換個 cadence 標籤。也就是說：即使你的推論（前提消失可以搬）哪裡想錯了，驗收④會在同一次交件裡當場抓到（次數＝0 ⇒ 空窗還在 ⇒ 紅）。**推論本身站得住，而且就算站不住也有硬指標兜著，不是純邏輯賭注。**

## ⇒ 結論
`premise_contradiction: false`，三處都核對過。**implementer 可以立刻動工，這是最短路徑：不用等我再審一輪。**
