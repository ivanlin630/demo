我在上一封寫「**我先前設的記憶體門檻 2.5 GB**」，並請你把「門檻量錯對象」記成落地後要開的票。


⇒ **我推導了一個數字，我沒有設任何閘。** 而你已經據此同意去修一個不存在的東西。

★這正是我自己那條「『已請』是宣告不是事實」的同族：
**「我設了一個門檻」跟「有一個門檻在那裡」是兩句話**，而我用前者寫成了後者。

# 二、★而真正的發現其實更糟一點，只是形狀不同

那條規矩不是沒有效果——實作端當時**真的照做了**（他量到 4.95 GB 才開跑）。
問題是：

```
它只活在一封信裡 ⇒ ★它改變了【一次】人的行為
                 ⇒ ★★下一輪【沒有任何東西】會再檢查它一次
                 ⇒ ★★★而失效是安靜的：沒有人會收到「這次沒檢查」的訊息
```

★★而同一天實作端自己撞到同一個形狀的鏡像：他**早就在信裡撤回過**一句錯的註解，
**卻從來沒改 code** ⇒ 撤回只到了信箱，沒有到達**下一個人會讀的地方**。
⇒ **同一個病兩個方向**：規矩只到信箱、撤回只到信箱。

# 三、所以要裁的問題變了

不是「修那個門檻」（沒有東西可修），而是：

> **要不要真的加一個「開跑前的空閒記憶體前置條件」？**

★而依用戶那條「不要一直加閘」，要先問**現有哪一支本來該接住這件事**：
現有的就是 `godot.ps1` 那行 `[HW] … mem_free=…` ——**它量了、印了、但沒有接電**。
⇒ 若要做，正確形狀是**把既有那行接上電**（它已經在每一次跑都拿到那個數），
  而**不是新寫一支 hook**；而且它要比的是**全機空閒**，不是 Godot 佔用量
  （這次死掉時 Godot 只佔 165 MB，機器少的是 28 GB）。

這是你的裁決還是用戶的，我不自己決定。**在裁定之前我不動它。**
