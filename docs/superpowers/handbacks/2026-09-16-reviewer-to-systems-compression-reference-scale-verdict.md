# 先核你的合法性主張：`ref` 沒有 god-view

`invariants.md` 感知鐵律那段（「★感知鐵律」＋「belief 通過≠內容任取」細則 1a）讀過——
`ref = 自家人口 × Σ(TARGET_PER_POP × BASE_PRICE)` 只讀**自己的人口**（自身狀態）跟
**兩張全域設計常數表**（不是任何他隊的真值），沒有踩到「決策路徑上每個他隊欄位都要是 belief 欄位」
這條——因為它壓根沒讀他隊欄位。★你擋掉「世界當期中位數」是對的（那個確實要讀全體他隊真值，
撞鐵律），這個新形狀沒有同樣的病，合法性成立。

# ①「CAP＝1.0 是不是又一個手填數」—— **不是同一種東西，但也不是 coin＝1.0**

先把 `local_value():194-195` 的 `coin` 特判原文找出來對照：

```gdscript
if res == "coin":
	return 1.0   # currency: always face value, no supply/demand modulation
```

★**這是零自由度的重定義**：貨幣的價值「就是」1 個它自己，換成任何別的數字不是「另一個設計選擇」，
是**换了整個經濟的計價單位**（等於把所有東西的價格都乘上同一個常數，比較關係不變）——
這是它能被叫「單位定義不是估計」的**真正原因**：不是因為它剛好等於別人的值域，是因為它沒有
第二種答案可選。

★★而 `CAP＝1.0` **不是這樣**：把它換成 0.5，`richness_compressed` 的上限就變 0.5，
`richness*greed` 在飽和端的貢獻會被砍半、相對 `weakness*cruelty`（上限 1.0）的重要性也跟著砍半——
**這是一個真的會改變遊戲平衡的選擇**，不是重定義單位。它有自由度，coin＝1.0 沒有。
⇒ **「跟 coin＝1.0 同型」這個類比，我判不成立**——這正是你自己疑心的「我是不是又在合理化」，
而這次合理化抓到的點是：**借一個零自由度的先例，去給一個有自由度的選擇背書**。

**但這不代表 CAP＝1.0 不合法**——它就落在你今天稍早自己立好的第三類：
**誠實具名的設計參數**（跟 `SCOUT_VALUE_BLIND_PRIOR`／`ARMED_FRACTION_BASE`／
`DiscountedFlow.DELTA_FLOOR` 同一族——世界答不出「richness 該跟 weakness 比重多少」，
這問題本身沒有物理答案，答不出就是它該留著當設計選擇的證明）。
⇒ **請把它標成 TEST VALUE、寫「這是設計選擇，靠 measure 調」，別借 coin 的理由**——
理由換了，數字可以留著，1.0 這個起點合理（跟其他項同尺度出發沒問題），只是別用零自由度的
名義去護一個有自由度的東西。

# ②「壓縮的代價有多大」—— 我粗算過，主操作區還好，只有極端尾被壓平

拿你 §①的兩張表實際算了 `ref` 的量級：`Σ(TARGET_PER_POP × BASE_PRICE)` 逐項相乘加總
（food 10×2=20、material 5×4=20、goods 3×15=45……weapon_melee_high 0.5×72=36……）
**≈ 每人 416**——這是真算出來的數字，不是估的。

用這個算 `x/ref` 在幾個點的壓縮結果：

```
x/ref = 0.1  → 0.09     （窮目標）
x/ref = 0.5  → 0.33
x/ref = 1.0  → 0.50     （跟自己溫飽線同量級）
x/ref = 2.0  → 0.67
x/ref = 5.0  → 0.83
x/ref = 10.0 → 0.91
x/ref = 100  → 0.99     （你舉的例子）
```

⇒ **0.1x～5x ref 這段（我判斷是大多數正常目標會落的區間——一個目標的持有量跟它「該有的溫飽線」
差在幾倍以內，是常態，不是離群）分辨力還在**：0.09 到 0.83，跨了快一個量級的差距，
weakness/border 一樣能跟它公平競爭，不是被單一項又碾壓一次。
**只有 >10x ref（目標比自己溫飽線富裕十倍以上）才進入壓平區**——這是真正的離群值，
「這個目標是溫飽線 10 倍還是 100 倍富裕」在直覺上本來就沒那麼重要（都是「巨富」，
細分意義有限）——這段被壓平，我不判它是「反過來變得不相干」，是壓縮**該有**的行為。

★**但我這是拿常數表算出 `ref`，沒有拿真實世界的 `x`（各隊實際估值）分佈去對——
「大多數目標真的落在 0.1x～5x」是我的推論，不是量出來的**。上線前建議跑一輪，
把 `x/ref` 的實際分佈印出來，確認主操作區真的吃到大多數目標，不是我猜錯量級。
