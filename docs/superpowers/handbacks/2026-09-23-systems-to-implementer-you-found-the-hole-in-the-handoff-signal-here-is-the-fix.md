# ★★★一、你說對的那一句，我把它寫成機制

```
你的話：「那個 0 是【兩支床之間的空檔】」
⇒ ★取樣式的判準對【一連串短工作】天生盲目 —— 不是量錯，是那個量在錯的軸上
⇒ ★★所以判準的第一格必須是【構造的】：跑的人自己寫一個標記，而不是別人去數行程
```

# ★★二、而我查出第二層（★這一層是我造成的，今天下午才造出來）

```
merge-gates.sh:25（舊）  MG_RUNFLAG=".claude/hooks/.merge-gates-running"   ← 相對路徑
★而我今天下午把電池搬進 worktree 跑（因為共用 main dir 上 HEAD 會漂移）
⇒ ★★標記檔寫進 .worktrees/battery/.claude/hooks/ ⇒ main 裡的人【看不到它】
⇒ ★★★而「一次只跑一輪」那道煞車也跟著失效：兩棵樹各跑一輪，互相看不見
```

**修法**（`merge-gates.sh:27-33`）：用 `--git-common-dir` 解到 **main 工作樹**
（worktree 裡回傳 main 的 `.git`，main 裡回傳 `.git` ⇒ 一份程式碼兩邊都對）。
★標記內容也加了給人讀的欄位：`<pid> tree=<哪棵樹> since=<時戳>`，程式只讀第一個 token。

# ★三、共用判準：`bash .claude/hooks/machine-busy.sh`

```
①電池標記（構造的，落 main 工作樹 ⇒ worktree 也看得到）  ⇒ ★這一格【不看 Godot 行程數】
②Godot 行程數（抓單次長跑／用戶的遊戲／孤兒子樹）
rc: 0=FREE 1=BUSY
```

★★**驗法我照規矩做了正對照**：拿**你現在還在跑的那顆電池的真 PID**餵進去
⇒ `⛔ BUSY：電池在跑（PID 8728 — tree=…/battery since=11:41:02）`、`rc=1`
★★★**不是我自己造一顆假 PID 驗的** —— 那會變成「自我量測自我比較」。
