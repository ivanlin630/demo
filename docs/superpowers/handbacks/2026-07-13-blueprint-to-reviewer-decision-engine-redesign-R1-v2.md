# 決策引擎架構重構v2 —— R①重驗

## 背景
v1（`34f2591`）被你打回四項風險。用戶決定**不接受縮小範圍迴避**，要求正面對決四個問題重新設計。已重新brainstorm並改寫spec：`docs/superpowers/specs/2026-07-13-decision-engine-needs-hierarchy-redesign.md`（`9d379e9`）。

## 核心結構改動（非小修，請重新審視）
**放棄「選一個active需求層」的設計**，改為**五層需求平行急迫度混合**——每層各自算急迫度（同一套EWMA公式套用在5個不同指標，非硬套rung單一數字），5個急迫度是「感測器」非「決策者」，只餵一個係數給`rank_scored`最後加總，不自己選行動。

## 四項v1風險的v2對案（請逐一驗證是否真解，非文字宣稱）
1. **候選池死鎖**：v1硬排除→v2軟性重度降權+持續卡住自動鬆綁（複用EWMA停滯偵測）。查§3。
2. **威脅整合矛盾**：v1硬塞金字塔且用EWMA累積(跟緊急插隊語意衝突)→v2同一判斷雙速輸出(低於劇變門檻EWMA累積；達劇變門檻直接TaskArbiter插隊，複用S3 crash-bypass判準)+插隊事件回寫主腦安全需求急迫度。查§5。**特別查**：這個設計是否真的沒有繞過/破壞既有`PRIO_SURVIVAL`機制本身，只是多接一個事件回寫。
3. **EWMA形狀不匹配**：v1硬套rung單一數字判定「選哪層」→v2放棄單選，改五層各自EWMA平滑（同款公式，不同輸入），不需要「選哪層」判定本身。查§2是否真的解決了你抓到的「趨勢窗機制無法直接產出多層優先序判定」這個具體質疑。
4. **found_score答非所問**：v1用建國/打弱敵專用分當通用賭命跳關判準→v2整個「賭命跳關」機制取消，改成候選池降權曲線的人格連續參數（§4），不再需要一個「目標價值判準」。查是否真的不需要found_score這類專用分數。
