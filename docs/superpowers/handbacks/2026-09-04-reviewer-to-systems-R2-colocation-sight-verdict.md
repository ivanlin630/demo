# 判決：`issues`（小），`premise_contradiction: false`

## (a) 分支非大乘數——**確認正確，同意**

「確定」跟「機率推高」是不同性質的東西——乘數再大都還是機率閘的一部分，理論上仍可能被 `_can_detect` 判為沒看到；分支直接跳過機率閘才是真的「保證」。跟今天已經反覆用過的「genuine value 不是 crank 分數」同一種紀律：這裡要的是【確定】這個性質本身，不是【很高的機率】湊出來的近似確定。寫入內容限定「真 pos ＋ 外觀層」不寫內部狀態，跟今天 `perception-two-layers` 那票的邊界一致。這半沒問題。

## ★★(b) 鄰近陡降——**三個候選都有問題你判得對，這裡是第四案**

讀了 `vision_system.gd:43`：`dist_f = 1.0 - (dist/(vrange+1)) * 0.5`——這是現行公式的確切樣子。

★**候選 2 的「1」跟候選 3 的「3」不是同一種性質的手填**：hex 距離是離散整數，「1」＝「最近的非零距離＝相鄰格」，這是**格點座標系統本身的結構事實**（跟這個世界用不用 hex 無關，只要是離散格子，1 就是最小非零距離，沒有別的選項可以是「更小的非零距離」）；而「vrange/3」的「3」是一個**在連續量尺上任意選的比例**（換成 vrange/2 或 vrange/4 一樣說得通，沒有結構性理由必須是 3）。**候選 2 的邊界不是候選 3 那種手填，不該被同一頂帽子扣住。**

⇒ **建議（第四案，補上候選2缺的那個「近場數值」，同樣零新常數）**：
```
dist <= 1 ⇒ dist_f = 1.0        （★不是新數字——這就是現行公式自己在 dist=0 時的值，沿用它的既有天花板）
dist >= 2 ⇒ dist_f = 1.0 - (dist/(vrange+1)) * 0.5   （現行公式，完全不變）
```
**這樣拿到的東西**：
- **零新常數**——`1.0` 不是我發明的，是現行公式本來就有的值（它在 dist=0 就已經是 1.0，只是把這個既有的極值延伸到 dist=1）；分界「1」是格點結構事實不是自由選的比例。
- **陡降是真的陡降**——dist=1 給 1.0、dist=2 給現行公式的值（例如 vrange=3 時約 0.917），這一步落差比現行公式原本從 dist=1 到 dist=2 的落差（原本兩者都在 [0.5,1.0] 帶內慢慢滑）明顯陡峭，滿足目標②「距離主導」。
- **遠場逐位元不動**——dist≥2 的分支完全就是原本那行程式碼，不改一個字元，驗收⑤（遠場行為未變）字面上就會過，不用另外驗證「新公式在遠場數值上剛好跟舊公式很接近」這種近似論證。

★**這不是候選 2 加候選 3 的縫合**——是把候選 2 缺的那個「近場該給多少」的空格，用【現行公式自己的極值】填上，不是另外挑一個獨立的新數字，跟你不想手抄物理的顧慮同一個方向。
