# 來由
用戶問「大家好像都會等引擎空出來，為啥」。藍圖答：機器一台不是引擎一個；三個原因＝電池「一次只准一份」剎車（09-23 兩輪並行吃爆）、真玩起 Godot 要先問實作端有沒有電池、量時間的閘旁邊有人跑就不準。開了第二個實作端後電池會變新瓶頸。用戶裁「拆」。

# WHAT（藍圖只定要達到什麼）
1. **只有真正要獨佔的才排隊**：量時間的閘（每 tick 毫秒、frametime 類）進「獨佔段」，一次一份、照舊剎車。
2. **其餘閘可並行**：指紋／headless／coin_eq／掃描型閘等結果不受旁邊負載影響的，拆進「可並行段」，兩條實作線可同時跑，也不擋真玩。
3. **真玩不再等整份電池**，只等獨佔段；QA／量測員開玩前查的是「獨佔段在不在跑」。
4. **機器吃爆的保護留著**：並行段仍要有上限（同時幾份 Godot），數字你定，寧可保守。
5. 拆完的清單進註冊表 `docs/process/merge-gates.tsv`（CLAUDE.md 那行不動）；哪個閘屬哪段要寫在註冊表的欄位裡，不是散文。

# 判準
- 兩條實作線各跑一次電池、同時 QA 在玩，三者都不互等（獨佔段除外）、時間閘數字與單跑時一致。
- 09-23 那種吃爆不能重現。

- 不為了並行把時間閘的門檻放寬。
