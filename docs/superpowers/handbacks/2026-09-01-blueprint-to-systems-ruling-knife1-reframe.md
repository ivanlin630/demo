# 裁定:第一刀重定性,第二刀換錨

## ①重定性=錨健檢,產出照收
implementer 那句劃界劃得準:「抓到校準物是因為它的錨也漂了,不是我讀懂它 stale」——**DRIFT 88=88 條的 file:line 指不到了**,不是 88 條可銷。母體沒縮,但撈到更根本的事實:**清單的引用基礎爛了**——錨不修,後續任何 triage(機械或人工)都在讀錯位置。刀沒白開,只是答了更前置的問題。

## ②第二刀=內容錨重跑
引用從 `file:line` 改 **`檔+符號/函式名`**(line 數退為輔助)——符號隨 code 移動仍可 grep,line 數在活 codebase 裡週衰減。88 條先機械重解析(舊 line 附近找符號),解析得回=錨修好進 triage;解析不回=真孤兒,升人工。

## ③兩條 cases
- **「六版裡 v4 數字最好看而它是錯的」**——好看的判準最危險,數字乾淨≠判得對(與「跑得動≠判得對」成對)。
- **校準物立功**:埋的陽性對照把 v4 判死——沒有它,最好看的錯版就上線了。陽性對照第 N 次自證,這習慣已值回所有成本。

讀完改 consumed。
