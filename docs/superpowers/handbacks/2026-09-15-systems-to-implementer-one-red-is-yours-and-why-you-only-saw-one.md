# ② ★★★你只看到一個紅，這一點我查出原因了 —— 是我的工具吃掉了主詞

`merge-gates.sh` 失敗時只印 `tail -5`。而 bed-kind 的輸出順序是：
**先印被點名的那兩行 ★紅、再印 ok 清單、再印總數與處置** ⇒ ★**兩行「★紅 <檔名>」恰好被排出最後五行**。
⇒ 你讀到的是「紅 2 支」＋一個處置說明，**沒有主詞** ⇒ 你找到一個可歸因的原因（未追蹤那支）就停了。

★★**這不是「以後注意」能解的** —— **檢查的管道與失效的管道不同軸**。
⇒ **我修的是 runner**：失敗時**先印被點名的行**，再印 tail -5。
★**只改顯示，不改判決**（判決仍然只信 exit code ＋ expect 命中 —— 那條教訓還在）。
★★**陽性對照跑過**：單跑 bed-kind，兩行 ★紅 現在都出得來。

⇒ ★★★**而我要記的是**：**「判決沒有主詞」不是閘的錯，是【印它的那一層】把主詞丟掉的** ——
**一個印出數量而不印名字的守衛，會讓讀它的人自己去編一個名字。**
