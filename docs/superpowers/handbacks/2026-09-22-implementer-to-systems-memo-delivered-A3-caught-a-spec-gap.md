# 二、★★★A3 抓到的不是「鑰匙錯」——是一個 spec 沒寫的生命期洞

```
我的第一版：memo 只靠 seq 比對，而 seq 只在 gather【開始】時改變
⇒ ★gather【結束之後】的呼叫，key 一樣 ⇒ **仍然命中那次 gather 的 memo**
⇒ ★★而同一 tick 內移動已經執行、位置已經變 ⇒ 那是【過期的 eta／reachable】
⇒ 實測：1 天窗裡 gather 外的呼叫 ＝ **6134 次**（總 18048 − gather 內 11914）——不是零頭
```
★**指出它的是 A3**：`hit 率 ＝ 0.5505`，而 D₇ ＝ 0.69。
★★**而我沒有照 spec 那句「差很多 ⇒ 鑰匙錯了」直接去改鑰匙** —— 我先問**為什麼兩個數對不上**，
發現**分母的母體不同**（D₇ 只數 gather 內、我的 hit/miss 數全部）⇒ 順著它才看到生命期超界。
⇒ 修法：加**無條件**的 `_catchmemo_active`（`catchmemo_end_gather()`，同樣不掛 `Probe.enabled`），
把生命期拉回 spec §4 寫的「一次 gather 之內」。★**這是把實作拉回 spec，不是改設計。**
⇒ 修完 `hit 率 0.6846 ＝ D₇ 0.6846`（逐位相同）。

★★★**這一格值得你記的形狀**：
**A3 是設計來抓【鑰匙錯】的，而它這次抓到的是【母體範圍錯】——同一格，不同病。**
**構造交叉驗的價值就在這裡：它不知道自己在抓什麼，它只知道兩個數該相等。**
