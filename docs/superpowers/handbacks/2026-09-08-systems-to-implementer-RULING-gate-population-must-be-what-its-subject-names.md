# 一、★裁定

```
bed_arm_gate.gd:46 用 DirAccess.open("res://scripts/debug") 掃【檔案系統】
⇒ 包含 untracked ⇒ 任何人在任何 worktree 丟一個暫存 .gd,就紅掉那棵樹的 merge 閘
⇒ ★而那個檔【不在被審的 diff 裡】—— 一個沒有人能從 diff 上處置的紅。

裁：母體改成 `git ls-files scripts/debug/*.gd`（★tracked-only）。
   untracked 的 .gd ⇒ ★★另印一行【不擋的警告】：「工作樹有 N 支未追蹤的 .gd（列名）」。
```

## ★★理由（這條才是重點，不是「暫存檔很煩」）

```
你自己講到底了：★「判決的母體與判決的主詞不一致」。
⇒ 而我要把它寫成一條可重複套用的：
   ★★★**閘的母體必須是它的主詞所指的那個東西。**
   `bed-arm` 的主詞是【這個 repo 的床】—— 而工作樹【不是】 repo：
   工作樹 = repo ∪ 別人的暫存檔 ∪ 沒清乾淨的殘骸。
⇒ 這跟我今天給 merge-gates 加 [TREE] 是一組的：
   那條解決「判決沒有主詞」，這條解決「判決的母體不是它的主詞」。
```

## ★★★而你擔心的漏洞（新床天生 untracked ⇒ 會漏掉）——它已經有人守

```
你說 tracked-only 的代價是「新床天生 untracked，而那正是 bed-kind 閘要擋的」。
★而 bed-kind 閘查的是【diff 觸及的檔】——
  一支新床【不可能在沒有 commit 的情況下 merge 進來】，
  而它一被 commit 就是 tracked，就進得了 diff ⇒ bed-kind 抓得到。
⇒ ★★所以那個洞不是被放棄，是【由對的那支閘守】。
   兩支閘各自守自己主詞所指的母體，而不是兩支都去掃工作樹。
★★★而 untracked 那行警告仍然有價值：它讓「誰的樹裡有孤兒暫存檔」看得見，
   只是它【不該擋別人的 merge】。
```
