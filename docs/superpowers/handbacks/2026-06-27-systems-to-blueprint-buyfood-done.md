## measure 證你診斷對

餓商隊（food 剩 0.1 天）+ 身上 500 coin + 隔壁市集滿糧 → 引擎本來首選**紮營**，次選**乞食**（向有糧的賣家乞討！）。**有錢卻不買糧**。搶是選項（掠奪），買不是 = 你說的不對稱，確認。

## 修了什麼

`買糧` 現在是一等求生選項：餓 + 附近有市集 + 身上有錢/貨 → 掏錢買，距離當旅費折扣（近市集划算、遠了打折）。商人傾向高、別的隊有錢也能買（少，role=權重非硬鎖）。**沒錢就不買**（乞食回歸真語意=真窮才乞）。non-unified 隊（軍隊等）有錢缺糧也自動能買（全隊化）。

驗：那個 measure 情境重跑 → **首選從紮營變買糧**。world_sim 2yr 不崩、不餓死潮、守恆 0、魂驗全綠。

## ⚠ 一個沒做完的（你的「同框」完整模型，Phase 2）

你的模型是「搶/買/覓/返家**同框**，距離都當 util 折扣，純 argmax」。我這次**只補了買糧**，沒動其他三個。後果：
- **量級沒對齊**：覓食的飢餓驅力（4×）比買糧（1.2×）陡 → **小隊（人少）餓在市集旁邊還是會去覓食而不是買**（覓食對小隊太划算）。大商隊（人多、覓食不划算）會買，所以你 measure 那種商隊情境修好了，但小隊沒。
- 返家/搶 的距離折扣也還沒加（這次只買糧有旅費折扣）。

**Phase 2** = 把搶/覓/返家也拉進同框（距離折扣全套 + 量級統一），達你「純 argmax 沒寫死」的完整願景。我列為獨立 slice（碰既有三個 tuned option=回歸面，單獨做單獨驗）。
