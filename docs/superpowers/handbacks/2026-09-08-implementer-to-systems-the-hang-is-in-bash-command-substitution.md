# ① 現場（進程樹，17:09 取樣）

```
29300 bash  bed-triage-sweep.sh        17:01:09   ← 主迴圈
 7028 bash  bed-triage-sweep.sh        17:01:33   ← subshell
10108 bash  bed-triage-sweep.sh        17:01:33   ← ★`$( )` 的那一層
       ↑ ★★它【沒有任何子進程】—— powershell 與 godot 都已經結束
```
⇒ **godot 沒在跑、wrapper 沒在跑，而 `o="$(...)"` 那一行回不來。**
⇒ 卡的是 **bash 讀端**，不是被呼叫者。

★而外層那個 `timeout -k 5 $((PER_BED_TIMEOUT + 30))` **也沒有救它**：
`timeout` 包的是 `powershell`，而 powershell **已經結束了** ——
`timeout` 對「子進程已經死了但管道還沒 EOF」這個狀態**沒有任何作用**。

# ② 這解釋了三件原本各自孤立的事

```
①「分段前景跑就正常」 —— ★那是【運氣】不是【機制】：chunk1 那 30 支剛好沒卡到。
②「背景 task 被殺 ⇒ 殭屍」 —— 殭屍只是【卡住的那棵樹沒人收】的結果，不是原因。
③「PER_BED_TIMEOUT 沒有上限效果」 —— 因為它包的那一層【已經結束】了。
```
★★★所以我先前給你的那條操作規則（「每段小到能在前景窗口內結束」）
**治的是症狀**：它讓孤兒少一點，但**不會讓卡住的那一次跑完**。

# ③ 我沒有做、要你裁的修法方向

`bed-triage-sweep.sh:～100` 現在是
```sh
o="$(timeout -k 5 "$((PER_BED_TIMEOUT + 30))" env GODOT_TIMEOUT=... powershell ... 2>&1)"
```
可能的形狀（我不自己改，這是共用工具且會改變所有掃描的語意）：
1. **不用 `$( )` 收輸出**：導到檔案再讀（`> "$tmpf" 2>&1`）——
   ★沒有管道就沒有 EOF 問題，而 wrapper 本來就已經把 godot 的輸出寫進檔案了。
2. 保留 `$( )`，但把 `timeout` 換成包住**整棵樹**的形式（`setsid` / job object），
   ★Windows 上這條我沒有把握，而沒把握的東西不該進守衛。
3. 兩者都做：檔案收輸出 ＋ 外層仍有硬上限。

★我傾向 1：它把「等 EOF」整個拿掉，而不是再加一層去殺。
**而它剛好也解掉我今天那個錯誤機制想解的問題** —— 只是原因跟我當時說的不一樣。
