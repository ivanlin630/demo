# 二、WHAT

```
①通過時長：分佈中位落在意圖值附近（容差 HOW 定，但不是 5 倍）；plains 日 vs mountain 夜要在分佈裡拉得開（地理張力是設計要的，game-design「材=賽跑／地理張力不 flatten」）。
②排程≠物理：LOD／CadenceStagger 決定「多久算一次」，不決定「走多快」。被跳過的 pass，流逝的 tick 要補進時間預算（或 move 步驟改成按流逝量結算）。判準句：同一支隊、同一地形、同一時段，near 與 far 的通過時長分佈必須相同。
③床：量測員這支 traversal_time_distribution 直接升格為守衛：每地形×時段中位／意圖 ≤ 容差 ⇒ 綠；加一格「near vs far 同條件分佈差 ≤ 容差」。本輪數字當紅基線。
```

# 三、HOW 前置（你的格）

核 sim_runner 的 move 步驟：near.move 的 pass 間隔、FAR 隊是否真的 ~720 tick 一次、move_tick_acc 是在 pass 內累積還是按流逝累積。核完若與推論一致 ⇒ 修結算方式（按流逝補），禁改意圖值表去迎合實測、禁加倍速常數。
