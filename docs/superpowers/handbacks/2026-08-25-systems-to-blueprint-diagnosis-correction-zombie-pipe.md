# 訂正：**我那句「watchdog 掛了 ＝ 否」，證據不成立**

**你挖出 6 隻孤兒殭屍（管道全死、仍持鎖心跳）之後，我必須回頭改自己的診斷。**

## ★★★我當時的推論缺了一環
**我寫**：「**watchdog 掛了 ＝ 否 —— lock 心跳新鮮（`17:21:49`），持有者 `7ddd77f1`（你的 session）**」。
★**那個推論是**：`lock 心跳新鮮` ⇒ `bash 在跑` ⇒ **`watchdog 有效運作`**
★★**最後一步是跳的。** 中間缺的是：**「它的輸出到得了任何人嗎？」**

**你查出的事實**：★**`TaskStop`／關 Monitor 只殺管道、不殺 bash** ⇒
| 殭屍狀態 | |
|---|---|
| bash **還在跑** | ✓ 還在 poll、還在分類、**還在 `touch` lock** |
| ★**stdout 沒人接** | ★★★**即使它 fire 了，也沒有人被喚醒** |

⇒ ★**功能上等於掛了，而所有「它活著」的證據都還在。**

## ★★所以我的診斷要改成：**兩個斷點，不是一個**
| # | 斷點 | 我當時 |
|---|---|---|
| ① | ★**`RUNNING` 遮蔽 `COMMIT-NO-LETTER`** | ★**這條仍然成立**（親讀 `watchdog.sh` 的 code 層事實，與心跳無關） |
| ★② | ★★**管道死的殭屍 —— fire 了沒人聽** | ★★★**我錯誤地把它排除了** |

★**兩個可以同時為真。我當時說「三個猜測全錯」，第三個（watchdog 掛了）不該被排除。**

## ★★★這對用戶的決定有實質影響 —— **請務必一起呈**
**用戶待裁的是「零產出偵測要不要補」。**
★**如果真正的病（或病之一）是【管道死】，那補偵測【也沒用】** —— **fire 了沒人聽。**
⇒ ★★**「要不要補偵測」和「fire 到得了誰」是兩個問題**，**我原本的診斷只答了前一個，而且答錯了排除項。**
