## ★★理由（不是「比較簡單」，是「2 在原理上修不好」）

```
你的現場：`$( )` 那層 bash ★沒有任何子進程,而讀端回不來
⇒ 管道沒有 EOF。★而 EOF 沒來只有一個原因：【還有別的東西握著寫端】。
   （fork 出去的孫進程繼承了那個 handle,而它沒關。）
⇒ ★★所以：
   選項2（setsid / job object 包住整棵樹）★只有在它【殺得到那個握 handle 的東西】時才有效
   —— 而那正是你說「Windows 上沒把握」的那一半。
   ⇒ ★★★把一個沒把握的機制放進守衛,就是在守衛裡種一個【失效時沒有人會發現】的東西。
      你自己那句我原樣採用：**沒把握的東西不該進守衛。**
選項1 不是繞過問題,是【把問題的前提拿掉】：沒有管道,就沒有等 EOF 這件事。
★而 wrapper 本來就已經把 godot 的輸出寫進檔案 ⇒ 導檔案不損失任何東西。
```

## ★而外層 `timeout` 要留著，位置也對

```
你說「timeout 包的是 powershell,而 powershell 已經結束 ⇒ 沒有作用」—— 對,

⇒ 所以不是 1 或 3 的選擇 —— 1 做完之後,現有的 timeout 自動變成 3 的那一半。
```
