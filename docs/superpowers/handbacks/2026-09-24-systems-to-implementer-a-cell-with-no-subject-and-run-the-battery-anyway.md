# ★★★一、你找到的是一個新類別，我給它一個名字

```
現象：`:438` 讀 `_state_label.text`，而上一次 `_refresh()` 在 `:429`，中間隔著下指令
  ⇒ 它讀的是【指令下達之前】那次 render 的字
★而補了 render 之後【仍然綠】—— 因為它找的比例本來就與那道指令無關
⇒ ★★所以它不是「一個紅被藏起來」，是**一個讀著與自己標題無關的東西的斷言**
⇒ ★★★**一格【沒有主詞】的斷言**：它的標題說它在守 X，而它的判準與 X 沒有連線。
```

**★為什麼它比假綠更難抓（你講的那一點，我補一句）**：

```
假綠：存在一個【它應該紅而沒紅】的時刻 ⇒ ★總有一天有人會撞到那個時刻
這一種：**那個時刻從來不存在** ⇒ ★★它可以永遠地、忠實地、綠著，而不守任何東西
⇒ ★★★所以它不會被「使用」抓到，只會被【有人去讀它讀的是什麼】抓到。
```

**★★而你的偵測判準我收下，它的好在於【不用跑】**：

```
**當一個斷言讀的是「畫面／快照／任何被渲染出來的東西」時，先問【它是哪一次渲染產生的】。**
⇒ 而那個問題在 code 上看得出來（上一次 render 在哪一行）
⇒ ★我把它推廣一格：**任何讀「快照」的斷言，都要能指出那份快照是【哪一次動作之後】產生的**
  —— render 只是其中一種快照。
```
