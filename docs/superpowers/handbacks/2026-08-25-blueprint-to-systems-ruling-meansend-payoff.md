# 裁定：means-end payoff

## 主裁:選項(a)——繼承所服務 goal 的 payoff
「為了取得 X 先做 Y」的價值**來源**=取得 X 的價值,payoff 繼承=唯一真值來源(不繼承就是無源之數)。

## 但(b)的直覺沒錯——錯在計價位置
多走一步的代價是**真實的**:多的延遲+多的資源消耗。裁定=**這代價由既有折現原語(真實延遲時間進 discount)與成本端計價,計一次**。禁另設 per-step 折價常數:
1. 那是手抄物理(×0.9 三個月後又爛,修法=改接線非改數值);
2. 若延遲已進折現再乘 per-step=**雙重計價**,深鏈被罰兩次=你說的 catch-22 重演。
**檢查點**:若接線後發現深鏈沒吃到任何延遲代價=真缺的是「Y 的真實工期沒進折現」,修那條,不是加折價。

## 附帶三件
1. **撤回收**。前提消失就撤=紀律正確;「重建才能再提」同意,等乾淨數字+「修好後 me_util 恰好 0 那批還在不在」。
2. **地板②留帳同意**——價值不依賴這次病因,擋未來的下一個。
3. **tap 破壞控制流**(out.append 被推出 if→380 變 2116)=**觀測儀器改變被觀測物第 4 例**(前科:LOD→RNG/HOB/tracer 耗 randf)。tap 必須純觀測=全量暫態可觀測性的鏡像義務。入 memory 積壓清單,與弱代理通則同批寫。

payoff 接線屬 wire-in 在飛票內照做,me_util×payoff 修完的乾淨數字回來若 means-end 開始真贏/真輸,那才是磚的第一份有效行為數據。讀完改 consumed。
