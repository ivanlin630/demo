## ★★★一、缺陷本體（我開檔逐行核過）

```
畫面（`text_ui_view.gd` action_block）：key = ACTION_DIGITS[action_id]  ← **靜態綁 id**
handler（`text_ui_main.gd:1639-1643`）：
    var num: int = (keycode - KEY_1) + _interact_page * 9     ← **位置**
    var actions: Array = _interact_action_split()["team"]
    if num < actions.size(): var act: Dictionary = actions[num]
⇒ ★兩邊用的是**同一個陣列**（`_render_screen` 的 `rows` 也是 `_interact_action_split()["team"]`），
  而**一邊用 id 查表、一邊用位置索引** ⇒ 只有在「宣告順序剛好等於數字表順序」時才一致。
```

**而它們不一致。陣列順序 ＝ `TEAM_TARGET_ACTIONS` 的宣告順序**（`_build_available_actions`
逐列 append，`get_action_availability` 逐個跑 `TEAM_TARGET_ACTIONS`）：

```
位置：1 ignore｜2 attack｜3 trade｜4 propose_alliance｜5 demand_tribute
      6 extort｜7 recruit｜8 recruit_anon｜9 invite_settle｜10 gather_intel｜11 beg
數字表：trade=1 propose_alliance=2 demand_tribute=3 recruit=4 gather_intel=5
      attack=6 extort=7 recruit_anon=8 invite_settle=9（beg／ignore 未綁鍵）

⇒ 玩家按下畫面上印的那個鍵，實際執行的是：
   按 1（畫面「交易」）      ⇒ **忽略**
   按 2（畫面「提議結盟」）  ⇒ ★★★**攻擊**
   按 3（畫面「索貢」）      ⇒ 交易
   按 4（畫面「招募」）      ⇒ 提議結盟
   按 5（畫面「打聽」）      ⇒ ★**索貢**（真的動錢、動名聲、可能寫恩怨邊）
   按 6（畫面「攻擊」）      ⇒ ★**勒索**
   按 7（畫面「勒索」）      ⇒ 招募
   按 8／9                   ⇒ 剛好對（recruit_anon／invite_settle）
   而 `gather_intel`（畫面印 [5]）與 `beg`（印「未綁鍵」）在位置 10／11 ⇒ 要翻頁才碰得到
```

⇒ **最嚴重的那一條：按「提議結盟」會開打。** 這不是排版瑕疵，是**玩家做了一件他沒有選的事**。


## ★★★三、要做什麼（我裁，而它有一個乾淨的形狀）

```
①**handler 改成用 id 查表**，不要用位置：
   ·從 `TextUiView.ACTION_DIGITS` 反查（digit → action_id），
     然後在 `rows` 裡**找那個 action_id 的那一列**（找不到 ⇒ 走未綁定鍵的一句回饋）
   ·★**唯一權威是 `ACTION_DIGITS`**：畫面與 handler 都讀它 ⇒ 順序改了也不會漂
   ·★★而 `key_for()` 已經是它的公開介面 ⇒ handler 用它的**反向**（我不在意你叫它什麼，
     但**不要在 handler 裡手抄第二份對照表**）
②**翻頁（`,`／`.`）在動作清單這一層要拿掉或改語意**：
   ★靜態鍵與分頁**在概念上互斥** —— `num + _interact_page * 9` 會讓同一個鍵在第 2 頁換意思，
   而那正是不變量 #10 禁的事（只是這次換頁是玩家按的 ⇒ 不違反字面，★但它讓
   「一個鍵永遠是同一個動作」這句話不成立，而那是這張票的全部理由）。
   ⇒ ★★裁：**動作清單不分頁**（母體 11 ＞ 9 的兩個就是「未綁鍵」，照你已經做好的誠實限）；
     目標清單那一層的分頁**不動**（那裡的鍵本來就是位置語意）。
③★★★**補那一格把兩側接起來的床**（這是本票最重要的一格）：
   **對每一列，按下【畫面上印的那個鍵】⇒ 被執行的 action_id ＝ 那一列的 action_id**
   ·母體 ＝ 畫面上那幾列（逐列跑，不要只挑一個）
   ·★負對照 a：把 handler 改回位置索引 ⇒ **必紅**，而且要**指名哪一列錯成哪一個**
   ·★★負對照 b：把 `ACTION_DIGITS` 裡兩個 id 的數字**對調** ⇒ 必紅（守的是「兩側讀同一份表」）
   ·★★★母體地板：印出【這一輪畫面上有幾列、其中幾列有鍵】——
     若「有鍵的列」＝ 0，本格恆綠 ⇒ 不可判
④「未綁鍵」那兩個（`beg`／`ignore`）要**真的按不到**：
   ★現在它們在位置 10／11，翻頁之後**按得到** ⇒ 「未綁鍵」這個字現在也是謊。
   ⇒ ②做完（不分頁）就自動成立，而**床要有一格斷言它**（按任何 1–9 都不會執行到它們）。
```
