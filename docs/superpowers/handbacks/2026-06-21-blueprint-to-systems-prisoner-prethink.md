# 戰俘 WHAT（預想，非急；衝突傘到戰俘子 spec 時消費）

藍圖預想，趁系統做統一框架時備好。屬衝突傘。接已定的敗北模型（戰兵決勝負→結果落全隊；低意志潰散、被圍→被俘）。

## 已有骨架（evolve 不 greenfield）
- `prisoner_population` 欄位、`is_prisoner` 旗標、戰鬥中隊友解救(encounter:616-627)、`subjugate` 收編、`execute_prisoner` 都在。
- 現 cap = winner population(1:1)、超額自動放(encounter:1291-1301)。**戰俘 spec 把這養肥。**

## 1. 核心
被俘 = **持久持有人口**（held pool），勝方 leader 依**人格×處境裁命運** = 統一決策框架的一個 captor driver-weighed 決策（殘忍/貪婪/義氣/野心 + 缺人/奴市/仇深/養不養得起）。

## 2. 命運（瞬間 / 過程）+ 後果（全 reuse）
- **屠**（瞬，殘忍+深仇+養不起）→ 血仇傳播(G2d) + 兇名↓(聲望)
- **放**（瞬，義氣/信義）→ 聲望↑、減仇；**贖**（過程：跟對方談判收 coin 放，對方可拒談改打）→ coin、不結奴仇
- **賣**（過程：押去奴市，貪婪）→ coin + 結仇 + 兇名
- **招降**（過程：馴化，缺人+魅力）→ 人力，**初忠低、會叛/逃**(reuse loyalty)，tier 保留（收老兵=賺）

## 3. 持有 stakes（讓「持有」活）
- **成本**：戰俘吃糧 + **看守從忠誠 pop 撥**（綁住、不能打/產）→ 拖久=真成本→逼處置。
- **逃脫**（個體）：guard vs 戰俘 tier×意志；**高 tier 越會逃**（高價值但難關）。
- **暴動**（群體）：戰俘 >> 看守 → 起義奪資源/逃散/殺看守。
- **救援**（連 feud！）：抓了人家 leader → 餘部來**劫獄**（reuse G2d feud/vendetta）→ **戰俘↔血仇↔戰鬥 串起**。

## 4. cap = guard-cap（改現有 1:1 pop-cap）
- **戰俘獨立池，不佔忠誠 pop cap（統領 cap）**——俘虜不是追隨者。
- **持有上限 = 看守能力**（看守數 × 每人看 K 個，可加統領修正）。**比 1:1 嚴。**
- **超 cap → 不自動放，改逃/暴動**（= 暴動的自然觸發；關不住就溢出）。
- 小 leader/少看守 → 關不了大批 → realistic（弱隊吞不下整支敵軍，只能殺/放/賣處理不掉的）。

## 5. 粒度
- **named 戰俘 = 個別命運**（贖回/招降那個高價值 leader）。
- **anon 戰俘 = bulk**（整批賣/招/屠）。

## 6. 邊界（OUT / defer）
- **賣→奴隸此階 abstract**（換 coin、人消失）。**奴隸當持久人口（勞動/反叛/釋放）= ④Trait 縫（身份）後做**，別拉進戰俘 spec。
- **玩家被俘**（逃脫/贖/turn 子遊戲）= 玩家迴路設計，留後。
- 完整 slave 經濟（奴市定價/供需）= G1/④ 之後。

## 7. 接統一框架
命運裁決、是否養得起、看守撥多少 = 全是 captor 的 driver-weighed 決策 → **應是統一決策框架的 consumer，不是另一坨 latch**。戰俘 spec 宜在框架後或同步設計，別又造平行子系統。

## 驗收方向
- 戰俘被持有、有看守成本、超 guard-cap 會逃/暴動。
- 抓 leader 引發救援戰（feud 連動）。
- 命運依 leader 人格分歧（殘忍→屠、貪婪→賣、義氣→放/贖、缺人+魅力→招降）。
- 招降者初忠低、會叛/逃。
- 守恆（賣得 coin、屠/放 pop 正確結算）。
