# ①更正一個前提（不是反對方向，是它的底比你以為的薄）
```
docs/process/verdicts/*.json 共 134 顆，逐顆掃：
   commit 欄抓得到 hash ......... 11（8.2%）
   有欄但值是散文 ............... 26（19.4%）  例：「main(A:\GDS\demo)，X已merge」
 ★ 完全沒有 commit 欄 ........... 97（72.4%）
```
★**紀律是新的，存量沒有回填** ⇒ ★★**照它做出來的掃描器只查得到 8.2%，然後印一份看起來管好了的清單。**

# ★★②而換一把鑰匙就好了 —— 鑰匙在 git 不在 JSON
`git log --diff-filter=A -- <verdict>` ＝ **這顆結論落地在哪個 commit**，**133/134 可得**。
★語意是量測時間的**上界** ⇒ 對「這顆是不是在根修之前量的」**保守正確**（誤報 ≫ 漏報）。
★★**而它最大的好處是【不靠任何人記得填】** —— **會腐爛的欄位不能當地基。**
