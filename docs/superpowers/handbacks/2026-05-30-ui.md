### 與 spec 的差異

1. **`draw_colored_polygon` API**：plan 寫 `draw_colored_polygon(pts, PackedColorArray([color]))` 有誤（第2參數應為 `Color`，非 `PackedColorArray`）。已修正為 `draw_colored_polygon(pts, color)`。

2. **`action_timer` 機制**：plan 的 `advance_encounter_tick` 假設 EncounterSystem 會遞減 `action_timer`，但現有 EncounterSystem 是同步一次解算（無 per-unit timer）。解法：每次 `advance_tick` 後強制將玩家的 `action_timer = 0`，保證玩家每回合都能行動。

3. **欄位名稱修正**：plan 中多處欄位名有誤，已修正：
   - `TileData` → `HexTileData`，`tile.position` → `tile.tile_pos`
   - 裝備槽 `hand_1`/`hand_2` → `right_hand`/`left_hand`
   - `body_parts` 無 `hp`/`max_hp`，改用 `status` 字串
   - `p.name` → `p.person_name`
   - 單位位置 `tile_pos` → `pos`（encounter_system.gd 實際欄位名）
   - `PlayerSystem` 有 `class_name`，直接 `PlayerSystem.new()` 即可

4. **`_unequip_slot` → `unequip_item`**：plan 呼叫不存在的方法，已改為 `PlayerSystem.new().unequip_item(state, slot)`。

5. **`encounter_ended` signal**：plan 未定義此 signal，但為讓 main.gd 在遭遇結束後重新顯示地圖，在 `encounter_view.gd` 新增此 signal。

6. **殭屍測試（headless_test.gd:928）**：person 1 有時死亡導致 `state.persons.get(1)` 返回 Nil，觸發非致命 SCRIPT ERROR。這是**預存在的不穩定測試問題**，與本次 UI 實作無關。測試仍能跑到 `=== DONE ===`。

## 連動風險

- **EncounterSystem**：`action_timer`/`_max_timer` 新增到單位 dict，若 EncounterSystem 未來實作 per-unit timer 系統，可能需要更新 SimBridge 的 `advance_encounter_tick` 邏輯（目前用 workaround：每 tick 強制重置玩家 timer）。
- **PlayerSystem**：`init_player` 目前在 main.gd 以 `person_id=0, team_id=0` 硬寫。若日後需要讓玩家選角色，需更新此段。
- **WorldGenerator**：main.gd 使用 `generate(state, {radius:4, seed:42})`，與 headless_test 一致。若 WorldGenerator API 有改動，main.gd 需跟進。
- **`interaction_system.gd`**：新增的 hostile team 標記使用已存在的 `player_tid` 變數（修正了 plan 中的重複查詢），若周邊邏輯有大幅重構需確認 `player_tid` 仍在 scope。
