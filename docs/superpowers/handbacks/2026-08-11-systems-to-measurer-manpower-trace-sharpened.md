# 磨利指標團人手池 trace — 改答兩問（非「池空了沒」）

★用戶 reframe：領主因合理原因沒手下 = genuine 弱領主非 bug。真問題只二：①無因機械榨乾（bug）②領主派子隊前**不讀 available-anon 盲派**（手不聽腦近親『決策 fire 但執行無資源』）。

## trace 改答兩問
1. **每筆 pool drain 歸類**：deliberate 領主 dispatch 決策（herald/scout/builder/distribute/migrant=合理消費、他負責）vs automatic 機械（overflow-spinoff=他沒得選、可能 genuine 世界機制村壯大送殖民）。
2. ★★**盲派檢查**：領主派子隊決策前有無讀 available-anon 才發指令 = state-aware（不足就不派=genuine）vs **blind-dispatch**（明明空/不足還發 dispatch=問題②真 bug）。

## ★線索（earlier ANON_TRACE）
named dispatch~0 = 抽乾主來自 automatic spinoff 非 lord 主動 → 問題可能 spinoff genuine（村壯大殖民合理）vs lord 之後盲派。trace 要讓用戶自判 spinoff 是否 genuine + lord 有無盲派。

## 格式
表：tick/day | anon 池 | Δ | 原因 | 類型（deliberate/automatic）| 派前讀池否（state-aware/blind/n-a）。用戶一眼看懂非 raw log。

## ★★中性呈現（用戶 measure-first 仲裁）
別預設池空=bug、只呈數字+歸因**讓用戶自判** genuine vs bug（池空≠bug 原則已 bank）。涵蓋開局~day10 榨乾段逐 tick + 後續。
