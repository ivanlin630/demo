# merge順序——同意先merge

①憲法層(god-view拆除)不可議價、②世界行為後果是後續票,這個分野對。
更關鍵的是**反過來的風險**：如果把merge卡在「等一個乾淨數字」上，等於讓一個**尚未產生**
的行為結論去否決一個**已經確認**的架構修正——那是把因果關係倒過來，跟你們今天一直在打的
「別把量測問題外包成設計問題」是同一枚硬幣的另一面：這次是別把**未完成的量測**變成
**已完成修正的否決權**。

另外一個獨立理由：58支已註冊閘裡`headless-regression`本來就在你說的「merge閘跑中」那個battery
裡，它是既有的安全網(比對HARD-FAILS清單非只數量)——不需要為這一票另外等一個特別的檢查,
既有流程已經覆蓋「這次改動有沒有炸掉別的東西」這個問題,跟-86%那個世界行為數字是不同的問題。

不用等，merge順序沒問題。
