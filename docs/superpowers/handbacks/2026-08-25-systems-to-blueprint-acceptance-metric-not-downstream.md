# 訂正一條 **你指定、我照抄** 的 acceptance

你裁 A 型時指定：**「落完立刻重量看 `236` 掉多少」**。★**我直接寫進票，沒有先問一句。**

## ★★implementer 指出它**不在 A 的因果下游**
> **`dispatch_fail.資源不足` 量的是【建造成本閘】；A 改的是【資源取得手段】。**
> ★**沒有任何機制讓「food 解封」去減它。**

★★★**決定性證據**：**`delegate.build_ok` 在 before 與 after 【都是 0】**
—— ★**這張床上從來沒有一次建造委派成功過。**
⇒ ★**那 23 的漲跌與 A 無因果關係**（**而我先前還追問他「為什麼只降 23 不是 120」——
 那個追問本身也建立在錯誤的因果假設上**）。

## ⇒ 我已撤下該條，並補上**真正在下游**的那條
| | |
|---|---|
| ⚠️**撤下** | `dispatch_fail.資源不足` 的變化量 |
| ★**補上** | ★**`build` 候選的【時間分佈】從 `day000-only` → 全 90 天** —— **在下游，且是行為層證據** |

★**A 的真正戰果是【質變】**：**手工表拿掉，「一次性凍結」就消失了。**
**那條比任何百分比都有力，而且它【真的在 A 的下游】。**

## ★立成通則（`05_acceptance`）
> ★**acceptance 指標必須在【本票改動的因果下游】** ——
> **要能說出「我改 X ⇒ 經過 Y ⇒ 影響 Z」；說不出來的，不該當本票的 acceptance。**

★**危害是雙向的**：**它會讓一張做對的票看起來沒效，也會讓一張沒效的票看起來有效** ——
**因為那個數字本來就跟它無關。**
★**而這條錯不會被閘擋住**：`seam-gate` 只驗產物在不在，
**「這個指標關你什麼事」是判斷題，只有寫票的人能把關 —— 這次我沒把關。**

## ★★★而 `delegate.build_ok = 0` 本身是個更大的發現
**這張床上【從來沒有一次建造委派成功過】。**
⇒ ★**它在建材閘的下游 ⇒ 屬 B 型／means-end 磚的範圍**，
**我已記進 B 磚的票當【基準事實】：在磚落地前，這個數字就是 0。**
