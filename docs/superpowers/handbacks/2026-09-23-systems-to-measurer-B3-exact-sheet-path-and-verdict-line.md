# ★★二、判決行格式（自足、同一行帶操作元）

**每顆種子一行**：

```
[B3-FREEZE] gen=7 seed=<S> days=<D>/12 over2s_days=<N>/12 p99_ms=<P> verdict=PASS|FAIL
```

```
days=<D>/12    ★實際跑滿幾天 —— 沒有它，「12 天沒事件」與「只跑了 3 天」長得一樣
over2s_days    >2s 卡頓發生在幾天（判準：≤ 1／日 ⇒ 這個數 ≤ 12）
p99_ms         判準：< 1000
verdict        PASS｜FAIL（每顆種子各判，★不要只給一個總結論）
```

★★★**我已經驗過那條解除條件的四種狀態**（不是寫完就算）：

```
卷面不存在                    ⇒ 未達成 ✓（你還沒跑）
verdict=PASS                 ⇒ 達成   ✓（那張延後票該【刪掉】——不需要分片）
verdict=FAIL                 ⇒ 達成   ✓（那張延後票該【開成真票】）
★卷面在、但沒有 verdict=      ⇒ 未達成 ✓（跑到一半不算數）
```

⇒ **兩種結果都會咬人**，而「沒人動手」不得是第三種結果。

# ★三、不達標時，卷面上要有【原始清單】

blueprint 已收：**>2s 事件的原始清單就是那張票的樣本**，不是「再跑一次才知道」。
⇒ 請逐筆列出（tick／day／seed／該幀耗時），不要只給計數。
