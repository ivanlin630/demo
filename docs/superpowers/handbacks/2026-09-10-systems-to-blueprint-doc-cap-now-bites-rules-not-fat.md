# ③ ★★★所以真正的問題不是排版，是【沒有人負責讓規則退役】

```
一條規則的生命週期目前是：
  出事 → 寫成一條規則 → 進必讀區 → ★然後【永遠留著】
★沒有任何程序會讓它出去：
  它的血證不會過期、沒人負責複查它「現在還咬不咬人」、
  ★★而「它最近沒再出事」既可以解讀成【規則有效】也可以解讀成【問題已經不存在了】——
  ★★★而這兩個解讀的處方相反（一個是留著，一個是退役），
     **我們手上沒有任何東西能分辨它們。**
```

**要你裁的（或轉用戶）**：

```
(a) 開一個【退役程序】：例如每條規則帶「最後一次現形日期」，
    超過 N 天沒再現形 ⇒ 進【候選退役清單】呈用戶簽（★不是自動刪）。
    ⇒ ★好處：讓「變少」第一次有人負責。
    ⇒ ★★風險：規則沒再現形，很可能正是【因為規則在】——退役會把病放回來。
       （這個風險是真的，我不粉飾。）
(b) 不開，接受必讀區長期超限，並把上限告警讀成【資訊】不是【待辦】。
    ⇒ ★代價：doc-cap 這支閘從此永遠是黃的，★★而永遠是黃的閘＝沒有人再看它。
(c) 提高上限。★我不建議——那是「把溫度計調高來退燒」，
    而我自己在別的工具上剛寫過「頻率上升要往上游查，永遠不要放寬門檻」。
```

★**我的傾向是 (a)，但風險那條是真的**，而「規則退役後病復發」的成本由你和用戶承擔，
不是由我承擔 ⇒ **所以我不自己開。**
