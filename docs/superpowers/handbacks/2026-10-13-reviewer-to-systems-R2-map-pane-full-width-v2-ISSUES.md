# 1 逐點
## ① :size 的鎖步（協定,會卡死客戶端）
```
play.py 的主迴圈是『sendall(一行) → read_frame(讀到框尾)』的鎖步（:309-310）;server 每收一行必須回一個 frame。
PlayerRepl._feed（player_repl.gd:215-228）:`:quit` 之外,keycode_for(token)==-1 ⇒ print『✗ 打不出這個鍵』並 return,【不送 frame】。
⇒ `:size 120 30` 若沿用這條入口:認不得 ⇒ 不回 frame ⇒ 客戶端 read_frame 卡到 socket 逾時(120s,:276)。
要求:_feed 在 keycode_for 之前辨識 `:size`,更新 view 狀態,並【重畫後 _send_screen】（版面可能因此改變,客戶端也需要新 frame）。
開場:第一屏在客戶端送任何東西之前就送出（:279）,它是用預設版面畫的;客戶端隨後送 :size 得到第二屏——開場會閃一次,可接受,但床要涵蓋『收第二屏後的版面』。
客戶端偵測視窗變動:單鍵模式阻塞在 msvcrt.getwch,收不到 resize 事件;做法=每次送鍵之前呼叫 shutil.get_terminal_size(),與上次不同才先送 :size（並讀回一屏丟掉）,再送鍵。寫進 spec,免得實作端去做 SIGWINCH（Windows 沒有）。
```
## ② ★依內容列數選版面會來回翻
```
spec:『需要的總列數(上下排) ≤ 回報列數 ⇒ 上下排;否則並排』。『需要的總列數』若是對【當下這一屏】的實際行數:
  分頁內容列數、事件區行數、動作區折疊都隨鍵變動 ⇒ 當前屏高在閾值附近時,一個鍵就把版面在『上下排(整寬地圖)』與『並排(視窗地圖)』之間來回翻,
  整張地圖在左右半屏跳來跳去,正是『畫面節奏均勻』要避免的事。
要求二選一:
  (a) 依【與內容無關的上界】選:上下排的最大列數 = top+first3+cursor+地圖框(2R+3)+分頁框(各頁最大列數+2)+動作+事件(上限)+腳,各段取其封頂值（feed_block 與 action_block 本來就有上限/折疊,請 spec 寫出數字來源）;
  (b) 或加遲滯:只在 rows 變動(:size)時重選,內容變動不重選。
  我建議 (b)+(a) 的上界當門檻——選擇只由 :size 觸發,內容不碰它。M6 加格:同一個 :size 下連續 50 個不同鍵,版面種類不變。
```
## ③ 警語位置與 cols
```
『畫面最上一列印「視窗高度不足(需 N 列,現 M 列)」(play.py 側印)』:屏高不夠時,終端把畫面【最上面】的列先捲出——警語放最上就是第一個看不見的東西,且多加一列讓問題更糟。
  ⇒ 放在【畫面最後一列之後】（游標落點附近,視窗永遠看得到底部）;N 由客戶端自己數收到的 frame 行數,不需 server 回報。
cols:`:size` 帶了 cols,spec 只用 rows。COLS=120 寫死;終端欄數 <120（例 VS Code 分割面板常見）時每列折行,框線整個錯位且列數翻倍。
  ⇒ 客戶端同樣警『需 120 欄、現 M 欄』;server 端 ≥120 才選上下排的 12R+4 門檻(欄數是另一個輸入,別只看列)。
```
## ④ 沒收到 :size 的預設
```
spec:『沒收到 :size(管道、床)⇒ 上下排』。production 的客戶端只有 play.py（會送),但任何不送的客戶端(舊版 play.py、nc/telnet、腳本)會拿到 46~53 列的版面,
比今天(34 列)更高,是對未知客戶端的退步。
建議:預設=不退步的版面(並排+視窗,約今日列數);床要上下排時【明示送 :size 120 60】。這樣『這支床測的是哪種版面』寫在床裡,不靠預設值暗中決定;
M1/M2（上下排）因此要在床裡明送 :size,否則會誤測並排。
```
## ⑤ 錨集合是版面的函式
```
『REGION_ANCHORS 六錨字面改(並排維持舊的)』:兩種版面兩組錨,現行 REGION_ANCHORS 是單一常數、三支床逐個迭代它。
  ⇒ 改成 `region_anchors(layout)`（或 STACKED_/SIDE_ 兩個常數）,compose 回傳或 view 暴露『本屏用哪個版面』,床迭代時帶 layout 參數;
     『六個錨各剛好一次』對兩種版面各驗一次（床里各 :size 一次）。否則床要嘛只測一種,要嘛兩組錨混在一個常數裡而斷言恆假。
```
## ⑥ 視窗重置
```
死區讓視窗有狀態(視窗原點)。游標瞬移(M 令下達後游標被設到目標/玩家位置、換隊、重置 _cursor = 玩家位置,text_ui_main.gd:190)時,視窗必須重置到以游標為中心,

```
