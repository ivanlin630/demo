# ★★★①整條鏈追到底：**它沒有壞，它是餓的**

```
候選生得出（day0 39）→ argmax 贏得了 → 路由對了 → infra path 每輪 24 次都被呼叫
→ 選得出要建什麼（pick_empty 很小）→ ★最後卡在「真的沒有材料」
```
**最後那道牆的九條拒絕理由，八條從來沒響過**：
```
reject_cannot_afford  180 / 196（91.8%）      accepted 16
其餘八條（level0／not_owner／busy／no_def／type／terrain／max_level／no_slot）＝ 全 0
```

★**而它是【物理】不是【判斷】**：`_can_afford` ＝ `avail < cost`，**1.0×，無緩衝、無門檻常數、無 utility 參與**

⇒ ★★★**七顆儀器下來，沒有找到任何 latch／補丁閘／藏起來的判斷。每一格都是「上游沒產出」或「物理不足」。**

★**這本身是一個結論，而且是好消息**：**這條鏈是通的，它只是沒有東西可吃。**

# ★★②而它推翻我自己給你的建議 —— **我要明確作廢**

**我當初建議 A／B 停站，理由是**：
> **「世界堆滿材料，day 1 起也沒有人會提出要蓋 ⇒ A／B 是給一個不會再開口的人多送食物。」**

★**那句話【一半是錯的】，而錯的原因是我把兩條路當成一件事**：
| 路 | 實際 |
|---|---|
| **founding**（新建 outpost） | ★**確實 day 1 起不再提出** —— **那半句成立** |
| ★★**facility**（自家 outpost 上蓋設施） | ★★★**每一輪都在提出**（infra path 30 天 336 次）**，而且被「真的沒材料」擋掉 180 次** |

⇒ ★**A（拉高初始庫存）與 B（伐木場加速）對 facility 這條路【是對症的】** ——
**它一直在開口，只是沒東西可吃。**
★★**我當初的判斷建立在「沒有人在開口」上，而那是把 founding 的沉默套到 facility 頭上。**

## ⇒ 要你重裁的（**我不自己改 WHAT**）
| 選項 | |
|---|---|
| ★**(a)** | **A／B 解凍**，驗收改掛在 **facility 路**（`built_in_place` 目前 30 天只有 8、`reject_cannot_afford` 180 ⇒ **兩個都是現成的因果下游判準，而且母體非空**） |

★★★**而 founding 那條「day 1 起不再提出」仍然沒有答案** —— **它是獨立的一條線，不該再跟 facility 綁在一起講**（我已經綁錯一次）。
