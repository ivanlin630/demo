# ① 為什麼先數次數，而不是照慣例再切一層

```
★80.77s 這個數字目前是一個【總量】—— 而總量有兩個完全不同的成因，處置相反：
   (a) **呼叫太多次**（每次很便宜）⇒ 修法在【誰在叫它、多久叫一次】
   (b) **每次太貴**（次數合理）⇒ 修法在【它裡面】⇒ 那時才輪到再切一層
⇒ ★★而分辨它們**不需要切相位**：在同一個計時點旁邊 `Probe.bump` 一顆計數即可
  ⇒ **us／call ＝ 80.77s ÷ 次數**，一個除法就分出來。
⇒ ★★★這比再切一層便宜一個數量級，而且它**先回答形狀**：
  ★若是 (a)，再切一層的那份工**完全是白做的** —— 因為錢不在裡面。
```

# ② 做什麼

```
①`unified.rank.from_leader` 的計時點旁邊加一顆 **呼叫計數**（★同一個 `Probe.enabled` 包裹、零 RNG）
  ⇒ 其餘三個 `from_*` **一併加**（★★否則你只會知道 leader 的形狀，
    而「leader 特別貴」與「rank 本來就貴、只是 leader 叫得多」分不出來）。
②交件報四欄：**次數／總計 us／us per call／單次 max**
③★而順手報一個【每隊每次】的分母：那一窗有幾支隊走 leader 這條路
  ⇒ ★★因為「叫很多次」還要再分成【隊很多】與【每隊叫很多次】——
    ★★★而後者才是【誰在叫它】那條線索（cadence／重評／事件喚醒）。
```

# ③ 驗收

```
①★母體地板：次數 **> 0**（★★若某個 `from_*` 是 0 次，**明寫它是 0** ——
  ★★★一個沒有出現的呼叫端與一個沒被登記的呼叫端在表上長得一樣，而 §① 那顆
  `from_unknown ⇒ 未登記具名紅` 只擋新增的，擋不住「本來就沒跑到」）
②us／call 要與 §②的總計對得上（★純除法，但要印出來讓人能自己驗）
③fp 不變（純觀測）＋零 RNG
```
