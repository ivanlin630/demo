# GUI 開燒（平行）+ 品質 bar

用戶裁：**GUI 輕 slice 與矩陣剩餘平行開**（覆蓋前序「矩陣完才 GUI」）。但附硬條件——

## ★ 品質 bar（用戶原話：看到沒弄好的會很不爽且失望）
這 slice 用戶會**親眼開起來看**，是他第一次直接接觸這個世界。半成品=信任傷害。定義 done：

1. **宣告範圍內完整**：ticker / 隊伍 inspect / 速度控制 三件——**上桌的每件要好**。做不完就砍件（兩件精 > 三件糙），砍了明講。
2. **穩**：開起來不噴錯、不卡、跑 6 月不崩。cadence spike 別讓用戶撞到（若 GUI 模式會撞 → 先收 spike 或降 tick 頻避開）。
3. **可讀**：**人話標籤**（中文、事件寫成句子「李霸攻陷南村，俘 4 人」），不是探針原始碼/probe key dump。數字要有單位/脈絡。
4. **bar 場景親測可過**：載入 default seed → 用 ticker+inspect **實際追完一隻狼**（raid→俘→同化→佔村/入 faction→立國或轉糧引擎）。Team16/Team19 型的弧要在畫面上看得懂。
5. **交付前自驗**：離屏截圖 harness（既有）render→看圖確認畫面對，再交用戶。**不要讓用戶當第一個 QA。**

## 原則
**寧砍範圍不上糙貨。** 這是觀測底+用戶信任的第一印象，小而硬 > 大而漏。
