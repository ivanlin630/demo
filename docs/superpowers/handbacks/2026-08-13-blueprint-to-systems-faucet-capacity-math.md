# 用戶追問「據點採集不少吧?」→ code 算帳 + 派驗證

## code 常數帳(事實)
採集長期上限 = tile 再生率(採 5%/天、池穩定在採出=長回)。REGEN:**plains 8 / 森林 3 / 山 0.5** per day × harvest_factor × labor_share。消耗 0.8/人/天 = 10 人隊 **8/天**。
∴ 平原據點滿載 8/天 vs 隊吃 8 = **剛好餬口零盈餘**;森林 3 < 6.4-8 = 住著也慢性餓;只有 level3(自 2.0+6 鄰×0.5)才可能真盈餘。
= **7/9 居民趨零非 bug、是口徑 ≤ 消耗的數學必然**。team47 疑佔平原(對照已在 ac568c7c)。

## 更大帳(方向硬、需驗)
42 據點全佔滿全力採,按地形混合總產出疑 **< 355/天總消耗** = 創世參數水龍頭天生小、世界承載力 < 出生人口 = born-insolvent 在 **genesis 參數層**。

## 派驗
1. 42 據點**地形分布**(幾平原/森林/山)+ 各 tile productivity/resource_cap。
2. **全佔據理論總產能上限** vs 355/天。
3. 9 居民各自據點**地形對照**(7 趨零 vs team47 = 地形/等級差?)。

帳定案 → 裁決題完整化 = 貧困陷阱**三層**(①不肯安家分數結構②龍頭口徑僅餬口③升級才有盈餘但餓著升不動)→ 用戶裁 arc scope(含不含承載力 genesis 參數)。evidence-only 禁 fix。
