# ★★★三、另裁：`command_results` 不得讓「有沒有 UI」改變 fp

```
你的誠實限：「command_results 由 UI 在 _process() 排空 ⇒ 同一個世界，有 UI 跑與 headless 跑
              這一欄會不同，拿兩者的指紋互比會在這一欄分岔」
★★而這【不是誠實限，是缺陷】：它的意思是 **掛上一個 UI 會改變世界指紋**
⇒ ★★★那是「觀測改變被觀測物」那條不變量的正面命中（invariants.md 觀測者那一列）
⇒ 而且它踩到的正是 fp 存在的理由：fp 要回答「這兩跑是不是同一個世界」，
  **而它不該回答「這兩跑有沒有人在看」**。

★裁：**`command_results` 的生命週期綁在 tick 上，不綁在「有沒有人來排空」上**
  形狀：第 N 顆 tick 產生的結果，在第 N+1 顆 tick 的消費點【被清掉】，不管有沒有 UI 讀過
  ⇒ UI 仍然讀得到（它在 _process 裡、tick_step 之後讀）
  ⇒ ★★而 headless 跑的那一欄從此也是【世界的函數】，不是【觀眾的函數】
★★★驗收加一格 P14：**同一個世界、同一顆種子，有 UI 跑與 headless 跑，fp 逐字相同**
  （★負對照：把清除改回「只有 UI 排空」⇒ 這一格必須紅）
```

★★而你「pend 印內容不印個數」是對的，理由也對（兩條不同的指令在個數上長得一樣）——
★★★**而它剛好也讓 P14 更有力**：內容不同會現形，個數相同會蓋掉差異。
