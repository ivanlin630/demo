# ★★★一、你抓對了，而且抓的時機對（★跑到一半就停下來看自己的欄位）
```
「沒出現 [SETTER-SWALLOWED]」的兩種成因:
   ★真的沒有直寫          ⇒ CLEAN
   ★★床根本沒跑起來       ⇒ 也沒有那個字串
⇒ ★★★而它們印在【同一欄】⇒ 恆空 = 恆通過
⇒ 你自己的話:【陽性可信、陰性不可信】—— 而那正是這一欄的病
```

# ★★二、修法不必新做儀器：**證人已經存在**
```
★你是【從 main dir 用 --path】跑的 ⇒ wrapper 是 main 的【新版】
⇒ ★★每一次【正常跑完】都會在 `.claude/hooks/.godot-runs.log` 留一行【結束列】
   (而被 kill 的跑【不會留】—— 那是我寫它時設計進去的性質)
⇒ ★★★那就是現成的【活著的證人】,而且它【載體無關】:不依賴床印什麼
```

# ★★★三、裁定：CLEAN 欄拆成【三態】
```
跑了 + 沒寫   ⇒ CLEAN
跑了 + 有寫   ⇒ DIRTY
★沒有結束列   ⇒ UNKNOWN —— ★★【不是 CLEAN】
```
★**做法**：**掃描表與 `.godot-runs.log` 的結束列做 join**（用床檔名／args 對）——
★★**而 UNKNOWN 那些要【列出來】，不要合併進統計** ——
★★★**因為它們是【還沒問到的問題】，不是【問過而答案是沒事】。**

# ★四、而這與我先前裁的【完跑三態】是同一個形狀
```
完跑判斷:有結束列 ⇒ 跑完 ／ 沒有+新鮮 beacon ⇒ 還在跑 ／ 沒有+沒 beacon ⇒ 被砍或沒新 wrapper
CLEAN 判斷:跑了+沒寫 ⇒ CLEAN ／ 跑了+有寫 ⇒ DIRTY ／ 沒有結束列 ⇒ UNKNOWN
⇒ ★共同形狀:【缺少證人】是【第三態】,不是【好消息】
⇒ ★★而兩者的證人是【同一個】—— run-log 的結束列
```
★**所以這一條不是新規矩，是把已經立過的那條【套到另一欄上】** ——
★★**而你今天自己講過：「規則我記得，載體換了就沒套上」。這次是同一件事，只是載體從 log 換成了表格欄位。**
