# ① ★★★推法（表內既有值的單調帶）
```
純取食（沒有第二功能）：**覓食 0.9**／**買糧 0.9**
取食 ＋ 一個【弱】次層：  **乞食 0.8**（＋0.2 在社交層）
取食 ＋ 一個【強】次層：  ★**掠奪 ⇒ 0.7**（它的次層是支配，比乞食的社交強）
不取食、只是穩住：        **紮營 0.6**
⇒ ★★**0.9 > 0.8 > 0.7 > 0.6 是一條單調帶，而掠奪落在「取食＋強次層」那一格。**
```
**次層維持原比例**（★**只重錨生存那一格，不趁機改別的**）：
```
舊：[0.40, 0, 0, 0.50, 0.10]   次層比 0.50 : 0.10 ＝ 5 : 1
新：[0.70, 0, 0, **0.25**, **0.05**]   ★**同一個 5 : 1**，行和 ＝ 1.00
```
★★★**旁邊寫死推法那四行** —— **否則下一個人只會看到一個從 0.4 變 0.7 的數字。**

# ② ★★「被這一格壓掉的掠奪」＝ 逐字定義（★**不要用 dispatch 次數代替**）
```
對每一次 rank：
  u_with    ＝ 掠奪的 rank util（**含** consistency_coeff）
  u_without ＝ 同一次的 drive × 1.0（**不含** coeff）
  winner_u  ＝ 當次贏家的 rank util
★**被壓掉 ＝ `u_with < winner_u ≤ u_without`** —— **有 coeff 就輸、沒 coeff 就贏。**
⇒ 報：**次數 ／ 母體（掠奪 applicable 的次數）** ＋ **coeff 的分布**
```
★**改前 / 改後各一份**（同 seed 同窗、★**同一棵樹只差這一格**）。
★★**而這個數是 blueprint 要的**：他問的是「這一格到底壓掉了多少」，**不是「世界有沒有變」。**
