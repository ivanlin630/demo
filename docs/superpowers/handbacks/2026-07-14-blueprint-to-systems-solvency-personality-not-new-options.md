# 修正診斷 + 用戶定修法原則（取代前信「加備糧option」講法）

補/修正 `2026-07-14-blueprint-to-systems-add-strategic-food-reserve.md`。深挖後前信「食物完全無戰略備糧、需加備糧option」的理解**不夠準**，真根是償付能力，且用戶定調**不要加新行為**。

## 修正後的真實圖像（file:line 已坐實）
1. **買糧不卡3天**：一旦 `<DESPERATION_DAYS(3)` 觸發，到市集會買到約 pop×10(≈12食物日) 或 coin 耗盡為止（`interaction_system.gd:_attempt_trade_direction`），food 載重僅0.1、carry 幾乎不綁 → **真天花板是錢，不是天數**。有錢隊一趟就超買越過7天、自動解鎖囤貨戰略層。3-7「死區」對有錢隊不存在。
2. **囤貨其實會順便低買囤糧**（前信說「只倒糧」不準）：商隊路過糧賤村、估價划算時會買糧進 merchant_inventory（`interaction_system.gd:804-808` 對 food 生效）。戰略備糧管道**存在**，只是 gated 在「已有餘糧/有貨可換」後，對缺糧隊空頭。
3. **★真兇=償付能力閘 + 武器不認變現**：`has_specie`(`decision_context.gd:211-214`) 只認 coin/goods/material/ore，**不認 weapon**。一支**武器一堆但無現金無礦**的軍備隊(Team14型)，糧跌破3想買糧時 → **武器不算「付得起」→ 買糧 option 根本不 applicable** → 直接掉乞食/掠奪 → 失敗餓死。
   - Team14 完整死亡故事：esteem門檻薄→脫離絕境就把資源換成武器→現金/礦耗盡滿手武器→糧跌回<3→想買糧但武器不算資產→買糧不出現→乞食/掠奪失敗→餓死。**牠明明有可交易的財富(武器)，卻因「錢包空」的機械判定餓死。**

## ★用戶定修法原則（關鍵約束）
> 「不要再多行動了，用個性與資源判斷買不買」

即：**不加新 option、不加新行為**（不要新「備糧」option、不要新填死區的動作）。改成讓**既有的買糧「買不買、買多少、留多少安全存量」這個判斷，從領袖個性 + 真實資源評估自然長出來**。具體兩軸：

1. **資源評估要誠實（償付能力軸）**：`has_specie`/可交易財富的認定，要納入**所有可變現資產（含 weapon/armor/軍備）**——一支武力強盛的隊該能拿武器 barter/變現換糧，不該因 coin=0 就被判定「買不起」而餓死。這是**修正機械誤判**（診斷通則：死判定 pre-empt 真實資源狀態＝變相補丁），非加行為。
2. **買不買由個性秤（人格化軸，跟前信門檻人格化收斂成同一件事）**：買糧的驅力/目標安全存量水位接領袖 trait——謹慎領袖糧價合適就主動補到高水位、留厚安全存量；賭徒容忍薄庫存去搏發展。這**不是新 option**，是讓現有買糧的 weight 曲線 + 目標水位變成 f(人格) 而非死常數。效果：糧食決策自然浮現個性，Team14 餓死變「賭徒領袖的性格缺陷致死」有故事性。

**一句話原則：資源判斷要認全部家當（含武器）、買不買交個性秤——都在既有買糧 option 內長出來，不新增行為。**
