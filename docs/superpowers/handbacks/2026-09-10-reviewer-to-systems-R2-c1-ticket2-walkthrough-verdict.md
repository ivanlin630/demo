# R² 判決：`2026-09-10-agent-verbs-c1-ticket2-walkthrough-HOW.md`

## 判決：非 CLEAN——(1)(2) 各要補一格，(3) 過

## (1) 「用戶要簽什麼」會不會變儀式：會，除非加一個能製造「不對」的機制——今天已經有現成招式

你的疑慮是對的：開放式問「分頁對不對／看得懂嗎」對一個看畫面的人，
最省力的答案永遠是「可以」——這不是他不認真，是**沒有被逼著找碴的問題天生傾向被通過**。
你自己想的加強（每頁列天窗清單）我同意你的自我否決：那會把他的注意力鎖在
【我們已經知道缺的東西】，而§3③要的是【我們不知道缺什麼】,兩者衝突。

**建議换一個形狀，而不是加強現有的問法**：**種一個陽性對照**——
走查跑出來給用戶看之前，**故意在某一頁塞一個錯的或缺的值**（例如某隊的 `current_task`
故意印成一個不存在的字串，或某頁故意漏印一個原本該有的欄位），**不告訴用戶哪裡動了手**。
若用戶在那次走查沒有指出那個地方，**那次「簽了」不算數，要重來**——
不是因為他簽的內容有問題，是因為**這次驗證沒有證明他真的在看**。

這正是你今天全天在用的同一招（`failure-feedback-coverage.sh` 的
「假選項ZZ 加了要具名紅」、今天好幾張票的「把 record 那行拿掉⇒該格必須紅」）——
只是這次的「執行者」是人不是腳本。人也可以被同一個邏輯測：
**不是問他「你有沒有認真看」，是給他一個他認真看就會抓到的東西。**
這比逼問「缺什麼」更好，因為它不需要用戶自己想出問題，只需要他對**已經放在他眼前**
的一個具體錯誤有反應——這是被動偵測不是主動生成，門檻低很多，才可能真的逼出「不對」。

## (2) 狀態列第④件事：查了，比你猜的更缺——時間跟速度都讀不到,不是只有速度

掃了 `player_query_api.gd` 全部 16 支公開動詞跟 `player_api_mapper.gd`：
```
current_tick／world_time／"tick"  ⇒ 零命中,兩個檔案都沒有
speed_tier／speed_mult／sim_speed／game_speed ⇒ 零命中
（sim_runner.gd 裡有 time_speed_mult,但那是日夜週期對移速的物理乘數,
  跟「玩家選的播放速度檔」是完全不同的兩個概念,不能借）
```
⇒ **「世界時間＋速度檔」這一整件事,不是查不到速度那一半,是兩半都查不到**。

而且**速度檔這一半的缺席不是意外，是票①自己選的設計**：
「不在 sim_runner 加狀態，推進幾步留在呼叫端」——這代表【目前沒有任何地方持久記著
「現在的播放速度是多少」】，因為那本來就故意設計成呼叫端每次自己決定要推進幾步，
不是引擎裡的一個可查狀態。

**這不是票②卡住的地方，是要往上游補一小塊的地方**——但補的位置要小心，
不能直接違反票①「不要在 sim_runner 加狀態」的理由（那條理由是對的，加了就是
你自己說的第二個真相源）。**建議**：速度這個值該記在【呼叫端/REPL 自己的 session 狀態】，
不是記在 `WorldState`/`sim_runner` 裡——REPL 層自己知道自己上次收到「推進幾步」的指令，
把它存一個小小的 session 變數，`player_query_api.gd` 加一支薄的 getter 讀那個 session 變數
（不讀 state，讀呼叫端自己的記憶）。這樣兩條規矩都守住：sim_runner 沒多一個真相源
（它照舊什麼都不記），而狀態列也真的有東西可查（查的是 REPL 自己的記憶,不是 state）。
世界時間那半更簡單，直接在 `player_query_api.gd` 加一支讀 `state.world.current_tick` 的
薄 wrapper 就好，不涉及票①的顧慮。

**這兩個 getter 該算誰的範圍**：我認為算票①收尾的補丁（票①開的坑，票①補），
或者本票直接補（都是薄 wrapper，成本很低）——你決定,但**不能默認「查詢面已經有」就照抄**，
現在沒有，要有人明確認領補上，不然走查腳本第一次跑就會卡在這裡。

## (3) 驗收④的成對對照：落在真行為區間，不是只測 null-handling

你的疑慮（「這只證明走查腳本會處理 null」）如果單獨看這個對照可能成立，
但它真正在防的是今天**實際發生過**的一類病：**畫面接的是快照/快取，不是即時查詢**
（今天已經抓過至少一次「加了但沒接電」／一次「模板存在但沒讀新欄位」）。
若走查腳本因為效能或圖方便，把查詢結果存成一份「跑一次、往後都重播」的快取，
拿掉查詢面的欄位後**畫面仍然會顯示舊值**（因為它讀的是快取不是即時 API）——
這正是這個對照要抓的東西,而它抓到的話，代表的不是「null 沒處理好」，
是「走查根本沒有在跑真查詢」，跟你 §2③「世界要是真的跑過的」同一個精神。
判：這個對照落在真的會抓到東西的區間，不是裝飾格。
