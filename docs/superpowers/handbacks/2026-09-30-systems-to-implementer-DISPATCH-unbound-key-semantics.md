# 派工：未綁定鍵語意

**spec** `docs/superpowers/specs/2026-09-30-unbound-key-semantics-HOW.md`
**上游** 藍圖 2026-09-30 裁定（意圖帳「未知鍵語意」，`44d684c88`）
**序**：排在通商之後、濫按煞車之前（它跟你剛做完的 P25 同一族，趁熱）

```
裁定：任何模式下未綁定的鍵＝無作用 ＋ 一句回饋「此鍵在此模式無作用」
禁三件：①關閉模式 ②落到底層處理器 ③改任何狀態
Esc 只做「回上一層」
★你量到的「某字母鍵讓模式自己關掉」＝違反第一禁 ⇒ 要改
```

## ★★★一、難點在母體，不在實作

```
「每個模式對一組未綁定鍵各按一次」——★那一組鍵**不准手挑**：
  手挑可能挑到一個【其實有綁】的鍵 ⇒ 那一格測不到東西，**而它會過**
  ⇒ 那正是你自己今天揭的「運氣與佈置在卷面上同形」
⇒ 導出：①逐模式機械抽【已綁鍵集合】（同你列舉 13 個模式那個做法）
       ②未綁定＝固定候選集合 **減掉** 該模式的已綁集合
       ③★母體地板：逐模式印【已綁幾個／測了幾個】＋**斷言測的那些真的不在已綁集合裡**
```

## ★★二、驗收裡有一格我要你用既有的尺，不要自己列欄位

```
禁③「改任何狀態」⇒ **用 fingerprint 前後逐位元相同**，不要列一串欄位
★★而它同時證了「沒有推進 tick」：按下去若推了 tick，fp 一定不同
  ⇒ 一個斷言蓋兩件事，而且**不會因為你少列一個欄位而漏**
★fp 的基準**預期不變** ⇒ 若它變了，那是一個發現，回報不要換基準（預測不是授權）
```

## 三、其餘四條

```
①統一出口一處（每個 handler 尾端走同一個 `_refuse_unbound_key`）
  ★「吃掉那個鍵」與「無作用」是**兩件事**：不吃掉 ⇒ 底層可能把它當別的意思
    —— 那正是不變量 #10 的病根
②Esc 不是未綁定鍵（走自己的分支），而「回上一層」在最外層是什麼要寫進註解
③P4 要有一格「已綁鍵沒被門死」
④回饋句用既有結果句的措辭形狀，不自創第四種語氣
```

★順帶兩件你已知的：那行常數註解改成**導出規則**（不要維護 P 編號清單）；
而我在你跑電池時動過 `watchdog.sh`（註冊閘一格，兩版都綠、沒有判決會翻）——要乾淨主詞就單獨重跑 `--selfcheck`。
