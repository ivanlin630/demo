# ★GATE-B 的形狀第三次改寫（這次有完整因果鏈）

**①守恆問題排除**：implementer **自我訂正**（30 天窗曾報「殘留 233 coin ＝ 守恆破口」，拉到 **75 天**後收回）——porter 在 **day37.9 全額回家**、母隊 coin **666.7→961.9**。
★**他的教訓值得入帳**：**太短的窗會讓「遲到」長得跟「破口」一模一樣。**

**②★真實形狀**：day10 dispatch（porter 按比例帶走母隊資產、**含現金 133 coin**）→ day15 DELIVER 成交（coin 133→223）**但 porter 被改派 `task=貿易`、phase 仍 RETURN** → day15–37.9 **自己在外面跑單**（coin 漲到 296）漂成 逃跑/外交 → **day37.9 剛好走回母隊那一格**才全額併回。
★**脫離 CONVOY 不等於斷**：`try_merge_back`（`subteam_system:183`）讀 `convoy_phase`、**對被 release 成別 task 的 porter 照樣認** → 遊魂是**一條很慢的路**、非死路；條件 ＝ **何時剛好走回母隊那格**（warring 12 天內 4 隻回家、peaceful 27.9 天）。

**③★對經濟的真實意義（這才是 GATE-B 的量級）**：**每個領主的貿易吞吐 ≈ 一趟／38 天**——「一隊同時只一支 convoy」（④ throttle）＋ porter **隨機漫遊才歸建**；我上一票量到的 **9 次 blocked 全掉在這個窗裡**。

**④★我的 HOW 建議（WHAT 面交你裁）：修「RETURN 收尾」而不是放寬 ④ throttle**
- **(a)** 它是**失敗反饋鐵律的成功對稱面**（**完成也要收尾**），正好補上反射弧缺口。
- **(b)** porter **真的回家** → throttle 鎖定期**自然縮短** → 吞吐自然上升，**不必改「一次一支」的設計意圖**。
- **(c)** **放寬 throttle 是加車、修 RETURN 是讓車回站**——**加車治標**。

**⑤仍未答**：day15 後 **`attempt` 完全停**（**不是被 throttle 擋、是領主不再選 deliver**）——這層在**選項生成/秤價**，要另一票；**但若 RETURN 修好、吞吐上來，這題可能自然改觀** → 建議**修完再量、不要同時動兩處**。
