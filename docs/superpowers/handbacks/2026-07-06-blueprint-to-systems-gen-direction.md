# gen 方向裁定

多 seed 完整圖收到。裁定，但先講一個改變調法的洞見。

## ★洞見：死亡潮很可能是「卡死」的症狀，非獨立問題
征服隊全被 readiness 閘死（8/8 prosperity_reached=0）→ 沒隊出征 → **餓了沒法靠佔村/征服拿產糧地解困 → 只能餓死**。∴ 6/8 死亡潮**很可能是階梯卡死的下游**：飢餓本該轉征服（佔生產村解糧），readiness 太重堵死 → 飢餓只剩「餓死」出口。
**∴ 不能兩旋鈕一起調，會失歸因。**

## 裁定
### 時序：現在調（param slice，平行序7/8，不擋）
圖已完整——序6 溶完（raid 接回）、反應本就在跑（序7=reframe 非新 pop 動力）。不必等。

### 範圍：先調 readiness 一個，單獨調，再量
- **readiness threshold 降**：讓 ready+armed 隊真能爬到出征。目標=**階梯通**（有些隊 loot→積累→出征），**非全員征服**。看 prosperity_reached 從 0 變「有一些」（非爆量）。
- **假設：這一調同時修卡死 + 緩死亡潮**（飢餓改走征服）。
- **調完重量。** 死亡潮/凍死若還在，才第二輪動 food/承載力。**別現在盲調 food**（readiness 可能連鎖，先看歸因）。

### 凍死 2 seed：分開診斷
凍死（零死零征服零 loot）與死亡潮是**相反極**，根因八成不同——不是餓（餓會死不會凍），較像該 seed 缺衝突觸發/無 prey。**別當同旋鈕修，單獨查根。**

## 調的靶（守住，別過調）
- 目標=**有動有起落**：階梯通、死亡靠**征服重塑**世界而非**均勻腰斬成空殼**。
- **別把 food 放太鬆**——飢餓是好戲（89-96%搏命=健康），只掐掉「腰斬成空殼」的死亡螺旋，非消滅飢餓。
- 全 param（readiness threshold / 承載力常數），合孿生條，非改引擎。

## ★前置修正（藍圖補，2026-07-06）：調 readiness 前先補探針
我上面「死亡潮=卡死症狀（飢餓→餓死）」**是假設，沒量到**。現況缺：
- **反應零 probe**（序7-reframe 標的：defect/riot/breed/panic 空白）
- **死因沒拆**：measure 有 attr%/pop/intent，但**沒拆「餓死 vs 戰死 vs 叛離縮編」**。
→ 沒死因分解，readiness 調完重跑**無法歸因**（看不出死亡有沒有從餓→征服位移＝我假設要驗的東西）。**這是「先量測再開藥」，別在沒證據的因果上調參。**

**順序改為（釘死）**：
1. **補 probe**：死因分解（餓/戰/叛離縮編）＋ 反應計數（wave QA 本來也需要，序7 觀測空白順補）。
2. **重跑 baseline**：先看**現況**死因組成，證實/推翻「餓死主導」。若餓死非主導 → 我的卡死-症狀假設垮，gen 方向重議。
3. **才調 readiness**：降完重跑，看死因有沒有從餓→征服位移。
