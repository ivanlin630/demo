# 判決：`issues`，`premise_contradiction: false`

## (1) `T_DAY` 第五檔——**技術上必要，不是你圖方便，但你自己給的理由比真正的理由弱**
你的理由講的是「單位不同,硬塞進小時檔像假搬家」——這是真的，但不是最硬的那個理由。★**更硬的版本**：`TICK_PER_DAY*1` 換算成小時＝24h，**這個數字不等於 T1(10)/T2(20)/T3(30)/T4(50) 任何一個**——本 slice 的核心承諾是「同值換來源,零值改動」，若把 `INTENT_CADENCE` 塞進任何一個既有檔位，**不是「讀起來像做了事」，是【真的改了值】**（24h 變成 10/20/30/50 之一）。這不是美觀問題，是「零值改動」這條硬承諾逼出來的必然結果——**沒有第五檔,這張票自己會違反自己的誠實限。**
⇒ **建議**：把 spec 裡的理由從「單位不同、感覺假」升級成「數值不重合，塞入任一既有檔＝違反本slice零值改動的承諾」——理由更硬，判斷不用改。

## (2) `(b)` 桶不搬——**可以，但「記進spec」不夠，要求逐個殘量常數現場也留一句**
你問「會不會造出一半在層級一半在原地的中間態，比原狀更難讀」——**不會，前提是殘量本身在原地也看得出「這是已知、非遺漏」**。現在 spec 只要求「(b)/(c) 的分界規則寫進 code 註解」，★★**但沒要求每一顆 (b) 桶常數自己那行也留一句「同族節律、S3 已知殘量、S5+ 收」**——沒有這句，下一個人（甚至你自己半年後）看到 `COLLECT_INTERVAL` 孤零零留在原地，會以為是漏掉，不是刻意留下。
⇒ **建議**：37 顆 (b) 桶常數各自補一行極短註解（同一句話複製貼上即可，不用逐顆客製理由——這條跟白名單「每條要理由」不同，這裡只是「標記已知」不是「判斷」），成本很低，效果是把「中間態看起來比原狀亂」的疑慮直接消掉。

## (3) ★★★層級擾動當歸因——**你的疑慮成立，單次一跑測不出你要的東西，這是本票最該收緊的地方**
你自己抓到的張力是真的：**T1 週期改變會讓整個世界分岔（`fp` 必變），那時的「決策率」是另一個世界的決策率**——跟 S2 教的「世界分岔後聚合不可比」是同一個結構。**這不是「操作 vs 觀察」能化解的**：操作性介入本身沒問題（那正是因果推論的正道），問題在於**你打算怎麼把「T1 變了」跟「決策率變了」這兩件事之間的因果鏈證明清楚，而不是量到一個巧合相關**。

★**具體風險**：spec 現在寫的「決策率」聽起來像是跟 S2 殘差同一個【全域聚合】指標（所有隊、所有決策類型的總量）——**這個聚合指標會被 T1 週期改變的一大堆間接後果污染**（資源分配節奏變了、戰鬥時機變了……），不是只被「T1 那三支系統本身少評估了幾次」這一件事單獨影響。**單一次跑、單一個聚合數字動了，分不出【T1 族節律真的驅動決策量】跟【隨便什麼全域擾動都會讓聚合數字晃一點】。**

⇒ **要求兩件（至少要有其中一件，兩件都做最硬）**：
1. **把量測的指標收窄到「T1 那三支系統自己的評估呼叫次數」**（個人目標/野心/勢力戰略各自的 eval 呼叫計數），不是全域「決策率」——週期加倍、呼叫次數大約減半，這條**幾乎是機制定義本身**（不太可能是巧合），可以先確認「T1 族自己的行為改了」，這是必要但不充分的第一步。
2. **在①的基礎上，再看那個【全域決策率殘差】會不會跟著同方向動**——★★**但這一步不能只跑一次**：至少 2-3 個不同 seed 各跑一次基線+擾動配對，看方向與量級是不是穩定重現，不是單一次的巧合波動。若沒有資源跑多 seed，**至少要把交件時的措�辭從「動⇒歸因到T1」軟化成「動⇒T1是候選歸因之一,還需要多seed才能坐實」**——不能用單次結果講出跟 S2 一樣自信的因果句子。

**這條不是要你推翻整個殘差義務履行計畫，是要求收緊「決策率」這個字眼的定義，並且不要讓單次跑出的方向被讀成已經坐實的因果結論。**
