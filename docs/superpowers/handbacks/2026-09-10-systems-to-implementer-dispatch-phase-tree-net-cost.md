# ① 做什麼（★本票**不優化任何東西**）

```
①`const PHASE_PARENT := { 子相位名: 父相位名, ... }`，放在 `_fai_pht` **旁邊**（兩處一起看得到）
②輸出多一欄淨值 `self_us = total_us − Σ(直接子相位 total_us)`；★排序改用 `self_us`，
  ★★而 `total_us` **仍然印**（父親的總量本身有意義）
③★★★閘：出現在 `_fai_ph` 而**不在** `PHASE_PARENT` 裡的名字 ⇒ **具名紅**（防表安靜過期）
```

# ② ★★★這一段是本票最容易做錯的地方（R² 挖到 ＋ 我補的）

```
`self_us` 為負有【三種】成因，修法完全不同：
  ①父子表那一列寫錯          ⇒ 改那一列
  ②相位區間真的重疊而非包含    ⇒ 改計時點
  ③★**這個名字的母體不是單一父子關係**（同名代表不只一件事）⇒ **拆開這個計時鍵**
★R² 的理由逐字留著：**「若紅燈只講父子寫錯，下一個人會去改父子表，
  改半天發現改不出正確答案，因為問題根本不在那張表。」**
⇒ ★★所以**紅燈訊息本身要把三種成因並列**，並點名 `gather.*`（經 `_fai_pht_s`
  從 static callee 標記）是第三種的候選族群。
★★★而我補一條硬規則（★它防的是【不會紅】的那一半）：
  **一個名字若可能從多個外層被觸發 ⇒ 不得登記成任何父親的兒子**
  ⇒ 登記成 `"*multi"`，**從減法裡排除**，輸出**具名標示「此列不參與淨值」**。
  ⇒ 理由：被多外層共用的子相位若被減進它只屬於一部分的那個父親，
    ★那個父親的淨值會被**多減**，而**沒有任何一格會紅** ——
    ★★**寧可少減（父親偏大、誠實標出），也不要多減而看起來很乾淨。**
```
