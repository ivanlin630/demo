# ① 終端 E2E 床（新票，排威脅欄之後）

```
走法：啟動 → 讀畫面 → 解析「可做的事」清單（只讀畫面文字，不讀 API）→ 挑一個 enabled 的 → 按它印的鍵 →
      讀下一屏：結果句存在、頁腳待執行歸零、且【世界狀態差異】非空（透過 bridge 的唯讀查詢比前後快照；差異要跟那個動作的語意對得上，例如移動 ⇒ 位置變、交易 ⇒ 兩邊資源變）。
      重複 N 步（N 從常數推導），每步印：挑了什麼／按了什麼鍵／結果句／狀態差異摘要。
母體：每一步的候選集從畫面導出；床印「本輪涵蓋了幾種動作」，涵蓋種數有地板（跟 TEAM_TARGET_ACTIONS 等常數比）。
失敗形狀：按了鍵結果句是別的動作（＝顯示≠執行）／結果句成功但狀態差異為空（＝說到沒做到）／狀態變了但結果句沒說（＝靜默）。
陽性對照：故意把鍵表錯位一格 ⇒ 第一種必紅；把某 handler 改成只回 ok 不改狀態 ⇒ 第二種必紅。
確定性：同 seed 同走法逐字相同。
```

# ② 觀察輪（不是票，是一個輪次）

```
時機：繼承回歸票＋威脅欄票 merge 後。
做法：seed 固定，跑 30 天 headless 世界（既有 story dump／specimen），產三份：事件故事、經濟帳、資訊傳播樣本。
讀者：我讀「像不像我們要的世界」（WHAT），QA 讀「因果講不講得通」（既有 story audit）。
產出：一張表，每列一個觀察 → 分類【真問題／原本沒想到但合理／不確定要量】→ owner。只有「真問題」開票。
紀律：這一輪不修東西；修要等表出來。
```

# ③ 分流

```
UI→實作、規則/模型→系統＋藍圖、效能→量測：維持。R² 不拆（它今天抓的洞太多）。
小 UI 修（文字／排版／鍵位）走輕路：spec 可一段、閘＝探索床＋終端自驗＋①E2E。
```
