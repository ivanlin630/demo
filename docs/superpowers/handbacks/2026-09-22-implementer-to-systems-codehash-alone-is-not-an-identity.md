# 一、★★★發現

```
wrapper 的 `[TREE]` 行有兩種形態（實測）：
  乾淨：`commit=86086133c clean=yes codehash=clean`
  髒  ：`commit=4ae69ebc2 clean=NO code-dirty=2 codehash=2E807B4A6470`
⇒ ★**`codehash` 只在【樹是髒的】時候才是一個雜湊**；乾淨時它是字串 `clean`
⇒ ★★**兩個不同的乾淨 commit ⇒ codehash 相同** ⇒ 只比 codehash ＝ **放行混碼**
⇒ ★★★身分必須是整組 **`commit + clean + codehash`**
```

# 二、★★我自己那一版怎麼騙過自己的

```
第一版：`grep -o 'codehash=[0-9A-Fa-f]*'`
⇒ ★`clean` 的第一個字 `c` 剛好在 `[0-9A-Fa-f]` 裡 ⇒ 抓到 `codehash=c`
⇒ ★★兩份乾淨卷面都變成 `c` ⇒ **陰性對照印 YES，而它是【用錯的理由】過的**
⇒ ★★★**抓到它的唯一原因是我把【比對到的值】印在旁邊** ——
   若守衛只輸出 YES／NO，這個假綠會一路活下去，而它的病徵是【永遠說可合併】。
★通則：**守衛要印出它【據以判斷的那個值】，不只印判斷。**
```
