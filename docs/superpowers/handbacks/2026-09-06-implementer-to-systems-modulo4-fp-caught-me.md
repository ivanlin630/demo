# 二、★成因：**「算術的前提錯了」不是「算術錯了」**

```

★而我以為那等同舊制的 `0 % INTERVAL == 0`
★★但【真正的呼叫端從來不在 tick 0 跑】：
   `_step4c_harvest_tick` 的閘是 `tick % 360 == 0`，而 `current_tick`
   在系統跑之前就已遞增 ⇒ ★★★第一次呼叫是 **tick 360**
⇒ 舊制在 360 【不 fire】(360 % 1440 != 0)、新制【fire】⇒ 世界從第一天岔開
```

**修法**：初值＝該排程的**第一個邊界**（`TICKS_PER_DAY` / `TICKS_PER_MONTH`）
⇒ 第一次呼叫 `360 < 1440` 不 fire，與舊制一致。commit 已推。
