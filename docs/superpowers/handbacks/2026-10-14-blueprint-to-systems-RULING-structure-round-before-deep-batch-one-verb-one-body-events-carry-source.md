# 為什麼現在
今天一個下午用戶問出三個同形的洞：建點三入口兩價、玩家子隊到場執行另寫一個殼、玩家子隊事件即時送達（違資訊憲法，NPC 側走 `_report_to_leader` 信使而玩家側走 `emit_player_subteam` 直發）。成因都是流程：WHAT 漏寫、接最近的管子、守衛不看那側。用戶問到「重做」。藍圖判斷：裁定／床／腦／物理是對的，碎的是執行層；原地重做執行層比重開便宜，且重開不改流程會再碎。路線圖板已改（progress §路線圖板 一之半）。

# 結構輪範圍（WHAT）
1. **一動詞一身體**：每個會改世界的動詞只有一支執行函式；腦（引擎／玩家）只選，不做。從 verb-catalog 逐列收。
2. **玩家層呼叫引擎**：`player_command_system` 裡自己重寫的動作身體刪掉，改呼叫 NPC 同一支；玩家與 NPC 的差別只剩「誰給任務」與「回句」。同盟參數反向那類病由此根絕。
3. **玩家事件帶來源**：`WorldEvents.emit` 給玩家的事件必填「怎麼知道的」＝親見（主體在視野內）／信使（帶幾天前、誰送）／傳聞；缺＝拒收並紅。這不是新閘，是欄位必填。推進停點看「信到」不看「事發」。
4. **子隊事件走信使**：玩家子隊的八種事件改走 NPC 同一條回報路（距離延遲、信使可死＝沒回音）；視野內即時；玩家召回令同樣要送到子隊才生效。★順帶修 NPC 側：`_report_to_leader` 報的是勢力領袖，母隊不是領袖時母隊不知道自己子隊出事 ⇒ 回報對象＝母隊（領袖另收是第二件事）。
5. **驗收＝目錄**：`docs/process/verb-catalog.md` 每併一個動詞登一列（身體、呼叫者、床）；grep 全庫寫入點只有那一處。

# 探針（先做這兩個，拆不開就停）
- 建點：紮根／派子隊／玩家建設 → 一支（L1 材料票的本體，就地採那段一起）。
- 子隊到場執行：NPC `_tick_subteam` 腦內「到了做什麼」那段＋玩家 `_tick_player_subteam` 殼 → 一支執行端；腦只決定「留／回」，玩家子隊沒腦。
停損：兩個探針若 faction_ai 拆不出、或床紅收不回一週 ⇒ 回報藍圖，藍圖把「重開」交用戶裁。

# 序
玩家可見批剩四張（附身隊三件／ETA／情報面板／游標即選中）＋第 7 張消滅三漏照做 → 結構輪 → 深層批照板。顧問與文本外置跟情報面板走不變。
