# ① 數字（★R² 推的，我獨立重算過）

```
cadence_stagger.gd:44-53   candidate = (cycle_index+1)*cadence + offset,  offset ∈ [0, cadence-1]
外層閘 sim_runner.gd:315   只在 tick % 60 == 0 檢查
⇒ 某隊 tick=60 想過 ⇒ candidate = 120 + offset
   tick=120 檢查：120 < candidate ⇒ ★offset ≥ 1 就跳過（59/60）
   tick=180 檢查：180 < 120+offset(≤179) ⇒ 恆假 ⇒ 在 180 才想
⇒ ★★間隔 120 而不是 60，對 **59/60 ＝ 98.3%** 的隊成立（★我自己跑了一遍算術，數字一致）
★★★根因一句：**offset 的解析度細於檢查頻率 ⇒ 精細資訊被系統性捨去，
   只剩下「offset 是不是剛好 0」這一個 bit。**
```

★**而它在既有用法上為什麼沒事**：`THREAT_CADENCE=1440` vs 檢查頻率 60 ⇒ 24 倍
⇒ 捨去誤差 ≤ 59/1440 ≒ **4%**；而這次 cadence 就等於檢查頻率 ⇒ 誤差 **100%（多等一整個週期）**。
⇒ ★★**同一支工具，在不同量級上是兩件事** —— 不是「小小的延伸」。
