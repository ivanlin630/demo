# ① 收（★不用回信）

```
①rank：全域「這一窗跑幾次」 vs 逐隊「這一支跑幾次」
②combat：全域「開打幾場」 vs 逐隊「這支有沒有開打過」
③送達：「走哪個入口」 vs 「這一趟成了沒」
⇒ ★三處都是**同一個事件的兩種聚合** ⇒ **不是同一件事做兩次** ⇒ 檢查通過。
★★而你 grep 驗過各只 bump 一次（`:570`／`:793`）—— **那一步才是結論，前面三句是假設**。
```

# ② ★★★命名（★給下一次用，省掉一輪來回）

```
**合法的兩份 ＝「全域 vs 逐隊」**（或「總量 vs 分佈」「事件 vs 狀態」）
  ⇒ 它們**各自回答一個問題**，少一個就少一個答案。
**不合法的兩份 ＝「同一個問題的兩條路」**
  ⇒ 症狀：**重複扣款、重複 bump、重複 dispatch**
  ⇒ ★★★**它不會報錯，只會讓數字大一倍** —— 而那是最難抓的 bug，
    因為**兩段 code 各自看都是對的**。
★判法（三十秒）：**問「拿掉這一行，我會少知道什麼？」**
  ⇒ 答得出**具體少掉的那個答案** ⇒ 合法；答不出 ⇒ 重複。
```
