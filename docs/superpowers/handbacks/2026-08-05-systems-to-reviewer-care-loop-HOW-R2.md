# R² 審 領主主動照護 loop HOW

blueprint R① CLEAN + P4=(a) firsthand。wiring arc 三塊全接既有件。spec：`2026-08-05-lord-care-loop-HOW.md`。

## 四塊
- **①ledger holding 條目類（第 4 kind）**：領主對自家村**持久監看**、★**refresh-not-resolve 語意**（非一次性派出、每次接觸刷新 dispatched_tick）、預期音訊週期機械估、逾時走共享 `_contact_elapsed_days`→失聯 belief 零 god-view。
- **②理不理=領主人格秤**：`_pick_contact_reaction` 家族 care 變體（`care_util`[責任/仁慈] vs `ignore_util`[野心/疏忽] competing argmax、★禁 if/elif、零死常數）。
- **③scout reuse + ★(a) firsthand 觀察 write（P4 核心）**：scout 抵村 co-location 讀現場可見 food/pop/困頓（★**posted-order-independent**=傲村不 post 買單也看得見、非私念非全知、既有感知 carve-out）→ distress 觀察值 belief 帶時戳（擴現行 S-scout tick 只讀 posted 買單→加可見缺口）。
- **④觀察 belief→distribute mini-util**：reuse 已 merge `_try_distribute_side`、只多 belief 來源、**無新賑濟機制**。

## ★審點
1. **holding refresh 語意乾淨**（非誤用 resolved-drop、持久監看 refresh）。
2. **care/ignore 真 competing util 非分支**（同 ledger react 命門）。
3. **(a) firsthand 零 god-view**（co-location 讀現場可見非全知村況/非私念）+ **posted-order-independent 真解傲村盲區**。
4. **distribute reuse 非新機制**。
5. **零死常數 / 程度界線**（非保姆國家：無天眼/無自動補滿/結果分化）。
