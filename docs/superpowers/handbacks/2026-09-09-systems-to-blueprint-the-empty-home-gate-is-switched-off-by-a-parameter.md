# ① 成對反事實第一次上工就付錢

你今天把「**有變異要問變異來自哪一項**」升格進 QA 判官清單，而它的可操作形式
（**成對反事實**：同一輪算「有機制」與「換回舊值」兩個結果）第一次跑就抓到：

```
批一③（返家門檻 = RETURN_HYSTERESIS_DAYS × 真 burn，已 merge 68f81148）
  raw   18/18 隊「算出來的門檻」真的變了      ← ★機制成立
  eff    0 隊  clamp 後真正進 drive 的值沒變
  gate   0 隊  options 的 home-empty 判斷沒翻
```

★**驗收該掛哪一個**：`raw`（機制的性質）。`eff`／`gate` **只印不斷言** ——
它們是**世界當下狀態**的性質，拿來斷言就是一格「世界一變就紅」的驗收。
⇒ 已立成 `01_architect` 設計 checklist 的**接線票必備一格**。

# ② ★★而 implementer 的第一版結論我更正了

> 他寫：`home_food` 中位數 800 而門檻上限 40 ⇒ **世界不產生會用到它的狀態**。

```
config/warring_states.json:11   "opening_granary_food": 800
床的窗                          BED_DAYS = 1（★昨天為了成本剛砍下來的）
量到                            home_food min 800 / median 800 / max 1005.9
```
⇒ ★`min == median == 800` ＝ **那是初始值，糧倉在那個窗裡根本還沒被吃。**
⇒ ★★`eff 0／gate 0` **與窗長混淆**，不能讀成「不咬人」。
   ★★★而這件事本身值得記：**降窗買到的時間，代價正好落在「咬不咬人」這個新問題上。**

# ③ ★★★更正之後，結論比原本【更強】——而這條是給你的

算糧倉要幾天才掉到門檻（純消耗、不計生產補充）：

```
門檻 = RETURN_HYSTERESIS_DAYS × pop × FOOD_PER_PERSON_PER_DAY = 4 × pop
  pop=10 ⇒ (800 − 40)/8   ≈ 95 天
  pop=30 ⇒ (800 − 120)/24 ≈ 28 天
★而糧倉還會被生產補充 ⇒ 上面是【下界】，真實更久，或永遠到不了。
```

⇒ ★**「空家不返」這個閘（`options.gd:149`）是被【參數】關掉的**：
   `opening_granary_food = 800` 對上一個 `≤40` 的門檻，**差 20 倍以上**。
⇒ ★★它不是「還沒演化到」，是**開局就設定成永遠不會發生**。

**這是 WHAT 面的東西，所以呈你**：

```
(a) 這個閘【本來就該是罕見情形的保險】⇒ 現況正確,不動。★那也是一個答案。
(b) 開局 800 太高 ⇒ 那是【世界初始條件】的設計問題,而它會連帶影響
    所有「家裡有沒有糧」的戲（圍城/飢荒/補給線斷都變得無關緊要）。
(c) 門檻太低 ⇒ 但門檻是【返家自己的成功條件】導出的（R² 判過同源）,動它要動 hysteresis。
★我的建議：先不改任何數字，把這條記成【已知的參數對比】，
  等圍城/斷糧那類戲真的要做時再回來 —— ★★因為現在改它會【沒有消費者】。
```
