# ①「算了但沒人讀」——你自己想到的解法就是對的，用既有圖案不是新風險

你提的做法(getter記一次被讀過,跑完比對算過次數vs被讀過次數)**就是構造式**——它不是清單,
是**衍生量**：不用列「誰會讀」，只要量「有沒有被讀」，答案自己浮出來，跟今天已經驗證過的
「推導不宣告」是同一個形狀(bed-arm第三種結果用的正是這一招)。

你猶豫的地方是「會改變production形狀」——**這個擔心成立但代價比你想的低**：`Probe.bump()`
包getter這個做法,你們今天已經在全庫用了幾十次(`recon.anchored`／`occupy.scan_kill_nopos`等等),
只要遵守既有規矩(`Probe.enabled`關時零成本、不碰RNG、不寫任何決策會讀到的state)，
這不是一個新的風險類別，是同一個安全圖案再套一次。**用它，不用另想。**

# ②2-b母體恆空——是一個真的洞，處置法你們今天已經用過三次

你自己抓到「母體=0時兩邊當然相同⇒恆綠」，而目前的寫法只要求「母體要印」，沒有規定
母體=0時該怎麼判——這正是今天重複出現的「母體塌陷判不可判非判綠」那條(escrow-audit的
`checked>0且三個都0`／stale-pos-recon的`母體非0`、今天全天都是同一個處置)。

**建議**：2-b那格明寫`母體=0⇒[不可判]`，不是隱含在「母體要印」這句話裡——印出來是給人看，
[不可判]才是給閘判的，兩者不是同一件事(你們今天已經在別的格區分過這兩個動作)。有了2-d
(陽性對照,故意弄壞一格確認2-b會紅)不能取代這一條——2-d證的是「2-b有鑑別力」，
不是「這一輪真的有東西被比較過」，兩者是不同的失效模式，要分開擋。

# ③「沒有便宜的省法就結案」——誠實答案：沒有機械觸發，而這次可以接受

先誠實面：這一列跟前兩列不一樣。前兩列(算了沒人讀/有可證明上界)都有一個**會被造出來的
東西**可以拿去核對(改成誰讀誰算、剪枝邏輯本身)；這一列是「決定不做什麼」，**不做的事情不會
留下痕跡讓機器去檢查**——這跟「沒有第二份算式」那種可以用內容錨守住的東西不同類，這裡連
「沒有」都沒有東西可以錨。

**但這次可以接受留成自律**，理由是失敗代價不對稱：這一列如果被違反(明知沒有便宜省法卻硬做
一個3%的剪枝)，最壞後果是**多寫了一段可能改變行為的code**——而那段code本身還是要過2-b/2-c/2-d
那些真的機械格才能綠，換句話說：**即使你在這一列騙了自己，後面的格子還是會抓到那段剪枝
到底安不安全**。這跟今天別的案例不一樣的地方是：別的案例(到場點名/自我比較恆真)違反了會
**讓真的bug溜過去而不被發現**；這一列違反了只是**多做一次不必要的工，而那次工還是要過安全
檢查**。風險等級不同，機械化的必要性也不同。

如果你還是想加一個信號，可以印當輪最大單一段落佔比的數字(不用設門檻，只是報數)，
讓「有沒有大頭」這個判斷有數字撐著而不是純粹憑印象——但這是加強誠實度，不是補一個機械閘,
不加也不算洞。
