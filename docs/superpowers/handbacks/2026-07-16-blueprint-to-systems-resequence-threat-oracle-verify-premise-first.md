# 裁：重排 threat oracle 上移 + 前提先驗（別重蹈稽核過度宣稱）

## 認可 R① reframe
R① 查證:4 個 `rank_*` 全是同 `DecisionOptions.applicable()` 池 + 同 `DecisionTerms` 權重的 filtered subset ＝ **非繞過引擎,無 bypass 可拆**。稽核當初看到多 dispatch 入口就推 split-brain,**過度宣稱**。R① 無 premise_contradiction 但重大 reframe＝**premise-factcheck 又擋下一個過度宣稱的 roadmap 前提**（繼 mis-cite/incomplete 後又一次）。

## 裁：重排
- **dispatch 收斂＝cosmetic cleanup（非 de-patch 真打架種子）→ 降級低優先**（日後或順手做；survival/threat 語意可併的開放 Q 併此時 R² 裁）。
- **Arc 2 ＝ threat oracle（原 Arc 3 上移）**：8 處各算威脅 + 3 種 rep 門檻（0.3/0.5/0.7）＝**像 need 一樣的真打架種子 + 擴充阻礙**,高值。

## ★但 threat 前提先驗（關鍵，別重蹈）
threat 的「8 處各算、3 門檻不一致」前提**來自同一份剛被 R① 打臉的稽核**（dispatch 就被證同源 filtered 非各算）。**說不定 threat 那 8 處也有幾個是同源 filtered。**
- **∴ Arc 2 threat oracle spec 前,先 R① factcheck 前提**：那 8 處（`ThreatAssessment.score`/`_max_threat`/raw threat_react 掃描/`_has_active_threat`/`_has_hostile_within`/`_threat_recent`/strategic threat_map/diplomatic power_gap）**真各算、3 門檻真不一致嗎?還是同源 filtered?**
- **驗實了是真各算打架種子才做 oracle;若多是同源 filtered → scope 縮或再重排。**
- **稽核前提本 arc 一直被修正（dispatch 剛被打臉）→ 不再假設,驗了再 spec。**
