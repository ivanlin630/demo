# ① 事實

```
config/warring_states.json:7   "radius": 14
world_generator.gd:63-67       _hex_dist(...) > radius 的格被剔除 ⇒ ★全圖任兩格距離上限 ＝ 28
goal_resolver.gd:1001          if d > max_range: continue        max_range ＝ SEEK_TILE_RANGE ＝ 30
⇒ ★★★30 > 28 ⇒ 那一行【從來沒有擋掉任何東西】。
```

⇒ **現況不是「每支隊都搜尋 30 格」，是「沒有任何隊有搜尋上界」。**

# ② ★★所以這張票不是我上一封說的那種

我上一封把它報成「**(ii) 型的教科書型：同一個量在兩層各有一份**」。
★**那句話仍然對**（30 是平版、真速度逐隊），
★★**但我漏了一格**：那個平版數字**大到讓整條規則不存在**
⇒ 接上真速度**不是把一個錯的值換成對的值**，是**第一次讓這個上界真的存在**。

⇒ ★★★**那是行為改變，需要你的 WHAT 確認，不只是 R²。**
問題不是「要不要用真速度」，是「**搜尋範圍到底該不該是一個限制**」。

★**我的看法（而它是意見不是裁定）**：該是 ——
一支走不動的隊「**看得到全圖並決定去對角線採木**」，正是今天 ① 在治的那種
「**拿著自己沒有的能力做計畫**」。★★但那句話是 WHAT，我不自己定。

# ④ 若你確認要做，spec 已經寫好且改過了

```
docs/superpowers/specs/2026-09-09-seek-range-from-real-move-cost-HOW.md
```
★**單位鐵則**：`SEEK_TILE_RANGE` 是【格】、真值是【格/天】⇒ 不能直接代
⇒ `seek_range = SEEK_DAYS × tiles_per_day(team)`，而 `SEEK_DAYS` 是**設計選擇留參數**。
★★**預設不發明**：中性隊實測 4.20 tiles/day ⇒ `30 ÷ 4.20 ≈ 7.1` ⇒ `SEEK_DAYS = 7.0`
⇒ **中性隊幾乎不動，快慢隊分開** ⇒ 本票是【差異化】不是【全域收緊】。

★★★**而驗收我也照可達區間改了**：
```
seek_range ∈ [14, 126]（SEEK_DAYS=7）,而全圖上限 28
⇒ 快隊那一端（≥28）【結構性不可觀測】⇒ ★「快隊變大」不能當驗收格
⇒ 真正可觀測的只有【慢隊】：tiles_per_day < 4 的隊 seek_range < 28 ⇒ 它們第一次真的被限制
⇒ 驗收掛在那裡,並【具名列出是哪幾隊】。
```
★另加一格「**不把慢變成瞎**」：最慢的隊 `seek_range >= 1`，且床要具名印出那些隊 ——
否則本票會把「慢」變成「瞎」，而**那是新的病不是修好的舊病**。
