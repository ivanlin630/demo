# ★★★①你抓到的是真洞，而且它比「留白」嚴重
> **「這不是可以事後選數字的空缺，是【整支公式都不存在】。」**

前者下游填數字，後者**下游得自己發明一套價值觀，還要自己判斷它跟既有的量可不可比。**
★★★**而尺度不可比的 argmax ＝「誰的數字剛好比較大」** —— **跟這張票要防的 first-match 搶答是【同一種病換個位置】。你講得比我準。**

# ★★★★②而答案是【不造新秤】—— 你的 code 讀出來的東西自己給了它
`_pick_facility` **本來就在比「怎麼騰出一格來蓋 `best`」**：
```
ok_slot_free  有空位 → 直接蓋            代價：無
ok_demolish   位子滿 → 拆掉 lowest 再蓋   代價：失去 lowest（既有法 best > lowest × 1.5）
★upgrade      位子滿 → 擴建多一格再蓋     代價：付升級全費（afford 已是 applicability gate）
```
⇒ ★★**三者共用同一個分數 ＝ `best` 的 `_facility_score`**，
★★★**因為它們想蓋的是【同一座設施】，差別只在【取得那一格的代價】** ⇒ **尺度天然可比，不是我湊出來的可比。**

⇒ **修法也因此變小了**：★**不是「兩段各自算分再比」，是【把 upgrade 加進 `_pick_facility` 既有的出口分類，成為第三個 `ok_*`】。**

## ★而它順便回答了「升級值多少」，而且是 genuine 的
> ★★**升級本身沒有價值。它的價值是【它讓你能蓋的下一座設施】。**
⇒ **slot 沒滿時升級價值 ＝ 0**（`ok_slot_free` 代價更低）⇒ ★**升級只有在 slot 滿時才是選項**
—— ★★**而那與實測相符**：`empty_slot_full_margin = 180`（69.8%）**正是「想蓋、蓋不下」的那一批。**
★**沒有任何一個數字是為了讓升級贏而調的。**
