# ★★★一個會擋住「照字面拆」的東西

```
trade_valuation.gd:158-163
   var shortage := (target - stock) / maxf(target, 1.0)
   (生存品放大)
   var sr := clampf(shortage, -0.5, 上界)
   return BASE_PRICE[res] * (1.0 + sr)
★拆掉下限 -0.5 之後:stock > 2×target ⇒ shortage < -1 ⇒ (1.0 + sr) < 0
⇒ ★★【價格為負】
```

## ★★★而我【不主張保留那個閥】—— 我主張分清楚兩件事
```

②★★【保留數學上的定義域】—— 「價格不得為負」不是穩定閥,是【這個量的定義】
   ⇒ ★★★把兩件事混成一件,會讓「拆閥」順手拆掉一個【本來就不該存在的可能性】
⇒ 而我【不替你決定】——★這是 WHAT:「一個東西多到爛掉時,它的價格是 0,還是負?」
```

# ★而我把這個爭論**變成可量的**（★★這樣它就不需要用講的）
```
D 格加【第四桶】:`shortage < -1`(＝會產生負價的那一段),與既有三桶並列
⇒ ★若它【恆為 0】⇒ 我的顧慮【本來就不存在】⇒ ★★直接照字面拆,零風險
⇒ ★若它【非 0】⇒ 那就是【拆之前必須先決定的事】,★★★而不是拆完之後才發現
⇒ 而【兩種結果都不用吵】—— 數字回來自己會說話
```
★**而這一格的成本是零**：clamp tap 已經在算 `shortage`，多一個桶就是多一個 `elif`。

# ★★而 D 格的讀法要跟著修正一句（★否則會被讀反）
```
★上界桶【恆為 0】是【構造性的】(effective_holding 兩項皆 >=0 ⇒ shortage 恆 <=1.0
   ⇒ 生存品放大後恰好 =4.0、非生存品恰好 =1.0 ⇒ 【恰好等於上界,永不超過】)
⇒ ★★所以你那條決策規則「命中率高 ⇒ 先治上游;低 ⇒ 直接拆」
   【只能用在下界桶】—— 上界桶的 0 不是「閥沒在扛事」,是【那隻手臂從來沒動過】
⇒ ★★★把兩者混在一起看,會得到「閥完全沒在扛事 ⇒ 直接拆」的結論,而【下界可能正在扛】
```
