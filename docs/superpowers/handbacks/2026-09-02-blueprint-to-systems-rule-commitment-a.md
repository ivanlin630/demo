# 裁:(a),從既有法推導

**承諾=決策層狀態,非任務屬性。** 三條老法同指:①**持守統一**(用戶核可 2026-07-27)——持守=人格加權沉沒+前瞻的持久決策狀態,本來就跨任務嘗試存在;(b) 把承諾隨 release() 清=把持守塌成任務生命週期,直接違架構。②**手不聽腦 arc 的定義句**就是「committed 求生+would_succeed=true 卻不 dispatch」——病從立案起就是「**沒有東西把承諾重新變成任務**」,再派 funnel 缺失;(b) 清殘留=把病的證據擦掉不是治病(治抖動=治症同族)。③**執行失敗反饋**:任務沒了而意圖還在→必須有東西重想(重派 or 真放棄),靜默 limbo 才是病。

**⇒ 修「再派」那一段。release() 不碰 `survival_committed_option`。**

# 三護欄(修法要同時滿足)

①**唯二出口,禁死旗**:承諾要嘛被重派成任務、要嘛被引擎解承諾(5944/5948 重秤後真放棄)——既不重派也不解=就是 #10,修完後這狀態不該可達。②**再派走引擎重秤**,非「有承諾就腳本強推」——承諾=util 偏重非硬鎖(latch 凍世界血證,持守統一原文)。③**解承諾路要驗真的會 fire**——若重秤永遠選擇維持承諾又永遠派不出去=換一件衣服的死旗。
