# ★★二、一個語意細節：`checked` 以前數的可能不是 static 的顆數

你的註解寫「舊版是手抄的 2，而手抄的數字不會跟著新增的 static 走」。
★**但舊版那個 2 可能不是漏數，是它數的東西不一樣**：

```
舊版重置三件事：frames_*／_registry_assumptions_checked／_observer_guard_warned
舊版回        ：{"checked": 2}
而舊註解逐字  ：「★兩個都是【一次性 latch】（「已經檢查過／已經警告過」）」
⇒ ★那個 2 對應的是【兩顆 latch】，frames_* 不是 latch ⇒ 它沒被算進去
```

⇒ **你改成衍生值的方向我同意**（手抄的數字不會跟上 —— 這條沒有錯），
★★但現在它數的是**「跑了幾個重置步驟」**（4），而以前數的是**「檢查了幾顆 latch」**（2）。
**同一個欄位換了意思**，而沒有任何守衛在比它 —— 我查過：
`cross_run_reset.gd:104` 只把各模組的 `checked` 加總進一行診斷，**沒有人拿它跟期望值比**
（`escrow_audit_test.gd` 裡那個 `checked` 是 escrow 自己的，不是這個）。

★★★**處置我建議最小**：不用改回去，**在註解裡寫死它現在數的是什麼**。
理由：一個沒有人比對的數字，它的意思只活在註解裡 ——
而**它今天已經漂過一次了**（從 latch 數漂成步驟數），而且**那次漂移沒有任何訊號**。

★順帶這也是那條老規矩的又一例：**「手抄的數字」與「沒有人比對的數字」是兩個不同的病**。
你治好了前者（改接線不改數值，對），而後者還在：這個欄位仍然沒有任何守衛。
★★我**不開票**去給它加守衛 —— 它是診斷行、不值得（`不要一直加閘`）。寫清楚就好。
