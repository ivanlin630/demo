# ①「低風險＝目標不同」—— 查到一個比你講的更底層的事實

去追了 `odds`（也就是 `cap`）的組成，發現它**完全不讀 prey 的任何強度資訊**——
`self_armed_ratio` 是**攻方自己**的量，跟被選中的是哪個目標**無關**。也就是說：

```
「低風險」這個物理差別，在這條公式裡【百分之百靠上游選目標的函式來承載】——
公式本身（odds/take/need/person）對「這個特定 prey 有多強」是瞎的，
它只知道「我自己有沒有牙」，不知道「對方有沒有牙」。
```

這跟 `faction_ai_system.gd` 自己的 `attack_scan/score` 不一樣——那邊的 `weakness` 項
是真的讀 `armed_est`（對方武裝估），這裡（`terms.gd`）的 `odds` 從頭到尾沒有這個維度。
⇒ ★**這不是說設計錯了**——`_find_weakest_prey` 用 `population_est` 當弱點代理，
只要人口與資產/戰力在這個世界裡是正相關（小村通常也窮、也弱），這個代理就大致成立，
跟你「目標不同,風險差自己出來」的直覺方向一致，不是反例。

⇒ 但這代表你自己標的「若兩者常打到同一目標,§2就垮」這句話**背後沒有第二道防線**——
一旦目標真的重疊，公式裡沒有任何東西能讓兩者的「風險」看起來不同（`odds` 對兩邊
完全一樣，因為它只讀攻方自己）；那時候掠奪跟攻擊的唯一差別就只剩
`RAID_TAKE_FRACTION` 造成的量級差——**變成「同風險、小報酬」而不是「低風險、小報酬」**，
物理故事會跟 blueprint 要的那句「低風險」對不上，即使數字本身不會顯性報錯。

⇒ 建議：這格量測（你自己已經標了「沒量過」）除了「重疊率」，**順便報一個共現時的
odds 是否相等**（照公式邏輯必然相等，這格量出來應該逐位元一樣——如果不一樣，
代表哪裡讀到了我沒看到的第二個 odds 來源，值得回頭查）。這格我判：**成立但脆弱**，
不擋 dispatch，但你自己標的驗證缺口確實是這張票唯一有機會垮的地方，值得列進§3。
