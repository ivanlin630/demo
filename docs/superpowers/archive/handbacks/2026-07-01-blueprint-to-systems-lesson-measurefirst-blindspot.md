# 教訓：為何一路沒發現「架構沒統一」是根（請寫 memory）

復盤：整條 (a) emergence/經濟 arc 跑了 N 輪 measure-fix（leader弱/攀爬/食物cadence/rung2→3/致富錨…），才發現核心之一是**架構沒統一**（獨立隊 vs faction 走不同決策路徑）。用戶問「為何系統跟藍圖都沒早發現」。教訓如下，請提煉進 auto-memory（feedback 型）。

## 核心教訓
1. **measure-first 抓「近端因」，不抓「架構模式」**：它找下一個近端 blocker（漂亮、每個錯猜都被打臉），但**是局部的**——看不到卡點背後的架構模式。單一個案像局部 bug；**要同型缺口重複出現（獨立不建國→又獨立沒致富）模式才浮現**。= measure-first 必要但不充分。
2. **架構缺口躲在行為症狀後**：「產不出征服者」看起來是平衡（leader弱/attrition/食物），**不追到碼看不出是「獨立隊架構上不在統一路徑」**。
3. **★ 過早喊 done 主動誤導**：宣告「統一決策三層全補/真根全清」→ 後續問題來時**不去懷疑決策架構（以為做完）→ 轉頭找平衡**。假 done 把診斷**導離**真根。**若誠實標「獨立那層=部分補丁」會早很多懷疑。**
4. **剛統一完的確認偏誤**：剛做完大 arc，心理 prime 成「決策統一了、問題在別處」，不回頭懷疑剛「做完」的。

## 該提煉的原則（memory）
- **兩隻眼並用**：measure-first（近端根）+ **結構映射/強制閘**（架構缺口）。缺結構視圖，架構缺口隱形。→ 統一矩陣 program 就是補的這半。
- **誠實標記**：補丁叫補丁、部分覆蓋叫部分，**別叫 done/全清**。假 done 主動誤導未來診斷。
- **新系統必問「涵蓋哪些實體型」**：faction-gate/named-only 要有意識，非意外（否則 (B) 涵蓋缺口）。
- **同型缺口重複 = 架構信號**：同一種修補出現第二次（獨立補 founding→又補致富）→ 停手，疑架構分岔，別再補第三次。

- 連 [[project_unified_decision_framework]] / 統一矩陣 program（`2026-07-01-...unification-matrix-program`）。
- 這是雙方教訓（系統 + 藍圖），藍圖認「過早喊 done + 沒早做結構稽核」之責。
