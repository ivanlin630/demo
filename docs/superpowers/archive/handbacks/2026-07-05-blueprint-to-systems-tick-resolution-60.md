# 時間解析度旋鈕 = TICKS_PER_HOUR 10→60（含運算頻率安全）

## 尺度真錨（用戶揭）：動 TICKS_PER_HOUR，不動遭遇戰動作 tick
- 遭遇戰動作 `BASE_ACTION_TICKS=10` = **守速度鑑別度下限**（再小=快慢級距不足分不出）→ **釘死不動**。
- **`TICKS_PER_HOUR`（現 10）= 時間解析度旋鈕**。10→60：
  - 遭遇戰動作 10 tick = 24 分 → **10 分/動作**（合理，鑑別度不變=仍 10 tick）。
  - 移動一格 = 10×24=240 tick ÷60 = **4 小時/格**（原 1 天）→ 一格代表真實距離縮 6×→**據點密度合理化**（承前空間尺度矛盾）。
  - 連動不變量守（動作 tick、遭遇戰尺度沒動，只換算變）。

## ★ 運算頻率安全（用戶點名重點）——初掃結論：多數安全
```
✅ 已導出 cadence（改 60 頻率不變，只解析度變）：
   NEAR_CADENCE=TICKS_PER_HOUR / FAR_ZONE_INTERVAL=10×TICKS_PER_HOUR /
   LADDER_EVAL/BETRAY_CHECK=N×TICKS_PER_HOUR / %TICKS_PER_DAY 家族
   → 語意=「每小時/每天跑一次」,非「每 tick 硬跑」→ ×6 解析度、同頻運算
   關鍵：系統不是每 tick 全算,是 cadence-gate 才算 → 60 下運算量不變
```
