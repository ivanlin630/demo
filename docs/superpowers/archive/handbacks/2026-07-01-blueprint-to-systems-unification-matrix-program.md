# 統一矩陣 program — 止打地鼠，不重做

用戶裁：**不 KILL 重做**（重做撞同樣 (B) 缺口 + 丟累積知識 + 核心抽象其實對），走 **refactor via 統一矩陣**。

## 背景：為何一直冒沒統一的東西
兩種「沒統一」：**(A) 漂移**（已知該統一被繞，稽核/閘抓得到）；**(B) 涵蓋缺口**（一整個情況當初沒考慮，如獨立隊要戰略意圖）。獨立/faction 分岔 = (B)。舊稽核（state-fight-scope/inventory）真做過但**沒涵蓋「實體×決策路徑」維 + 後加的沒重驗 + 我過早喊 done**。(B) 增量開發本質沒法一次根絕，但可大幅少犯。

## ① 統一矩陣稽核（產出全貌，止驚喜）
grep 實碼，列 **實體 × 領域** 表，每格標 **統一 / 補丁 / 缺口**：
- **實體（列）**：named 個人 / anon cohort / team / subteam / faction / 獨立 team / player / 物品 / tile。
- **領域（欄）**：思考決策 / belief情報 / 狀態所有權 / 物品資源 / 互動 / 人力 / combat捕俘。
- 每格：這實體在這領域走哪條路徑、是否統一路徑。
- **產出 = 完整統一地圖**：第一次知道還有多少格沒統一，不再一個個驚喜。

## ② 強制閘推廣（守住不退化，抓 (A)）
「無因令=0」式稽核**推廣到全部點** → **CI 掃到有決策/意圖/狀態點沒在統一路徑就 FAIL**。填好的格不能靜默退化。

## ③ 設計 checklist（少犯 (B)）
新決策/狀態/意圖/互動系統**必列「涵蓋哪些實體型」**——faction-gate/named-only 要是**有意識選擇**不是意外。+ **誠實標記**：補丁叫補丁，別叫 done。

## ④ 判準（每格填統一時守）
> 一領域一套機制；所有實體型插同一套；**實體型只決定 LOD/規模/細節，非另起爐灶。** 別按實體型分岔（named/anon、faction/獨立、player/NPC）。

## 燒清單（矩陣出來後照排，首格已知）
1. **★ 獨立/faction 戰略合併（首燒）**：戰略 intent-forming 統一成「任何 leader 一套菜單」（致富/擴張/征服/守成/建國），**faction 只是執行規模 context**（協調隨規模、獨立建國後升級獲協調）。**非再補獨立菜單**。
   - **帶出致富 + 征服錨一次解**（合併後獨立商隊有致富、好戰隊有征服，不用逐個補）。前面 CONQUER=0/致富不存在 可能一起活。
2. **B = R1 食物（張力目標）**：給野心牙（tracer 證食物碾致富行為，強耦合）。目標**張力非死亡**。隨戰略合併後/耦合。
3. 其餘缺口格照矩陣優先序燒（捕俘存儲統一 Phase 2、背叛已折、E-2、subteam…）。
