### Background

`skill_system.gd` has `class_name SkillSystem` with `const MAX_SKILL: float = 1.0`. GDScript 4.2 supports `static func` — callers can call `SkillSystem.cap_add(p, skill, delta)` without instantiation.

Four places currently inline the same capping logic:
- `skill_system.gd:_grow()` line 63: `p.skills[skill] = minf(float(p.skills.get(skill, 0.0)) + growth, MAX_SKILL)`
- `interaction_system.gd:_grow_commerce_skill()` line 935: `p.skills["商業"] = minf(float(p.skills.get("商業", 0.0)) + growth, 1.0)`
- `manufacturing_system.gd:_grow_skills()` line 116: `p.skills["製造"] = minf(float(p.skills.get("製造", 0.0)) + growth, 1.0)`
- `vision_system.gd:_grow_skill()` line 70: `p.skills[skill] = minf(float(p.skills.get(skill, 0.0)) + growth, 1.0)`

All four grow their own `growth` value locally — that logic stays. Only the final `minf(current + delta, cap)` line gets replaced.

static func cap_add(person: PersonData, skill: String, delta: float) -> void:

In `scripts/simulation/population_system.gd`, replace the entire `check_overflow` function and add the new public function:

```gdscript
func check_overflow(state: WorldState) -> void:
	for tid in state.teams.keys():
		check_overflow_for_team(state, tid)

func check_overflow_for_team(state: WorldState, tid: int) -> void:
	if not state.teams.has(tid):
		return
	var team: TeamData = state.teams[tid]
	var leader = state.persons.get(team.leader_id)
	var cmd: float = float(leader.skills.get("統領", 0.0)) if leader else 0.0
	var cap: int   = TeamData.pop_cap_from_leadership(cmd)
	var overflow: int = team.population - cap
	if overflow <= 0:
		return
	var spare_id: int = -1
	for nid in team.named_members:
		if nid != team.leader_id:
			spare_id = nid
			break
	if spare_id != -1:
		SubteamSystem.new().dispatch(state, tid, spare_id, overflow, "idle", team.tile_pos)
		print("[PopMgmt] Team%d 超額 %d 人，advisor Team%d 帶走" % [tid, overflow, spare_id])
	else:
		_create_overflow_team(state, team, overflow)
```
