## §1 做什麼

```
①★**一支分類函式**決定「這一個 pass 這隊有沒有耗力」（單一來源，`_step6d_fatigue` 與床都呼它）：
  耗力 ＝ 這個 pass **真的移動了**（`_run_systems` 的 `moved` 陣列，`sim_runner.gd:470` 已存在）
        **或**在戰鬥中（`combat_target != -1` 或 encounter 參與方）
        **或**當下任務屬於「執行即耗力」那一組（採集／施工／搬運 —— 組名用 TeamData 既有常數列一張表，表放在分類函式旁）
  不耗力 ＝ 其餘（駐守、紮營、idle、在市集交易、夜裡沒移動）
  ⇒ 耗力 ⇒ 照現行累積算式（常數不動）；不耗力 ⇒ 照現行回復算式（`FATIGUE_RECOVERY_PER_DAY`，常數不動）
  ⇒ ★`moved` 要傳進 `_step6d_fatigue`（它今天只拿 team_ids）—— 確認 fatigue 在 move **之後**跑（registry 順序），否則讀到的是上一個 pass
②★「休息」決策選項（新，`options.gd`）：進**求生需求層**（體力那一格），util ＝ 疲勞 × 人格（慎重／求生欲）
  ⇒ to_task ＝ TASK_REST（原地，target ＝ (-1,-1)）—— ★這是 TASK_REST 的**第一個寫入者**
  ⇒ ★禁「疲勞 > X 強制休息」硬門檻（util 秤，不 override）
  ⇒ 它的意義是「主動停下來」：選了它就不移動 ⇒ 由 ① 自然進入不耗力 ⇒ 回復；`rest_mult`（崗哨）照現行
  ⇒ 連帶：`npc_combat_system.gd:820` 夜襲判定讀 TASK_REST —— 有了寫入者後這條第一次會活起來（紮營無崗哨易被夜襲）⇒ 寫進交件
③玩家面：生存分頁一欄印疲勞（數值＋文字級距）；玩家「休息」指令（終端自驗床加一格：走法到生存分頁，疲勞欄與休息鍵都在）
```

## §2 驗收（藍圖的四格＋我加兩格）

```
P1 [每隊都會降] 30 天內 **51／51 隊**（母體印出）fatigue 至少下降一次
P2 [紅基線，只准變少] 全界在地板（mult＝0.3）的隊·tick 比例 ⇒ 本輪數當基線
P3 [反向] 移動中不得回復：任何 `moved` 的 pass，fatigue 不得下降
P4 [駐守一夜必降] 佈置一支駐守的隊過一夜 ⇒ fatigue 下降
P5 [分類窮盡] 每個 pass 每隊恰落一類（耗力／不耗力），Σ ＝ 該 pass 處理的隊數
P6 [休息被選過] 30 天內「休息」至少被某隊選中一次，且 util 隨疲勞上升（印疲勞 vs util 的對照）
   ⇒ ★若 0 次：不是加門檻，是回報（util 秤錯了 —— 判準庫：被吸收的需求不會回來敲門）
P7 fp 會變 ⇒ 量、基準與改動原子落地
★T 修完後，票 T 的三格（中位／撞上限比例／地形差）應該自己變綠；剩下的才是地形／隊速題
```
