## §3 ★★★月交易量的推導 —— **而它有一個【我不打算藏起來】的假設**
```
★最小的同源估法(全部來自 §2):
   月食物需求 = Σ_teams pop × FOOD_PER_PERSON_PER_DAY × 30 × BASE_PRICE["food"]
★★而【交易量 ≠ 消費量】:自己種得出來的糧【不會進市場】
   ⇒ 用總消費當交易量【會高估】,而高估多少【取決於自產率】——
   ⇒ ★★★而【自產率是湧現的,worldgen 當下不知道】
```
**⇒ 兩條路，我選第二條**：
```
✗ 硬選一個「交易佔比」係數 ⇒ 那就是【新的手抄常數】,而它會被當成物理
✅ ★把【總消費值】當成【明確具名的上界】,而讓 k 吸收那個比例:
     初始 coin 總量 = (Σ pop × FOOD_PER_PERSON_PER_DAY × 30 × BASE_PRICE["food"]) × k
   ⇒ ★★而【k 的意義因此改變】:它不只是「幾個月的週轉」,
     它同時吸收了【交易佔消費的比例】—— ★★★這件事要寫在 code 註解裡,不是只寫在 spec
   ⇒ ★而 k=2 起跑(用戶裁 2 或 3)⇒ pilot 漂移一輪內定
```
★★**而驗證床要量【真值】**：**前 90 日的實際月交易量**（市場成交額 ＋ 隊間 trade 成交額），
⇒ **拿它跟推導值比** ⇒ ★★★**那才是「k 該是 2 還是 3」的證據，而不是感覺。**
