# HOW spec：成功的結果句要用 handler 自己的話（67 條句子今天到不了玩家）

owner: systems ｜ 2026-09-25 ｜ **player_reachable: yes**
上游：不需要新 WHAT —— blueprint 的回饋契約②（指令佇列 spec §3-5）已經裁過
「消費點必回結果句：成功一句／拒絕一句＋原因」。本票修的是**那條原則只被套用在一半的分支上**。
發現者：implementer（2026-09-25，做打聽 v1 時撞到）。

---

## ★★★§1 前提（逐字，`sim_runner.gd:566-571`）

```gdscript
var why: String = String(res.get("message", res.get("msg", "")))
state.command_results.append({
  ...,
  "text": ("%s：完成" % PlayerCommandApi.describe(name, args)) if ok
       else ("%s：被拒絕（%s）" % [PlayerCommandApi.describe(name, args),
              why if why != "" else "沒有給原因"])})
```
```
★`why` **算出來了，而它只餵給【拒絕】那一支**。
★★而同一段的註解自己寫著：「原因取自 handler 自己回的 message ⇒ 零第二份真相」
  ⇒ **那條原則只套用在一半的分支上。**
★★★母體已量（★★訂正後）：`player_command_system.gd` 有 **67 個** `"ok": true, "msg": ...` 的回傳
  （其中 33 條帶格式化參數，例：「索貢成功（獲得 %.0f coin）」「拔擢 %s 為記名成員」）
  ⇒ **全部到不了玩家**；玩家看到的是「<動作人話>：完成」。
```

## §2 做什麼（一行）

```
成功時：`why` 非空 ⇒ "%s：%s" % [describe(name,args), why]
        `why` 為空 ⇒ 維持 "%s：完成"
★保留 `describe` 當前綴（不要只印 msg）—— 前綴是玩家分辨「哪一道指令」的那一半。
★★不新增欄位、不動 handler、不動拒絕那一支。
```

```
  「等待確認」「選擇招募方式」（兩段式動作的第一步）
  ⇒ 換上去之後玩家會看到「打聽情報：選擇招募方式」這種句子。

  ⇒ 先讓它們【看得見】（§4 P2），怪的那幾條再逐條處置。
```

## §4 驗收

```
P1 [換得上] 一個會回 msg 的成功動作 ⇒ 結果句 ＝「<動作人話>：<handler 的話>」
   ｜★負對照：把換用那一行改回寫死「完成」⇒ P1 必紅
P2 ★★★[母體看得見] 床把那 67 條**全部印在卷面上**（來源檔＋行號＋字面）
   ⇒ 「哪幾條讀起來不像結果」自己現形，而不是等玩家撞到
   ｜★母體地板：印出來的條數要跟一個【來自 spec 的常數】比（本票寫 67），
     ★★不要拿「印了幾條」跟「掃到幾條」比 —— 那是自己跟自己比，寫幾條都會綠
P3 [空的仍退回] 一個成功但不回 msg 的動作 ⇒ 仍印「…：完成」（不得印出空的冒號）
P4 [拒絕那一支沒動] 一個會被拒絕的動作 ⇒ 句子逐字不變
P5 [fp] `command_results` 的 text 會變 ⇒ ★**world-fp 變是預期內的**（它進 canon）
   ⇒ 基準值與本改動【同一顆 commit】落地
P6 ui-flow 綠；merge 前全電池 BATTERY_RC=0
```

## ★★★§7 訂正：那個常數本身的【來源】差點讓 P2 恆真（R² 抓出，2026-09-25）

```
★我原本寫 65，而它是用【同一行 `"ok": true, "msg":`】這種窄比對數出來的。
★★R² 用寬視窗獨立數一次＝67；我自己重數也是 67：
   `"ok": true` 的回傳共 67 處，而窄比對抄到 65，差的兩條是
   `:798`（msg 在下一行）與 `:1270`（用 `message` 鍵不是 `msg`）
   ⇒ 兩集的聯集 65＋2 ＝ 67 ＝ `"ok": true` 的總數
   ⇒ ★**每一個成功回傳都帶話**，所以 67 才是真正的母體。
★★★而這一條比數字錯了更重要：**漏洞藏在【常數從哪裡來】而不是【比對邏輯】**。
  若 implementer 寫 P2 的掃描時用了跟我一樣窄的比對，它會剛好也停在 65
  ⇒ 與 spec 的 65 【互相印證】⇒ 綠燈，而那兩條從頭到尾沒被列進卷面。
  ⇒ ★★這就是 P2 自己在警告的「自己跟自己比」的另一個變體。
⇒ ★★★**動工前的硬規**：先用【寬視窗】獨立驗一次真實條數，
  **不要直接信 spec 的 67**；若數出不同的數，回信而不是默默改常數。
```
