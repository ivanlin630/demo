# §0 這一票為什麼存在（★不是「多一個欄位」，是【拆掉一個 god-view】）

**blueprint 的裁定**：「第二個消費者」的合格證據 ＝ **已經為欄位缺席付出成本的 code**（建了 proxy ＋ 自書缺陷）
＞ 說將來會用的論證。`faction_ai_system.gd:5884` 付過費 ⇒ 算 ⇒ **據點 claim 欄准開**，三件綁定（§2）。

## ★★★而我查了那個消費者的內部，它比註解說的更嚴重

`_enemy_outpost_positions()`（`faction_ai_system.gd:5876-5891`）逐字：
```gd
for tile_id in state.world.tiles:            # ★全圖掃【真實 tile】
    if tile.outpost_level == 0: continue     # ★★live 讀：這格有沒有據點
    var owner := state.teams.get(tile.outpost_owner)   # ★★live 讀：它是誰的
    …
    if BeliefSystem.belief_pos(state, leader_team.team_id, owner.team_id) == Vector2i(-1,-1): continue
    out.append(tile.tile_pos)
```
★**地點知識【整段是 god-view】**：據點在哪、是誰的，都直接讀真實 tile。
★★**那道 belief 閘擋的不是地點，是【主人】** —— 它問「我對這支隊有沒有情報」，
**而不是「我有沒有看過這座城」。**
★★★**所以它有兩個方向的錯，而註解只寫了一個**：

| 方向 | 現況 | 註解有沒有寫 |
|---|---|---|
| ① **知道得太多**：我沒看過這座城，但因為我見過它的主人（可能在千里外看到的）⇒ **它對我存在** | 是 | ★**有**（「belief_pos 給 owner 隊 last-seen 非據點位；owner 可 roam」） |
| ② ★★★**知道得太少**：**我親眼走過那座敵城**，但我從沒見過它的主人 ⇒ **它對我不存在** | 是 | ★**沒有** —— 這一個方向沒有人寫下來過 |

⇒ **這一票不是「換一個比較準的欄位」，是把【地點的知識】從 god-view 拆出來。**

# §1 資料形狀（★★★這是要 R② 打的主決策）

**消費者的存取樣式決定形狀**：它要的是「**把我知道的敵據點列出來**」，
**不是**「關於某支隊，我知道什麼」。
```
(A) 掛在 team-belief 的 claim 上（value 多一個 outpost_pos）
    ★問題：消費者要【列舉】，就得掃過所有隊的 belief 再反查 ⇒ 形狀不合
    ★★而且一支隊可以有多座據點 ⇒ 單欄位裝不下，變成陣列 ⇒ 更不像 belief 的其他欄
(B) ★【地點鍵】的觀察者知識：observer → { tile_pos → {owner_id, level, last_tick} }
    ★問題：這是一個新 store（blueprint 註解當年正是為了【免建 team_outpost_known 大 store】才用 proxy）
```
```
(C) ★★★【R② 2026-09-17 補上的第三個選項 —— reviewer 挖出來的，我原本沒問過自己】
    `state.team_tile_known`（`world_state.gd:57`）**已經存在**：觀察者 → {tile_id: true}，
    寫入端 `BeliefSystem.harvest_tile_known`（`belief_system.gd:317-334`）已經在跑
    （bounded vision ＋ relay、零 RNG），且**已有兩個生產消費者**
    （`faction_ai_system.gd:7435-7474` 佔村候選掃／`strategic_ai_system.gd:305-317` 商隊找據點位）。
    ★**它只是欄位淺**（值就是 `true`，沒有 owner／level／時戳）。
```
★**我裁 (C)：延伸既有的 `team_tile_known`，不開平行新 store** —— 而且它比我原本的 (B) 好：
★★**最貴的那一半【寫入端】已經建好了**（觀察怎麼變成知識的那條路）——
**而寫入端正是 god-view 出生的地方**；開一個平行 store 等於把那條路再寫一次（〈禁第二份實作〉）。

## ★★★但延伸要守一條線：不要把兩個【衰減理由不同】的事實壓成一個值

```
「我見過這塊地」    ← ★不會過期（地不會走、也不會消失）＝ 現在 key 存在的那個語意
「它當時有一座 L 級據點、屬於 T」← ★★會過期（可能被拆／易主）＝ 我要加的東西
```
★**若把它們壓成同一個值，就是我在上面否決 (A) 時用的【同一個錯】**（兩個層混回去）。
⇒ **形狀**：
```
known[tid] = true                       ← ★★保留：key 存在 ＝ 見過這塊地（語意逐字不變）
known[tid] = {"outpost": {...}, ...}    ← ★加值時，key 仍然存在 ⇒ 舊消費者的 `has()` 判斷不變
   outpost = {"owner_id": int, "level": int, "last_tick": int}   ★★★自己的時戳，自己的線
```
★**舊的兩個消費者只問 `has(tid)`** ⇒ 只要 key 還在就行為不變（★**這一點要驗，不要用猜的** ⇒ 格 3-g）。

## ★★★ relay 進來的 tile 不得帶據點子記錄（§1a）
`harvest_tile_known` 有**兩條**寫入路徑（`:320-327` 視野內 ／ `:329-333` relay 訊息位置）：
```
視野內  ⇒ ★親見 ⇒ 可以寫據點子記錄（外觀層、看得到）
relay   ⇒ ★★只聽說【有這麼一個地方】⇒ **不得**寫據點子記錄（我沒看過它的城）
```
★**這一條就是 §1a 的「三態」在地點上的樣子**：**見過這塊地 ≠ 看過它上面有什麼。**
⇒ 格 3-h 盯它。
