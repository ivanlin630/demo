# §0 這一票為什麼存在（★不是「多一個欄位」，是【拆掉一個 god-view】）

**blueprint 的裁定**：「第二個消費者」的合格證據 ＝ **已經為欄位缺席付出成本的 code**（建了 proxy ＋ 自書缺陷）
＞ 說將來會用的論證。`faction_ai_system.gd:5884` 付過費 ⇒ 算 ⇒ **據點 claim 欄准開**，三件綁定（§2）。

## ★★★而我查了那個消費者的內部，它比註解說的更嚴重

`_enemy_outpost_positions()`（`faction_ai_system.gd:5876-5891`）逐字：
```gd
for tile_id in state.world.tiles:            # ★全圖掃【真實 tile】
    if tile.outpost_level == 0: continue     # ★★live 讀：這格有沒有據點
    var owner := state.teams.get(tile.outpost_owner)   # ★★live 讀：它是誰的
    …
    if BeliefSystem.belief_pos(state, leader_team.team_id, owner.team_id) == Vector2i(-1,-1): continue
    out.append(tile.tile_pos)
```
★**地點知識【整段是 god-view】**：據點在哪、是誰的，都直接讀真實 tile。
★★**那道 belief 閘擋的不是地點，是【主人】** —— 它問「我對這支隊有沒有情報」，
**而不是「我有沒有看過這座城」。**
★★★**所以它有兩個方向的錯，而註解只寫了一個**：

| 方向 | 現況 | 註解有沒有寫 |
|---|---|---|
| ① **知道得太多**：我沒看過這座城，但因為我見過它的主人（可能在千里外看到的）⇒ **它對我存在** | 是 | ★**有**（「belief_pos 給 owner 隊 last-seen 非據點位；owner 可 roam」） |
| ② ★★★**知道得太少**：**我親眼走過那座敵城**，但我從沒見過它的主人 ⇒ **它對我不存在** | 是 | ★**沒有** —— 這一個方向沒有人寫下來過 |

⇒ **這一票不是「換一個比較準的欄位」，是把【地點的知識】從 god-view 拆出來。**

# §1 資料形狀（★★★這是要 R② 打的主決策）

**消費者的存取樣式決定形狀**：它要的是「**把我知道的敵據點列出來**」，
**不是**「關於某支隊，我知道什麼」。
```
(A) 掛在 team-belief 的 claim 上（value 多一個 outpost_pos）
    ★問題：消費者要【列舉】，就得掃過所有隊的 belief 再反查 ⇒ 形狀不合
    ★★而且一支隊可以有多座據點 ⇒ 單欄位裝不下，變成陣列 ⇒ 更不像 belief 的其他欄
(B) ★【地點鍵】的觀察者知識：observer → { tile_pos → {owner_id, level, last_tick} }
    ★問題：這是一個新 store（blueprint 註解當年正是為了【免建 team_outpost_known 大 store】才用 proxy）
```
★**我裁 (B)**，三個理由：
1. **消費者的動詞是【列舉】**，(A) 要反查 ⇒ 形狀不合是設計問題不是效率問題。
2. ★★**blueprint 自己已經把層拆開**（他 2026-09-17 原話：「不動產的知識不該走 team-belief 的過期線 ——
   這句我原裁混了兩個層」）⇒ **(A) 正是把兩個層又混回去。**
3. ★★★**過期語意不同**：隊的位置會過期是因為**它會走**；
   據點的知識會過期是因為**它可能被拆／易主** —— **兩個衰減理由不同，不該共用一條線。**
   ⇒ (B) 讓它有自己的線；(A) 會強迫它借 `BELIEF_STALE_TICKS`（**而那條線我已裁該物理化、且不在這票動**）。

★**規模的誠實標**：當年那句「免建大 store」是**真的考量**。
⇒ **§4 要量**：`observer × 已知據點` 的實際條目數（世界級 10 天）。
★★**若它真的大到不能接受，正確反應是回來改形狀，不是偷偷退回 god-view。**

# §2 blueprint 的三件綁定（逐字執行）

| # | 他的話 | 我的落法 |
|---|---|---|
| ① | 寫入 ＝ 親見據點時（外觀層合法，零 god-view） | 在**已經發生親見**的那條路徑上寫（`vision_system` 記錄親見的同一刻）——★**不新增一條「掃描據點」的路徑**：看得到就記，看不到就沒有 |
| ② | `:5884` 那個 proxy **遷移**到真欄，**換掉不並存** | `_enemy_outpost_positions()` 改成**列舉觀察者自己的據點知識**；★**全圖 `for tile_id in state.world.tiles` 那一段刪掉**（★★殘留 ＝ 下個讀者的陷阱，同族：殘表教訓） |
| ③ | 它自書的缺陷案例釘成**成對對照** | §3 格 3-a／3-b（★**而我要釘的是【兩個方向】**，註解只寫了一個） |

★**另外一條 blueprint 明令**：**錨定性 decay 那條【不接】這個新欄** ——
他原話「你量到反向（受害者有家佔比低於母體），那條路的答案已經是『不需要』，**別因為欄開了就順手接**」。
⇒ ★★**寫進驗收**：格 3-e ＝ `decision_context` 的錨定判準**逐字未改**（仍只認 `ACT_SETTLED`／`ACT_BUILDING`）。

# §3 驗收（★每格能紅，★★而 3-a／3-b 是【成對】的）

| 格 | 內容 | 反向（機制關掉要紅） |
|---|---|---|
| 3-a | ★**知道得太多那一半消失**：觀察者**見過 owner**（在別處）、**沒見過那座據點** ⇒ 據點**不在**它的迴避集 | 退回 proxy ⇒ 它會在 ⇒ 紅 |
| 3-b | ★★**知道得太少那一半消失**：觀察者**親眼走過那座據點**、**從沒見過 owner** ⇒ 據點**在**它的迴避集 | 退回 proxy ⇒ 它不在 ⇒ 紅（★**這一格是註解沒寫的那個方向**） |
| 3-c | ★**零 god-view**：`_enemy_outpost_positions()` 內**不再出現** `state.world.tiles` 全掃與 `tile.outpost_owner` live 讀 | 殘留任何一個 ⇒ 紅 |
| 3-d | ★**三態**：從沒觀察過 ⇒ 空集（**不是** fallback 到全圖）；觀察過但很舊 ⇒ **仍在集合裡**（據點不會自己走），★而**舊到什麼程度仍算數**由本票自己的線決定，**不借 `BELIEF_STALE_TICKS`** | 借了那條線 ⇒ 紅 |
| 3-e | ★★**錨定性逐字未改**（blueprint 明令不接） | 有人順手接上去 ⇒ 紅 |
| 3-f | ★**世界級**：迴避行為**兩個方向都真的發生過**（各 ≥ 1 例，帶 tap），★★**且對照落在會改變行為的區間**（★前一票的教訓：不要在「兩條路都走得到」就收） |
