# 決策引擎架構重構 — 需求金字塔驅動決策（blueprint WHAT）

> 2026-07-13 brainstorm定案。blueprint願景層。HOW（公式/TEST VALUE/seam）交systems。

## 動機（真根，本session established調查鏈挖出）

established調查鏈六輪深入查證，逐層修（farming死鎖→A門人口→B2統領閘→leader週轉→急性崩→四道B門）後發現：**每個門各自修完，established依然卡死或只鬆一點縫**，且逐層修呈現「打地鼠」模式。

深入到決策引擎本身才發現真根：**現有決策模型不是真正的統一框架，是N個互相不知道彼此存在的獨立term生成器**（intent/phase/survival/threat/faction_duty/loot_drive/occupy_drive/join_drive/camp_drive/buyfood_drive/diplo_drive/levy_drive/attack_drive/train_drive……）。每個term各自從原始世界資料獨立推導一個信號，只在`rank_scored`最後加總成一個公式——**看起來統一（單一公式），實際上是一鍋粥（N個瞎子各自投票，彼此互不知道對方在算什麼）**。

具體症狀：`select_strategic_intent`選「征服」（推訓練/攻擊加分）跟`derive_plan_phase`判「成長」（推紮營/返家補給加分）同時獨立算，沒人協調，隊伍行為在訓練跟紮營之間搖擺，沒有連貫故事。`plan_phase`的ESTABLISH階段偏置是空的（`{}`），立國仍完全靠一個跟這整條鏈脫節的機械四重AND閘——這正是「瞎子各自為政」架構問題在立國這個點上的具體症狀，非孤立bug。

**這個專案自己歷史上宣稱的「統一決策框架」**（真根=AI決策不統一,DecisionEngine utility weigh）只解決了「不要有第二個競爭引擎」（技術上正確：沒有bespoke planner跟rank_scored打架），但**沒有解決語意層的統一**——沒有真正的統一可以被本次重構「打破」，因為現況本來就是假統一。

## 核心原則：不建第二個引擎，是給第一個引擎接上真正的認知

延續本專案「延伸階梯，非新求解器」的既有原則——這次重構**複用**：
- 既有rung/milestone累進門檻（重新賦予真正驅動intent的功能，非只是顯示天花板）
- S1已驗證的EWMA趨勢+crash-bypass機制（複用給needs金字塔的active層判定，也複用給威脅/安全需求的持續期累積）
- 既有archetype/disposition_scores（人格決定風格，不決定要不要追求）
- 既有plan_phase_drive偏置機制（延伸為前瞻偏置的實作基礎）
- 既有found_score/weak_enemy（複用當「賭命跳關」的目標價值判準）

**仍是`rank_scored`一個求解器**——這次重構不新增決策器，是重新設計「誰給rank_scored餵訊號、訊號之間怎麼協調一致」，取代現況N個獨立瞎子。

## 架構設計

### 1. 需求金字塔（Maslow式，複用既有rung/milestone累進門檻）
```
生存需求(食物) → 安全需求(威脅/危險) → 歸屬需求(faction/社交) → 尊重需求(地位/征服/擴張) → 自我實現(立國/稱霸)
```
威脅/危險**不是外掛插斷系統**，是金字塔裡「安全需求」那一層本身——用同一套主腦邏輯判定，非平行系統。

### 2. Active需求判定（複用S1+S3已驗證機制）
- **正常情況**：active需求 = 當下最低的未滿足需求層（Maslow優先滿足原則：下層沒滿足，上層不會被啟動當主導）。判定用EWMA趨勢窗（避免瞬間亂跳），需求層升降對應milestone達成/持續失敗（複用S1機制）。
- **威脅/安全需求的累積**：威脅訊號同樣走EWMA趨勢累積（持續低強度威脅會累積成警覺，瞬間尖峰不會立刻打亂節奏），劇變（車子突然衝過來）走crash-bypass立即reprioritize（複用S3機制）。

### 3. 賭命跳關（人格打破金字塔順序，非鐵律）
```
賭命跳關觸發 = 絕境程度夠深（當前需求層持續嚴重失敗，crash-bypass級劇變）
             AND 目標夠有價值（要跳去的上層追求有一個分數夠高的具體標的，複用found_score/weak_enemy）
             （人格：低謹慎+高野心 決定兩條件到位時觸發機率/強度，不決定條件是否存在）
```
低謹慎+高野心的leader，在「照順序爬也是死」的絕境下，遇到夠份量的賭注（不是隨便一個小機會），會破釜沉舟跳過當前未滿足需求，直接賭上層追求（例如無視飢餓直接攻擊）。**兩條件缺一不可**，避免狂人24小時梭哈。

### 4. Intent導出
active需求層 → 決定追求方向（求生/備戰/結盟/擴張/立國等）；人格值（含現有archetype武力/商業/定居）決定「用什麼風格追求」該方向，不決定「要不要追求」。

### 5. 候選池篩選（真篩選，取代現況純加分）
intent → narrow `rank_scored`的23個option候選池（真的排除不相關選項，非只加一點分讓它有機會贏）。在篩選後的候選池內，`rank_scored`仍是唯一決策點，做最終argmax。

### 6. 前瞻偏置（輕量版，非重量級展望模擬）
```
prep_bias強度 = f(當前需求層進度比值)：進度<70% → 0；70%~100% → 線性爬升到某上限（低於當前層主偏置）
```
當前需求層接近滿足門檻時，對**下一層**典型行動加一個較弱的偏置（複用`plan_phase_drive`的MAG偏置機制，延伸應用到下一層），讓行為從「階段式突然切換」變成「連續漸進」，產生「正在準備」的感覺。**強度上限低於當前層主偏置**，不搶主導權。

### 7. 不變的部分
- `faction_duty`（服從母團命令：攻擊/徵收/歸建）維持現況——這是「社會權威層級」而非「個人需求」，不同性質的gate，不折進金字塔。
- 子隊`STRATEGIC_SELFINIT_SET`限制維持不變。

## 驗收
- **行為連貫性**：同一隊不會在同一階段內於不相關行動間搖擺（例如同時被拉向訓練又拉向紮營），organic多seed跑驗證。
- **候選池真篩選**：驗證intent確實排除不相關option，非只是加分（可測「征服intent下，隊伍幾乎不選貿易/乞食」這類負向驗證）。
- **賭命跳關可觀測**：低謹慎高野心隊在絕境+高價值標的下確實有機率跳關，且發生頻率遠低於「24小時常態」（不能變成常見行為）。
- **established調查鏈收尾**：this redesign完成後，established是否終於>0（既有B2/B3/B4門檻問題，理論上因為「有意圖層篩選」而非「條件過了機械觸發」，用戶原本否決的「人人可立國」疑慮應該被架構本身解決，非額外補丁）。
- **determinism**：全流程byte-identical驗證（同session先例）。
- **統一框架自審**：確認這次改動沒有製造第二個獨立引擎——所有需求判定/intent導出/候選池篩選最終仍只餵訊號給`rank_scored`一個函式做最終argmax。

## 對established調查鏈的意涵
- 現有farming死鎖修/forage-floor-tune修**保留**（這些是「候選池內某個option能不能被選中」層級的修正，不受這次架構重構影響——架構重構動的是「怎麼決定候選池+怎麼協調訊號」，不是這些底層option本身的機制）。
- B2統領閘/B3野心倒序/B4 readiness——這次架構完成後需要重新評估：**立國本身應該成為需求金字塔「自我實現」層的intent**，而非現況脫節的機械四重AND閘。B2/B3/B4門檻可能降級為「立國intent的風格修飾」（人格驅動追求立國的強度/速度），而非硬gate——但這是「立國」如何被架構進需求金字塔的具體HOW，交systems設計。
- 繁殖/pop成長瓶頸arc——維持獨立，這是候選池內某個option（繁殖/征服吸收/俘虜）本身的機制問題，不受架構重構直接影響，architecture重構完成後再視organic數據決定優先序。
