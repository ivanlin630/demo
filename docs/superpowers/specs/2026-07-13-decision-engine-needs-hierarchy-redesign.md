# 決策引擎架構重構 — 需求金字塔驅動決策（blueprint WHAT）

> 2026-07-13 brainstorm定案 v2（R①打回後重新設計，正面回應四項風險，非縮小範圍迴避）。blueprint願景層。HOW（公式/TEST VALUE/seam）交systems。

## 動機（真根，本session established調查鏈挖出）

established調查鏈六輪深入查證，逐層修（farming死鎖→A門人口→B2統領閘→leader週轉→急性崩→四道B門）後發現：**每個門各自修完，established依然卡死或只鬆一點縫**，逐層修呈現「打地鼠」模式。

深入到決策引擎本身才發現真根：**現有決策模型不是真正的統一框架，是N個互相不知道彼此存在的獨立term生成器**（intent/phase/survival/threat/faction_duty/loot_drive/occupy_drive/join_drive/camp_drive/buyfood_drive/diplo_drive/levy_drive/attack_drive/train_drive……）。每個term用**各自不同的公式**從原始世界資料獨立推導一個信號，只在`rank_scored`最後加總成一個公式——**看起來統一（單一公式），實際上是一鍋粥（N個瞎子各自投票，彼此互不知道對方在算什麼）**。

具體症狀：`select_strategic_intent`選「征服」（推訓練/攻擊加分）跟`derive_plan_phase`判「成長」（推紮營/返家補給加分）同時獨立算，沒人協調，隊伍行為在訓練跟紮營之間搖擺，沒有連貫故事。`plan_phase`的ESTABLISH階段偏置是空的（`{}`），立國仍完全靠一個跟這整條鏈脫節的機械四重AND閘——這正是「瞎子各自為政」架構問題在立國這個點上的具體症狀，非孤立bug。

**這個專案自己歷史上宣稱的「統一決策框架」**只解決了「不要有第二個競爭引擎」（技術上正確：沒有bespoke planner跟rank_scored打架），但**沒有解決語意層的統一**——沒有真正的統一可以被本次重構「打破」，因為現況本來就是假統一。

## v1被R①打回的四項風險 + 這版怎麼正面解決（非迴避）

v1提案（needs金字塔單選active層+候選池硬排除+威脅硬塞進金字塔+賭命跳關用found_score）被reviewer抓到四個真實風險。這版**不是縮小範圍迴避**，是重新設計解決：

| v1風險 | v2解法 |
|---|---|
| 候選池硬排除=「條件過不了永遠死鎖」同構bug | 改**軟性重度降權**（見§3），且降權曲線隨「持續卡住多久」自動鬆綁（複用EWMA停滯偵測，第三次同款複用） |
| 威脅=金字塔一層 vs 既有PRIO_SURVIVAL插隊機制自相矛盾 | 改**同一判斷、雙速輸出**（見§5）：低於劇變門檻走金字塔慢判斷；達劇變門檻直接輸出TaskArbiter插隊（不繞過既有機制，是同一訊號源分岔成兩種派發速度），且插隊事件結束後**回寫**主腦安全需求急迫度（見§5.2），非切割的獨立系統 |
| EWMA(單一遞增數字rung)硬套「多層選一層」判定，形狀不匹配 | 改**每層各自EWMA平滑同一款公式**（非硬套rung的邏輯），且**放棄單選active層**，改五層平行急迫度混合（見§2），根本不需要「選哪層」這個判定 |
| found_score/weak_enemy答非所問（建國/打弱敵專用分硬套通用價值判準） | 賭命跳關**整個機制取消**，改成候選池降權公式裡的連續參數（見§4），不需要額外的「目標價值」判準 |

## 核心原則：不建第二個引擎，是給第一個引擎接上真正的認知

延續本專案「延伸階梯，非新求解器」的既有原則。**仍是`rank_scored`一個求解器**——這次重構不新增決策器，是重新設計「誰給rank_scored餵訊號、訊號之間怎麼協調一致」，取代現況N個獨立瞎子。

**架構紀律（守住「非第二引擎」的關鍵）**：以下所有機制只能產生**乾淨的數字/係數**餵給`rank_scored`最後一步的加總，**不能自己決定選哪個行動**。感測（算急迫度/係數）可以有很多個，決策只能有一個。

## 架構設計

### 1. 需求金字塔（Maslow式，複用既有rung/milestone累進門檻）
```
生存需求(食物) → 安全需求(威脅/危險) → 歸屬需求(faction/社交) → 尊重需求(地位/征服/擴張) → 自我實現(立國/稱霸)
```

### 2. 急迫度（五層平行，非單選active層）
**放棄「選一個active需求層」的設計**，改為：**每一層各自算一個急迫度分數**（0~1，越沒滿足越高），五層**同時存在、平行貢獻**，不是二選一開關。

- 每層急迫度 = 該層底層指標（食物流/威脅累積/faction人數/尊重滿足度/立國條件）距離門檻的差距，經EWMA平滑（同一套公式套用在5個不同指標上，非硬套rung的單一數字邏輯——這是v1被抓到的具體錯誤，這版訂正）。
- 5個急迫度不互相知道彼此存在，各自純粹是「這層還缺多少」的讀數——**是感測器，不是決策者**（見上方架構紀律）。
- **前瞻/漸進效果天然浮現，不用額外機制**：當某層急迫度隨滿足程度下降，另一層的急迫度會自動在混合結果裡佔比升高——這就是原本v1想用「前瞻偏置」額外機制做的事，現在是五層平行混合的自然結果，不用另外設計。

### 3. 候選池篩選（軟性重度降權，非硬排除；卡住會自動鬆綁）
```
最終分數(option) = 既有term總和(option) × 一致性係數(option, 五層急迫度混合)
```
- **一致性係數是一張新表**（option → 跟哪些層有affinity，類似現有REGISTRY的結構），對**全部23個option統一套用**（v1只有intent/phase涉及的11個option有偏置，這版全覆蓋，這是回應「其餘12個term還是獨立」的缺口）。不改20個既有term函式的內部邏輯，只在`rank_scored`最後加總這一步乘一個係數，風險最小。
- **軟性降權，非硬排除**：不相關的option被壓低但不歸零，理論上仍可能被選中（只是要非常極端的情況）。
- **卡住自動鬆綁**：若某層急迫度持續高檔很久、但該層對應option持續選不中/持續失敗（複用EWMA停滯偵測），降權強度會逐漸放鬆，避免v1那種「條件過不了永遠不可能」的死鎖模式。

### 4. 人格決定降權曲線陡度（取代賭命跳關，非額外機制）
不做獨立的「賭命跳關」觸發判斷（found_score答非所問，整個機制砍掉）。改為：**人格（謹慎度/野心）決定§3一致性係數表裡「跟當下急迫度層距離越遠的option，降權曲線多陡」**——謹慎的人，距離遠的option降權壓得極重（幾乎不考慮）；狂人，降權曲線平緩（遠層option也還有機會被選中）。

任何隊伍理論上都能「跳階」，不是狂人專屬——差別在於門檻高低（人格決定），不是二元開關。絕境（近層急迫度高但對應option持續低分）+機會夠好（遠層option若有客觀存在的機會訊號，如weak_enemy/可達盟友，這些訊號本身也是既有的、跟人格無關的，各自只影響其對應option在§3表裡的基礎分，非另開判準）**自然疊加**讓遠層option分數浮出，不需要額外的「賭命跳關」觸發邏輯。

### 5. 威脅——同一判斷，雙速輸出（非硬塞進金字塔，也非維持現況不動）

#### 5.1 雙速機制
威脅訊號統一由一個判斷處理，依嚴重度輸出兩種派發速度：
- **一般威脅**（低於劇變門檻）：走EWMA累積，影響「安全需求」層的急迫度（§2），走正常的候選池降權+rank_scored流程（慢，深思）。
- **真正致命威脅**（達crash-bypass級劇變門檻，複用S3判準）：同一個判斷直接輸出**TaskArbiter優先插隊**（`PRIO_SURVIVAL`同款機制），繞過候選池/rank_scored，反應跟現有插隊機制一樣快（反射）。

#### 5.2 事件回寫（解決v1「威脅=金字塔一層」的自相矛盾，同時解決「插隊機制是否有回饋主腦」）
插隊事件處理完後，**必須把這次事件寫回§2的「安全需求」急迫度**——不只是平常的慢速累積，經歷一次真正的劇變insert後，安全需求急迫度**直接大幅推高**（類似受驚後會有一陣子特別警覺）。這樣插隊機制不再是切割獨立的系統，是主腦的快速反射手，**事後有回報**，主腦真的「知道」發生過事情。

### 6. Intent導出
五層急迫度混合 → 決定當下整體追求方向的**主敘事標籤**（取急迫度最高的那層當標籤，用於GUI顯示/敘事可讀性）；人格值（含現有archetype武力/商業/定居）決定「用什麼風格追求」，不決定「要不要追求」。**注意**：驅動實際行動選擇的是§3的完整五層混合係數，不是這個單一標籤本身——標籤只是給人看的簡化摘要。

### 8. plan_phase去留（R②明確要求交代，三選一中選(a)+(b)）
**`derive_plan_phase`（既有S1-S4，判斷「求糧/成長/聚勢/立國」四選一的機械函式）整套retire，不與五層急迫度並存**——否則等於把「N個瞎子」的病縮成2個還沒根治，違背本次重構動機（見§動機引用的「intent跟phase各自為政」正是這個病的具體症狀）。

- **`derive_plan_phase`函式停用**：其原本做的「照順序找第一個沒滿足條件」判定，被§2的五層急迫度計算完整取代（本質是同一件事的更完整版本：4選1→5層連續混合）。
- **`plan_phase_drive` term停用**：其原本掛在6個option上的偏置機制，功能併入§3的23-option統一一致性係數表，不再是獨立term。
- **GUI「現在階段」標籤**（§6主敘事標籤）：改成純粹的**顯示層衍生值**（從五層急迫度取當下最高者），不是獨立計算——跟舊`team.plan_phase`欄位語意類似但**來源不同**（舊：獨立算；新：從五層急迫度衍生），需要implementer在遷移時明確處理欄位語意轉換（例如`team.plan_phase`欄位保留給GUI讀，但寫入來源改成從新五層系統衍生，非自己算）。
- **拆分序意涵（回應R②#4）**：「五層急迫度基礎設施」與「plan_phase退役」須放進同一早期slice討論清楚，不可留到最後才處理兩套機制打架——建議第一個slice就同時完成「五層急迫度計算上線」+「derive_plan_phase/plan_phase_drive停用+GUI標籤改接新來源」，一次到位不留過渡期的並存風險。

### 7. 不變的部分
- `faction_duty`（服從母團命令：攻擊/徵收/歸建）維持現況——「社會權威層級」而非「個人需求」，不同性質的gate，不折進金字塔。
- 子隊`STRATEGIC_SELFINIT_SET`限制維持不變。

## 驗收
- **行為連貫性**：同一隊不會在同一時段內於不相關行動間搖擺（例如同時被拉向訓練又拉向紮營），organic多seed跑驗證。
- **全面覆蓋**：驗證全部23個option都受五層急迫度混合影響（非只有原本11個），可用「刻意製造某層急迫」+「觀察原本沒有plan_phase_drive/intent_fit的12個option分數是否也隨之變化」驗證。
- **軟降權不死鎖**：驗證候選池不會出現「structurally永遠選不到」的現象——可比照established調查鏈的「gate_fail_*恆等於分母」偵測手法，加對應probe。
- **卡住鬆綁可觀測**：持續卡在某層的隊伍，該層以外option的選中率應隨時間逐漸回升（非永遠鎖死在低點）。
- **跳階連續性**：不同人格（謹慎vs狂）在同樣絕境+同樣機會條件下，遠層option選中率有連續梯度差異，非二元開關。
- **威脅雙速+回寫**：既有`PRIO_SURVIVAL`插隊行為不回歸（determinism/行為對照）；插隊事件後安全需求急迫度確實提升（可測事件後一段時間內偏防衛行為的比例）。
- **established調查鏈收尾**：redesign完成後，established是否終於>0（B2/B3/B4門檻理論上因為「有意圖層篩選」而非「條件過了機械觸發」而鬆動）。
- **determinism**：全流程byte-identical驗證（同session先例）。
- **統一框架自審**：確認§2/§3/§4/§5.1的每個機制只產生數字/係數，沒有任何一處自己選擇行動——決策權仍只在`rank_scored`最終argmax一處。
