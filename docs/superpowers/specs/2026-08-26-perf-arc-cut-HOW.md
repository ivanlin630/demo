# 效能 arc：切法（HOW）

`from: systems`｜**WHAT**：用戶裁定 2026-08-26（TG「然後沒變數就照原路線圖」）——
★**事件比例計算五刀，目標＝零 LOD、50+ 隊。**
★★**模擬層零 LOD：計算跟隨【事件密度】，不跟隨任何觀察者；玩家遠近不分班、不刪除、禁降真實禁凍結。**

## 五刀（blueprint 轉述用戶原案）
```
① T0 事件驅動          ② 髒旗快取          ③ 掃描剪枝（換迭代源，治 team_discovered N²）
④ 錯峰                 ⑤ 隊數收斂
```

## ★★★而第一件不是刀，是【分母】—— slice 0
★**目標寫的是「50+ 隊」，而我現在不知道【現況幾隊會爆、爆在哪一段】。**
⇒ ★★**沒有一條 scaling 曲線**：
- **每一刀的效果無法歸因**（改完變快了，是這刀還是上一刀？）
- ★**「到了沒」根本回答不了** —— **那是一個不可達驗收。**

### ★★★★而 `team_discovered` 這一格特別需要先分解
```
world_state.gd:25   team_discovered: Dictionary   # int team_id → Array[int] 已知 team_id 清單
★production 讀者：48 處，跨 13 個檔（faction_ai 16／vision 7／message 4／strategic_ai 4／player_query 4／…）
```
⇒ ★★★**N² 的成本不是「它存在」，是【誰在每 tick 走它】。**
★**不做熱點分解就換迭代源 ＝ 改 48 處，而其中絕大多數毫無效果** —— **成本高、風險高、收益不明。**

## ★slice 0（★純量測，零 code 改，已派 measurer）
| 要的 | 形狀 |
|---|---|
| ★**scaling 曲線** | **config-only 隊數階梯**（`perf_scale.json` 變體，★**seed 固定**），每階段報 **per-tick 中位數** |
| ★★**熱點分解** | 既有 `SimRunner.phase_timing`（★**不必新增儀器**） |
| ★★★**每段要有分母** | **該段每 tick 被走到幾次** —— **否則「這段很慢」分不出是【單次慢】還是【被走很多次】，而那兩者的刀完全不同** |

★**判準沿用 `reference_hob_perf_protocol`：比 per-tick，★不撞絕對門檻**（機器差異會製造假 reject）。

## 五刀的依賴與序（★slice 0 回來後才定死）
| 刀 | 依賴 |
|---|---|
| ③ 掃描剪枝／換迭代源 | ★**強依賴熱點分解** —— **先知道 48 個讀者裡哪幾個在熱路徑上** |
| ① T0 事件驅動 | 依賴「哪些計算其實可以由事件觸發」＝ 分解的另一面 |
| ② 髒旗快取 | 相對獨立，但**收益大小要靠曲線判**（快取沒被打到的東西＝零收益） |
| ④ 錯峰 / ⑤ 隊數收斂 | 相對獨立；★**⑤ 會改變世界內容 ⇒ 它不是純 perf 刀，驗收要含行為面** |

## ★每一刀的共同驗收
1. ★**同床同 seed 同隊數階梯重跑曲線** —— ★★**報【曲線形狀】不只單點**（斜率變了才是治了 N²；截距降低只是常數項）
2. ★**`fp` 預期要連【床】＋【機制有沒有 fire】一起寫**（本日血證；純 perf 刀應 `fp` 不變，★而「不變」要是【驗過的】不是【假設的】）
3. 對帳／headless（baseline 7）／憲法閘 PASS
