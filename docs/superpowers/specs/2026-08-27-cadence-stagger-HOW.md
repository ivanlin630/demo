# cadence 錯峰：把「所有隊同時想事情」攤開（HOW）

`from: systems`｜`tier: behavior`（★**blueprint 裁定 2026-08-27：錯峰＝【行為改動】——「誰在哪個 tick 想事情」是世界的一部分**）

## ★病（實測，非推論）
```
ambition 每 ~100 tick 爆一次（105~110 隊同批）｜order 每 ~120 tick 爆一次（105~106 隊同批）
其餘 37 個 spike tick：過閘數 0~9（零星幾隊）
★burst tick dt 中位數 14.9M us  vs  non-burst 4.2M us ＝ 3.5×（統計顯著）
```
`faction_ai_system.gd:843-849`：`ambition_eval_next_tick` / `order_eval_next_tick` **一律 `current_tick + CADENCE`**
⇒ ★★**開局同時起跑的隊，之後【永遠】同批到期。**
★**機制與 `known_issues:912` 舊診斷一致（位置活）；★★而當年數值 300ms 已死（現 23 秒），不引用。**

## 修法
★**設定 next_tick 時加一個【per-team 相位偏移】，讓同一 cadence 的隊散佈在整個週期上。**

### ★★★三約束（blueprint 裁定，逐條）
| # | 約束 | 做法 |
|---|---|---|
| ① | ★**偏移決定性、由 id 導出、禁 RNG** | `offset = f(team_id)`，★★**不得呼叫 `randf()`／`randi_range()`** —— **血證：濾鏈含 RNG 副作用曾讓 pointwise dirty（`known_issues:912`）** |
| ② | ★★**偏移分配不得與「優勢屬性」相關** | 見下段 |
| ③ | ★**驗收＝守恆帳＋行為面，非 byte-identical** | 見驗收段 |

### ★★★★②的具體形狀（★這是本票最容易做錯的一格）
★**問題**：`team_id % CADENCE` **給每隊一個【固定】的相位** ——
**而若 `team_id` 與任何優勢屬性相關（例如低 id ＝ 開局隊 ＝ 較強），
★★那「誰先想事情」就變成一個【永久的、與強弱相關的】位置。**
★★★**而「先想的先搶」在資源／目標競爭裡是真的優勢。**

**⇒ 建議形狀（★兩層，第二層才是關鍵）**：
```
①打散：offset 由 team_id 經一個混合函式導出（不是直接 % ），讓相位與 id 順序無關
★②輪轉：offset 隨【週期序號】前進 —— 例如 (hash(team_id) + cycle_index) % CADENCE
   ⇒ ★★每隊的相對位置逐週期變化 ⇒ 長期沒有人固定排在前面
```
★**只做①不做②** ⇒ **相位打散了，但每隊仍【永遠】在同一個位置** ⇒ **系統性優勢仍在，只是看不出規律。**
★★**②才是真正消掉②號約束的那一層。**

#### ★★★★R² 補的一層，比我寫的更根本（2026-08-27）
> ★**就算①的 hash 完全打散、offset 跟 `team_id` 的任何既有屬性都不相關，只要 offset 是【固定終身】的，
> 「誰抽到好位置」本身會【隨時間複利成優勢】** —— **早想的隊先搶資源，優勢滾雪球。**
⇒ ★★**①防的是「起手不公平」；②防的是「起手公平，但機制自己把它變不公平」。兩個不同的病。**

#### ★★★`cycle_index` 必須是 `current_tick` 的【純函式】（R² 要求，不留給實作選）
```
cycle_index = current_tick / CADENCE      ←★整除，純函式
★禁止：另存一個遞增計數器
```
★★**理由**：**另存狀態 ＝ 存檔／重播／多執行緒都要跟著同步一個新變數。**

#### ⚠️★★★★★而輪轉有一個【邊界】必須明寫並夾住（R² 揭）
**團在 `cycle*C + offset(cycle)` 思考。★相鄰兩次思考的間隔 ＝ `C + (offset_{n+1} − offset_n)`。**
★**`+1/cycle` 的輪轉在【wrap】那一次**（`offset` 由 `C−1` 回到 `0`）**差值 ＝ `−(C−1)`**
⇒ ★★**間隔塌成 `1` tick** —— **同一隊連續兩次思考幾乎黏在一起。**
★★★**而 wrap 是模數輪轉的【內在性質】，換公式消不掉，只能【夾住它的後果】。**

★**R² 建議的「有界步進」與「`cycle_index` 純函式」之間有張力**（`offset_prev` 是狀態）——
⇒ ★★**本 spec 取【純函式 ＋ 明夾下限】**：
```
next_tick = max(  cycle_index 算出的那個 tick ,  last_eval_tick + MIN_GAP  )
★MIN_GAP 由 CADENCE 導出（例如 CADENCE / 2），★★不得手抄一個新的魔術常數
```
★**驗收要直接量它**：**同隊相鄰兩次思考的【最小間隔】** —— ★★**必須 ≥ `MIN_GAP`，且不得有任何一隊出現 1~2 tick 的連思。**

### ★時間重錨相容性（blueprint 要求，★免兩案打架）
★★**本 spec【不假設 cadence 的絕對值】** —— **只規定「同一個 cadence 內的相位分散」。**
⇒ ★★★**時間重錨改動 cadence 頻率（T0–T4）時，錯峰邏輯【不需要改】** ——
**它是那一層內部的執行細節，不是層級本身。**
★**禁止**：**在本票裡寫死任何 cadence 的 tick 數。**

## ★★驗收（★全局 wall 不可用，先講死）
★★★**不得用全局 wall-clock 宣稱加速** —— **既有紀錄：全局 wall 雜訊 ±4~8% > 本刀效果**（`progress.md` B 刀那條）。
1. ★**burst 消失**：**過閘數集中度下降** —— **「單一 tick 過閘 ≥100 隊」的 tick 數 → 0**（現況：ambition ~每 100 tick 一次、order ~每 120 tick 一次）
2. ★★**burst/non-burst dt 中位數比值 3.5× → 趨近 1**（★**方向不是數值**）
3. ★★★**spike 中位數【不保證】下降** —— **靶 B（`unified.rank` cross-cutting）不在本票範圍**，★**若沒降，照原樣回報，不得調任何東西去追**
4. ★**②號約束的行為面驗收**：**量 offset 分桶 vs 結果**（★例如各分桶的隊在 N 天後的存活／資源／據點數）——
   ★★**若某個相位分桶系統性佔優，回報，不要自己調** —— **那是 WHAT 的問題。**
5. ★★★**機械 guard：`CADENCE` 常數本身逐位元不變**（R² 要求 —— ★**「不得改 cadence 長度」只寫在 spec 是文字，擋不住**）
   ```
   本票前後 grep 'CADENCE\s*=' scripts/simulation/faction_ai_system.gd 逐字元相同
   ```
   ★**理由（R² 原話的形狀）**：**凡是只寫在 spec 裡、沒有機械檢查的規則，遲早被繞過或無意間違反** —— **今天已在多張票上驗證。**
   ★★**而它是【配套】不是附加**：**若①②能被「改 cadence 長度」繞過，本票就可能在【什麼都沒真的修】的情況下，
   靠①②的表面改善 ＋ ③的「不保證」交出一張看起來合格實則空的票。**
6. ★**同隊相鄰思考最小間隔 ≥ `MIN_GAP`**，★★**且無任何隊出現 1~2 tick 連思**（★wrap 邊界的直接驗收）
7. **守恆帳不新增不平**；headless（baseline 7）＋憲法閘 PASS
8. ★**`fp` 會變（兩張床都會）** —— **這是預期，不是回歸；★★並照紀律【當場重測新基線寫進 handback】**

### ★★★★★公平性驗收改成【機制層兩步】（2026-08-27，measurer 提形狀＋我裁）
★**原本寫「各 offset 分桶 N 天後的存活／資源／據點數」＝【行為層】** ——
★★**measurer 判它量不出來**：**16 天內 team 101→202，戰鬥／飢荒／立國／分裂的量級遠大於 offset 這種細微效應。**
★★★**而我補的一點**：**在這題裡「雜訊」與「效應」是【同一條通道】**（offset 若有優勢正是透過那些事件實現）
⇒ **不能靠控制事件降噪 ⇒ 只能靠樣本量，而樣本量沒有底。**

⇒ ★★★★**改成量【機制】**：
```
★步驟①（★已答，measurer file:line 坐實）：同 tick「先搶先贏」的機制存在嗎？
   ★★確鑿一處：interaction_system.gd:910-924 市場訂單撮合 —— qty_remaining 即時扣減
              ⇒ 同 order_id 被多隊同 tick 爭搶時，【評估順序早的先扣量】
   ★疑似未驗：outpost 選址／weakest-prey 鎖定（★標為【疑似】，不進母體）

★★步驟②（★落地後）：在那個確鑿機制上量兩個數
   (a) 爭奪頻率 —— ★★★機制存在 ≠ 常常發生（★measurer 自己標的誠實限）
   (b) 只在真的發生爭奪時：【先被評估的一方勝出的比例】
```
| 結果 | 判 |
|---|---|
| ★**爭奪頻率 ≈ 0** | ★★**offset 無從產生優勢 ⇒ 命題解決，不必再擴母體** |
| **頻率非零、勝率 ≈ 50%** | ★**樣本窗內未見（★仍不能寫「沒有」，窗要寫出來）** |
| **頻率非零、勝率顯著偏離 50%** | ★★**offset 有優勢 ⇒ 回報 blueprint（★是 WHAT 問題，不自己調）** |

★**母體紀律（我裁，防 scope creep）**：**步驟②以【那一處確鑿的】為主母體**；
★★**另兩處寫進誠實限「疑似同型、未逐一驗證」** —— **若第一處頻率就近零，再驗另兩處的成本 > 價值。**
