# HOW spec（草案；★待 R²）— **新鮮度洗白：一個欄位的新鮮度不該被別的欄位背書**

## §1 病灶（★file:line，已量過）
```
★vision_system.gd:111  snap = BeliefSystem.best_estimate(obs, tgt).duplicate()
   然後【只覆寫真的看到的】:population_est／tile_pos／last_tick／tags_seen／activity
⇒ ★★其餘欄位【原樣帶走】,而 `last_tick` 【被刷新】
⇒ ★★★一個欄位的新鮮度,被【另一個欄位的觀察】背書 ⇒ BELIEF_STALE_TICKS 對那些欄位【失效】
★而它【不是】god-view 違憲(帶走的是觀察者自己的舊信念,不是真值)——★已判過
```

## §2 兩種形狀（★implementer 不挑是對的：這是設計選擇）
```
★A【逐欄位時戳】:每個欄位帶自己的 observed_tick
   ⇒ ★精確;★★而成本是【每個讀取端都要改成看對的那個時戳】
★★B【只帶真的觀察到的欄位】:不 duplicate 舊值
   ⇒ ★★★而它【會毀掉資訊】:一次只看到位置的目擊,會把資源估計【清空】
   ⇒ 除非「不帶」的意思是【逐欄位保留舊值＋各自時戳】—— ★而那就是 A
⇒ ★所以 B 若照字面做是【更糟】,而 B 的合理版本【等於 A】
```

## §3 ★★★建議：**A，但只先做【tile_pos】一個欄位**（★而這一格請 R² 判）
```
★理由:這個缺陷【被證明的傷害】全部經由【位置】——
   JOIN 走去一個宿主已離開的地方／徵收「無目標」100% 是 belief 沒位置
⇒ ★★所以先給 `tile_pos` 一個獨立時戳,而 `belief_pos` 的過期判斷改讀它
⇒ ★★★其餘欄位【具名條目】,不在本 slice —— 而理由是【先做有證據的那一格】
★而我自標的疑點:這樣會出現【兩種時戳並存】(record 的 last_tick ＋ tile_pos 的 observed_tick)
   ⇒ ★★而「兩種時戳並存」本身就是下一個誤讀的來源 —— ★★★請 R² 判要不要一次做完
```

## §4 驗收
