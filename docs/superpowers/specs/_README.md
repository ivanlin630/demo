# ★這個目錄的 `status:` 欄【不是索引】—— 不要拿它回答「還有什麼沒做」

```
實測（systems 2026-09-22，162 份 spec）：
  ★119 份【根本沒有 status 欄】（73%）
  ★★24 份寫【待 R²／draft】｜2 份寫【已結束】｜17 份其它
⇒ ★★★所以它從來就不是一個索引，它是【零星的】——
   而一個【零星又看起來像索引】的欄位，比沒有更糟：它會讓下一個人得到一份錯的待辦清單
```

## 那要看哪裡

```
①「還有什麼沒做」 ⇒ ★docs/process/defers.tsv（★★它有閘顧著：met_check 到期或達成會【自己紅】）
②「這一票的結論是什麼」 ⇒ ★merge commit 的訊息（判決、閘的 sha、誠實限都寫在那裡）
③「現在誰手上有什麼」 ⇒ ★docs/superpowers/handbacks/（status: open 的那些）
```

## ★為什麼不去逐份把 status 補齊

```
★那是【手工翻】—— 而手工翻出來的索引，下一週就會再失真一次
★★正確的形狀是：讓「還沒做」這件事【自己會紅】（＝ defers 的 met_check），
   而不是讓某個欄位【被記得去更新】
⇒ ★★★同一條規矩：規矩要有【不靠記得】的那一半
```

★**而 spec 檔頭的 `status:` 仍然可以寫** —— 它的語意是**「寫給當下那一輪的人看」**，
**不是**「這個 repo 的狀態」。★★寫了就不保證會被更新，**而讀的人要知道這件事**。
