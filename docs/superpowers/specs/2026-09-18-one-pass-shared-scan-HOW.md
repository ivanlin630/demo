# §1 形狀：**只合併【走訪】，不共用【計算結果】**

```
把三段的 per-element 計算搬進【同一個 for】：一圈之內，三段各自累積自己的結果
★★★禁止：因為「反正算過了」而把某一段的中間值借給另一段
   ⇒ 那是【少算一次】，而今天已經證明「少算一次」會踩到別的通道（RNG／cadence）
⇒ ★本票的省法只有一個來源：**迴圈開銷與元素取得從三次變一次**
```

# §2 ★★★等價性的三個條件（**每一條都要有一格驗它**）

```
①【走訪順序】：合併後的順序必須與原本三段【各自】的順序逐字相同
   ★argmax 的 tie-break 常常是「先遇到的贏」⇒ 順序變了，結果可能變而 fp 才會告訴你
②【提前跳出】：若原本某段會 break，合併後它會被迫走完全程
   ★而 §0 的數字已經先回答了一半：三段圈數【逐字相同】⇒ **目前沒有任何一段提前跳出**
   ⇒ ★★這一格要【釘成守衛】：三段圈數相同，否則本票的前提不成立
③【副作用與 RNG】：一圈之內每個元素的副作用次數（`Probe.bump`／cache 寫／`randf()`）
   必須與合併前【完全相同】
   ★所以三段各自該呼的還是要各自呼（見 §1 的禁止條款）
```

# §4 ★量測員的儀器教訓（寫進本票，因為它差點改掉本票的結論）

```
第一版計數器是【全域】的（含 gather 以外的呼叫端）
⇒ _find_weakest_prey = 479154（≈2.4 倍）⇒ 床印「否：母體不同」
⇒ ★而那個錯誤答案的方向最糟：它會把這一票推回【剪枝】那一列，而剪枝要證明上界＝更大更易錯的票
修法：_in_gather 旗標（進入設 true、唯一的 return 前設 false），所有樁 `Probe.enabled and _in_gather`
```
★★★**教訓不是「不小心」**：**把一個【全域】計數器除以一個【局部】母體（每次 gather），
那個除法在形狀上就不成立** —— 而它印出來是**一個很像答案的數**。
⇒ ★**通則：計數器的範圍必須與問題的範圍一致**；**問「一次 X 之內幾次」就不能用全域計數。**
