# §1 形狀：**只合併【走訪】，不共用【計算結果】**


# §2 ★★★等價性的三個條件（**每一條都要有一格驗它**）

```
①【走訪順序】：合併後的順序必須與原本三段【各自】的順序逐字相同
   ★argmax 的 tie-break 常常是「先遇到的贏」⇒ 順序變了，結果可能變而 fp 才會告訴你
②【提前跳出】：若原本某段會 break，合併後它會被迫走完全程
   ★★★**主證據＝構造，不是圈數**（R² 2026-09-18 指出我的推論太弱，並自己去讀了三支函式）：
     `_find_weakest_prey`／`attack_scan`／`_max_threat` 的迴圈體 **零 `break`、零【迴圈內】`return`**
     ⇒ ★**這是「不會提前跳出」的構造證據**；而「三段圈數逐字相同」只是**佐證**（它也可能來自
       「break 從來沒被觸發」或「被同一個上限截斷」——★那正是我原本推論的兩個漏洞）
   ★★**而核這一格要先剝註解**：`_find_weakest_prey` 裡唯一命中 `break` 的是
     **一行註解裡的「tie-break」** —— ★裸 grep 會報「有一個 break」⇒ 又一次「命中名字不命中意思」
   ⇒ ★這一格照樣釘成守衛（3-g），但守的是【構造】：迴圈體裡沒有 `break`／迴圈內 `return`
③【副作用與 RNG】：一圈之內每個元素的副作用次數（`Probe.bump`／cache 寫／`randf()`）
   必須與合併前【完全相同】
   ★所以三段各自該呼的還是要各自呼（見 §1 的禁止條款）
```
