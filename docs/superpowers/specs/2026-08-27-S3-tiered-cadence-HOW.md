## ★scope

### ①核心命題（★這是設計，不是整理）
> ★★**一個節律的歸宿只有【層級】** —— **鏡射憲法 B 重框「行為門檻的歸宿只有兩處（世界代價／人格）」。**

**現況**：節律寫成 **N 個各自為政的乘數**，散在 8 個檔：
```
GOAL_CHECK_INTERVAL   = 10 * TICKS_PER_HOUR   （個人目標，reaction_system.gd:3）
LADDER_EVAL_CADENCE   = 10 * TICKS_PER_HOUR   （野心，ambition_ladder.gd:13）
STRATEGIC_INTERVAL    = 10 * TICKS_PER_HOUR   （勢力戰略，strategic_ai_system.gd:3）
ALLIANCE_CHECK_INTERVAL = 30 * TICKS_PER_HOUR （結盟，strategic_ai_system.gd:4）
BETRAY_CHECK_INTERVAL = 50 * TICKS_PER_HOUR   （背叛，diplomatic_ai_system.gd:4）
INFRA_INTERVAL        = 50 * TICKS_PER_HOUR   （基建，faction_ai_system.gd:4596）
FACTION_UPDATE_INTERVAL = 20 * TICKS_PER_HOUR （派系，faction_ai_system.gd:4）
INTENT_CADENCE        = TICK_PER_DAY * 1      （意圖，faction_ai_system.gd:116）
```
★**它們【已經】跟著根縮放**（S1/S2 的功勞）⇒ ★★**S3 要治的不是「會不會縮放」，是【為什麼是 10 而不是 20】沒有人答得出來。**
★★★**8 個乘數 ＝ 8 個沒有理由的數字**；**4 個層級 ＝ 4 個有語意的檔位，而「這件事屬於哪一檔」是可以講理由的。**

### ②不在 scope（★明列，免得順手做大）
- ★**不改根**（`TICKS_PER_HOUR` 已定 60，S2 收）。
- ★**不做 T0 事件驅動**（那是 S4，且與 LOD arc 同體）。
- ★**不碰 S3a 那 4 顆真每 tick 站**（`_step_captives`／`_step_cleanup_extinct_teams`／`get_speed_mult`／`get_vision_mult`）
  —— ★★**其中 2 顆是純讀取 accessor；把它們搬進層級是【S4 的事】，這裡動它們會混淆 S3 的歸因。**
- ★**不改任何行為門檻／人格權重**（本 slice 只動「多久評一次」，不動「評出什麼」）。

## ★★母體（★普查不推導；★★枚舉指令寫在這裡，別人重跑得出同一個數）
```bash
grep -rnE "^const [A-Z_]+: *int *= *[^#]*(TICKS_PER_HOUR|TICKS_PER_DAY|TICK_PER_DAY)"      scripts/simulation/ --include=*.gd
# 2026-08-27 實測 = 45 顆
```
★**四桶，互斥且窮盡，加總必須 ＝ 45**：
| 桶 | 定義 | 處置 |
|---|---|---|
| ★**(a) 八支** | LOCKED spec 點名的那八支 | ★**本 slice 搬進層級** |
| **(b) 同族未點名** | 也是「多久評一次」，但 LOCKED 沒點名（如 `COLLECT_INTERVAL`／`ORDER_POST_CADENCE`／`PROSPERITY_CADENCE`…） | ★★**列出但【不搬】** —— **記進 spec 當 S3 的已知殘量**，S5+ 再收 |
| **(c) 非節律** | 語意時長（`BELIEF_STALE_TICKS`／`FOOD_RESERVE_TICKS`／`SURVIVAL_BUILD_MAX_TICKS`…）＝**某件事多久算過期**，不是**多久評一次** | ★**不搬**（★★**混進來會把「節律」這個概念稀釋掉**） |
| **(d) 衍生量** | `MOVE_TICKS_PER_HEX` 等由其他常數算出 | 不搬 |
> ★★★**(b) 與 (c) 的分界要寫在 code 註解裡，不是只寫在 spec** —— **下一個人加常數時看到的是 code。**

## ★★★T1–T4 的定義（★層級是【引擎結構】，週期值是【參數】——憲法孿生條）

| 層 | 語意（★這是層的定義，不是它的值） | 預設週期 | 現有歸屬 |
|---|---|---|---|
| **T1** | ★**貼身反應**：跟「我這個人現在要幹嘛」同尺度 | **10 小時** | 個人目標／野心／勢力戰略 |
| **T2** | **經營節律**：資源/人力/組織的週期性經營 | **20 小時** | 派系 |
| **T3** | **關係節律**：跟別人的關係要不要重估 | **30 小時** | 結盟 |
| **T4** | ★**重決策**：代價高、反悔貴的那種 | **50 小時** | 背叛／基建 |
| ★**T_DAY** | **日結**：以「天」為單位的盤點 | **1 天** | 意圖 |

★**為什麼是這五檔而不是四檔**：★★**`INTENT_CADENCE` 本來就寫在【天】的單位上，硬塞進小時檔會製造一個假的搬家**
—— ★★★**而 LOCKED 說的是「T1–T4 骨架」，沒說「只能有四個」。★我把「日結」獨立成一檔並在此標明偏離，設計權在 blueprint，若他要求併入 T4 我照改。**

### ★★★★而【層級歸屬】必須可講理由，這是本 slice 的驗收之一
> ★**每一支搬家都要在 code 註解寫「為什麼是這一層」，一句話。**
> ★★**寫不出理由的那一支，就是我們還不知道它該多久評一次** —— **那要標出來，不是隨便塞一層。**

## ★★★★驗收（★主軸 ＝ per-team-day／率，aggregate 降附錄 —— blueprint 准 2026-08-27）

### ①★逐支「遷移前後事件率」對照（LOCKED §S3 驗收原文）
**八支各自一列**，★**每列都要有分母**：
```
<支名>   事件數 / 隊 / 日   before(main) vs after(branch)   ★同 seed 同床同窗
```
★★**判讀規則【事前】宣告**（沿用 S2 那條，不是看到數字才定）：
**若某支的週期值【沒變】⇒ 它的事件率必須落在 ±5% 內；★若落在外，那是【搬家本身引入了行為變化】＝ 缺陷，不是調參。**
★★★**若某支的週期值【變了】（例如 20h→T2 的 20h 沒變、但某支被歸到不同檔）⇒ 它進 `intended-change` 清單，逐項標注預期方向，不得混進不變項。**

### ②★★★履行 S2 留下的殘差義務（★blueprint 硬條款：以一次為限）
> **S2 具名開放殘差**：★**決策 +21.0%／訊息送達 +39.2%（per-team-day）** ——
> ★★**S3 終量必須給出【歸因】或【收編判決】，不許三度順延（殘差老化上限：一次路由可，兩次＝回工）。**

★**而 S3 讓這件事從「再量一次」變成【可操作】**：
★★**八支收進層級之後，「決策次數」本身變成一個【可控變數】** ——
★★★**可以只動一層的週期值，看決策率動不動。★那是【操作】不是【觀察】，而操作才能歸因。**
**要跑的兩件**：
```
①★完成率 vs 流量（blueprint 給的刀，S2 spec 殘差程序段已載）
   送達：★【送達數】(流量) vs 【送達/發出 比值】(完成率)
        ⇒ 若比值持平而流量升 ⇒ 是【發出更多】不是【傳得更好】
        ⇒ 若比值升 ⇒ 傳播效率真的變了 ⇒ 回到 propagate 節律（S3a 已測 1.10 次/小時）
②★★層級擾動（★一輪為限）：把 T1 週期 10h→20h 單獨跑一次
   ⇒ 決策率若隨之明顯下降 ⇒ 決策 +21% 歸因到 T1 族節律
   ⇒ 若幾乎不動 ⇒ ★★★決策 +21% 【不是節律驅動】⇒ 收編判決：它不屬於時間重錨 arc,轉出去
```
★**兩個出口都算「給出判決」** —— ★★**「不是我們造成的」也是一個判決，而且是合法的那種。**

### ③★`fp` 預期（★完整寫法：床 ＋ 機制 fire 條件 —— 這條踩過兩次）
