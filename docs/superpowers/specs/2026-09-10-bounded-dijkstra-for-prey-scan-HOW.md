## ⓪ ★★★上一版的診斷【錯了一層】—— 而正確的那一層更好修

```
我上一版寫：「每支隊對每個 discovered 隊跑一次尋路 ⇒ N=135 ⇒ 18,000 次尋路」。
★而我去讀 `catch_cost`（path_system.gd:54-66）之後發現：**它已經有快取**，
  而且是比 R² 提的【位置對】更好的形式：
     `_sssp_cache[world][from_key] = _dijkstra(state, from)`   ← ★**單源、全目的地**
  ⇒ 同一個 `from`，對【所有 to】只算一次。
⇒ ★★所以真正的成本【不是 18,000 次尋路】，是 **135 次【全圖單源 Dijkstra】**
   —— 每支正在決策的隊各一次，因為 `from ＝ 它自己的 tile_pos`。
```

★**而快取為什麼救不了**（★這一格是【推論】，要量）：

```
`from` ＝ 那支隊【當下的位置】，而隊【每 tick 都在動】
⇒ ★下一次它決策時 `from` 已經換了 ⇒ **新的 key ⇒ 新的一次全圖 Dijkstra**
⇒ ★★**快取的命中率可能接近 0**，而它看起來像一個有在運作的快取。
⇒ ★★★**這是【待驗】，不是結論** —— 驗收①就是量它。
```

## ① ★★★修法：**把 Dijkstra 收邊**（語意不變）

```
現況：`_dijkstra(state, from)` 算【整張圖】的最短成本。
★而 `estimate_catch_up`（:257-259）**把 `eta > AI_ETA_LIMIT` 的通通丟掉**：
     eta = cost × BASE_MOVE_TICKS ÷ relative_speed
     if eta > AI_ETA_LIMIT: return { reachable: false, reason: "too_far" }
⇒ ★★**遠的那一半【算完就丟】** —— 而 Dijkstra 是【由近而遠】展開的，
   ⇒ ★★★**只要在成本超過上界時停止展開，結果一模一樣。**
```

**上界怎麼取（★保守，語意不變是硬要求）**：

```
cost_bound ＝ AI_ETA_LIMIT × max_relative_speed ÷ BASE_MOVE_TICKS
★而 `max_relative_speed` 要取【這個世界可能的最大值】（不是這一隊的）——
  ⇒ ★★因為同一份 SSSP 結果會被不同速度的隊共用，
  ⇒ ★★★**上界取太緊 ＝ 改變語意**（某隊本來搆得到，變成搆不到）。
⇒ 實作要點：`_dijkstra` 多一個 `cost_limit` 參數，超過就不再 push；
   ★快取的 key 要**包含 cost_limit**（否則一個緊上界的結果會被寬上界的呼叫重用 ⇒ 靜默錯誤）。
```
