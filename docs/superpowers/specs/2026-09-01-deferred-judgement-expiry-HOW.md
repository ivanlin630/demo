# ★①要治的病
> **`b_defer` 是唯一一種【自帶到期日】的判決（「延到 S2」）—— 而沒有任何東西在到期日檢查它。**

★**它們沒有害人，只因為病碰巧被順手治好了**（兩個目標常數都已從根導出）——**不是因為有人回來看。**

# ★★②形狀裁定：**掃描一行，不做現況板**
```
(a) 現況板加欄（列延後項＋解封條件，人來讀）  ⇒ ★駁回
(b) 掃描一行（機器算）                        ⇒ ★★採用
```
★**駁回 (a) 的理由**：★★**不能用一個「要被讀」的東西，去治「沒被讀」的病。**
★★★現況板會單向長大，然後沒人讀 —— **那正是我們這一路在數的同一個形狀**（`nobody-owns-shrinking`／`存在≠被讀到`）。

# ★★★③判準：**不是「到期日到了 ⇒ 紅」，是「判決失去對象 ⇒ 紅」**
```
一條 b_defer 規則存在的理由 ＝ 「現在有東西命中它，而我們決定【延後】處理」
⇒ ★命中數 == 0 ⇒ 延後的【對象不存在了】⇒ 判決失去對象 ⇒ ★★紅
```
★**為什麼不用到期日**：★★**到期日需要有人【寫對】，而「對象還在不在」是機器本來就在算的東西。**
★★★**而它會在 S2 merge 的當天就紅** —— 這次的兩條，用這個判準會被當場抓到。
