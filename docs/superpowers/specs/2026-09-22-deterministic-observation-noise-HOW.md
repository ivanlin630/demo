# §2 修法形狀

```
observed_speed 的雜訊來源從 randf() 換成【決定性雜訊】：
  由 (world.current_tick, observer.team_id, target.team_id) 推出
★必要性質①：同一 tick ＋ 同一對 (observer,target) ⇒ ★【同一個值】（這是本票的【功能】）
★★必要性質②：不同 tick ／ 不同對 ⇒ 值要【看起來像雜訊】（不得有結構性偏差：
   例如「team_id 大的永遠偏高」）
★★★必要性質③：★它【不得】再耗 global RNG —— 否則這一票什麼都沒解
```
★**禁止**：順手改 `noise_factor` 的大小、順手改任何決策 —— **本票只換血統，不調參數。**

# §3 驗收（★每格能紅）

| 格 | 內容 | 反向 |
|---|---|---|
| 2-a | ★★★**同一 tick、同一對，問兩次 ⇒ 逐字相同**（★這是本票的功能，要有專門一格） | 不同 ⇒ 沒解到病 ⇒ 紅 |
| 2-b | ★**global RNG 抽取次數 ＝ 0**（在 `observed_speed` 這條路上），★★母體要印 | ＞0 ⇒ 還在耗 ⇒ 紅 |
| 2-c | ★★**三跑 byte-identical**（「觀測儀器禁耗 global RNG」家族的既有驗法） | 不同 ⇒ 紅 |
| 2-d | ★**雜訊分佈健檢**：對一個窗內的所有 (tick,obs,tgt) 取值，印出 min／max／平均／分位 ——★★**不得**出現「隨 team_id 單調」這種結構 | 有結構 ⇒ 雜湊選錯 ⇒ 紅 |
| 2-e | ★★★**呼叫次數不再影響取值**：同一 tick 對同一對呼叫 1 次 vs 5 次 ⇒ ★世界指紋逐字相同 | 不同 ⇒ 耦合還在 ⇒ 紅 |
| 2-f | ★**世界會改變一次**（預期）：fp 與逐 tick 軌跡**與修法前不同** ——★★而這一格是【預期會紅的紅】，要**逐字記下新舊兩個值** | 沒變 ⇒ ★反而要停下來（表示雜訊根本沒被用到） |
| 2-d' | ★★★**短 lag 精確不重複**（R² 給的形狀）：固定 `(observer,target)`，取 `k ∈ {1,2,3,5,8}`（互質小步長、非等差），**逐點斷言** `value(tick) != value(tick+k)` —— ★**不是機率檢定，是逐點【不等於】斷言**，與 2-a 同一個模具（方向相反） | 任一 k 出現相等 ⇒ 雜湊對相鄰 tick 產生重複／近似值 ⇒ 紅 |
| 2-h | ★★★**同一 tick 內，不同 pair 的值【不得全相同】**（R² 自己抓到的退化情形：雜湊若只吃 tick、不吃 observer／target，★**2-a 會【平凡通過】**）——★★母體要印：該 tick 有幾個 pair、幾個相異值 | 相異值 ＝ 1 ⇒ 全隊同值 ⇒ 紅 |
| 2-g | 到場點名 ＋ expect 釘 `N／N` | 少一格 ⇒ 紅 |

★★★**這幾格要【一起判】—— 單看任何一格都可能被騙過**：
```
★2-f 單獨綠【不算過】—— 它只證「有東西變了」，不證「變對了」
★★2-a 對【不隨輸入變】的壞實作是【平凡通過】（任何輸入都同值 ⇒ 同 tick 同對當然同值）
★★★只有 **2-a ∧ 2-d ∧ 2-d' ∧ 2-h ∧ 2-f 全綠** 才算真的接上
```
★**為什麼要寫成一句 AND**（R² 的理由，我照收）：本專案已有「grep 命中名字不命中意思」「判決沒有主詞」的血證
⇒ **不寫成明句，日後有人挑 2-f 單獨貼出來當「已解」的證據時，沒有東西擋得住。**

★**2-f 的方向要特別講**：這一票**就是要改變世界一次**，所以「fp 變了」是**通過**；
★★**而「fp 沒變」才是紅** —— 它表示那個雜訊**根本沒有進入任何決策**（＝一個裝飾）。
