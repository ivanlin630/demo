## ⓪ 這張票的判斷基礎（★兩句，缺一不可）

```

   ⇒ ★★而一旦是預設寫法，**逐處修就是錯的處置**：改完 75 處，

⇒ ★所以：**不專案化、不逐處修**，改【換掉預設路徑】＋【棘輪擋新增】。
```

## ④ ★為什麼這張票值得現在做（★序的理由）

```
今天量到：自然世界【幾乎不滅團】⇒ 殭屍窗幾乎不開 ⇒ 那 75 處【現在】幾乎不咬人。
★★而攻擊門那張會讓世界【開始有滅團】——
★★★**那一天，這 75 處會從「幾乎不開的窗」變成「常常開的窗」。**
⇒ 所以便捷式與棘輪【做在攻擊門之前比之後便宜】：
  ★之前做 ＝ 新寫的 code 一開始就走對的路；
  ★★之後做 ＝ 攻擊門期間新增的每一處都要再回頭轉一次。
```
