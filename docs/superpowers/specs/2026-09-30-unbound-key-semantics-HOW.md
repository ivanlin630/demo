# HOW：未綁定鍵＝無作用＋一句回饋（三禁）

**上游 WHAT** 藍圖 2026-09-30 裁定（意圖帳「未知鍵語意」，`44d684c88`）：

```
任何模式下【未綁定的鍵】＝無作用 ＋ 一句回饋「此鍵在此模式無作用」
禁三件：①關閉模式 ②落到底層處理器 ③改任何狀態
Esc 只做「回上一層」
★實作端量到的「某字母鍵讓模式自己關掉」＝違反第一禁 ⇒ 改
```

## ★★★§1 這張票的難點不在實作，在【母體怎麼來】

```
「每個模式對一組未綁定鍵各按一次」——★那一組鍵**不准手挑**：
  ·手挑可能挑到一個【其實有綁】的鍵 ⇒ 那一格測不到東西，而它會過
    （＝今天剛學到的「運氣與佈置在卷面上同形」）
  ·手挑一個鍵也不夠：一個模式可能只對某些鍵有洞
⇒ 母體要【導出】：
  ①每個模式的**已綁鍵集合**機械抽出（同 P25 列舉 13 個模式那個做法：
    從該 handler 的 `keycode == KEY_*` ／ `match keycode` 逐一抽）
  ②未綁定鍵＝一組固定候選（例如 KEY_A..KEY_Z ＋ 數字 ＋ 幾個符號）**減掉**該模式的已綁集合
  ③★母體地板：逐模式印【已綁幾個／測了幾個未綁】，並斷言【測的那些真的不在已綁集合裡】
    —— 沒有這一條，一格測到綁定鍵也會過，而它過的理由是錯的
```

## §2 做什麼

```
①未綁定鍵的統一出口：**一處**，不是每個模式各寫一份
   ⇒ 每個 `_handle_*_mode` 的尾端（所有已綁分支都沒命中時）走同一個
     `_refuse_unbound_key(mode_name, keycode)`：印回饋句、**什麼都不改**、吃掉那個鍵
   ★★「吃掉」＝不得落到底層處理器（禁②）—— 而它與「無作用」是兩件事：
     不吃掉 ⇒ 底層可能把它當別的意思（那正是不變量 #10 的病根）
②修那個實體缺陷：某字母鍵讓模式自己關掉 ⇒ 違反禁① ⇒ 拆掉那條關閉路徑
③Esc **不是**未綁定鍵：它有語意（回上一層）⇒ 它走自己的分支，不得落進 ① 的出口
   ★而「回上一層」的定義要寫在 code 註解裡（最外層按 Esc 的行為是什麼，要講明）
④回饋句用既有結果句的措辭形狀，不自創第四種語氣
```

## ★★§3 驗收

```
P1 [三禁逐一] 逐模式 × 每個未綁定鍵：
   (a) 模式旗標**前後相同**（禁①）
   (b) ★**fingerprint 前後逐位元相同**（禁③）—— 用既有的尺，不要自己列欄位
       ★★而它同時證了「沒有推進 tick」：按下去若推了 tick，fp 一定不同
   (c) 回饋句出現，且**只出現一次**
   (d) 佇列長度不變（禁②的一半：沒有任何動作被排進去）
   ｜負對照①：拿掉統一出口 ⇒ 至少一個模式的旗標變了或 fp 變了 ⇒ 必紅
   ｜負對照②：把回饋句拿掉 ⇒ 靜默 ⇒ 必紅（★「無作用」不等於「沒反應」）
P2 [母體地板三道] 逐模式印：已綁鍵數／測的未綁鍵數／★**測的那些不在已綁集合裡**
   ＋總計印「13 個模式 × N 個未綁鍵 ＝ M 次按壓」，而 M 要跟實際跑的次數對得上
P3 [Esc 不被當未綁定] 每個模式按 Esc ⇒ **走回上一層**，而**不得**印「此鍵在此模式無作用」
   ｜負對照：把 Esc 併進未綁定出口 ⇒ P3 紅
P4 [已綁鍵沒被門死] 每個模式挑**一個已綁鍵**按下去 ⇒ 它原本的效果仍然發生
   ★這一格守「我沒把功能門死」
P5 全電池 BATTERY_RC=0；★fp：先量再換基準（未綁定鍵不該動 fp ⇒ 基準**預期不變**，
   若變了那就是一個發現，要回報而不是換基準）
```
