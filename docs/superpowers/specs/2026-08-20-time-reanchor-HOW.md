## §0 systems 裁定摘要
1. **切成 8 個 slice**（§1），每個**自帶 gate、可獨立回退**；★**S1 是純標籤重構、要求 fp byte-identical**——這條讓「重錨」的行為改動被**隔離在 S2 一支**，不與 refactor 混在一起（本 session 血證：混在一起就無法歸因）。
2. **T0 與 LOD arc 合併為同一 arc**（blueprint 授權我裁）——理由：兩者是**同一個機制的兩面**（事件驅動喚醒 ⇄ 取消輪詢），分開做會**做兩次同樣的接線**。
3. ★**執行順序由 S0 的數字決定、不由直覺決定**（§2）。

## §2 ★排程裁定：先量再排（S0）
**風險**：`TICKS_PER_HOUR 10→60` ＝ 每遊戲日 tick 數 **240 → 1440（6×）**。真實工作量不變（cadence 以小時宣告、自動跟隨），但**每 tick 的固定開銷 ×6**；而大考剛測出 **k≈2.004（O(N²)）**、day60 已 **0.85 s/tick**。
**先查到的事實（systems code-read）**：no-op tick 只跑 `_step1_advance_time`（+1 與兩個 modulo）＋幾個 `%` 判斷＋`cleanup_extinct_teams`（空即 return）＋`ManpowerSystem.tick_all`（**自帶 `CAPTIVE_CADENCE` 早退**）→ **固定開銷本身很小** → 6× 放大的是一個小常數，**多半可承受**。
★**但「多半」不是數字** → **S0 前置量測**（便宜、短窗）：
- 同 seed/config，**現制 vs 6× 制**各跑 3 遊戲日，比 **每遊戲日 wall time**（非每 tick——tick 定義變了，比 per-tick 會自欺）。
- 判準：**每遊戲日 wall 增幅 < 15%** → S2 可直接做；**≥ 15%** → **先做 S4（T0×LOD arc）再回頭做 S2**（T0 取消輪詢正好抵銷 tick 密度）。
∴ **順序有兩條路，由 S0 的數字選**：
- **路 A（增幅小）**：S1 → S2 → S3 → S5 → S6 → S7 → **S4（T0×LOD）**
- **路 B（增幅大）**：S1 → **S4（T0×LOD）** → S2 → S3 → S5 → S6 → S7

## §3 統計等價床（S2 的主 gate）
**重錨的純標籤部分必須統計持平**（RNG 消耗模式必變 → **不驗 byte**、驗**率**）。
- **不變項（每遊戲日**事件率/速率**）**：採集量/日、消耗/日、製造產出/日、移動格/日、決策次數/日、訊息量/日、starve/日、交易成交/日。
- **允許變項（列入 intended-change 清單、逐項標注）**：移動 4.8h→4h、糧耗/格 −17%、徵收 30h→T2 24h（R² 補漏）。
- **判準**：不變項**相對差 < 5%**（同 seed、≥30 遊戲日窗）；超出者**逐項解釋或回退**。

## §4 規約守衛（`debug/time_const_check.gd` 擴充）
- **新增裸 tick 字面量 ＝ FAIL**。「裸 tick」定義：**時間語意**的 int 字面量出現在 `%`／比較／加減 tick 的位置，而非經 `TimeScale.hours()/days()`。
- **既有豁免白名單**：`TICKS_PER_DAY`/`TICKS_PER_HOUR` 本身、fp/序列化用的純計數、debug 床。**白名單必須逐條寫理由**（否則守衛會被當成「加進白名單就好」的橡皮圖章）。
- ★守衛**與 constitution_gate 同級**：merge 前跑、新增違規即 FAIL。

## §5 相對錨定的實作形狀（§2 規約的 HOW）
- 形狀：`timeout = clamp(k × 該活動預期時長, floor, ceiling)`；`k`、floor/ceiling 以**小時**宣告。
- 錨對象**逐顆標**（審計表一欄）：工地＝k×預期工期／貿易・JOIN＝k×往返 ETA／失聯＝k×訊息往返尺度。
- **找不到自然錨才准絕對小時**，且需在審計表註明「無自然錨」的理由（護欄型如 L0 衰敗 3 天＝物理，不在此限）。

## §6 風險與回退
- **最大風險＝S2 一次改變全世界節奏**：故以 §3 統計等價床為硬 gate，且 S1 先行（純標籤）使 S2 的 diff **只剩根旋鈕本身**、回退成本最低。
- **S5 飢餓/疲勞減半**：直接影響死亡率 → **必須與生育 slice 的新基線一起看**（兩者都動人口動力學）；建議 S5 排在生育 merge 之後，避免兩個人口變因同時進場無法歸因。
- **S6 工期表全面變慢**：與「沒人蓋 workshop」的既有病症**方向相同**（更難蓋）→ ★S6 落地時**必須同時看 facility 建成率**，否則會把一個已知病灶推深而不自知。
