## ① 修法（★兩層，先做便宜的那一層）

### (1) ★短路：**這支隊根本沒有任何據點 ⇒ 直接 false**

```
`_team_has_facility` 的條件是 `outpost_owner == team.team_id and outpost_level > 0 and level_key > 0`
⇒ ★**沒有自己的據點 ⇒ 三個條件的第一個就不可能成立** ⇒ **答案必為 false**
⇒ 用**既有且已驗證**的索引：`state.own_outpost_tile(team.team_id) == null ⇒ return false`
  （★★那支索引今天已經被 shadow 驗過 670 次／0 不一致，★★★不是新造的東西）
⇒ ★語意等價**可證明**：`own_outpost_tile` 為 null ⇔ 該隊在 `outpost_owner` 上零命中
  ⇒ 而三個條件是 AND ⇒ **短路後的回傳值逐次相同**。
```

### (2) 聚合設施索引（★給**有**據點的隊）

```
`owner → { facility_level_key: bool }`，**跨它所有據點聚合**
⇒ ★★這是**存在量詞**（「有沒有【任何一個】據點的該設施 > 0」）
  ⇒ ★★★**聚合對存在量詞是精確的** —— 即使一隊有多個據點，答案**逐字相同**
  ⇒ ★而這正好繞開今天早上判 `need_oracle.gd:161`「不可盲換」的理由：
    那次不能換是因為索引**只回一個 tile**；**聚合索引不回 tile，它回【有沒有】**。
⇒ 失效沿用既有形狀（`OwnerOutpostIndex` 的 epoch）：**設施等級跨 0 ／ outpost 所有權變更 ⇒ invalidate**。
```
