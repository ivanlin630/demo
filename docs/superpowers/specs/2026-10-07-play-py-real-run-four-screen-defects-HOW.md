## §1 四條（file:line 為起點，實作端核實）

```
D1【事件流印英文識別字 intel_arrived】`world_events.gd:327` 已有中文句「%s 收到了情報」⇒ 有一條路沒走它（印了 kind 原名）
   修：事件流的每一筆一律經同一支「kind → 玩家句」函式；沒有對照的 kind ⇒ 不印（並在 debug 走法印原名），不准把識別字漏給玩家
   E2E 格 a：整個走法的**事件流區**也掃英文識別字（終端自驗 (d) 那套字表與排除，同一份）
D2【右欄內部備註漏到玩家面】「── 其他（尚未分頁） ──」（`text_ui_main.gd:1146`）、「…：尚未提供」（`ui_pages.gd:34`）、「Tick: 60 (Day 0)」
   規則：玩家走法**不印沒有寫入者的欄**（不印佔位句也不印值主張）；那些只在 debug 走法印（同真值·debug 區的處理）
   ★威脅欄例外不再需要：它現在有寫入者（`threat_line`），沒寫入者時同規則＝不印
   E2E 格 b：玩家走法的每一屏掃佔位句字樣（「尚未提供」「尚未分頁」「Tick:」…字表放一處），命中＝紅；★反向：debug 走法下它們出現
D3【結果行≠完成句】按「建立勢力」結果行印「✓ 已排入：行動：建立勢力」，事件流同 tick 印「行動：建立勢力：完成」
   規則（press-is-do）：令結算後，結果行換成那道令的**完成句**（或被拒句）；「已排入」只在結算前的一瞬存在，玩家拿到畫面時已結算（P10）
   E2E 格 c：每一道令回來的那一屏，結果行＝該令的完成句／被拒句（逐字比事件流那一筆）
D4【面板中按 X 回「現在沒有要回應的事件」】`text_ui_main.gd:1888` 字母鍵一律落到事件回應處理器
   規則：全域推進鍵（X／Space／G）在面板中要嘛照推進、要嘛印「面板開著時不能推進（Esc 關閉）」——不得落到事件回應那支
   ★字母鍵空間歸強制回應獨佔（不變量 #10）⇒ 判別：面板上**有列出**的字母才歸回應；沒列出的全域鍵照全域語意
   E2E 格 d：每種面板開著時按每個全域鍵，回應句＝全域語意的句子（不是事件回應的句子）
```
