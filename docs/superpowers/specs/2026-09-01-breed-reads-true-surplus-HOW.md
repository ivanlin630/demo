# ★①病：**breed 讀的不是盈餘**
```
用戶的法：per-capita【盈餘】＝ 產出 − 消耗（★流量）
★而 breed 實際讀：【存量差分 EMA】（★倉庫這一刻比上一刻多多少）⇒ ★★連正負號都不同
```
## ★★兩個症狀，而第二個是 blueprint 揭的
```
①★【滿倉而不再增加】的隊：盈餘為正，存量差分 ≈ 0 ⇒ 被判「沒盈餘」⇒ 不生
   ⇒ ★★越穩定的富裕隊越生不出來（實測：team9 盈餘 62/90、team8 53/90 ⇒ 生育皆 0）
②★★★【花盈餘去投資】的隊：存量【下降】⇒ 被讀成【饑荒】⇒ 更不生
   ⇒ ★★★而那是【反建設耦合】：越是拿盈餘去蓋東西的隊，越被判成餓 —— ★雙倍毒
```

# ★★②修法：**改讀真盈餘，且【同源推導】**
```
★breed 的輸入 ← per-capita 盈餘（產出 − 消耗）
★★同源推導：★★★不得手抄一份「盈餘」的算法 —— 若 production 已有該量就讀它；
   若【只有量測床算得出來】⇒ 那本身是發現，先報我（★而那正是上一票要你先確認的那格）
★不動任何常數（blueprint 明裁）—— ★★包括那個「假設 5 人」
```

# ★★★③驗收（★④是 blueprint 揭的症狀，獨立可驗）
```
①★盈餘隊的出生率 > 0（★★而 blueprint 定的下一步是「全隊重量 per-適齡出生率」，本票先只驗方向）
②★陽性對照：把修法拿掉 ⇒ ★★必須回到 0（否則這條驗收沒有偵測力）
③★★【滿倉靜態隊】必須能生 —— ★★★那是本 bug 的【字面症狀】，不是代理
④★★★【花盈餘投資的隊】不得被判饑荒 —— ★構造一個「盈餘為正而存量下降」的隊，
   ⇒ 舊版必須判它饑荒、新版必須不判 ⇒ ★★兩端都要跑
⑤★fp【會變】（intended-change），變了不是失敗，但要標注
```
