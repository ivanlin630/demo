1. **輸入模式提示上終端（一個咽喉）**：
   - 來源讀**狀態**不讀 bar：`_input_bar.text` 全檔 32 個寫入點、兼作非輸入用途（:341），且有隱藏 fallback（prompt 空時用「跳過 tick 數: 」，:665、673）。抽 `_input_line()`＝`_input_mode_prompt`＋buffer，GUI 的 bar 與終端 view 都呼叫它。fallback 拿掉（空 prompt 由下一條擋）。
   - 20 處入口收進一支 `_open_input(prompt, …)`，**拒空 prompt**（空 ⇒ 不開輸入模式＋push_error）。床加結構格：全檔裸寫 `_input_mode = true` 次數 == 1（就在 `_open_input` 內）。
   - 終端位置：**輸入模式期間，結果行那一列印「輸入：<_input_line()>」**（同一列換內容，不新增列 ⇒ 版面不跳）；離開輸入模式恢復結果行。`press_on` 每鍵後 `_refresh()`，打字即時可見。
   - **藍圖追加（c5b3bf396，用戶：「派子隊時就會跳回大地圖卡畫面」）**：機制＝`text_ui_main.gd:410` 輸入模式先吃所有鍵、數字模式對非數字鍵靜默（:633-668）、面板在輸入模式下不畫。
     - **輸入模式吃掉的鍵一律回句**，不得例外。病根（R²）：`_input_mode_binds_key`（:618-623）不分 numeric／string，任何字母與數字都回真 ⇒ numeric 按字母通過綁定檢查卻沒有分支、靜默落空（用戶回報的「按字母沒反應」）；string 按數字同理。
       ⇒ **binds_key 依 `_input_mode_type` 分型**；不收的鍵走 `_refuse_unbound_key`。
       ⇒ 另三格「收下卻靜默」：緩衝滿（6 位／30 字）、Enter 空緩衝、numeric 無 callback 時輸入 0 ——各給一句。
       ⇒ 寫成：handler **每條 return 路徑**都有狀態變化或一句話；床以枚舉分支驗。
       - 回句要短（「只收數字」）且有壽命（下一個合法鍵就消失）；提示＋回句共用輸入列，按 120 欄算最長組合不被截。
     - **輸入期間鍵列**：現在回 "main"（:1355、:1368-1372）⇒ 面板留著但鍵列說謊。改輸入模式鍵表（依型），登進 `unbound_key_bed`。
     - **鏈式輸入的 callback 被抹（藍圖 d9f237b19 讀碼抓到，我已核 text_ui_main.gd:674-681）**：Enter 先 `callback.call()`（步驟 N 在裡面裝上步驟 N+1 的 callback），之後才 `_input_mode_callback = Callable()` ⇒ 下一步的 callback 被抹掉，模式仍開 ⇒ 玩家打「人數 Enter」落到舊路 `_request_key_advance(n)` 跳 n 顆 tick；五步鏈派不出子隊。
       修：先把 callback 取到區域變數並清欄位、清 buffer，**再**呼叫；並收進 `_open_input`／關閉輸入的同一處。「跳過 tick 數」那條舊路只屬於 G 的入口，不得作為其他輸入模式的落空分支。
     - **`_open_input` 帶 origin**：Esc 回 origin；鏈式入口（一個輸入接下一個）沿用原 origin。
     - **輸入模式開著時，開它的那個面板留在畫面上**（子模式面板照畫），輸入列連已鍵入字元一起印。Esc ⇒ 回到那個面板（不是回大地圖）。

## 第二刀：派遣子隊按即做（依 R² ③ 重寫，待重審）
現況鍵：子隊面板 `_subteam_mode_binds_key` 只綁 Esc／U、A／B／N、1-9；WASD 未綁（走「此鍵在此模式無作用」）；selection==-1 時 A／B 綁了但靜默。
- **目標格＝開面板前在主畫面定的游標格**：玩家先在主畫面 WASD 移游標，再按 U 開子隊面板；面板頂端印「目標＝(q,r)」（游標格）。面板內**不**放行 WASD（不動 binds_key 的 WASD、不解 A 衝突）。
- 按 N ⇒ 依序開三個**模態子狀態**（全走 `_open_input`，提示在結果行）：
  ① 選隊長：模態中數字鍵＝隊長序號（模態期間 [1-9]選隊不生效，所以不撞）。**候選清單印在面板上**；提示列只印「選隊長 (1~N): 2_」（名字長塞單列會被 clip_to 靜默截，同威脅句的病）。
  ② 人數：數字輸入＋Enter，提示印上限。（＋／－ 刪：handler 不收、PlayerRepl 打不出 "+"。）
  ③ 任務：可選任務清單印在面板上，各一個數字鍵；提示列只印「選任務 (1~N): _」。
  ④ 確認 ⇒ 出發，目標＝面板頂端那格。
- **R² §4（20bd09e4a）檢查順序**：off_map → **未知格**（`PlayerQueryApi.tile_knowledge`，player_query_api.gd:412-430 的 unvisited）⇒ 回「還沒去過／看過這格」、**不呼叫 find_path** → 自己腳下（見下，待藍圖裁）→ 可達。

- **目標值在按 N 當下凍結**，每步提示印凍結值，不每步重讀 `_cursor`。
- 自己腳下：**合法**（藍圖裁 d9f237b19）。覓食／建設／安頓／留守待機都是自然用法；合不合法由任務自己的前提判，回句用任務的原因。⇒ P6b 改：游標在腳下按 N ⇒ 進流程；選了前提不成立的任務 ⇒ 回該任務的原因句。
- **可達判斷在開面板／按 N 當下做**，不是答完三題才拒：面板頂端印「目標＝游標處 (q,r)（可達）」或「（不可達：原因）」；不可達時 N 直接回原因、不開模態。判斷把 `player_command_system.gd:2046` 那段抽成共用函式（不呼叫 `move_to`——它會寫 task），多格移動與派遣都呼叫它。
