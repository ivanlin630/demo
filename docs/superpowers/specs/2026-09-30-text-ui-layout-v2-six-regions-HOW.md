**上游 WHAT**：藍圖的排版稿 ＋ §二 八條規則 ＋ §四 四點補裁
（`docs/superpowers/handbacks/2026-09-30-blueprint-to-systems-DRAFT-text-ui-layout-v2-mock.md`，`996465d21`）。
**用戶核可**：2026-09-30「**版面先這樣**」（藍圖轉述）⇒ 稿子照現狀生效，#10 可派工。
**用戶的驗收句**：「**排列合理且資訊豐富**」——★那一句**機器判不了**，見 §5 誠實限。

**★前置**：本票吃「動作全列＋原因」那張票的 API

## ★★★§1 六區 ＝ 一個具名母體（不是「版面很多區」）

```
①頂列狀態  ②左地圖  ③右分頁  ④中下動作區  ⑤下事件流  ⑥底結果句＋鍵位
★六區位置**固定**，任何模式都不搬；模式只改【動作區】的內容（藍圖 §二①）。
⇒ 驗收母體 ＝ **6**，而且是**指名**的六個（不是「數到六個標題」）：
  每一區有一個**機器可讀的標題錨**（HOW 定字串，例如 `─ 動作（`／`─ 事件（`），
  而斷言是「這六個錨**各出現剛好一次**」。
★★為什麼要「剛好一次」：出現兩次 ＝ 有人複製了一區（版面搬了），
  出現零次 ＝ 那一區沒畫出來 —— ★**兩種都要紅，而只數總數會讓它們互相補償**。
```

## §2 做什麼（逐區的 HOW 決定）

```
①寬度：**一個常數**（例：`TextUiLayout.COLS = 120`）——★禁第二處寫 120。
   藍圖說「120 欄寬為準，HOW 可縮」⇒ 縮的話改那一個常數，不改版面 code。
   ⇒ 斷言：輸出每一行的**顯示寬度** ≤ COLS（★全角字算 2，半角算 1 —— 中文介面必須這樣算）。
②頂列六欄：日期時刻／隊名人口／家／糧撐幾天／威脅一句／待執行 —— ★**指名六欄**，不是「頂列非空」。
③動作區：吃全列版 API，**逐列印 `label` ＋（不可：`disabled_reason`）**。
   ★★★排版層**禁自己寫文案**（藍圖③）⇒ 機械形式：UI 檔裡「（不可：」後面**只能接變數**，
     不得出現字面中文原因 ⇒ 驗收用 grep 咬（見 §3 P5）。
   ★「▸」表示有下一層；展開層 ＝ 招募（具名候選 1..N 各帶價／[0] 匿名帶價）、打聽、外交、勢力。
   ★★STUB 的泛用 `recruit` **不列**（藍圖④；那張票已經處理，本票只是不要把它畫回來）。
④事件流：最近 **8** 條，每條帶「第N天 HH:MM」＋來源（#4 那條佇列已存在）。
   ⇒ 斷言：每一條**逐條**匹配時間格式（★不是「有幾條」——格式壞掉的那一條會被總數蓋過去）。
⑤底部：最後一道令的結果句**一行** ＋ 鍵位提示**永遠印全**。
⑥Esc：**只回上一層** ⇒ HOW 用**一個** `_ui_stack`（push/pop），
   ★禁用一堆 `_mode_xxx` 布林（那是「零隱藏模式」在 code 層的反面）。
   ⇒ 斷言：從每一個展開層按一次 Esc ⇒ 深度 −1、**而六區的六個錨仍然各一次**（版面沒搬）。
★而地圖那一區沿用 #9 的四態字元＋圖例常駐（本票不改地圖語意）。
```

## ★★§3 驗收（★母體都要指名，不要數總數）

```
P1 [六區各一次] 六個標題錨**各出現剛好一次**
   ｜負對照 a：刪掉一區 ⇒ 必紅　｜★負對照 b：複製一區 ⇒ 必紅（★只數總數會讓 a、b 互相補償）
P2 [頂列六欄] 指名六欄都在｜負對照：拿掉任一欄 ⇒ 必紅（★指名，不是「頂列非空」）
P3 [寬度一個常數] grep：`120` 這個字面在版面這條路上**只出現一次**（在 COLS 宣告處）
   ｜負對照：在別處再寫一次 120 ⇒ 必紅
   ★並斷言每行顯示寬度 ≤ COLS（全角 2／半角 1）｜負對照：把 COLS 改成 40 ⇒ 必紅（證它真的在讀那個常數）
P4 [動作區逐列有原因] 造一個「有幾條不可做」的狀態 ⇒ 那幾列都印出非空原因
   ★母體地板：印出【這一輪有幾列 false】—— 0 的話這一格在「什麼都能做」的世界裡恆綠
P5 [★原因來自引擎] **把引擎那一條原因改一個字 ⇒ 畫面那一行跟著變**（藍圖的驗收句）
   ｜★★負對照：在排版層寫死一句原因 ⇒ 必紅（grep：「（不可：」後面出現字面中文 ⇒ 紅）
P6 [事件流逐條] 8 條**每一條**匹配「第N天 HH:MM」＋來源非空
   ｜負對照：讓某一條少掉時間 ⇒ 必紅（★逐條，不是總數）
P7 [Esc 只回一層] 從每一個展開層按一次 Esc ⇒ 深度 −1 且**六個錨仍各一次**
   ｜負對照：讓 Esc 直接回頂層 ⇒ 必紅　｜★負對照 b：讓某個展開層搬動了某一區 ⇒ P1 必紅
P8 [未綁定鍵] 按一輪未綁定鍵 ⇒ 動作區不變、**無模式關閉**（沿用既有「未綁鍵語意」那票的三態）
P9 全電池 BATTERY_RC=0；★fp：本票只改呈現面 ⇒ **先量；沒變不要動並寫明為何沒變**
```

## ★★★§5 誠實限（寫在這裡，因為它決定了「綠」是什麼意思）

```
★用戶的驗收句是「**排列合理且資訊豐富**」——**機器判不了**。
  本票的所有格加起來只證明**結構**：六區各一次、頂列六欄、每行不超寬、原因來自引擎、
  事件流逐條帶時間、Esc 只回一層。
⇒ ★★所以「P1–P9 全綠」**不等於**「版面可以交」：可以交的判準是**用戶看過**。
  ★★★而這一條要寫進交件信，否則下一個人會把「床綠了」讀成「這一票做完了」。
·★而「120 欄」本身也不是機器判得出對不對的事：床只能證「沒有超過那個常數」，
  證不了「120 是對的寬度」。★★後者只有用戶的終端能回答。
```
