## ★★★§1 六區 ＝ 一個具名母體（不是「版面很多區」）

```
①頂列狀態  ②左地圖  ③右分頁  ④中下動作區  ⑤下事件流  ⑥底結果句＋鍵位
★六區位置**固定**，任何模式都不搬；模式只改【動作區】的內容（藍圖 §二①）。
⇒ 驗收母體 ＝ **6**，而且是**指名**的六個（不是「數到六個標題」）：
  每一區有一個**機器可讀的標題錨**（HOW 定字串，例如 `─ 動作（`／`─ 事件（`），
  而斷言是「這六個錨**各出現剛好一次**」。
★★為什麼要「剛好一次」：出現兩次 ＝ 有人複製了一區（版面搬了），
  出現零次 ＝ 那一區沒畫出來 —— ★**兩種都要紅，而只數總數會讓它們互相補償**。
```

## §2 做什麼（逐區的 HOW 決定）

```
①寬度：**一個常數**（例：`TextUiLayout.COLS = 120`）——★禁第二處寫 120。
   藍圖說「120 欄寬為準，HOW 可縮」⇒ 縮的話改那一個常數，不改版面 code。
   ⇒ 斷言：輸出每一行的**顯示寬度** ≤ COLS（★全角字算 2，半角算 1 —— 中文介面必須這樣算）。
②頂列六欄：日期時刻／隊名人口／家／糧撐幾天／威脅一句／待執行 —— ★**指名六欄**，不是「頂列非空」。
③動作區：吃全列版 API，**逐列印 `label` ＋（不可：`disabled_reason`）**。
   ★★★排版層**禁自己寫文案**（藍圖③）⇒ 機械形式：UI 檔裡「（不可：」後面**只能接變數**，
     不得出現字面中文原因 ⇒ 驗收用 grep 咬（見 §3 P5）。
   ★「▸」表示有下一層；展開層 ＝ 招募（具名候選 1..N 各帶價／[0] 匿名帶價）、打聽、外交、勢力。
   ★★★~~STUB 的泛用 `recruit` 不列（藍圖④；那張票已經處理）~~ ⇒ **兩處都錯，2026-10-01 訂正**：
     ①`recruit` **不是 STUB** —— `player_command_system.gd:487 _action_recruit`（implementer 揭、我在他那棵樹上核過）
       檔頭逐字「**Always return a menu — never auto-execute**」⇒ 它**回一份真菜單**。
       那個「STUB」字眼講的是【**這一列按下去不改世界**】，不是【沒實裝】。
     ②「那張票已經處理」**與事實不符** —— 他沒有排除它，因為排除＝**門死記名招募**（有血證）。
     ★★★而它有**孿生兄弟**：`:923 _action_gather_intel` 形狀完全一樣（`InquirySystem.get_options`）
       ⇒ **第三類的母體是【兩個】不是一個**：`recruit`、`gather_intel`
       —— ★上一版只點了一個，`gather_intel` 那一半今天沒有人在問它。
     ⇒ 兩者**都留在列上**（它們正是 `:33` 那幾個「▸」的父節點），而它們的身分由 §7 的 `opens_submenu` 表達。
④事件流：最近 **8** 條，每條帶「第N天 HH:MM」＋來源（#4 那條佇列已存在）。
   ⇒ 斷言：每一條**逐條**匹配時間格式（★不是「有幾條」——格式壞掉的那一條會被總數蓋過去）。
⑤底部：最後一道令的結果句**一行** ＋ 鍵位提示**永遠印全**。
⑥Esc：**只回上一層** ⇒ HOW 用**一個** `_ui_stack`（push/pop），
   ★禁用一堆 `_mode_xxx` 布林（那是「零隱藏模式」在 code 層的反面）。
   ⇒ 斷言：從每一個展開層按一次 Esc ⇒ 深度 −1、**而六區的六個錨仍然各一次**（版面沒搬）。
★而地圖那一區沿用 #9 的四態字元＋圖例常駐（本票不改地圖語意）。
```

## ★★§3 驗收（★母體都要指名，不要數總數）

```
P1 [六區各一次] 六個標題錨**各出現剛好一次**
   ｜負對照 a：刪掉一區 ⇒ 必紅　｜★負對照 b：複製一區 ⇒ 必紅（★只數總數會讓 a、b 互相補償）
P2 [頂列六欄] 指名六欄都在｜負對照：拿掉任一欄 ⇒ 必紅（★指名，不是「頂列非空」）
P3 [寬度一個常數] grep：`120` 這個字面在版面這條路上**只出現一次**（在 COLS 宣告處）
   ｜負對照：在別處再寫一次 120 ⇒ 必紅
   ★並斷言每行顯示寬度 ≤ COLS（全角 2／半角 1）｜負對照：把 COLS 改成 40 ⇒ 必紅（證它真的在讀那個常數）
P4 [動作區逐列有原因] 造一個「有幾條不可做」的狀態 ⇒ 那幾列都印出非空原因
   ★母體地板：印出【這一輪有幾列 false】—— 0 的話這一格在「什麼都能做」的世界裡恆綠
P5 [★原因來自引擎] **把引擎那一條原因改一個字 ⇒ 畫面那一行跟著變**（藍圖的驗收句）
   ｜★★負對照：在排版層寫死一句原因 ⇒ 必紅（grep：「（不可：」後面出現字面中文 ⇒ 紅）
P6 [事件流逐條] 8 條**每一條**匹配「第N天 HH:MM」＋來源非空
   ｜負對照：讓某一條少掉時間 ⇒ 必紅（★逐條，不是總數）
P7 [Esc 只回一層] 從每一個展開層按一次 Esc ⇒ 深度 −1 且**六個錨仍各一次**
   ｜負對照：讓 Esc 直接回頂層 ⇒ 必紅　｜★負對照 b：讓某個展開層搬動了某一區 ⇒ P1 必紅
P8 [未綁定鍵] 按一輪未綁定鍵 ⇒ 動作區不變、**無模式關閉**（沿用既有「未綁鍵語意」那票的三態）
P9 全電池 BATTERY_RC=0；★fp：本票只改呈現面 ⇒ **先量；沒變不要動並寫明為何沒變**
```

## ★★★§5 誠實限（寫在這裡，因為它決定了「綠」是什麼意思）

```
★用戶的驗收句是「**排列合理且資訊豐富**」——**機器判不了**。
  本票的所有格加起來只證明**結構**：六區各一次、頂列六欄、每行不超寬、原因來自引擎、
  事件流逐條帶時間、Esc 只回一層。
⇒ ★★所以「P1–P9 全綠」**不等於**「版面可以交」：可以交的判準是**用戶看過**。
  ★★★而這一條要寫進交件信，否則下一個人會把「床綠了」讀成「這一票做完了」。
·★★★**P1 管不到的那一類（reviewer 2026-09-30 推演出來的，點名寫在這裡）**：
  **六個錨各剛好一次，而區塊【內容】溢出／重複／位置錯位** ——
  例如事件流的內容印了 16 行而標題只印一次 ⇒ ★P1 **看不見**它。
  ⇒ 不要誤以為 P1 綁得住這一類；它落在**用戶看得出而床看不出**的那一邊，
    ★★而這正是「排列合理」那句驗收句真正在守的東西。
·★而「120 欄」本身也不是機器判得出對不對的事：床只能證「沒有超過那個常數」，
  證不了「120 是對的寬度」。★★後者只有用戶的終端能回答。
```

## ★★★§6 R² 加固（reviewer verdict=issues，2026-09-30；★本節取代 §3 的 P3、擴充 §5）

### ①P1 的管轄範圍要講清楚（他判 P1 本身沒問題，而洞在別的地方）

```
他核過：P1 **結構上不可能**被「總數對而結構壞」騙 —— 它是**六個獨立的「剛好一次」斷言**，
不是總數比對；(a)(b) 只是代表性擾動，不是窮舉。
★★而他推演出真正的第三類洞，**不在 P1 的管轄裡**：
  **錨字串各剛好一次，而區塊【內容】溢出／重複／位置錯位**
  —— 例如事件流的內容印了 16 行，而標題只印一次 ⇒ P1 看不見。
⇒ ★★★處置：**不硬塞進 P1**（硬塞會讓 P1 變成一個什麼都管而什麼都不保證的斷言），
  改成在 §5 誠實限**點名這個具體案例** ⇒ 下一個人不會誤以為 P1 綁得住它。（已補，見 §5 末。）
```

### ★★②P3 換掉：現在它只驗「讀了 COLS」，**沒驗寬度算法本身**

```
他 grep 全庫 ⇒ ★**零 CJK 顯示寬度計算函式**（一個都沒有）⇒ 這是本票**第一個要寫的東西**。
★★而 P3 原本的兩道（`120` 只出現一次 ＋ 把 COLS 改成 40 必紅）只證明
  「**比較**那一步讀了那個常數」—— ★一個永遠回 `text.length()`、不分全半形的函式
  **一樣會通過 COLS 擾動測試**。
⇒ P3 拆成兩格：
  P3a [常數只有一份]（原本那兩道，不變）
  ★P3b [**寬度算法定樁**]：餵一個已知 **N 個全形 ＋ M 個半形** 的字串
     ⇒ 斷言算出的寬度 **精確等於 2N+M**（★不靠 COLS 擾動間接推論）
     ｜負對照：把算法換成 `length()` ⇒ 必紅
  ★★★而 P3b 是**獨立定樁**：它的期望值來自算術（2N+M），不是來自任何 code
    ⇒ 它不會跟被測物同源（同本 session 反覆驗證過的那條）。
```

### ③grep 的粒度（他核過風險是真的，而且今天有同型活例）

```
「（不可：」後面出現字面中文 ⇒ 紅 —— ★這個 grep 會命中**描述規則的註解**。
★★他點出今天的同型活例：`simp-lint` 自己就承認「討論這些字的文件本身是正當的提及」
  ⇒ **描述規則的註解跟真正違規的 code 長得一樣**。
⇒ 處置兩條，缺一不可：
  ①比照全床已經在用的 `_code_only()` 手法 —— **先剝整行註解再 grep**
  ②★把範圍限定在**真正負責 render 那一區的函式**，不要對整份 UI 檔裸搜
```

### ★④P7 的母體：**「找到來源」本身是動工第一步的交代項**

```
他查過：字母鍵那票驗證過的 **13 個 `_mode` 旗標**涵蓋範圍**比「展開層」更廣**
（含 `pre_encounter`／`advisor` 等不算子選單的模式）⇒ ★**不能直接套用**。
⇒ spec **不在這裡定案是哪個常數**，而是明文要求：
  ★**P7 的母體必須是 implementer 找到的真實機械來源**，不是 spec 手抄的四個名字
  ⇒ ★★「找那個來源」列進**動工第一步要交代的東西**（回報形狀：來源是什麼 file:line、
    它涵蓋幾個、跟「展開層」的差集是哪幾個 —— ★差集要指名，不要只給數字）。
```
