# 勒索拿到 0（或近 0）不得說「完成」——HOW

狀態：收 R²（…-R2-extortion-zero-take-ISSUES，同版不需再審）＋藍圖裁定 43817c7d1（最小單位 0.1）
來源：藍圖 2026-10-13-blueprint-to-systems-TICKET-extortion-with-zero-take-must-not-say-completed（第五輪用戶回饋 #5）
順位：地圖整寬之後、附身隊三件之前。

## 事實（main a8fe0924a）
- `interaction_system.gd:1507-1534 resolve_extortion_direct`：玩家為勒索方時先 `DiplomaticAiSystem.tribute_accept`；拒 ⇒ `_record_extorted(…, 0.0)`。接受 ⇒ `_resolve_extortion` 回 `gained`。
- 格式器就在同一函式（:1527-1533）：只印 `amt > 0.0` 的項；`amt < 1.0` 印一位小數 ⇒ **0 < amt < 0.05 的量印成「食+0.0」**。用戶看到的「食+0.0, 幣+0.0」最可能是這種近 0 正值（藍圖沒找到另一支格式器，因為就是這一支）。真 0 會被濾掉、全濾掉印「少量資源」——也是錯句。
- `gained` 空 ⇒「勒索完成（對方資源耗盡，無所得）」——說「完成」而世界沒變。

## 改法
1. **一支格式器（單一來源）**：新增 `ResourceFormat.amount(x) -> String`（按 0.1：`snapped(x, 0.1)`，取整＝round 到 0.1；寫法只有一種：**一律一位小數**（1 寫「1.0」、0.95 寫「1.0」），不並存「1」與「1.0」；為 0 回 ""）。面板資源欄寬要放得下小數；釘了面板字面的床會動，交件信列出。勒索結果句、事件行、**資源面板**都用它（R² ⑤：玩家對帳看的是面板，面板若仍整數就對不到帳；用戶裁單位是 0.1 ⇒ 面板跟著顯示 0.1）。不新增 sim 欄位。
2. **結果句由格式後的量決定，不由 accepted 決定**（判準只活在組句，R² ①：不在 sim 造「得手」欄）：
   - 各項格式後皆為 ""（或 `gained` 空）⇒「對方已經沒有東西可給」。
   - 否則 ⇒「勒索到：食 3.0、幣 0.4」型；不再出現「+0.0」「少量資源」與「完成」。
   - 物理照轉、不改（量化在深層批）。
   - accepted 的讀者母體已查（R²）：只有 `player_command_system.gd:938`（拒絕時加 unrest）、:944 轉 UI、:1937 丟掉回傳 ⇒ 無「得手」讀者，不需處理。
3. ~~怨照記~~：接受路徑已寫 `_record_extorted`（interaction_system.gd:508）——**不要再補一條**。
4. **事件行帶對象與結果**：「Team15 勒索 Team6：對方已無可取」／「Team15 勒索 Team6：拿到 食 3.0」；句子走 `WorldEvents.describe`。**玩家是被勒索方時也成立**（R² 鄰近缺口）：`player_command_system.gd:1937 _pay_extortion` 目前丟掉結果、只回「支付勒索」⇒ 改帶實際被拿走的量（同一支格式器）。
5. **煞車有沒有生效**：`tribute_eval` 是確定性 score > threshold（沒有機率）。量：連續勒索同一隊時每次的 score／affinity／feud／threshold，以及 `_update_relations` 的 cadence（affinity 何時更新）；先量再下結論，不低 ⇒ 停手交我。

## 藍圖裁定（43817c7d1）：資源最小單位 0.1
- 糧與幣（材料比照，藍圖假設）最小單位 0.1：畫面與可見量不得比 0.1 細；不足 0.1＝沒有。
- **本票只做顯示側**：上面那支格式器就是這把尺。物理量化（轉移／結算以 0.1 為步＋守恆床）在深層批，本票不動物理。
- 其他畫面上比 0.1 細或把近 0 印成 0.0 的地方，交件信列出（grep `%.2f`、`%.3f`、直接 str(float)），由我判是否併入。

## 驗收
- X1（修前紅）：床**直接設目標庫存**（每次只取剩餘 25%，兩次勒索造不出近 0）：gained 四形態——全空、全近零（<0.05）、混合、全可顯示——各一格；全空／全近零 ⇒「對方已經沒有東西可給」，不含「完成」「+0.0」「少量資源」。
- X2：可顯示的量與兩隊資源差（經同一格式器）逐項相等；面板顯示與結果句同一格式。
- X4：接受一次 ⇒ 被勒索方領袖 memory 恰多一筆 "tributed"；累計 ≥ FEUD_MIN ⇒ feud 邊形成；負對照拿掉 :508 ⇒ 第一格紅。
- X5：事件行含勒索方、目標、結果；玩家為被勒索方時，結果行含被拿走的量。
- X6：連續勒索同一隊，印每次 score／affinity／feud／threshold 的數列；score 不降 ⇒ 停手、交件信附數列。
- 負對照：結果句改回看 accepted ⇒ X1 紅；面板改回整數 ⇒ X2 紅。
- world-fp 不變（只改組句與顯示）。
