# 勒索拿到 0（或近 0）不得說「完成」——HOW

狀態：草稿，待 R²
來源：藍圖 2026-10-13-blueprint-to-systems-TICKET-extortion-with-zero-take-must-not-say-completed（第五輪用戶回饋 #5）
順位：地圖整寬之後、附身隊三件之前。

## 事實（main a8fe0924a）
- `interaction_system.gd:1507-1534 resolve_extortion_direct`：玩家為勒索方時先 `DiplomaticAiSystem.tribute_accept`；拒 ⇒ `_record_extorted(…, 0.0)`。接受 ⇒ `_resolve_extortion` 回 `gained`。
- 格式器就在同一函式（:1527-1533）：只印 `amt > 0.0` 的項；`amt < 1.0` 印一位小數 ⇒ **0 < amt < 0.05 的量印成「食+0.0」**。用戶看到的「食+0.0, 幣+0.0」最可能是這種近 0 正值（藍圖沒找到另一支格式器，因為就是這一支）。真 0 會被濾掉、全濾掉印「少量資源」——也是錯句。
- `gained` 空 ⇒「勒索完成（對方資源耗盡，無所得）」——說「完成」而世界沒變。

## 改法
1. **先量**：床重現用戶情境（同一目標一分鐘內勒索兩次），印 `gained` 原始值，確認是「近 0 正值」還是「0」。交件信寫數字。
2. **結果句由轉移量決定，不由 accepted 決定**：
   - 所有項的量在顯示精度下都是 0（`snapped(amt, 0.1) == 0`，或 `gained` 空）⇒ 結果句「對方已經沒有東西可給」；`accepted` 照回，但**不算一次得手**（下游任何「成功勒索」計數、聲望、記憶不寫「得手」那一份）。實作端列出 accepted 之後有哪些讀者把它當成功，逐一處理。
   - 有可顯示的量 ⇒「勒索到：食 3、幣 1」型；不再出現「+0.0」與「少量資源」。
   - 近 0 正值確實轉移了（世界有變）：照轉、不改物理；只是不宣稱得手（顯示精度以下＝玩家無從對帳）。
3. **對方的怨照記**：被威脅了就記（`_record_extorted` 在接受路徑上也要寫，帶實際轉移量；先查現況接受路徑有沒有寫）。
4. **事件行帶對象與結果**：「Team15 勒索 Team6：對方已無可取」／「Team15 勒索 Team6：拿到 食 3」。事件產生點與句子走 `WorldEvents.describe`（同一份），不在 UI 另組。
5. **怨累積煞車在這條路上有沒有生效**（2026-10-07 合併的勒索煞車）：讀真實 util，不手抄門檻。

## 驗收
- X1（修前紅）：目標身上只剩近 0 資源 ⇒ 結果句「對方已經沒有東西可給」，不含「完成」「+0.0」「少量資源」。
- X2：目標有可觀資源 ⇒ 結果句列出實際量，與兩隊資源差逐項相等。
- X3（修前紅）：近 0 那次不計入「得手」讀者（列出的每一個）。
- X4：接受路徑對方的怨有記，量與實際轉移一致。
- X5：事件行含勒索方、目標、結果。
- X6：連續勒索同一隊 N 次（N 由床定，相隔一分鐘），第 N 次的 `tribute_accept` 接受機率（讀真實 util 或其輸入分數）低於第 1 次；若不低 ⇒ **停手，交件信附 util 分解**，煞車修法由我定（不在本票自創）。
- 負對照：結果句改回看 accepted ⇒ X1 紅。
- world-fp：句子與計數改動不應動 fp；若 3 動了 NPC 的怨帳 ⇒ fp 可能變，先二分再報。
