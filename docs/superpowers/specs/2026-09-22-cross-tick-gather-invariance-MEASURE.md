# §1 為什麼要量（★而不是直接做快取）

```
跨 tick 快取 ＝ 把上一個 tick 的 `gather` 結果借給這一個 tick 用。
★它安不安全，取決於一個【可以量的事實】：**那份結果到底有多常不變**。
★★而今天已經有一次血證：同一個量的兩種讀法**跨在門檻兩側**（L ＝ 71.2% vs 44.6%）
   ⇒ **定義沒鎖就量，會得到一個看起來可以引用的廢數** ⇒ 所以定義先鎖、門檻先寫。
```

# §2 ★★★量什麼（WHAT 2026-09-22 裁；★主量與對照欄是兩件事）

```
【主量 (丙)】同一隊、相鄰兩 tick，**`gather` 產出的【整份】內容**是否逐欄相同 ⇒ 不變率
【對照 (甲)】同一隊、相鄰兩 tick，**rank 第一名**是否換人 ⇒ 不變率
★★為什麼主量不是 (甲)：快取要共用的是【整份結果】，不是只有第一名
   ⇒ (甲) 回答的是「決策穩不穩」，**回答不了「快取安不安全」**
★★★而 (甲) 仍要印：它便宜、直覺，而且**兩個數的差距本身就是一個發現**
   （若第一名幾乎不變而整份常變 ⇒ 變的是**不影響排序的欄位** ⇒ 指向一個更窄的快取形狀）
```

## §7.1 訂正後的定義（**WHAT 2026-09-22 裁，最終版**）

```
【主量】同一隊的**相鄰兩次 `gather`**（不論隔幾 tick）產出是否逐欄相同 ⇒ 不變率
   母體 ＝ **≈ 9134**（9237 − 103）★真的有母體
★★**為什麼這才是對的量**（WHAT 的話，我照收）：
   **它就是快取的反事實** —— 「跳過這一次 gather、沿用上一次的結果」，結果一不一樣。
   ⇒ 而「相鄰兩 tick」問的是一個**快取根本不會遇到的情境**。
```

## §8.1 ★★★「定義有瑕疵」≠「結論待定」

```
★瑕疵是真的：`tick` 自己就是 `snapshot_dict()` 的一個欄位 ⇒ 跨 tick 比【構造上】不可能整份相同
   ⇒ (丙) ≡ 0 有一部分是**我的定義自帶的**
★★**而 implementer 沒有就此改判準（那是我的權），他加了一個診斷欄**：
   **排除 `tick` 之後的不變率 ＝ 仍然 0.0000（0／1368、0／1239）**
⇒ ★★★**所以不是一個欄位擋住了** ⇒ **結論不因那個瑕疵而改變** ⇒ 結案成立。
★這一格的形狀值得記：**先把瑕疵修掉再看結論，而不是拿瑕疵當「所以還不能判」。**
```

## §8.2 ★★訂正我自己 §5⑥ 的措辭（**我把「成本」與「失真」混為一談了**）

```
★我寫的是：「樁佔 gather 的比例…若它貴到改變了世界的時序，**這一輪的數字作廢**」
★★而實測：樁成本 > 10%（`snapshot_dict` 1.18s／1.10s ＋ `rank_scored_ctx` 5.17s／5.53s）
   **但 implementer 做了直接對照**：樁開 vs 樁關，`gather` 呼叫 677 ＝ 677、
   `attack_scan` 圈數 3758 ＝ 3758（**逐字相同**）⇒ **世界沒有被改變**
⇒ ★★★**訂正**：成本超標**作廢的是【時間量】**；而本票的判準是 **(丙)／(甲) ＝ 次數比**，
   **不受樁成本影響** ⇒ **裁定成立，不作廢**。
⇒ ★**下次寫這一格要分開兩句**：①「樁成本 > X% ⇒ 時間量不可引用」
   ②「樁改變了世界（對照不逐字相同）⇒ **整輪作廢**」——★★它們是兩個失效，不是一個。
```
