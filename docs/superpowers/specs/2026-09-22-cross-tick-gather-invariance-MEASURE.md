# §1 為什麼要量（★而不是直接做快取）

```
跨 tick 快取 ＝ 把上一個 tick 的 `gather` 結果借給這一個 tick 用。
★它安不安全，取決於一個【可以量的事實】：**那份結果到底有多常不變**。
★★而今天已經有一次血證：同一個量的兩種讀法**跨在門檻兩側**（L ＝ 71.2% vs 44.6%）
   ⇒ **定義沒鎖就量，會得到一個看起來可以引用的廢數** ⇒ 所以定義先鎖、門檻先寫。
```

# §2 ★★★量什麼（WHAT 2026-09-22 裁；★主量與對照欄是兩件事）

```
【主量 (丙)】同一隊、相鄰兩 tick，**`gather` 產出的【整份】內容**是否逐欄相同 ⇒ 不變率
【對照 (甲)】同一隊、相鄰兩 tick，**rank 第一名**是否換人 ⇒ 不變率
★★為什麼主量不是 (甲)：快取要共用的是【整份結果】，不是只有第一名
   ⇒ (甲) 回答的是「決策穩不穩」，**回答不了「快取安不安全」**
★★★而 (甲) 仍要印：它便宜、直覺，而且**兩個數的差距本身就是一個發現**
   （若第一名幾乎不變而整份常變 ⇒ 變的是**不影響排序的欄位** ⇒ 指向一個更窄的快取形狀）
```

# §3 ★★★怎麼比（**硬性：構造保證，不准手抄欄位清單**）

```
★**用既有的 `DecisionContext.snapshot_dict()`**（`decision_context.gd:1454-1466`）——
  它用 `get_property_list()` 走訪，而那支函式自己的註解就寫著：
    「★用 get_property_list 而不是手抄清單：★★手抄的清單【不會跟著新欄位長大】」
  ⇒ ★★**這正是我們要的構造保證** ⇒ **不要另外寫一份欄位清單**
★★★判準句：**「我的比法會不會因為【有人新增了一個欄位而沒列進來】而變成『不變』？」**
  —— `snapshot_dict()` ⇒ 不會；手抄清單 ⇒ 會，**而且它會讓不變率虛高**（偏向「快取很安全」那一側）
★比對方式：對 `snapshot_dict()` 取穩定序列化後的雜湊，逐 tick 比【同隊上一 tick】的雜湊
```

# §4 ★預註冊（★**在看到數字之前寫死**，WHAT 已確認）

```
門檻：**(丙) 不變率 ≥ 95%** ⇒ 值得開快取票（省的是整個 `gather`，而 gather ＝ 整場 tick 時間的 43.7%）
      **< 95%** ⇒ ★**那個快取形狀從一開始就錯** ⇒ 永久結案（不是「調低門檻再說」）
★★而 95% 的意思要講死：**每 20 次借用會有 1 次借到錯的**
   ⇒ 低於它，這個形狀要的就不是快取而是**失效偵測**（那是另一張票的形狀）
```

# §5 ★★卷面必帶（★母體與尾巴同印 —— 2026-09-22 立的規矩）

```

★★★⑥**樁自己的成本**：`snapshot_dict()` 每隊每 tick 跑一次不便宜 ⇒ **印出它佔 gather 的比例**；
   若它貴到改變了世界的時序，**這一輪的數字作廢**（★不是「差不多啦」）
```
