
## §1 走法（★透過終端，不透過 API 下指令）

```
transport ＝ `tools/play.py` 的 `start_server`（`:132`）＋ `read_frame`（`:183`）—— ★不另寫第三套 socket 迴圈
每一步：
  ①讀一屏 ⇒ **只從畫面文字**解析「可做的事」（鍵 ＋ 動作名 ＋ enabled／disabled）
  ②挑一個 enabled 的（★挑法：確定性 —— 由 seed 與步數決定，不用 randf）
  ③送那一行印出來的鍵
  ④讀下一屏 ⇒ 結果句 ＋ 頁腳待執行
  ⑤取世界狀態差異（§2）
  ⑥印一行：步數｜挑了什麼｜按了什麼鍵｜結果句｜差異摘要
N 步：從常數推導（★不寫死；例：可做的事種數 × 2）
確定性：同 seed 同走法 ⇒ 輸出**逐字相同**（★換 seed 必須**不同** —— 否則正規化器過寬，恆穩）
```

## §2 ★★★世界狀態差異：要扣掉「世界自己在動」（這是本票最難的一條）

```
問題：每按一鍵 ＝ 推一 tick（press-is-one-tick），而那一 tick 裡**整個世界都在動**（別隊移動、經濟結算、時間流逝）
  ⇒ 直接比前後快照 ⇒ 每一步都「有差異」⇒ (紅二) 永遠不紅、(紅三) 永遠在紅 —— 兩個都沒有鑑別力
⇒ ★解法 ＝ **雙世界對照**（確定性讓它成立）：
  同 seed、同一個走法前綴，**分叉成兩份**：A 按那個鍵；B 不按（推同樣的 tick）
  ⇒ **動作的效果 ＝ diff(A) − diff(B)**
  ⇒ ★★這一條的前提是兩份在分叉前**逐位元組相同** ⇒ 一格：分叉點兩份的 fp 相同（不同 ⇒ 不可判，ABORT 不是綠）
★讀狀態只准唯讀查詢（bridge 的 snapshot），★**不准耗 RNG**（判準庫：觀測儀器禁耗 global RNG）
  ⇒ 一格：跑 E2E 前後，同 seed 不跑 E2E 的世界 fp 相同（觀測沒有改變被觀測物）
```

## §3 動作語意 → 期望差異（★單一來源）

```
「移動 ⇒ 位置變、交易 ⇒ 兩邊資源變」這張對照表**只能有一份**
⇒ ★放在 `player_command_system.gd:366 ACTION_SHAPE`（已是動作的單一形狀表）**加一欄** `effect`
  （例：`"position"`／`"resources_both"`／`"relation"`／`"none_expected"`）
⇒ 床讀那一欄，**不在床裡另抄一份**（判準庫：估算器禁手抄物理；兩份會漂而漂掉的那份是靜默的）
★反向掃：畫面上**出現過的**每一個動作，ACTION_SHAPE 都要有 `effect` ⇒ 缺 ⇒ 紅並指名
★`"none_expected"` 的動作（純查詢、打聽）⇒ (紅二) 不適用，但 (紅三) 適用（它不該改世界）
```

## §4 驗收（P）

```
P1 [母體地板] 每一步候選集**非空**；整輪涵蓋的動作種數 ≥ 地板
   ★地板跟**畫面那一輪實際提供過的種數**比，不跟一個手寫常數比（否則畫面少列一種，床也跟著少期望一種）
   ⇒ 印：畫面提供過 X 種／本輪按過 Y 種／從沒被按到的是哪幾種
P2 [紅一] 結果句的動作名 ＝ 按下那一行印的動作名
   ★陽性對照（藍圖逐字）：鍵表錯位一格 ⇒ 必紅
P3 [紅二] 結果句說成功 ⇒ diff(A)−diff(B) 在 `effect` 指的欄位**非空**
   ★陽性對照（藍圖逐字）：某 handler 改成只回 ok 不改狀態 ⇒ 必紅
P4 [紅三] diff(A)−diff(B) 非空 ⇒ 結果句非空且提到那個動作
   ★陽性對照（我補）：某 handler 改狀態但不寫結果句 ⇒ 必紅（藍圖給了兩種的對照，第三種也要有）
P5 [確定性] 同 seed 逐字相同；換 seed 必須不同
P6 [雙世界前提] 每次分叉兩份 fp 相同
P7 [觀測不改物] 跑不跑 E2E，同 seed 世界 fp 相同
```
