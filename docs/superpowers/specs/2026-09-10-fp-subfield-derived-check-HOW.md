# HOW spec：fp 的導出檢查往【子層級】再做一次

owner: systems ｜ 2026-09-10 ｜ 觸發：implementer 的技術債清單第一名
上游：頂層欄位的導出檢查已上線（`0661f892c`），**而它自己寫明看不到子層級**。

---

## ① 為什麼這是第一名（★不是我排的，是他提的，而我同意並補上理由）

```
今天上線的導出檢查：母體 ＝ WorldState 的頂層 var 欄位，
判準 ＝ 該欄位有沒有【真的被讀】（`state.<欄位>`）⇒ 沒有 ⇒ 進「本尺排除」。
★而它【自己寫明】看不到子層級：
   「_emit_teams 有沒有漏掉 TeamData 某個新欄位」這一類 —— 本尺明說看不到。
⇒ ★★那句誠實限是對的，★★★而【一個被寫下來的洞仍然是洞】。
```

★**而我要補一個他沒寫、但決定排序的理由**：

```
攻擊門那張大票會【大幅改動 team 的行為】，而它的驗收會用到 fp。
⇒ ★若 `_emit_teams` 漏掉某個 TeamData 欄位，那張票的「fp 變了／沒變」【都不可信】。
⇒ ★★所以這張票是【攻擊門證據可信度的前置】，跟哨兵那張同一個角色。
⇒ ★★★排序理由一句：**先讓儀器可信，再拿它去量大改動。**
```

---

## ② 修法：★形狀照抄頂層那支，母體換一層

```
母體（逐個被 _emit_* 序列化的資料類）：
   TeamData ／ PersonData ／ FactionData ／ TileData(HexTileData) ／ WorldData
   ⇒ ★每一類用 get_property_list 抽它的 var 欄位（不手抄）
判準：★該欄位名有沒有在【對應那支 _emit_*】裡被真的讀到（`<obj>.<欄位>`）
   ⇒ 沒有 ⇒ 進【子層級排除清單】，★而那份清單同樣是【導出值】不是手抄
輸出：★★`blind_note()` 現在印兩段 ——【頂層排除】＋【子層級排除】，
   ★★★兩段都標明它是【哪一個粒度】的（沿用 EXCLUDES_SUBFIELD 旁邊那句話的做法）。
```

★**已知會被判為「排除」而【那是對的】的一類**：ephemeral 快取／cadence 排程欄
（`food_runway`／`*_eval_next_tick` …）—— ★它們**本來就該排除**，
⇒ ★★所以本票的產出**不是一份「要修的清單」**，是**一份【被具名的清單】**：
★★★**每一欄要嘛在尺裡、要嘛被具名排除 —— 不得有第三種狀態（沒人提過）。**

---

## ③ 驗收

| # | 格 | 判準 |
|---|---|---|
| ① | **子層級清單是導出的** | 在 `TeamData` 加一個假欄位（不進 `_emit_teams`）⇒ **必須具名出現在子層級排除清單**；★移除後消失 |
| ② | **★不得亂紅** | 一個**真的在 `_emit_teams` 裡被讀**的欄位（例如 `population`）**不得**出現在排除清單裡 |
| ③ | **★★「提及 ≠ 讀取」不得重演** | 在 `_emit_teams` 的**註解**裡提到那個假欄位 ⇒ **它仍然必須留在排除清單裡**（★★★這一格是今天那個坑的直接對照，**必做**） |
| ④ | **兩段輸出都在** | `blind_note()` 同時印【頂層】與【子層級】，且各自標明粒度 |
| ⑤ | **fp 值不變** | 本票**只改自我描述** ⇒ fp 必須完全相同（同 fp-EXCLUDES 那張的紀律） |
| ⑥ | **★★★第三種狀態要歸零** | 交件要附一個數字：**每一類各有幾欄「在尺裡」／幾欄「具名排除」** ⇒ 兩者相加 ＝ 該類 var 欄位總數；★差額不得為非零 |

---

## ④ 誠實限與不做

```
①★本票【不修】任何被抓到的漏欄 —— 它只讓它們【具名】。
  ★★要不要納入 fp 是逐欄的判斷（有些本來就該排除）⇒ 逐欄修另票。
②★★★它仍然看不到【第三層】（例如 TeamData 裡某個 Dictionary 的鍵）——
  ⇒ **交件要把這句寫進 `blind_note()` 旁邊**，★而不是只寫在交件信裡
    （今天已經學過：誠實限要跟它描述的東西住在一起）。
③不改 hash 內容、不碰 EphemeralStateHash。
```
