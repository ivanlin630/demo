```
★★★**所以 blueprint 要的「去偵查分池」在今天的 code 上【不可能發生】** ——
**掠奪丟掉它、攻擊丟掉它、而偵查也丟掉它** ⇒ **那 6 筆目標對那支隊而言等於不存在。**

★**而那一行的註解本身就是這個洞的來源**：
> 「**不知道在哪 ⇒ 連去都去不了**」

⇒ ★★**那句話把兩件事寫成了一件**：
```
**「不知道它【現在】在哪」**  ⇒ 真的

```
⇒ ★★★**差一個字，差掉整個偵查動詞。**

## §1 修法：偵查候選的位置來源改成【last-known ＋ 年齡】

```
現況：`_rpos = BeliefSystem.belief_pos(...)`  ⇒ 過期 ⇒ `(-1,-1)` ⇒ `continue`
新：   `_rpos = <last-known 位置>`（**不經新鮮度閘**）＋ `_rage = now − claim.tick`
      ⇒ ★**位置未知【只有在真的沒有任何 claim 時】才 `continue`**
```
★**而年齡要進【價值】不是進【門】**：
```
`_rval = _prior × δ^days × freshness_factor(_rage)`
  ★`freshness_factor` **單調遞減、永不歸零**（★★**歸零＝又變回一道靜默的門**）
  ★★而它的形狀要**物理**：**目標越會跑、情報越舊 ⇒ 撲空機率越高**
     ⇒ **不是「三天後價值 0」，是「三天後那裡有它的機率比較低」**
```
★★★**零新旋鈕**：`freshness_factor` 的分母走**移動能力**，**不是一個新的死常數**。
★**而「誰的移動能力」在 §5④ 被改掉了**：不是目標的（那會讀 god-view），是**不讀任何隊狀態的基準旅行者**
（`MovementSystem.baseline_tiles_per_day()`，由 `BASE_MOVE_TICKS` 導出）。**讀本節請直接跳 §5④。**

## §2 ★為什麼不放寬掠奪／攻擊那兩道門（blueprint 明示，而我同意並補理由）
```
放寬 ⇒ **隊會【直接打】一個它不知道在哪的目標** ⇒ ★**那是隔空作用，違反感知鐵律**

⇒ ★★**而那正是對的戲**：**絕境者「先找到獵物再動手」。**
```

## §6.1 ★★★他沒看到的閘：錨定性【自己】會在同一條線上過期

`BeliefSystem.appearance()`（`belief_system.gd:394-414`）在回 activity 之前**自己先過 `BELIEF_STALE_TICKS`**：
```

:407      return {"activity": ACT_UNKNOWN, ..., "state": "stale"}
```
⇒ ★**「這則位置情報三天了，它還準嗎？」——而你要拿來判斷的錨定性，在同一個第三天也變成 UNKNOWN。**
**在最需要它的那一刻它剛好不在。**

**修法（★不是特例，是本票已經立好的同一個模式）**：本票對【位置】的作法是
「繞過新鮮度閘取 last-known ＋ 帶年齡回來，年齡進**價值**不進**門**」⇒ **錨定性用同一個模式讀 activity**。

**不新增姊妹 accessor** —— `appearance()` 整支只是 `best_estimate()` 的 wrapper，而 `best_estimate()`
**本身不過期**（`belief_system.gd:144-161`，回的是 claim 的 `value`，`activity` 與 `last_tick` 都在裡面）
⇒ **呼叫端直接讀 `best_estimate()` 就有原值**，跟本票 §1 讓 `pick_recon_target` 直接讀 `tile_pos`/`last_tick`

```
呼叫端（decision_context.gd，本票 §1 已經在那裡呼叫 best_estimate 了）:
  var bel := BeliefSystem.best_estimate(state, 觀察者, 目標)
    bel["tile_pos"]   ← 本票 §1 已在用
    bel["last_tick"]  ← 本票 §1 已在用（算年齡）
    bel["activity"]   ← ★本節新增的讀取，**同一次讀、同一個 tick**
★ appearance() 逐字不動 —— 它唯一的生產消費者 faction_ai_system.gd:934-935 有一道
  `if state != "fresh": continue` 的邀請門，靠的正是它現在的過期行為（reviewer 窮舉核實）。

## §6.2 ★「甚至不過期」不採 —— 只降斜率，不設無限期

本票 §1 已立：`freshness_factor` **單調遞減、永不歸零**。錨定性**對稱地**只准動**斜率**：
```
錨定（believed ACT_SETTLED 或有據點 claim） ⇒ 慢線衰減
無錨                                        ⇒ 快線衰減
★兩者都仍然單調遞減、都永不歸零、都沒有「不過期」這一檔
```
**三個理由**：
1. ★**錨定的隊會拔營** —— 「不過期」讓一則**已經錯了的** belief 變成**不可證偽**（它永遠不會掉到會被重新偵查的價值）。
2. ★★**它會從後門鬆開攻擊門**：`_find_weakest_prey` 的 reachable 走 `belief_pos`，而 `belief_pos` 吃的就是
   `BELIEF_STALE_TICKS`。若「不過期」是做在 `BeliefSystem` 那條線上 ⇒ **駐紮目標的舊座標會直接通過攻擊門** ⇒
   **正是本票 §2 明文擋下的那件事**（隔空作用）。
3. ★★★**而這正是 ① 的兩個落點不同義**：
   | 落點 | 影響範圍 | 本票立場 |
   |---|---|---|
   | (A) 錨定性餵 `freshness_factor`（偵查目標的**價值折扣**） | 只有偵查選點 | ★**就做這個** |
   | (B) 錨定性改 `BELIEF_STALE_TICKS`（`BeliefSystem` 的**全域閘**） | 所有讀者，含攻擊/掠奪門 | ★**不做** —— 它是 `defers.tsv` → `belief-staleness-line-is-a-dead-constant`，且會違反 §2 |

## §6.5 ★★★錨定的判準是什麼（systems 裁 2026-09-17，implementer 交件時提問）

**實測**：只認 `ACT_SETTLED` ⇒ 錨定佔母體 **0.96%**（1320／137356）⇒ **機制幾乎不影響世界**。

**先把事實查清楚**（`belief_system.gd:380-389` 逐行）——★**寫入端的判斷順序很重要**：
```
combat_target != -1                      → ACT_COMBAT
腳下 tile 的 construction_team_id == 它   → ACT_BUILDING
last_tile_pos != tile_pos                 → ACT_MOVING     ★★動沒動【先被判掉】
腳下 tile 是自己的 outpost / camp_level>0 → ACT_SETTLED
其餘                                      → ACT_IDLE
```
★**所以 `ACT_IDLE` 不是垃圾桶** —— 它是「觀察到 ∧ 不在戰鬥 ∧ 沒在蓋 ∧ **上一步沒移動** ∧ 不在自己據點上」。
★★**我原本想用「fall-through 桶不能當正面訊號」否決它，而那個理由在事實上不成立**（MOVING 先被判掉）⇒ 我不用那個理由。

|---|---|---|
| `ACT_SETTLED` | ★**算錨定** | 它在自己的據點／營地上 ＝ **有理由留在那裡** |
| `ACT_BUILDING` | ★★**算錨定（新增）** | 工地綁在那格 tile 上 ⇒ **要蓋就得在那裡** ＝ 同樣是【留下來的理由】，而且是正面訊號不是預設值 |
| `ACT_IDLE` | ★★★**不算錨定** | ★**理由不是「它是預設值」，是【它是瞬時觀測不是駐留理由】**：`IDLE` 只說「上一步沒動」，**沒有任何東西讓它下一步也不動**。★★**而 belief 的 activity 是【凍在觀察當下】的** ⇒ 一支當時 idle 的隊，即使已經行軍三天，它的 claim 仍然寫著 idle ⇒ **拿 IDLE 當錨會【隨年齡越錯越多】，而這裡要的正是一個「隨年齡仍站得住」的訊號** |

★★★**判準一句話**：**錨定問的是【有沒有理由留在那裡】，不是【這一刻動沒動】。**

### 誠實標：blueprint 的 ① 有一半今天做不出來

★★這一格要回報給 blueprint（他的 ① 只有約 1% 落在世界裡），**不由我替他決定要不要補那一半**。

## §6.6 ★複查格：1% 什麼時候該被重新議（blueprint 裁 2026-09-17，systems 把它寫成可執行的）

**blueprint 逐字**：
> 「③1% 的讀法：錨定性的職責本來就是『讓不動的少數過期慢』—— 世界 99% 的 team-belief 是動者，
> 他們走快線是對的，不是覆蓋不足。『村的三天舊座標仍好』那句話的主場在 **tile／據點知識（不動產）**，
> 不動產本來就不該走 team-belief 的過期線 —— 這句我原裁混了兩個層。」
> 「④若後續量到 stale-drop 的受害者【實測多是有家的隊】⇒ 據點 claim 就有了第二個消費者級的證據，
> 回來議開欄；沒有那個數之前，1% 就是誠實的世界。」

★**我接受 ①②③④**，而 ④ 照現在的寫法**量不出來** —— 把它寫成能執行的：

### ★★ ④ 要的不是我已經要到的那個數
```
我已經要 implementer 加的： recon.act.<activity>          ＝【母體】依活動分桶
④ 真正要的：              recon.act.<activity> ∧ 位置已過期 ＝【受害者】依活動分桶
```
★**兩者不是同一個問題**：母體裡 99% 是動者，**不蘊含**「被過期卡掉的那一批也是 99% 動者」。
★★**這正是我這一輪一直在講的那條**：**聚合量回答不了逐個體的問題；母體的組成回答不了受害者的組成。**
⇒ **加這個交叉桶的成本 ≈ 0**（同一顆 tap 多一個維度，併進同一次世界跑）。

### 重新議的條件（★機械的，不是「覺得夠多了」）
```
若 (錨定候選 ∧ 位置已過期) / (全部 位置已過期) 明顯高於 (錨定 / 母體)
  —— 白話：被過期卡掉的那一批，【有家的隊佔比】高於它們在世界裡的佔比
  ⇒ 據點 claim 就有了第二個消費者級的證據 ⇒ 回去找 blueprint 議開欄
反之（兩個比例差不多）⇒ 1% 就是誠實的世界，不再議
```
★**現有的數就能算一半**：`錨定∧過期 = 476`／`全部過期 = 80939` ＝ **0.59%**，
而 `錨定/母體` ＝ **0.96%** ⇒ ★**受害者裡有家的隊【比世界裡還少】**
⇒ **就這一輪的數字而言，④ 的條件【不成立】** —— 不是「還沒量」，是**量到了而且是反方向**。
★★**誠實限**：`錨定` 現在只有 `SETTLED`（`BUILDING` 還沒進去）⇒ **加了 `BUILDING` 之後要重算這兩個比例**。

### ★★★ blueprint ③ 那半句我另外記帳
「不動產的知識不該走 team-belief 的過期線」＝ **一個新的層**（tile／據點知識），
**不在本票、也不在錨定票** ⇒ 進 `defers.tsv`：`outpost-knowledge-is-not-team-belief`。

## §6.7 ★★★為什麼加「規模必報」這一格（2026-09-17，implementer 揭）

**事實**：判準只認 `ACT_SETTLED` 時，錨定 ＝ **1320／137356（0.96%）**；
加上 `ACT_BUILDING` 之後 ＝ **13320／136843（9.7%）**——**而 `SETTLED` 自己只有 801（0.59%）**。

★**兩個版本的六格【全部都綠】。**
⇒ ★★**驗收格證明的是「機制有效」，它【不證明】「機制有規模」** ——
**一個只碰到世界 0.96% 的機制，和一個碰到 9.7% 的機制，在我的驗收表上長得一模一樣。**

★★★**而這不是「再加一個閘」**（用戶 2026-09-10 明令不准）：
```
★不是門檻：我【不】寫「錨定必須 ≥ X%」—— 那會變成一個沒有依據的旋鈕
★是必報欄：世界級那格【必須把佔比與分佈印出來】
⇒ 規模可以很小，但【不可以沒有人看見它很小】
```
★**判準一句話**：**擋不住縮水，但讓縮水無法靜默。**
（同族：`defers.tsv` 的誠實標、§5④ 的「函式裡成立、世界裡不成立」——**都是同一個處置：不阻擋，但不許靜默。**）
