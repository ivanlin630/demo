## §0 systems 裁定摘要
1. ★**「零 LOD（拆 near/far 分班）」排在五刀之後**——理由見 §2：**它是花預算的動作，不是賺預算的動作**。

4. **k≈2.004 是唯一的頭號目標**：五刀裡**只有兩刀直接打 N²**（掃描剪枝、隊數收斂），其餘三刀打常數項 → 排序照這個排。

## §2 ★排序衝突與解法（本 spec 最重要的一段）
**衝突**：WHAT 說「模擬層零 LOD、玩家距離分班刪除」。但**拆掉分班 ＝ 原本每 100 tick 想一次的遠隊，改成每 T1/T2 想一次** → **計算量往上跳**（今日世界多數隊是 far）。若照字面先拆，會在**還沒賺到預算前先花掉**，且正好撞上 k≈2.0。
**且**：拆分班後「大家多久想一次」的答案**來自時間 spec 的層級制（T1–T4）** → G **實作上依賴時間包**。
**解法（systems 裁）**：
- **A–F 先行**（賺預算：B/C 砍 N²、D/E 砍常數與尖峰、F 砍 N）→ **G 最後**，且 **G 與時間包的層級制同批落地**（G 的 cadence 語意由層級制給）。
- ★**驗收綁定**：G 落地時必須量「**每遊戲日 wall time**」而非每 tick（tick 定義與分班都變了，比 per-tick 會自欺）——與時間 spec §2 的 S0 同一個量法、**共用同一組對照**。
- ∴ **執行序：A → B → C → D → E → F →（時間包 S1/S2/S3）→ G → 新基線考**（兩包共用一考、blueprint ④）。

## §3 驗收框架：先分類再驗收
每刀**先標**「應否 byte-identical」，再選驗收法——**混淆會讓真 regression 躲在 intended-change 標籤後面**（本 session 血證：LOD 修若沒要求 rate-equivalence，就會用「反正世界變了」蓋掉降真實）。
- **必須 byte-identical（B、D）**：fp 三跑相同 ＋ 效能對照。★**這兩刀若 fp 變了＝有 bug，不准用 intended-change 解釋**。
- **intended-change（A、C、E、F、G）**：統計等價床（每遊戲日事件率/速率）＋ 逐項 intended 清單 ＋ 故事 QA。
- ★**每刀獨立量化**（blueprint 紀律）：單刀 A/B 對照、報「**每遊戲日 wall**」與「**k 值變化**」；**禁止把五刀一起量再宣稱總效果**（歸因不了就是沒量）。

## §4 與「剛落地的 LOD 補償碼」的關係（避免日後誤讀）
本 session 剛 merge 的 **LOD 降頻補償**（`reactions/cleanup` 改 `LOD_BOTH` + `trials` 補償 morale/XP/loyalty/unrest）**會在 G 落地時被移除**（零 LOD ⇒ 沒有 far pass ⇒ 沒有補償對象）。
★**這不是白做**：在 G 之前的所有輪次（含下輪長考前的一切量測）都靠它才不是「凍結的世界」；且它產出的〈LOD 降頻補償紀律〉**通用於任何降頻機制**（G 之後若仍有任何 tier 降頻，判準照用）。**移除時要一併更新 invariants 那節的適用範圍註記**，不要整節刪掉。

## §5 風險
- **F（隊數收斂）是設計改動偽裝成 perf 刀**：它改變世界組成（小團歸隊）→ **會改所有經濟/人口基線**。★建議 **F 單獨一輪、單獨量測、單獨故事審**，不要與 B/C/D/E 混在同一次比較裡。
- **D（髒旗快取）的失效訊號漏一個就是靜默 stale**：★要求**失效清單與寫入點對帳**（每個會改變被快取值的寫入點都必須發訊號），並用 byte-identical 當硬證據。
- **C（belief 剪枝）與感知鐵律相鄰**：剪掉「不知道的東西」是**正確方向**（本來就不該評估 god-view 候選）→ ★順帶檢查：**現行是否有靠掃全世界偷看的候選**（若有，C 同時是憲法修正、要標出來）。
