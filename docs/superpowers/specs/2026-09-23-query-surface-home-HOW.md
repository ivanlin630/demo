# HOW spec：查詢面補「家」（家在哪／離家多遠）

owner: systems ｜ 2026-09-23 ｜ **player_reachable: yes**
上游：blueprint 裁 (甲)「補查詢面」——生存頁③「身在何處、家在哪（位置、據點或營地、離家多遠）」
現況：那一格是天窗「位置與家（查詢面無此欄）」⇒ **那一頁答不出它自己承諾的問題**。

---

## ★★★§1 前提（★三條都是 file:line，而第二條會騙人）

```
①【沒有儲存的 home 欄位】：TeamData 沒有 home_tile／home_id
②★★`faction_ai_system.gd:3185`／`:5387` 的區域變數叫 `home_tile`
   —— ★★★而它其實是【當前格】（拿來檢查「我現在站的這格是不是我的據點」）
   ⇒ ★grep "home" 會先撞到它 ⇒ 實作端請【不要】照著它推語意
③`resource_system.gd:627 own_granary_tile()` 同理：只回【我現在站的這一格】
   ⇒ 它答的是「我現在在不在家」，★不是「我家在哪」
```

**⇒ 而它答得出來，靠既有索引**：

```
scripts/simulation/owner_outpost_index.gd  ＝ owner → 自家據點 tile
★語意逐字（該檔 §等價語意）：「state.world.tiles 迭代順序中的【第一個】
  outpost_level>0 且 outpost_owner==X 的 tile」
★★它已取代 12 處 production 的全圖掃 ⇒ 便宜、且語意已被釘死
```

## ★★§2 感知鐵律（★我 owner invariants，先自查）

```
「我自己擁有哪些據點」＝ self-knowledge ⇒ ★不是 god-view
⇒ 本票【不】讀別人的隱藏狀態、不跨距瞬間作用
★★而距離只用【我的當前格】與【我自己的據點格】兩個我本來就知道的位置
⇒ ★★★所以本票在感知鐵律上是乾淨的 —— 這一行寫下來是為了讓 R② 可以打它，不是宣告
```

## §3 要加什麼

```
player_api_mapper.gd 的 controlled_team 快照新增：
  home_pos      ：{q, r}｜★沒有據點 ⇒ 明確給 null（不是 (0,0)、不是 (-1,-1)）
  home_kind     ：據點／營地…（沿用 tile 既有的分類，★不要新造詞）
  home_distance ：hex 距離（整數）｜★home_pos 為 null ⇒ 也是 null
★★★三個欄位【同時】給或【同時】為 null —— 半套會讓畫面印出「家：？ 離家 3」這種句子
```

## ★★★§4 語意（★blueprint 已裁 2026-09-23，本節從「待裁」改成「已裁」）

```
★裁定：畫面「家」欄的語意 ＝ **本城**。
  而這【不是新語意】—— 機制意圖帳 #55⑤【本城】2026-09-10 就裁過了：
  單點自動／多點秤選人格調製／可遷都＝事件+廣播。
⇒ ★★所以 §4(乙) 不需要「它自己的票」，它需要的是【本城欄落地】那張票。

★★★本票怎麼做（本城欄未落地前）：
  ①照 (甲) 做：取值點用 owner_outpost_index（語意＝state.world.tiles 迭代序的第一個）
  ②畫面「（共 N 處）」旁**再標【暫代】** —— ★這三個字是分流器：
    沒有它，玩家（與下一個讀 code 的人）分不出【這就是家】與【這只是先湊一個】。
  ③★★票B **不落地本城欄**（那是「家與歸屬窗」的接線票，不在這裡偷渡）
  ④營地不是家（blueprint 同意，見 §6）
```

## §5 驗收

```
P1 [天窗消失] 生存頁的「位置與家（查詢面無此欄）」★不再出現，改印真值
P2 [成對對照] 把 home_pos 從查詢面拿掉 ⇒ ★那一格【變回天窗】（不是整頁壞掉）
P3 [★★無家的情形] 造一隊沒有據點 ⇒ 三欄皆 null ⇒ 畫面印「家：無」★而不是 (0,0)
P4 [多據點] 造一隊有 2 個據點 ⇒ ★home_pos 等於索引給的那一個，且畫面標「（共 2 處）【暫代】」
   ★★「暫代」兩個字是**判準的一部分**，不是文案：grep 不到它 ⇒ P4 紅。
P5 [fp] world-fp 不變（★本票只讀不寫）
P6 [ui-flow] 綠；P7 merge 前全電池
★★★而 P3／P4 是【母體地板】：沒有它們，P1 在「剛好每隊都有且只有一個據點」的世界裡恆綠
```
