# §0 WHAT 的裁定（逐字）

> ★裁 target：**`*multi` 感知蒐集塊** —— 兩輪（異 seed）它都是最大的錢（**371.8s／186.7s** ＝ 排行第一的 **2.73×／2.16×**），
> 而**排行第 4／5 兩輪換位 ⇒ 單輪排行不可依**。
> 修法方向 ＝ **快取／髒旗／事件驅動**（憲法既有形狀：**計算跟隨事件密度**，同 10× 索引案）；★**禁降真實、禁凍結**。
> 驗收 ＝ **同 seed 同窗前後對照**（176 幀掉多少**如實報**）＋ **【語意零改變閘】**（fp 指紋等價驗證現成）。

# §1 ★★★驗收的第一格不是效能，是【語意零改變閘自己會不會紅】

```
★fp 等價驗證是這一票的命門：它若對【被快取的那部分狀態】不敏感 ⇒ 它會恆綠
⇒ ★★所以【在做修法之前】先做一次陽性對照：
   手動把快取的值弄髒一格（例如故意回一個過期的蒐集結果）⇒ ★fp 指紋必須【不同】
   ⇒ 若 fp 仍然相同 ⇒ **那支閘對這一票沒有鑑別力，先修它再談修效能**
```
★★★**理由**：**「效能變好而語意沒變」這句話，完全靠那支閘撐著** ——
**而我今天已經見過四種「綠得不一樣」。**

# §2 修法（方向由 WHAT 定，形狀我補）

```
★允許：快取／髒旗／事件驅動 —— 計算跟隨【事件密度】而不是跟隨 tick
★禁止：降真實（少看幾格／少掃幾隊）、凍結（整段不算）
⇒ ★★判準一句話：**同樣的輸入必須得到同樣的輸出，只是不必每次重算**
```
★**髒旗的正確性條件要寫在 code 註解裡**：**哪些寫入點會讓快取失效** ——
★★**而那份清單要用【裸符號全庫掃】得到，不是憑印象列**（★今天的教訓：假窮盡最兇的形態是「我自己加的過濾條件」）。

# §4 ★附註：`unified.prosp` 兩輪零出現 —— 我查了，而答案要分兩層

```
它的 bump 在 faction_ai_system.gd:3590，而那一行【在一個四重合取的分支裡】：
   opt == "攻擊" and _solo_type(team) == "征服" and team.faction_id == -1 and _is_prosperity_candidate(...)
⇒ ★所以它【不是死登記】：bump 確實接在一條真的 code path 上（登記表 :1104 也對得上）
⇒ ★★而「那條 path 有沒有執行過」是【另一個問題】—— 零出現也可能是母體稀
⇒ ★★★分辨法（便宜）：在【外層條件】上加一顆計數（例如 opt=="攻擊" 且 征服 的次數）
   外層 > 0 而 prosp ＝ 0 ⇒ 卡在 _is_prosperity_candidate ／ 外層 ＝ 0 ⇒ 母體稀
```
★**我不猜**：**「死登記」與「母體稀」要做的事完全不同**（前者刪／修，後者留著並記一筆「這個窗口沒遇到」）。
