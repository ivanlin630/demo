> 修法方向 ＝ **快取／髒旗／事件驅動**（憲法既有形狀：**計算跟隨事件密度**，同 10× 索引案）；★**禁降真實、禁凍結**。
> 驗收 ＝ **同 seed 同窗前後對照**（176 幀掉多少**如實報**）＋ **【語意零改變閘】**（fp 指紋等價驗證現成）。

# §1 ★★★驗收的第一格不是效能，是【語意零改變閘自己會不會紅】

```
★fp 等價驗證是這一票的命門：它若對【被快取的那部分狀態】不敏感 ⇒ 它會恆綠
⇒ ★★所以【在做修法之前】先做一次陽性對照：
   手動把快取的值弄髒一格（例如故意回一個過期的蒐集結果）⇒ ★fp 指紋必須【不同】
   ⇒ 若 fp 仍然相同 ⇒ **那支閘對這一票沒有鑑別力，先修它再談修效能**
```
★★★**理由**：**「效能變好而語意沒變」這句話，完全靠那支閘撐著** ——
**而我今天已經見過四種「綠得不一樣」。**

# §2 修法（方向由 WHAT 定，形狀我補）

```
★允許：快取／髒旗／事件驅動 —— 計算跟隨【事件密度】而不是跟隨 tick
★禁止：降真實（少看幾格／少掃幾隊）、凍結（整段不算）
⇒ ★★判準一句話：**同樣的輸入必須得到同樣的輸出，只是不必每次重算**
```
★**髒旗的正確性條件要寫在 code 註解裡**：**哪些寫入點會讓快取失效** ——
★★**而那份清單要用【裸符號全庫掃】得到，不是憑印象列**（★今天的教訓：假窮盡最兇的形態是「我自己加的過濾條件」）。

# §6 ★裁定（systems 2026-09-18，依 implementer 的實測回報）—— 修法形狀與**一顆前置地雷**

## §6.1 §1 格 1-a：**過了**（閘有鑑別力）

```
乾淨 fp=3951597c0fd9…｜行為軌跡=3496867408
注射 fp=562749ac9518…｜行為軌跡=1859034031（讀到快取 510 次，其中快取值≠重算值 237 次）
```
★**而第一版注射差一點送出一封假警報**：注射在 `scout_*` ⇒ 欄位髒了 14 次而 **fp 相同**。
照 §1 的字面，那時就該停工回報「閘擋不住」——**但那是錯的**：逐 tick 行為軌跡**逐字相同**
⇒ 沒有任何決策因此改變 ⇒ **fp 相同是對的**。
⇒ ★★**「咬到欄位」≠「改到行為」，而它們在 fp 那一欄長得一樣、結論相反。**
⇒ ★★★**§1 的判準改成四格**（沒咬到／咬到但行為沒變／咬到且行為變而 fp 相同／都變）——已併入 `03_implementer` 既有那條注射規則。

## §6.2 修法形狀：裁 **(丙-2)**

**每一個欄位一支 `static` 純函式為【唯一權威】，`gather` 自己也呼它**（`gather` ＝ 組合者，不得保留第二份 inline 算式）。
★**延伸既有形狀，非新造**：`decision_context.gd:313 pick_recon_target` ／ `:1069`（gather 呼它）／ `options.gd:586`（to_task 呼同一支）。
⇒ 你原本擔心的「兩份算式 drift 而不會紅」在這個形狀下**不存在**（沒有第二份）。

- **否決 (甲)【欄位級同-tick 快取】**：可記憶化母體只有 **44 次**，而其中 **65.9% 與當下重算不同** ⇒ 上限小、風險大。
- **否決 (乙)【跨 tick ＋ 髒旗】（在本票內）**：錢確實在那裡，但它需要資料結構（堆／分桶）
  ⇒ 另開票，登 `defers.tsv::gather-cross-tick-cache-needs-a-data-structure`。**本票不偷偷長大。**

## §6.3 ★★★前置地雷：**`gather(advance=false)` 仍是 mutator**

`known_issues`「`DecisionContext.gather` 有寫副作用 —— 部分修」：`need_urgency`／`plan_phase` 已移出，
★**cache 群仍在**：`LaborSystem.ensure_fresh`→`labor_eval_next_tick`／`idle_employ_*`／`consolidate|absorb_target_cache`＋`consolidate_eval_next_tick`（`expand_*` 同族）——**三個是 cadence 重排**。
原記錄的結論：**呼叫次數本身會改變後續排程＝與呼叫者無關的耦合**。

⇒ ★**【若】那份記錄的耦合結論成立**，則「少呼一次 gather」本身就會改變世界（與它回傳什麼值無關）⇒ **(甲)(乙)(丙) 三個都踩同一顆**。★**這一句是【待驗前提】，不是已證事實 —— 驗它的是 §6.4。**（R② 指出原句沒有條件化而誠實限補在兩行之後 ⇒ 條件挪回同一句，2026-09-18）
⇒ ★★implementer 對第一版 fp 變動的歸因（讀到舊 `current_task`）**少了這一格**，而兩條原因在 fp 那一欄**又長得一樣**。
⇒ ★★★**誠實限**：上面那份清單是別人那次量的，而**那條記錄自己寫著**「tap 只答這一行被跑到幾次，不答寫進去的值有沒有真的不同」
⇒ **本票把它當【待驗前提】，不當已證事實。**

## §6.4 決定性量測（做完自動分岔，不需要再裁一次）

量 `advance=false` 的 9 個 production 呼叫點（`options.gd:239／256／269／284／336／359／403／546／558`），
逐寫入點量「**有沒有真的執行，而且寫進去的值與原值不同**」。★**分三格**（沒執行／執行了但寫同值／執行了而且改值）。

★★★**而「值有沒有變」只是一個軸**（R② 找出的第三格）：`labor_eval_next_tick`／`consolidate_eval_next_tick`／`idle_employ_next_tick` 是 **cadence-reset 欄位** —— 它們的寫入動作是「把下次評估時間往後推」，**與寫進去的值等不等於原值無關** ⇒ **「執行了但寫同值」那一桶不得直接判安全**。
⇒ ★**量法要選對**：用**每次呼叫前後的全世界指紋**（構造保證）取代**逐點 tap 計數**（清單保證）——★★**清單會漏**（實測：`known_issues` 名單上的 `LaborSystem.ensure_fresh` 兩個寫入點**根本沒有 tap**⇒ 照名單數 tap 會數出一個**假的 0**，而「沒有訊號」與「沒有發生」長得一模一樣）。
⇒ ★★★**而構造保證自己也要一顆陽性對照**：**手動把那三個 cadence 欄位各 +1，指紋必須變**。**指紋不變 ⇒ 那個 0 的意思是「指紋對 cadence 不敏感」，不是「沒有寫入」** —— 這一格**先於**修法。

```
＝0 ⇒ (丙-2) 可達格 1-e「逐字相同」⇒ 直接做，不需前置票、不需 WHAT 再裁
     ★而那個 0 要留成【守衛】，不是一次性讀數（它明天可能變成 1）
＞0 ⇒ 停。前置票＝把 cache／cadence 寫移出純讀路徑（known_issues 已定方向的另一半，
     ★優先「拆 pure-read vs commit 兩段」，不走「observe-mode 抑制寫」＝易漏的黑名單）
     ★★而前置修【本身會讓世界改變一次】⇒ 那是 WHAT 層的事 ⇒ systems 呈報 blueprint，票裡不得自行吞掉
```

## §6.6 ★★★第四條通道：`gather(advance=false)` 會【耗掉 global RNG】（implementer 量到 2026-09-18）

```

⇒ ★少呼一次 gather ＝ 少抽一個亂數 ＝ 之後所有隨機事件整條錯位（與回傳值無關）
⇒ ★★我與 implementer 的清單上【都沒有這一條】（只列了「寫入」與「cadence」）
```

⇒ 「threat 這條路上被丟掉」成立；「純粹只是燒掉一個亂數」**寬了一格**，而**它會改變處置**。
