# HOW spec：`_build_state_str()` 不得寫 state（資源趨勢箭頭）

owner: systems ｜ 2026-09-23 ｜ **player_reachable: yes**（它改變玩家看到的畫面何時變）
起點：票B 的 P1-b 需要一條**具名豁免**才能綠，而那條豁免的理由是這支函式**不是冪等的**。

---

## ★§1 問題（★file:line）

```
scripts/ui/text_ui_main.gd  _build_state_str() 內：
  var day: int = _bridge.get_current_tick() / WorldState.TICKS_PER_DAY
  if day != _res_baseline_day:
      _res_baseline_day = day
      _res_baseline = res.duplicate()      ← ★★一個【render 函式】在寫 state
⇒ 資源那一行的【趨勢箭頭 ↑↓】是拿現值與 _res_baseline 比出來的
⇒ ★★★所以【同一份世界】，呼叫順序不同 ⇒ 畫面不同
```

**實測（implementer 2026-09-23）**：票B 的聯集比對呼叫它 **5 次**，而「前」是**單獨一次**產生的
⇒ 箭頭不一致 ⇒ P1-b 紅。

## ★★§2 為什麼這不是測試的問題

```
★測試只是【第一個撞到它的消費者】
★★真正的性質是：**同一個世界狀態，畫面不是唯一的** —— 它取決於【這是第幾次畫】
⇒ ★★★而玩家也會遇到：任何多畫一次／少畫一次的路徑（切分頁、開關 overlay、
  一個 frame 多跑一次 _refresh）都可能讓箭頭變或不變
⇒ 那是【可預測性】的缺口，不是整潔問題
```

## §3 修法形狀（★不指定寫法，指定性質）

```
★render 函式【只讀不寫】：`_build_state_str()` 與它呼叫的每一支 `_build_*_lines`
  ⇒ 不得寫任何 `_res_baseline*`（或任何跨呼叫存活的欄位）
★★基準線的【擁有者】改成日邊界那一側：誰負責「換日」，誰更新基準
  ⇒ ★★★判準是【誰有權設它】，不是【它現在是什麼值】（同 CrossRunReset 檔頭那條分界）
★而箭頭本身不變 —— 本票不改玩家看到的【內容】，只改它【何時被決定】
```

## ★★★§4 驗收（★第二格是這張票的關鍵）

```
P1 [冪等] 連續呼叫 `_build_state_str()` 兩次 ⇒ ★輸出逐字相同
   ★★母體地板：那一輪必須真的有【資源行】（否則兩次都沒有箭頭 ⇒ 恆真）
★P1b [★★★堵住「搬到姊妹函式」] 直接呼 `node._refresh()` **兩次** ⇒ 驗 `_state_label.text` 逐字穩定
   ⇒ ★reviewer 2026-09-23 抓到的漏洞：**P1／P2 都直呼 `_build_state_str()`，完全繞過 `_refresh()`**
     ⇒ ★★若「修法」只是把 `_res_baseline` 的寫入從 `_build_state_str()` **搬進 `_refresh()`**
       （仍然是 render 路徑，只是換一個函式）⇒ **P1／P2 照樣綠，而 §2 點名的真實風險一格都沒測到**
       （切分頁／開關 overlay／一個 frame 多跑一次 `_refresh()`）
   ⇒ ★★★通則：**判準要打在【使用者真的會走的那條路】上，不是打在我方便呼叫的那個函式上。**
P2 [★★★債還了] 票B 的 **`P1B_EXCLUDE.is_empty()`**（★整張清單清空，不是比對某一條具名前綴字串），而 P1／P1b 仍然綠
   ⇒ ★改綁「清單長度」而不是「那一條的名字」：票B 還沒 merge，行號與措辭會漂，而**綁名字的判準會跟著漂成恆綠或恆紅**
   ⇒ ★這一格不是形式：**豁免清單變短，就是這張票的成果本身**
   ⇒ ★★而它同時證明修法有效（若沒修，拿掉豁免就會紅）
P3 [陽性對照] 把基準線的更新【搬回 render 裡】⇒ ★**P1 與 P1b 都必須紅**
   ⇒ ★★新加的格子一定要有自己的陽性對照，否則它只是【多一行綠】
P4 [fp] world-fp 不變（★本票不改模擬）
P5 [ui-flow] 綠（★而在 `fix/ui-flow-determinism` 併入之前，它的綠只是參考）
P6 [電池] merge 前全部 merge-gates
```

## §5 不在本票

```
✘ 改箭頭的呈現（方向、門檻、要不要顯示）—— ★那是 blueprint 的格
✘ 其他 render 函式的全面稽核 —— ★★本票只修這一處；
  ★★★若要「所有 render 都不得寫 state」變成規則，那是另一張票（而它需要先有母體：先數有幾處）
```

## ★§6 誠實限

```
①本 spec 沒有跑 Godot ⇒ 全部靜態 file:line
②★我沒有數【還有幾支 render 函式在寫 state】—— 所以本票【不宣稱】它是唯一一處
③★★「玩家也會遇到」是我的推論（畫面重畫次數會變）—— ★★★我沒有實際讓玩家路徑重現它
```
