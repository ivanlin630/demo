# 大地圖整張看得到（合成畫面不切右半）——HOW

狀態：收 R² 兩輪（…-R2-map-pane-full-width-ISSUES、…-v2-ISSUES），定案不需再審
來源：藍圖 2026-10-13-blueprint-to-systems-TICKET-map-pane-clips-right-half-full-map-never-fits（第五輪用戶回饋 #3）
順位：Q 鍵、子隊輸入之後；附身隊三件之前。

## 事實（藍圖已坐實，main cc2db2d25）
- `text_map_renderer.gd:112-135`：整張地圖每列＝縮排 `"  "×(dr+R)` ＋ 每格 4 字元 ×(2R+1)；R＝8 ⇒ 68～100 欄。
- `text_ui_view.gd:118-122 box_widths()`：地圖欄＝(COLS−3)/2＝58（COLS＝120，`text_ui_layout.gd:24`）。
- `map_pages_box` 逐列 `clip_to` ⇒ 每列右側被靜默切掉。F10 的床只驗 renderer 輸出。

## 決定（HOW，systems）
### 版面依視窗大小選（R² §1：總列數不是範圍外）
現況一屏約 34 列，已超 Windows Terminal 預設 30 列；上下排約 46～53 列。play.py 每鍵清屏重印、不知道視窗高度 ⇒ 屏高不夠時最先被捲出去的是頂列與地圖上緣＝「看不到地圖」換形狀復發。
- **客戶端回報視窗大小**：play.py 用 `shutil.get_terminal_size()` 取列數，開場與每次變動時送 harness 指令 `:size <cols> <rows>`（走 `:` 前綴的 harness 層，不是遊戲鍵；PlayerRepl 認它、記在 view 狀態）。
- **`:size` 協定（R² v2 ①，鎖步）**：play.py 是「送一行→讀一屏」鎖步。`PlayerRepl._feed` 必須在 `keycode_for` 之前辨識 `:size`，更新 view 狀態、重畫並 `_send_screen`（認不得就不回 frame ⇒ 客戶端卡到逾時）。開場第一屏用預設版面；客戶端送 `:size` 得第二屏（閃一次可接受）。
  - 客戶端偵測變動：單鍵模式阻塞在 `msvcrt.getwch` 收不到 resize（Windows 沒有 SIGWINCH）⇒ **每次送鍵前**呼叫 `get_terminal_size()`，與上次不同才先送 `:size` 並讀回一屏丟掉，再送鍵。
- **server 選版面（R² v2 ②，不翻版）**：只在收到 `:size` 時重選，內容變動不重選。門檻＝上下排的**內容無關上界**：top＋first3＋cursor＋地圖框（2R+3）＋分頁框（各頁最大列數＋2）＋動作區（折疊上限）＋事件區（`FEED_ROWS`）＋腳；各段數字的來源常數交件信寫出。rows ≥ 上界且 cols ≥ 120 且 12R+4 ≤ COLS−2 ⇒ 上下排；否則並排＋視窗。
- **沒收到 `:size`（R² v2 ④）⇒ 並排＋視窗**（不比今天高，對未知客戶端不退步）。床要上下排就明送 `:size 120 60`。
- 目標視窗高度：藍圖裁採自適應，不等數字（同時問用戶，有答案再轉）。
- **三態畫面都要說自己是哪一態**（藍圖 2026-10-13）：地圖框標題印「整張」／「只顯示一部分（游標為中心）」。
- **高度／寬度不足警語（R² v2 ③）**：由 play.py 印在**畫面最後一列之後**（視窗底部永遠看得到；放最上會第一個被捲掉）。N＝客戶端自己數收到的 frame 行數；cols < 120 時同樣警「需 120 欄、現 M 欄」。

### 地圖視窗（R² §2：不切格）
- renderer 收「可見格範圍」參數，**以格為單位輸出**：每列只輸出完整落在範圍內的格（縮排 2×(dr+R) 使相鄰列相位差 2 欄，事後切字串必切到格中間）。renderer 回 `{text, max_width}`，不 render 兩次。
- 視窗中心＝游標，**死區**：游標在視窗內側一定範圍移動時視窗不平移（避免整張左右跳）；死區寬由視窗格數推，不新增絕對常數。
- **視窗重置（R² v2 ⑥）**：游標離開視窗（瞬移：M 令後、換隊、`_cursor` 重置 text_ui_main.gd:190）⇒ 視窗跳到以游標置中，不是漸進平移。
- 框標題印「只顯示一部分」；`@` 不在視窗內 ⇒ 標題加 `@` 的方位與格數（例「你在西北 6 格」）。
- 整寬上下排時的門檻：12R＋4 ≤ COLS−2 ⇒ R ≤ 9；R ≥ 10 的世界即使上下排也走視窗。
- 地圖列超寬（不該發生）⇒ push_error **且**框標題印「（版面異常）」（終端看得到）。

### 錨與既有床（R² §3）
- 上下排後 `A_PAGES` 獨佔一行、`┬` 不成立 ⇒ 錨集合變成**版面的函式**（R² v2 ⑤）：`region_anchors(layout)`（或 STACKED_／SIDE_ 兩常數）；view 暴露本屏版面；床迭代帶 layout，「六個錨各剛好一次」兩種版面各驗一次。讀它的床同步：`terminal_selfcheck_bed:230,344`、`text_ui_layout_bed:224-232`、`ui_flow_test:3223`；「六個錨各剛好一次」斷言跟新字面。交件信列出改了哪幾行。
- 其他 `clip_to` 靜默截清單（交件信列、我判）：`map_pages_box` 分頁列、`panel_block` 每列（`clip_to(COLS)`）、頂列以外各處。

## 驗收（合成後的最終畫面）
- M1（修前紅）：床明送 `:size 120 60`，上下排，預設世界，地圖每列格數＝2R+1 減縮排應少的格（R 從 world 讀）。
- M2（修前紅）：明送 `:size 120 60`，上下排，`@` 與游標在畫面內；游標移到最右下角也在。
- M3：分頁區——改前輸出是改後輸出的**逐列前綴**（舊的 clip_to(58) 截掉的尾巴改後會出現）。
- M4：並排＋視窗——每列只有完整格（無半格）；`@` 在畫面內，或標題有 `@` 方位句；反向格：游標離 `@` 超過視窗寬 ⇒ 標題必有方位句。
- M4b：死區——游標在死區內移動，視窗不平移；出死區才平移；反向格：游標一次移動超過視窗半寬（瞬移）⇒ 視窗置中。
- M5：無任何地圖列被靜默截。
- M6：`:size 120 30` ⇒ 並排＋視窗；`:size 120 60` ⇒ 上下排且總列數 ≤ 60；`:size 100 60` ⇒ 並排（欄不足）；不送 `:size` ⇒ 並排。三態標題字面各斷言。
- M6b：同一個 `:size` 下連送 50 個不同鍵 ⇒ 版面種類不變。
- M6c：`:size` 一定回一屏（鎖步不卡）。
  - ★並排現況就約 34 列（> 30）：選版面解決不了「連並排都放不下」⇒ 總列數 > 回報列數時，畫面最上一列印「視窗高度不足（需 N 列，現 M 列）」（play.py 側印，不佔遊戲版面），交件信量出並排與上下排的實際列數。壓縮並排版面的列數不在本票。
- M7：R＝10 世界 ⇒ 走視窗。
- 負對照：`box_widths` 改回左右各半且不出視窗 ⇒ M1 紅；renderer 改回事後切字串 ⇒ M4 紅。
- terminal E2E、ui-flow、text_ui_layout 床照綠（錨字面同步後）。world-fp 不變。
