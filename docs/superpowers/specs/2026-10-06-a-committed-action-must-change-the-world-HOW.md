## §0 病（藍圖逐字）

```
A1 建設：Team0 三把鎖全開、建設 util 0.43→0.70 一路是 winner、連續 29 天 committed，材料零消耗、建物零變化
   全世界普查：宣稱 11 隊，材料有進出 4、建物有變化 4，兩組不同批，**兩者皆無 7 隊**
A2 貿易：Team7 d20–29 at_market、「貿易」committed 40+ 次，coin 41→38
A3 領取：Team7 committed 5 次，coin 不動
⇒ 同一個病：winner 被 commit 了，世界沒被它改變，而 util 因需求未滿足繼續升 ⇒ 更黏在那個選項上
⇒ 合法出口只有兩條：(a) 前提不足 ⇒ 不該是候選（或帶 ineligible）(b) 能失敗並讓 failure_memory 記住
⇒ ★禁第三條：committed 永遠、世界不動、util 漲
★另：`strategic_intent.why` 寫「建材枯」而 material＝80 ⇒ 理由字串沒讀真值（＝對讀卷面的人說謊）
★它跟玩家側的終端 E2E「紅二：說到沒做到」是**同一條規則的 NPC 側** ⇒ 兩張的判準要同義
```

## §1 第一階段：普查床（三格常駐，方向只准變少）

```
C1 「宣稱建設／紮根的隊裡，窗內材料零進出**且**建物零變化」的隊數
C2 「at_market 且 committed 貿易 ≥ 1 天而 coin 零變動」的隊·日
C3 「committed 領取而 coin 零變動」的次數
```

### ★★★窗口是本階段最重要的一條（不是三格本身）

```
藍圖給的紅基線（7／11 等）是 **seed 1337、30 天** 量出來的
⇒ ★而 30 天的模擬放進電池太貴（先量一次耗時再說）⇒ 床很可能要用較短的窗
⇒ ★★**一個數字沒有窗口長度就不是一個數字**：30 天的 7／11 **不能**當 10 天床的基線
⇒ 規矩：床的窗口 N 天由**量出來的耗時**決定（量測員量）；**基線在那個窗上重量**，
  並把「窗 N 天、seed、樹」三樣印在同一行（主詞跟著數字走）
⇒ ★而窗太短會讓 C1 恆為 0（7 天內本來就蓋不完）⇒ 必須先量「這個窗上 C1 的分母（宣稱建設的隊數）≥ 1」
  —— 否則那一格在一個沒人宣稱的世界上恆綠（母體地板）
```

### 棘輪方向（★判準庫：方向相反的常數不要放在同一個衝突熱點）

```
三格都是「只准變少」⇒ 常數放在同一區、該區第一行寫明方向
⇒ rebase 衝突時取**小**（取大＝讓守衛閉嘴而卷面像「衝突解完了」）
⇒ ★而本專案其他棘輪多半是「只准變大」（地板）⇒ 這一區要跟它們**分開放**
```
