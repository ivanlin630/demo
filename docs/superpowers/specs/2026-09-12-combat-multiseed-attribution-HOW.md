# HOW spec：戰鬥面多 seed —— **分開「真趨勢」與「蝴蝶」**

- **WHAT 授權**：blueprint 2026-09-11「兩筆帳拆成獨立調查票；帳①先多 seed 定真趨勢，真趨勢再問好壞」
- **★而這張票【到今天為止只存在於信裡】** —— systems 2026-09-12 補寫（★**我先前說「折進帳①那張票」，
  而那張票【並不存在】** ⇒ 這正是我們記過的「**『已請』是宣告不是事實**」）。

---

## ① 要答的問題（★只有一個）

```
**開打數／滅團數／勒索數的變化，是【真趨勢】還是【蝴蝶】？**
⇒ ★因為它們全是**湧現聚合** ⇒ **單 seed 的前後對照不可歸因**（blueprint 通則）
⇒ ★★而我們手上已經有三個很大的單 seed 數字：
  開打 **391 → 81（−79%）**｜勒索 **2298 → 182（−92.1%）**｜滅團 **0／0**
  ⇒ **它們現在一個都不能引用。**
```

## ② ★★★前置：**先讓兩棵樹可比**（★不做這一步，多 seed 只是多跑幾次不可比的東西）

```
★問題：**before 樹上沒有新 tap**（＝「第四種 0」：量測器還沒出生）
  ⇒ 血證：兩棵樹目前**只有 `raid.extort` 這一格可比**。
⇒ ★★做法：**把【純觀測】的 tap commit cherry-pick 到 gen2 的樹上**
  ⇒ ★**只搬 tap，不搬行為** —— 搬完要驗 **fp 與該樹原本逐字相同**
    （★★**那就是「我只加了溫度計、沒有改天氣」的證明**）
⇒ ★★★**若某一格的 tap 搬不過去**（相依於新機制）⇒ **那一格退出本票**，
  **並在交件裡具名列出** —— 不要讓它以 0 的形式留在表上。
```

## ③ 跑法（★便宜優先：先 3，不一致才 5）

```
**兩臂**：**世代 2**（`a5e78e73d` 之前的行為）vs **世代 4**（`c6c9704ac`）
**seed**：先 **3 個**（1337 ＋ 另外兩個），★**每臂同一組 seed**
**窗**：與既有卷一致（30 天）｜★**一次只跑一趟**（機器與用戶的遊戲共用）
⇒ ★★**判準**：
  ・**3 個 seed 方向一致** ⇒ **真趨勢**（★這不是統計檢定，而本票只需要分辨兩種可能）
  ・**方向不一致** ⇒ **蝴蝶** ⇒ ★**那三個大數字全部作廢**，而**那本身就是交件**
  ・**一致但幅度差很大**（例如 −79%／−12%／−90%）⇒ ★★**標「趨勢成立、幅度不可引用」**
⇒ ★★★**若 3 個一致 ⇒ 不用跑第 4、5 個** —— **省下的那兩趟就是這個設計的價值**。
```

## ④ 驗收

```
①**每一格都標它屬於哪一臂、哪一個 seed**（★禁把兩臂的數字混進同一張表）
②**fp**：每一趟都附；★**同臂同 seed 兩跑必須逐字相同**（確定性）
③**可比欄位清單**：**哪些格在兩臂都有 tap**、哪些**退出本票** ⇒ 具名
④★**方向表**：三個 seed × 三個指標（開打／滅團／勒索）的**符號**（升／降／持平）
⇒ ★★**結論只能是三種**：**真趨勢｜蝴蝶｜趨勢成立而幅度不可引用**
⑤★★★**不准出現「攻擊門讓 X 下降 Y%」這種句子** —— 本票**不做單一改動的歸因**
  （兩臂之間有**兩次 merge**）⇒ 它只答「**變化是不是真的**」。
```
