# 游標懸停印整格真值（debug）——HOW spec（systems 2026-09-25）

用戶裁（逐字）：**「先顯示真值 我好 debug」**。blueprint 開票、意圖帳 #42 已補句。
現況 `text_ui_main.gd:939-962` **已經是真值**，只是①要按 Enter ②欄位少 ③沒有標示。

## ★★★§1 這張票最重要的一條：它是【明裁的 god-view 例外】，而例外要有牆

```
★感知鐵律（invariants.md）：決策／reaction 只能吃 belief，不能吃 god-view 真值。
★★而本票是【用戶明裁的例外】——它的正當性【只存在於「這是畫給人看的」這件事上】。
⇒ ★★★所以 HOW 的核心不是「怎麼印」，是【怎麼讓它結構上流不進決策】：
  ①真值只在 **render 路徑**上被讀，**不得寫進 `state` 的任何欄位**（含不得快取進 `player_state`）
  ②不得回傳給 `query_player`／不得進 `command_results`／不得進 `_events`
  ⇒ **沒有儲存，就沒有消費者** —— 這比「規定大家不要讀它」強，因為它不依賴任何人記得。
```

## §2 要做什麼

```
①游標移動時【即時】印（不用 Enter）
②欄位擴到整格：地形／收成係數／全部 resources／據點型別+等級+主人／
  格上所有隊（含人口、勢力）／（若有）控制方／tile id
③★區塊標題固定印：**「真值·debug（非附身者所知）」**（★機械可查，見 P2）
```

## ★★§3 而標題那一行不是裝飾，它防的是一個【認識論】的坑

```
★用戶拿真值 debug 時，會看到【附身者不知道的事】
⇒ ★★於是「AI 怎麼這麼笨」與「AI 根本不知道」在畫面上長得一樣
⇒ ★★★那一行字的作用，是讓每一次觀察都自帶【它的來源標籤】——
  否則用它得出的每一個關於「遊戲合不合理」的結論，都建在一個玩家拿不到的資訊上。
★同一件事的另一半：blueprint 已說【玩家版（讀 `team_tile_known`）另存小票不作廢】。
```
