**溯源**：merged-base 終量 `peaceful 製造 −7.5%` ⇒ systems 判【病】、blueprint 准並命名家族＝**盲派**（決策不讀自己資源狀態，用戶 2026-08-11 定）。


## ★scope
### ①要改的四處對稱化中的兩處（投入端）
```
★①投入檢查：改讀【與產出檢查同一組池】= team.resources + tile.public_storage
★★②投入扣款：改成從同一組池扣,且★★★用 remove/withdraw 不用 add(負數)
```
### ②★★不在 scope
- ★**不動產出端**（它已經是對的，★★動它會把「修盲派」與「改產出行為」混在同一次驗收）。
- ★**不新增所有權概念** —— **複用既有 `_team_works_tile`**（owner 本人或同 faction）。★★**它已經是這支流程的資格閘。**
- ★**不改配方、不改產量、不改 cadence。**

## ★★★HOW 的四個必須釘死（★缺一個都會造出比原病更糟的東西）

### ①★池優先序【必須明寫】
```
★私產先、公庫後
理由:公庫是共有/稅制標的 ⇒ ★★先花自己的,是【誰的成本】的問題,不是效率問題
★★★而它必須是【寫死的順序】不是「哪個多用哪個」—— 後者會讓同一情境有兩種結果
```

### ②★★★守恆：**以【實扣】為準，且要原子**
```
★ResourceBank.remove / TileBank.withdraw ★都回傳【實際扣到多少】⇒ 必須接回傳值
★★兩者加總必須 == 應扣;不等 ⇒ ★★★**loud-fail**（R² 給的形狀，取代我原本想的回滾）
★而現行 code 是 ResourceBank.add(team, res, -(cost)) —— ★★add 負數不保證 clamp
   ⇒ 一旦檢查與扣款不同池,它會把私產扣成負數 =【憑空造材料】
```
> ★★★**這條是本票最大的風險**：**「檢查讀兩池、扣款只扣私產」比原本的病【更糟】** ——
> **原病只是少做事；那個是守恆破洞。**

#### ★★★★而「不等」時的處置 ＝ **loud-fail，不是回滾**（R² CLEAN 2026-08-27，★取代我原本的設計）
★**我原本寫「整筆不做」並自陳「已扣掉的那一半怎麼還」沒寫** —— ★★**R² 指出：在【單執行緒同 tick】下原子性本來就成立**
（檢查與扣款之間沒有任何東西能改變那兩個池）⇒ ★★★**「不等」不是需要被處理的情況，它是【不可能發生】的情況。**
```
⇒ 一旦發生 ⇒ ★它是缺陷不是例外 ⇒ ★★必須【吵】：push_error + Probe.bump("manufacture.debit_mismatch") + 不繼續
★★★禁靜默修補（回滾/夾住/湊數）—— 那會把一個【不變量被違反】的訊號變成一次正常運作
```
★**同既有紀律**：「**『假設不靜默』的完整形狀 ＝ 偵測 ＋ 主動告知**」——**只偵測不告知＝沒做。**

### ③★單寫者：**禁直接寫 `tile.public_storage`**
**用 `TileBank.withdraw`。**★**理由不是潔癖**：`TileBank` 有 cap／溢出落地／audit 掛在上面（見 `_add_output` 的 overflow 處理）。

### ④★所有權閘複用既有的
**只有 `_team_works_tile(state, team, tile)` 為真時，才可讀／扣該 tile 的公庫。**
★**同「共用函式裡的『我』是誰」那條教訓**：**公庫屬於 tile 的 owner，不是站在上面的人。**
