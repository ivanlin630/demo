# §0 這一票的前提

`belief_system.gd:10`：
```
const BELIEF_STALE_TICKS: int = WorldState.TICKS_PER_DAY * 3   # TEST VALUE
```
所有觀察者、對所有目標、用同一條 3 天線。血證：絕境 22 筆裡 16 筆沒上場，最大單一原因是位置情報過期（`no_belief_pos` 6／10）。

# §1 ★★★先報規模 —— 而這個數字當場打掉了我的第一個判準

```
TICKS_PER_DAY = 1440｜MOVE_TICKS_PER_HEX = 240 ⇒ baseline_tiles_per_day() = 6 格/日
MAX_MOVE_TICKS = 720                          ⇒ 最慢的一端          = 2 格/日
⇒ 現行 3 天線 ＝ 容許【18 格】的可能漂移（基準旅行者）
```
★**我原本要寫的判準是「它可能已經移出那一格 ⇒ 過期」**（門檻＝資料結構自己的解析度，聽起來不是旋鈕）。
⇒ **算出來是 1／6 日 ＝ 4 小時 ＝ 240 tick** ⇒ 比現行線**緊 18 倍** ⇒ 幾乎所有 belief 立刻過期。
⇒ ★★**這個判準會把世界弄壞，而它在紙上讀起來很漂亮。** 規模必報救了它，不是我小心。

# §2 ★★★真正的形狀：「過期」不該長在供給端

現行是**供給端硬切**：`belief_pos()` 超過 3 天就回 `(-1,-1)`（`belief_system.gd:135／140／451`）。
⇒ **所有讀者被迫共用同一個容忍度**，而它們要做的事情不一樣：

```
攻擊／追擊   位置要準（打空＝浪費一次行軍）      ⇒ 容忍小
偵查         就是要去看「那裡現在怎樣」          ⇒ ★容忍應該【很大】，甚至無限
外交／記憶   只要知道「大概在哪個方向」          ⇒ 容忍中等
```
★**而前置票已經證過這個副作用**：偵查因為 `belief_pos()` 回 `-1` 而 `continue` ——
**看不到「需要被偵查的目標」**，那正是「過期位置進偵查池」在修的東西。
⇒ ★★**修法方向＝把「多舊」交給讀者，供給端只回【事實 ＋ 年齡 ＋ 漂移估計】**，
**不要在供給端替讀者做判斷**（同不變量 #6 的形狀：一次回傳全部，讀者自己秤）。

★★★**誠實限（我自己先講）**：供給端硬切**是一個保守的預設** —— 拆掉它，預設就從【安全】變成【不安全】：
**有讀者忘了定容忍度，就會拿 18 天前的位置去攻擊，而它不會紅**。
⇒ 所以 Slice 2 的規矩是：**遷一個讀者＝在那個呼叫點明寫它的容忍度**，★**沒有預設值可用**（給了預設值，忘記定的人就會沉默地吃到它）。
★而 `belief_pos()` 現在把**「沒看過」與「過期」都回成 `(-1,-1)`** —— 新介面的 `blind` 欄位把這兩件事分開，**那是本票順手修掉的一個真混淆**（兩者該做的事不同：沒看過 ⇒ 去偵查；過期 ⇒ 可能還堪用）。

# §3 切片

## Slice 1（本票）：加介面，**不改任何既有讀者**
```
新增 BeliefSystem.position_estimate(state, observer_team_id, target_id) -> Dictionary
  { pos, age_ticks, drift_tiles, blind }
    drift_tiles ＝ age_ticks × baseline_tiles_per_day() ÷ TICKS_PER_DAY   ← ★分母是物理，不是旋鈕
    ★錨定過的目標（ACT_SETTLED／ACT_BUILDING）用【最慢那一端】估（既有形狀，前票已立）
★既有 `belief_pos()` 一行不動 ⇒ 格 1-e：fp 與逐 tick 行為軌跡【逐字相同】
```
★**理由**：這一票只造尺，不量東西。**造尺的票不准同時改世界** —— 否則「尺對不對」與「世界變好沒」會混在同一個 fp 裡。

## Slice 2（下一票，不在本票）：讀者逐一遷移，各自定容忍度
★**每遷一個讀者要報母體變化**（該讀者拿到位置的次數：遷移前 vs 後），**一次一個**。

# §4 ★★★本票的第一個動作：把【借用】拆掉（否則 Slice 2 會靜默改到別人）

`BELIEF_STALE_TICKS` 現在同時是**兩種語意**：

```
(A) 位置 belief 的過期線          belief_system.gd:135／140／451
(B) ★失敗記憶（乞食被拒）的 TTL   interaction_system.gd:1564／player_command_system.gd:1008／sim_runner.gd:385
    （`FailureMemory.record(..., ttl_ticks, ...)` 的實參）
```
★而 `interaction_system.gd:1558` 那行註解自己寫著：**「TTL＝BELIEF_STALE_TICKS（＝3 天）：不是挑一個數字，是【借這件事自己的週期】」**
⇒ ★★**借的對象一旦變成 per-observer 的函式，就沒有「一個數字」可借了** ——
而如果不先拆，Slice 2 動 (A) 會**靜默改掉 (B)**：乞食被拒的記憶會跟著位置線一起變長變短，**而沒有人會知道**。
⇒ **裁：(B) 立自己的常數** `AID_REFUSED_TTL_TICKS: int = WorldState.TICKS_PER_DAY * 3`（**值不變 ⇒ 行為不變**），四個實參改指它。

```
  §1a 尾巴逐字「哪些欄位能進 belief 由 WHAT 定」⇒ 那一格是 blueprint 的
  （defer：target-speed-belief-field-or-flat-forever）
```
★★**而 defer 原文寫「有效期由【移動能力 × 距離】推」—— 我在這裡更正【距離】那一項**：
**「我離它多遠」不影響「它還在不在那裡」**（漂移只跟 時間×速度 有關）。距離影響的是**我要不要為此出動**，
那是**決策層**的事。⇒ 本票只物理化 **時間×速度**，距離不進 belief 層。
