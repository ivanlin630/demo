## ★★★★HOW 的裁定：**預設全喚醒，例外要寫理由**（★這是「不搞白名單」的可執行形狀）
★**WHAT 原文**：「**任何突發即喚醒【相關決策層】，★不搞白名單挑食**」——
★★**「相關」看起來像要一張映射表，而「不搞白名單」禁止我們挑** ⇒ **兩句話會打架。**
⇒ ★★★**解法是【把預設反過來】**：
```
★預設:30 種事件【全部】喚醒七支（★★＋既有的統一決策層）
★★例外:某一支不被某一類事件喚醒 ⇒ 必須在 code 就地寫一行理由
   ⇒ ★★★「白名單」是【挑要的】,而這是【挑不要的並負舉證責任】——
     ★兩者的差別在【沉默的預設落在哪一邊】
```
★**而它可機械檢查**：**例外清單非空時，每一條都要有理由字串**（同 `TIER_UNJUSTIFIED` 的形狀）。
