# §3 ★★★第一步：**不選架構，先做相位拆解**

```
★理由：1.2 秒 ÷ ~100 隊 ＝ **每隊 12 毫秒** —— 那是一個【大得可疑】的數字
   ⇒ ★★**先問它花在哪**，再決定要不要動結構。**現成的量具就有**：
     `phase_timing` / `_pht("near.*")` / `[FaiPhase]` spike dump（`sim_runner.gd:140`）
⇒ **要的輸出**：pass tick 的 dt **按 phase 拆解**，兩顆種子，印母體與樣本數
⇒ ★**若某一個 phase 佔掉大半** ⇒ 修那一個，**架構不用動**（最便宜的出口）
⇒ ★★若**攤平在很多 phase 上** ⇒ 才是結構問題 ⇒ 進 §4
⇒ ★★★**三格，不是兩格**：還有一格是**幾個中等的頭** ⇒ 那要修 2~3 處，仍不必動架構
```

# §4 架構選項（★**等 §3 回來才選**，此處只記形狀與代價）

```
(甲)**分片**：每隊的 pass 落在 `tick % 60 == mix(team_id) % 60`
   ⇒ 每隊頻率不變、工作攤平到 60 個 tick
   ⇒ ★★**但違反不變量 #8 的警告**：隊的**生與滅 100% 發生在這個 pass 裡**
     ⇒ 同一小時內各隊看到的世界狀態不再一致 ⇒ **語意改變，且我們今天剛看過這種改變的代價**
(乙)**幀分片＋邊界快照**：語意不變（仍是同一個邏輯 tick），只把**牆鐘工作**攤到多幀
   ⇒ ★★★**它可以做到 fp 完全相同** ⇒ **驗收硬閘 ＝ fp 必須【不變】**
     （★與窗 #3 相反：那次 fp 變是預期；**純 perf 修法若改了 fp，它就失敗了**）
   ⇒ ★代價：`advance_tick` 有 **263 個呼叫點** ⇒ 只有「第二個 driver」路線可行
(丙)**降低 pass 內單隊成本** ⇒ ★由 §3 決定它存不存在
★**我的傾向**：**丙 → 乙 → 甲**。甲最便宜而**它改世界**，乙最貴而**它可以不改世界**。
```
