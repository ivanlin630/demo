# ★★★這張票的一句話（藍圖裁，逐字進 spec）

> **「我不知道它有多肥」的正確反應是【去看】，不是【假設它一文不值】。**

# ① 病（已由 R² CONFIRMED 窮盡）

`faction_ai_system.gd:379-384 _belief_richness()` —— **三個 return、兩種單位**：

```gdscript
:380  if bel.has("coin_est") or ... : return (coin_est + food_est + material_est) / 100.0   # ★不同單位直接相加，除一個手填的 100
:382  if bel.has("resource_scale") : return float(bel.get("resource_scale", 0))              # ★★直接回 0..3 的【等級編號】
:384  return 0.0                                                                             # 中性 fallback（皆無資料）
```
⇒ ★**72% 撞頂的真因是「等級編號剛好等於除數」**（`clampf(3/3,0,1) = 1.000`；實測 tier1 p10/p50/max ＝ 2.0/3.0/3.0 逐字吻合）。

# ② 第一步：**單位對齊**（只動有分項情報那條路）

`:380` ⇒ **`Σ (各項估值 × TradeValuation.BASE_PRICE[該項])`**，**拿掉那個手填的 100**。
★**單位的來源不是發明的**：`derived_payoff` 用的就是 `BASE_PRICE` ⇒ **兩側同幣別**。

# ③ ★★★第二步：**型別可行性 —— 估不出價值的目標【不進攻擊排序】**

`:382` 那條路（只有等級編號）⇒ **不產生 richness 值**，而該目標 **不出現在攻擊 candidate 集合裡**。

## ★這一格的實作【必須是結構上的】，不是少加一項

```
R² 的血證：`score = (richness*greed + weakness*cruelty + border*ambition) / eta_days * logistics`
   ⇒ **A ＝ X ＋ Y（X 缺席）** 與 **A ＝ 0 ＋ Y（X＝0）** ⇒ **印出逐位元相同的分數**
⇒ ★★**所以「不參與」若只是把那一項拿掉，它與「算成 0」在行為上不可分辨**
⇒ ★★★**必須讓那個目標【不被產生成 candidate】** —— 而不是「產生了但少一項」。
```

**驗收格（必須能分辨這兩者）**：
- 同 `weakness`／同 `border` 的兩個目標，一個有分項情報、一個只有等級編號
  ⇒ ★**後者【不得出現在候選清單裡】**（不是「出現但排最後」）。
- ★★**反向對照**：把後者的情報補齊 ⇒ **它必須出現**。
  ⇒ **兩格成對，否則「永遠不出現」與「機制沒接上」不可分辨。**

## ★而「只修第一步、第二步維持現狀」是【不安全】的（★算術，非量測）

```
今天    有情報：600 / 100 ＝ **6**      只有等級：**0..3**   ⇒ 量級剛好同級（★巧合，不是設計）
修完①  有情報：600 × 2  ＝ **1200**     只有等級：**0..3**   ⇒ ★★量級差【幾百倍】
⇒ ★★★低情報目標永遠排最後 ⇒ **那不是保守，是靜默判死** ⇒ **①②必須同一刀。**
```

# ④ ★★★第三步：**偵查進秤，不是自動派**（藍圖硬格）

```
「不進攻擊排序」＝ **型別可行性**（估不出價值的東西不能被排序）—— 合法
「所以去偵查」   ＝ **一個 option**，★**要跟其他選項在同一把秤上比**
⇒ ★★★**禁走廊**：不得在「不進攻擊排序」之後直接 `try_set(TASK_SCOUT)`／直接派遣。
```

## 偵查 option 的價值：**解鎖資訊的期望價值 × 折現**

- **折現**走既有 `DiscountedFlow`；★**慎重人格 → δ**（`discounted_flow.gd:27-30 delta_of` 讀「慎重」，
  而**不是**貪婪 —— 用戶 2026-08-21 已裁「貪婪≠短視」）。
- ★★**單位必須是 coin 當量** —— 因為它要**進外層 argmax** 與攻擊／貿易等 option 同場比較。
  （★對照：票乙那條「先弄到錢」的 PV **只排內部序、不進外層**，所以那裡不受此限。**兩者不同，別抄錯。**）

## ★★★留白格（**要 R² 打**）：「解鎖資訊的期望價值」怎麼**導出**而不手抄

**禁手抄物理**（本專案立法）⇒ 不得填一個常數。候選形狀（**我列，並說明各自的毛病**）：

```
(i)  **機會成本形式**：偵查的價值 ＝「可能找到一個【比我現在最好的目標更好】的目標」
     ⇒ 用**本隊目前已知目標中最高的那個 richness** 當基準（★純自身狀態，零 god-view）
     ⇒ ★毛病：若本隊什麼都不知道，基準是 0 ⇒ **偵查價值也是 0** ⇒ **最需要偵查的隊最不想偵查**
(ii) **自估 base rate**（R² 找到的非 god-view 變體）：用本隊**已升到高情報**的其他目標的
     richness 取中位數當「這個世界一般長什麼樣」
     ⇒ ★★毛病：**是新機制不是接現成線**（`belief_system.gd` 沒有跨目標聚合），工程量大一截
     ⇒ ★★★且它與 (i) 有同一個病的變體：**一個都還沒升級過的隊，母體是空的**
(iii)**兩者取大**（有已知就用已知、沒有就用 base rate）
     ⇒ ★毛病：**它把「我不知道」拆成兩種來源而沒有回答【什麼都不知道時怎麼辦】**
```
★**要 R² 打的問題**：**「一個什麼都不知道的隊，它的偵查價值該是多少？」** ——
★★**三個候選全部在這一格塌成 0**，而**那正是這張票要解決的情境的極端版**。
⇒ ★★★**若這一格沒有非手抄的答案，那就要老實寫進 spec：這個機制在【全盲】狀態下不會啟動** ——
**而不是填一個讓它啟動的數字。**

### ★★★而它必須帶三道守衛，否則就是下一個桁號


# ⑤ 驗收（★三格，成對）

1. **不進排序**：低情報目標**不出現在候選清單**；補齊情報後**出現**。（★成對）
2. **偵查真的在秤上**（★★母體照 R² 改：**每一次 argmax 呼叫、且候選集裡確實含偵查 option 的那些次**
   —— ★**用【候選集裡有沒有】這個結構事實篩，比用隊的情報標籤篩精準**：
   **標籤是分類，候選集才是決策當下真的比較過的東西**；
   ★★★否則【生成失敗】會混進【生成後輸掉】，把勝率稀釋或扭曲）：
   ★**要有它【輸掉】的樣本** ——
   ★★**若偵查 100% 贏，那就是走廊換了個皮**，而那違反藍圖那一格。
3. **單位**：偵查 option 的 util 與攻擊 option 在**同一個量級**（coin 當量）
   ⇒ ★印出兩者的分布，**不是只印偵查有沒有 fire**。
