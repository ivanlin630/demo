## ★★盤點的可執行定義（★而 propagate 那顆給了我們判準）
> ★★★**「看起來掛在每 tick」不算數** —— **`propagate` 看起來掛在每 tick 的 arrival 事件，
> 而實測呼叫次數兩根兩床完全相同（1.08/小時），因為它早就是 cadence 驅動。**
⇒ ★**所以 S3a ＝【靜態列舉】＋【實測驗證】兩步，缺一不可。**

### ①靜態列舉（★終止條件【重用既有機械判準】，不是人眼判「像不像 gate」——R² 訂正）
> ★**退化的根源是「判斷有沒有 gate」目前只能靠人眼** ⇒ **那會讓「我追了幾層」變成自由心證。**
★★**而 S1 那票已經建出一套【機械可重跑】的 cadence-gate 形狀規則表**（`bare_tick_scanner.gd` ＋ `bare_tick_triage.gd`）
⇒ ★★★**直接重用它當終止條件。**

```
traversal 規則（★可重跑、非人眼）：
  從 sim_runner 的 tick 迴圈頂層直接呼叫的每個函式出發，靜態遞迴追呼叫鏈；
  ★撞到【bare-tick 規則表裡任一個 cadence-gate 形狀】⇒ 分支終止，記 `gated` ＋ 那一行 file:line
  ★★追到【沒有再往下呼叫的葉節點】都沒撞到 ⇒ 分支終止，記 `true_candidate`
  ★★★撞到【變數持有的函式參照／`.new()` 動態解析】⇒ 分支終止，記 `untraceable`
```
⇒ ★**「我追了幾層」不再是自由心證，是【撞到規則表裡哪一條、在哪一行】** —— **別人照同一份規則表能重跑。**

#### ⚠️★★★★第三桶 `untraceable` 是必要的（R² 揭，我原本只有二分）
★**GDScript 的鴨子定型讓「透過變數持有的函式參照／動態解析類別」對靜態掃描【不可解析】。**
★★**那種分支的真實深度是【未知】，不是【確認沒 gate】。**
⇒ ★★★**硬把它算進 `true_candidate` ＝ 虛報一個根本沒驗過的「真每 tick 站」。**
★**與 bare-tick-gate 誠實承認「文字比對看不到別名」是同一種揭露** —— **它要出現在輸出裡，不是只在信裡。**

★**母體要可宣告**：★★**`gated ＋ true_candidate ＋ untraceable ＝ 從入口能到達的分支總數`**（★三桶對帳）。

### ②★★★實測驗證（★這一步是 propagate 教的，不得省）
```
★對每一個【候選真每 tick 站】，量它每遊戲小時的【實際執行次數】
★★判準：次數 ≈ TICKS_PER_HOUR ⇒ ★★★真的是每 tick 站
        次數 ≪ TICKS_PER_HOUR ⇒ ★它有 gate（靜態沒追到）⇒ 回頭補靜態列舉的漏
★★★★而【後者本身是發現】：它說明靜態列舉在哪裡看漏了
```

## ★驗收
1. ★**靜態列舉有【可宣告的母體】**（★「從 tick 入口能到達的進入點總數」）—— ★★**不是「我找到 N 個」**
2. ★★**每一個候選都有【實測次數】** —— ★★★**靜態說是、實測否掉的，逐個記下來**（★那是列舉方法的缺陷紀錄）
3. ★**零 production 改動** ⇒ ★★**`fp` 兩床逐位元不變**（★**若變了就是動到了不該動的，直接回退**）
4. ★**陽性對照**：**臨時把一個【已知有 cadence gate】的站的 gate 拿掉 ⇒ 它必須出現在候選裡；還原後消失**
   ★★**沒有這一格，我們不知道列舉是【抓到了】還是【剛好沒有】**
   ### ⚠️★★★程序保險（R² 加）：**這個實驗【絕不能落進 commit】**
   ```
   ★在獨立 worktree 或【明確不 git add】的暫存修改下做
   ★★操作完跑 `git status` 確認乾淨才繼續 —— ★★★把「還原」從【口頭承諾】變成【可檢查的步驟】
   ```
   ★**血證（今天，我自己）**：**我的 `git add -A` 把別 session 的暫存檔掃進了 repo 根目錄。**
   ★★**而「零 production 改動」講的是【落地的那份 diff】，不是開發過程不能動一行** ——
   **暫時改、驗證、還原、`fp` 驗回原值 ＝ 同 implementer「做完就撤掉」那條紀律，不衝突。**
5. 三閘 PASS（憲法／裸 tick／headless baseline 7）
