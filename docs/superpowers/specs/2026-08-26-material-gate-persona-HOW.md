# D 件：`cost × 1.5` 建造閘 → 人格化（HOW）

`from: systems`｜`tier: behavior`｜`R①: CLEAN`（`premise_contradiction: false`，但把「一個常數」訂正成「三閘＋兩下游引用」）
`arc: 建造漏斗解鎖／材料經濟`（blueprint 定形 2026-08-26；WHAT 出處＝用戶 2026-07-24 意圖帳 material row）

## 病
建造漏斗四段（`main`）收斂到一句：
> **提案提得出來 → argmax 真的贏了 39 次 → 卡在 `avail < cost × 1.5`，39/39；其餘六閘一次都沒響。**

★**而那 `0.5 × cost` 不是價格，是【緩衝】** —— R① 逐一查過三個「它可能在替什麼物理站崗」的候選（施工期間持續消耗／子隊途中損耗／檢查與扣款的時間差），
★★**三個都找不到**（`_deduct_cost` 一次性扣、`_fund_subteam_cost` 只轉 `cost` 不轉 `cost×1.5`、檢查與扣款同一次呼叫同一 tick）
⇒ ★★★**它是一個【行為選擇】（開工前留多厚的一手）被寫成了死常數** —— 合格的照妖鏡標的。

## ★★★首先寫死一件事：**這張票【不會】讓漏斗解鎖，而且它的驗收不准這樣寫**

**實測（`dispatch-builder-denominator-90d`，★sample cap=30 之下的 30 筆，母體 41 —— 見「誠實限」）**：
```
need_1.5x = 75  ⇒ cost = 50
avail     = 0（21 筆）／20（9 筆）   ★從未超過 20
```
⇒ ★**把緩衝整個拿掉（1.0×，need 50），`avail` 最高 20 仍然過不了。**
⇒ ★★**D 是必要不充分。`build_ok 首次 > 0` 對【D 單獨】是一條不可達驗收** ——
**能把 `avail` 從 ≤20 推到 ≥50 的是 A（初始庫存）與 B（伐木場），不是 D。**
> ★★★**我在寫這張 spec 之前先查了這件事** —— **否則 D 交件時會看起來像失敗，而失敗的原因與它做了什麼無關。**

### 形狀
**`avail < cost × margin(persona)`**，其中 `margin` 由既有人格值連續調變（**慎重 → 厚；大膽 → 薄**）。
★★★**anti-crank 鐵律（照妖鏡 program 既有形狀，F1 血證）**：
> ★**中性人格必須得到【剛好 1.5】** —— **零漂。**
> **中性值一旦不是 1.5，這張票就從「人格化」變成「偷偷調數值」，而後者要走 WHAT。**

★**禁止**：新增常數、手抄任何數值、把 `margin` 的上下界寫成新的魔數
（★**上下界要從既有人格值域導出**，或**明確標成本票新增的設計常數並說明理由** —— 二選一，不得含糊）。

## 驗收
1. ★**中性零漂**：中性人格 ⇒ `margin == 1.5`（**逐位元**），⇒ ★**中性世界 `fp` 逐位元不變**。
2. ★★**分化真的發生**：慎重與大膽兩端的 `margin` **嚴格不同且連續**（非一刀切）；
   ★**且必須有一筆實跑樣本顯示【同一 `cost` 下兩種人格的閘結果不同】** —— **否則它只是算得出來、從沒 fire。**
3. ★**三閘收斂**：`grep -c 'cost\[k\]) \* 1\.5' scripts/simulation/` **＝ 0**（★**錨在定義側、掃全樹、排除法**）。
4. **零新常數**：`estimator-lineage-scan.sh` 綠。
5. ★★★**不驗「解鎖」** —— **`build_ok > 0` 不是本票的驗收**（見上）。**它是 A＋B 交付後、整批一起重量漏斗時的驗收。**

## ★必須順手修的一句註解（**不是順手，是它在說謊**）
`faction_ai_system.gd:2236`：
```gdscript
const INVEST_SAFETY: float = 1.5   # 送料安全餘量（鏡射 _dispatch_builder cost×1.5，確保村端 _can_afford 過）
```
★**R① 查了 `_can_afford` 本體（`outpost_system.gd:812`）：它只吃 `1.0×`，從來沒有 1.5。**
⇒ ★★**這句註解宣稱了一個【不存在的耦合】** —— 同 `117` 那條：**一個錯的因果留在註解裡，下一個人會把它當規格。**
⇒ **改成陳述現況**（送料用 1.5、村端檢查用 1.0、兩者不同步是現況），**不要複述那個錯的耦合。**
