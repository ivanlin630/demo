## ⓪ ★★★裁定的理由【與我原本想的相反】，而這決定了本票的形狀

```
我原本的正方理由：「玩家操作會改 state ⇒ 不進 fp 就驗不了玩家路徑」。
★blueprint 的理由【恰恰相反】：
   玩家 ＝ 可插拔的控制器（用戶裁定）⇒ ★★**sim 永遠不該讀／寫 player_***
   ⇒ 把 player_* 放進 fp ＝ 一道【免費崗哨】：
     ★★★**兩顆【無玩家】的 seeded 跑，若在 player_* 上分岔 ⇒ 有系統偷碰玩家欄 ⇒ 憲法違規當場現形。**
⇒ 所以本票【不是】「擴大 fp 涵蓋範圍」，是【裝一個哨兵】。
   ★而這改變了驗收：主格不是「fp 變了」，是【無玩家跑裡 player_* 恆為初始值】。
```

⇒ ★★在【無玩家】的跑裡，`player_*` 必須【恆為初始值】。

## ③ 驗收

| # | 格 | 判準 |
|---|---|---|
| ① | **★哨兵成立** | 兩顆**無玩家** seeded 跑（同 seed／同窗）⇒ fp **完全相同**，且 player_* 段落等於【初始值的 hash】 |
| ② | **★★成對對照：偷碰會現形** | 暫時把某一處 player_* 寫入的 gate 拿掉（例如 `diplomatic_ai:170` 的 `if state.player_id != -1`）⇒ 兩跑**必須分岔**；★★★恢復後回綠 —— **沒有這格，①的綠證明不了哨兵有裝上** |
| ③ | **RNG 位移也抓得到** | 在同一個被拿掉 gate 的路徑上確認：`str(randi())` 被執行 ⇒ ★不只 player_* 欄位變，**後續世界也跟著位移**（★★這一格要分開報，因為它證明哨兵的價值不只是「多守一個欄位」） |
| ④ | **有玩家的跑不受影響** | 玩家 scenario 下 fp 仍可重現（同 seed 同操作序 ⇒ 同 fp）；★不同操作 ⇒ 不同 fp（**這是對的，不是 bug**） |
| ⑤ | **baseline 全部更新** | ★grep 出所有硬寫 fp 值的地方逐一列出並更新；★★交件要附【更新前後對照表】，不得只說「都改好了」 |
| ⑥ | **`blind_note()` 跟著變** | 導出的排除清單裡**不再有** player_*（★上一張票的紅利，順手驗一格） |

★**誠實限**：①②只證明【頂層 player_* 欄位】沒被偷碰 ——
★★子層級（例如 `player_state` 這個 Dictionary 內部的鍵）**由 hash 的實作決定看不看得到**，
⇒ ★★★**交件要寫明它看到哪一層**（同上一張票的紀律：兩個粒度都說出來）。
