# HOW：`join_request` 按「接受」卻回「被拒絕（隊伍已滿）」

**來源**：死輸入床成因 ③（1 筆）。
★**與用戶第二輪那句「我按 T 跳出表單後 還是寫我拒絕事件」同族**：回應與結果不一致。
⇒ 而那一族今天已經修過一次（提案類型漏接）⇒ **這是第二個實例，所以要問母體**。

## ★★★§1 這張票的重點是【還有第三個嗎】

```
①先定位那一筆：`join_request` 的 accept 分支在「隊伍已滿」時回的是**拒絕句**
   ⇒ 而玩家按的是「接受」⇒ ★**兩件事都真**（他接受了、而隊伍滿了），
     但那一句話把【我的決定】與【世界的結果】混成一句 ⇒ 玩家讀成「我按的沒生效」
②★★★所以修法不是把句子改順 —— 是把**兩件事分開講**：
   「你接受了他的請求，但你的隊伍已滿 ⇒ 沒有加入」
   ⇒ ★而這與「按 T 還寫我拒絕」的修法**同源**：回應是回應，結果是結果
③★★而本票的真正產出是**母體**：`_forced_responses()` 的每一種回應 × 每一種
   forced_event，逐一問「它的結果句會不會把我的決定說成別的決定」
   ⇒ 床要把那個母體**印出來**（幾種組合／幾種被檢查／幾種不適用）
```

## §2 做什麼
```
①那一筆：把回應與結果分開講（措辭形狀沿用既有結果句）
②★逐一掃 `_forced_responses()` × forced_event 的全部組合 ⇒ 指名列出：
   ·結果句與回應一致的（綠）
   ·把回應說成別的回應的（★要修）
   ·不適用的（要具名理由）
   ⇒ **三數相加＝總組合數**（同「按鍵三態」那張的母體地板形狀）
```

## ★§3 驗收
```
P1 那一筆：按接受 ⇒ 句子裡**同時**有「你接受了」與「隊伍已滿」，且不得只有「被拒絕」
   ｜負對照：改回單一句「被拒絕」⇒ 必紅
P2 [★母體地板] 三數相加＝總組合數；★若「要修」那一欄 > 1 ⇒
   **那不是本票失敗，是本票找到第三個** ⇒ 照樣修並寫進卷面
P3 重跑死輸入床 ⇒ (b) 那一類歸零
P4 全電池綠
```

## §4 不在本票
```
·「隊伍滿了該不該能接受」＝WHAT（本票只管那一句話不得說謊）
```
