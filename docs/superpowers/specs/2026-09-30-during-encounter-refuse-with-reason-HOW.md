# HOW：遭遇戰進行中，非戰鬥指令＝拒絕＋原因（41 筆靜默的成因）

**上游 WHAT**：藍圖裁 (a)（`2026-09-30-blueprint-to-systems-RULING-during-encounter-keys-refuse-with-reason.md`）
逐字：非戰鬥指令一律 `ok=false` ＋「**遭遇戰進行中，先處理戰鬥**」，走結果句與事件流；
戰鬥本身的鍵由遭遇戰畫面管，不在此列。**這是按鍵三態②在該前提下的執法，零新機制。**

## ★★★§1 前提：那 41 筆不是 41 件事

```
死輸入床（`docs/measurements/2026-09-30-scripted-exploration.txt`）逐字：
  「41 筆 ← 靜默當下：玩家 person 在／**遭遇戰 進行中**／玩家隊 在」
⇒ ★三個條件裡【玩家在／隊在】是常態 ⇒ **唯一的變數是「遭遇戰進行中」**
⇒ ★★所以它是【一個成因】，而 41 是它的暴露面 —— 修一處，41 筆一起走
★★★而它就是用戶第二輪那句「按了沒反應」的可重現前提（用戶原話，不是我們的詮釋）
```

## §2 做什麼

```
①在指令的**單一咽喉**（`execute_action` 那一層，同同格檢查那張票的位置）加一道前提：
   遭遇戰進行中 且 該動作不是戰鬥內動作 ⇒ `{ ok=false, msg="遭遇戰進行中，先處理戰鬥" }`
   ★★而「哪些是戰鬥內動作」**不准手抄清單** ——
     戰鬥內鍵由 `encounter_view` 管（上游明寫）⇒ 母體＝**它處理的那些**，機械抽出來
     ⇒ ★若抽不出來（它不是一個可列舉的集合）⇒ **回報，不要自己編一份**
②結果句走既有那條路（佇列消費點）⇒ 玩家看得到；事件流也要有
   ★不新增第四種語氣（同「按鍵三態」那張的措辭紀律）
③★不動遭遇戰本身的任何行為（它由 `encounter_view` 管）
```

## ★★§3 驗收

```
P1 [41 筆回到有句] 重放床裡那 41 步 ⇒ **每一筆都有句子**，且 state 逐欄不變
   ｜負對照：把原因句拿掉 ⇒ 41 筆回到靜默 ⇒ 必紅（★上游指定的那一道）
   ★母體地板：印出【這一輪遭遇戰真的在進行中】——
     否則這一格會在一個「沒有遭遇戰」的世界裡恆綠（而那 41 筆本來就不會出現）
P2 [戰鬥內動作沒被門死] 遭遇戰中，**戰鬥內的鍵仍然可用**
   ｜負對照：把它們也擋掉 ⇒ 必紅（★這一格守「我沒把功能門死」）
P3 [不是靜默也不是假成功] 那一句是 `ok=false` ＋原因，**不是** `ok=true` 配一句安慰
   ★理由：`ok=true` 會讓佇列／事件流以為事情發生了（今天「按接受卻說被拒」的鏡像）
P4 [★成因數要降] 重跑死輸入床 ⇒ **成因從 5 降到 4**，而 41 筆從「症狀」移到
   「設計上的靜默（看得到但不算症狀）」那一區 ★★或者它根本不再出現 —— 兩種都可以，
   但**卷面要說出是哪一種**（「消失」與「改分類」是兩件事）
P5 全電池 BATTERY_RC=0；★fp 預期不變（只多一條拒絕路徑、不動世界）
   ⇒ 變了就是發現，回報不要換基準
```
