# HOW：根修 merge 必附「舊世界結論清單」

> **問題**：**根修會讓建立在舊世界上的結論默默過期，而它們不會自己舉手。**
> **委託**：blueprint（2026-09-03）。他提示「雜湊交件必附 commit 的紀律已經給了一半機械底」。
> ★★**而我先去量了那個底 —— 它不是一半。**

## ★①先把底量出來（134 顆 `docs/process/verdicts/*.json`，逐顆掃，不抽樣）

| 問法 | 數 | 佔比 |
|---|---|---|
| commit 欄位裡抓得到 7–40 位 hex | **11** | **8.2%** |
| 有 commit 類欄位但值是散文（例：`"main(A:\GDS\demo)，X已merge"`） | 26 | 19.4% |
| **完全沒有 commit 類欄位** | **97** | **72.4%** |

⇒ ★**「雜湊交件必附 commit」是【新紀律】，存量沒有回填** —— **靠它查，實際只查得到 8.2%。**
★★**而 8.2% 的掃描器會印出一份「看起來管好了」的清單** —— **那正是我今天已經踩過兩次的形狀（born-with 過期紅／橡皮圖章）。**

## ★★②而機械鍵【已經存在】，只是不在 JSON 裡 —— 在 git

```
git log -1 --format=%H --diff-filter=A -- <verdict.json>   # 這顆結論【落地】在哪個 commit
```
- **133/134 查得到（99.3%）**，唯一查不到的那顆是未追蹤/剛寫的。
- ★**語意**：verdict 檔在 commit C 落地 ⇒ **它量的世界不晚於 C**。
  ⇒ ★★**對「這顆結論是不是在根修之前量的」這個問題，它是【保守正確】的**（可能低估新鮮度，不會高估）。
- ★★★**不需要任何人記得填欄位** —— **這是它比 `measured_at_commit` 強的地方：不會腐爛。**

## ★★★③而真正的缺口不是時間，是【對得上哪個系統】

| 問法 | 數 | 佔比 |
|---|---|---|
| verdict 檔裡有指名至少一個 `scripts/**/*.gd` | **73** | 54.5% |
| ＋靠 `landed_paths` 指到的 raw report 再撈 | **+1** | → **74（55.2%）** |
| ★**一個 code 路徑都對不上** | ★**60** | ★**44.8%** |

⇒ ★**檔案交集法的真實涵蓋率是 55%，不是「全部」。**
★★**第二層（追 raw report）只撈回 1 顆 —— 我原本以為它會撈回不少，量了才知道不值得當賣點。**

## ④設計（依上面三個數字，不是依直覺）

**形狀：第 13 道閘，`stale-conclusion.sh`，`warn-only`（比照 `tree-div`）。**

```
輸入：本次 merge 的 changed production files（git diff --name-only base...HEAD -- scripts/）
對每顆 docs/process/verdicts/*.json：
   add=$(git log -1 --format=%h --diff-filter=A -- $f)
   若 add 是本次 merge base 的祖先（＝這顆結論在根修之前落地）
     且 verdict 檔內指名的 scripts 路徑 ∩ changed files ≠ ∅
   ⇒ 列為【候選過期】
輸出：候選清單（檔名＋命中的那個 code 路徑）＋★★★三行誠實限
```

### ★★★三行誠實限（**必印，不可折疊**）
```
①涵蓋 55%：60/134 顆結論【一個 code 路徑都沒指名】⇒ 本閘對它們天生盲，數字不會因此變紅
②只印不判：候選過期【不會擋 merge】——要不要重驗是人的判斷，本閘只負責讓它【舉手】
③「落地 commit」是量測時間的【上界】：可能把新結論誤列為舊，方向保守（誤報 ≫ 漏報）
```
★**而①那 60 顆不是四捨五入掉的餘數，是【本閘最大的失效面】** —— 印在最上面，不是註腳。

## ★⑤止血在寫入端（治 60 那格，唯一能真的把它變小的地方）

新 verdict 必帶 **`touches`：一個 `scripts/**/*.gd` 路徑陣列**（＝「這顆結論建立在哪些 code 上」）。
- ★**可機械檢查**（比照 `ki-status-gate`：新條目硬檢、存量列為存量並且**明說沒被檢查**）。
- ★★**不回填那 60 顆**：回填＝**憑印象替過去的量測填來源＝捏造**。
  ⇒ 它們永久留在盲區，而**盲區大小每輪印出來**。★★★**「盲的」跟「以為不盲」差在有沒有印那個數字。**

## ⑥不做的事
- ★**不自動作廢任何結論**：本閘不改任何檔、不動 verdict 的狀態 —— **它只會說「這幾顆可能過期了」。**
- ★★**不新增「到期日」**：到期 token 會變成沒人看的裝飾（`known_issues` 回訪條件那次已經學過）。
  **這裡的觸發是【根修真的 merge 了】，是事件不是時鐘。**

## ⑦驗收
1. 陽性對照：拿一個**已知**的根修 commit（例：`threat` 常數不對稱那次）當輸入，**必須**列出至少一顆命中該檔的舊 verdict；把該 verdict 的 code 路徑抹掉再跑 ⇒ **必須從清單消失**。
2. 三行誠實限逐字出現在輸出裡（**人讀的是 print，不是檔頭註解** —— `bed_arm_gate` 那次的教訓）。
3. 掛進 `docs/process/merge-gates.tsv`（第 13 道），計時登記。
