# HOW：玩家面字串不得出現英文識別字（72 筆／兩個修點）

**來源**：死輸入床成因 ④（70 筆）＋⑤（2 筆）。
★**兩者同一張票的判準**：它們是**同一個掃描**（床的 (d) 條：玩家面字串零英文識別字）
—— 而「兩件事該不該同一張票，看它們的母體是不是同一個掃描」是藍圖今天定的判準。

## ★★§1 前提（指名）

```
④70 筆：`player_command_api.gd:237 describe()` 把**指令參數原樣**印給玩家
   ⇒ ★**70 筆但只有一個修點** —— 這是「症狀數 ≠ 工作量」最清楚的例子
⑤2 筆：handler 自己的 msg 裡有英文（床已逐筆指名，見那份人讀清單）
★而床的 (d) 條**已經有白名單並且印出來**（專有名詞、Team%d 這類）
  ⇒ 本票**不動白名單**；若需要加，要就地具名寫理由（白名單變寬 ＝ 判準變鬆）
```

## §2 做什麼
```
①`describe()`：玩家面的那條路**不印參數原樣** —— 改成人話（動作名用既有中文表）
   ★★而那張中文表**要與既有那份同源**（`_forced_label` 那一系）⇒ 不另開第二張表
   ⇒ ★不認得的 id ⇒ 印「（未知動作：<id>）」**不得吞掉**（同 #7 那條）
②那 2 筆 handler msg：逐筆改人話
③★不動白名單、不動 (d) 那條判準
```

## ★§3 驗收
```
P1 重跑死輸入床 ⇒ (d) 那一類**歸零**（或剩下的每一筆都在白名單裡並印出來）
   ｜負對照：把 `describe()` 改回原樣印 ⇒ 70 筆回來 ⇒ 必紅
P2 [★不認得的 id 不吞] 造一個不在中文表裡的動作 ⇒ 印「（未知動作：xxx）」
   ｜負對照：改成印空字串 ⇒ 必紅
P3 [★★中文表沒有第二份] 斷言那張表的**呼叫點指名**，且玩家面那條路**不得出現第二張表**
   ⇒ 這一格守的是「一個真相只存一份」
P4 全電池綠；fp 預期不變（只改字串）⇒ 變了就是發現
```

## §4 不在本票
```
·白名單該收窄還是放寬（那是判準層，另議）
·非玩家面的 log／print（它們本來就可以有英文）
```
