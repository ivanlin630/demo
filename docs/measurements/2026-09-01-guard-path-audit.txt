# 守衛掛在哪條路上 —— invariant「守衛不掛被動路徑」的存量稽核（只盤不修）
#
# ★起因：LOD 那一票我自己踩到 —— 假設告警放在 runs_per_day() 裡，
#   跑對照時 registry 已經改壞而告警印 0，因為那一跑【沒人呼叫估算器】。
#   ⇒ systems 已立成 invariant：守衛要掛在【一定會發生的事】上，不是掛在【有人來問】上。
# ★★這份是回頭問：既有的守衛，有幾顆也犯同一個病？
#
# ═══ 母體【先寫死再數】═══
# 母體 ＝ scripts/simulation/**.gd 裡的「守衛型輸出」，兩類：
#   A 類：assumption / stale 型告警（grep `stale|assumption` ∩ `bump|push_`）⇒ 4 處
#   B 類：loud-fail（push_error 4 處 ／ push_warning 9 處）⇒ 13 處
# ★判準（每一列都要能指出【誰呼叫它】）：
#   主動 ＝ 掛在每 tick／每 dispatch 一定會走的路上
#   被動 ＝ 只有「有人來查詢」時才走（估算器、accessor、deprecated API）
#   ◆不適用 ＝ 它不是守衛（是量測 tap、或是動作結果回報）
