# 贏家 util 分布 vs 攻擊的可達上限（2026-09-15）

跑法：herald @ `42ec03e31`｜seed 1337｜12 天窗、第 9 天清空（只含 tick 12960–17280）
原始：`docs/measurements/2026-09-15-winner-util-distribution-raw.txt`

## 實得

```
★贏家 util 分布（n=200）：**p25 0.640｜中位 0.739｜p75 1.085｜max 2.831**
★★攻擊的可達上限 ＝ `0.6 × odds × person`（★而 0.6 這個數只在 `need ≡ 0` 時成立）
   ・用中位帶入（odds 0.741、person 0.613）⇒ **0.27**
   ・隊 80 自己（odds 1.000、person 0.710）⇒ **0.426**
   ・**絕對最好**（odds 1.0、person 撞 clamp 1.5）⇒ **0.900**
```

## ★★★判定：假說成立，**而「結構性不可能」要收窄一格**

```
★**成立的部分**：**贏家中位 0.739 ≫ 攻擊的典型上限 0.27** ⇒ **2.7 倍** ⇒ 形狀題成立。
★★**要收窄的部分**：**攻擊的【絕對最好】0.900 > 贏家中位 0.739**
  ⇒ ★★★**所以不是「結構性不可能贏」，是【只有極窄的角落能贏】**：
    要贏中位贏家 ⇒ `odds × person ≥ 1.232`
    ⇒ **person 要接近 clamp 上限 1.5（極端好戰／貪婪、且不慎重）且 odds ≥ 0.82**
    ⇒ **用 person 的中位 0.613 帶入 ⇒ 需要 odds ＝ 2.01 ⇒ 不可能**
★**而隊 80 正好證明那個角落有多窄**：它的 odds 已經滿格 1.000，
  **而 person 0.710 ⇒ 上限 0.426 ⇒ 它那個人格【永遠】贏不了中位贏家。**
```

## ★這個差別對 spec 有後果

```
・**若寫「結構性不可能」** ⇒ 讀的人會以為**改公式形狀是唯一出路**。
・★**而實測是「窄角落」** ⇒ **它也可能被【人格分布】或【odds 分布】改變** ——
  ⇒ ★★**那是兩條不同的線**，而選哪一條是設計問題。
★★★**我不主張任何一條** —— 本卷只把角落的寬度量出來：**`odds × person ≥ 1.232`**。
```

## ★邊界（結論旁邊）

```
★**這是一個窗、一個 seed**（12 天窗的後段）⇒ **不是「這個世界普遍如此」**。
★★`attack.rank_row` 是 **first-N 上限 200** ⇒ **贏家分布也帶那個偏差**。
★★★**而「贏家」是每一次 argmax 的贏家，不是「好的決策」** —— 本卷不評價它們對不對。
```
