# ★母體定義（兩趟逐字相同）：episode＝同一隊在 current_task 上連續停留的一段；
#   長程＝episode 起算時 move_target 與所在格 hex 距離 ≥ 3；到場＝存續期間任一 tick tile_pos == move_target；
#   ★被窗切掉的 episode 單獨一列、不進分母。
#
# ═══════ 四個結論 ═══════
# ①★★★【比本票更大的發現，systems 要我單獨報】**這個世界的長程到場率本來就很低**：
#   before 87／374 ＝ **23.3%**；after 116／655 ＝ **17.7%**
#   ⇒ ★也就是說「出發了卻到不了」是**全域常態**，不是求居專有的病。
#   ⇒ ★★而它直接影響驗收①的讀法：門檻綁基準 ⇒ **門檻本身只有兩成**。
# ②★求居在兩趟都是【母體 0】—— 沒有任何一段 SEEK_HOME 的長程 episode
#   ⇒ ★★所以「到場率」這一格**這張床答不出來**（不是 0%，是不可判）⇒ 由漏斗床（registration_verbs_bed）接手。
# ③★★★我上一封的懷疑【被自己的量測否定】：「覓食 episode 從不結束」**不成立** ——
#   episode 長度中位 **479 tick ＝ 0.33 遊戲天**（after 420 tick）⇒ ★大多數覓食段**很快就結束**
#   ★★而 max ＝ 39000 tick（27 天）⇒ team 65 那一段是**長尾**，不是常態。
#   ⇒ ★★★所以擋住求居的不是「一段永不結束的覓食」，是**每個 cadence 又選一次覓食**（重複進入）。
# ④★★而「覓食真的會餵飽」這句也要收窄：**Δfood_days 中位是 −0.25（負的）**，
#   只有 **11.4%（after 18.2%）** 的段上升超過半天。
#   ⇒ ★誠實限：**Δfood_days 不等於「覓食產出」** —— 它是這段期間**全部收支**的淨變化
#     （吃掉、賣掉、人口變動都在裡面）⇒ 它**不能**單獨用來判覓食有沒有效。
#     ★★能說的只有：**覓食段結束時，多數隊的存糧天數沒有變多。**
#
# ═══════ 副作用守衛（驗收②③） ═══════
# ★餓死：before 隊滅絕於餓 0／有名角色餓死 0；after 同為 0／0 ⇒ **不升**（★而兩邊都是 0＝這一格本窗沒有鑑別力，要講明）
# ★★無登記隊數：before 92（寄居 2）→ after 83（寄居 2）⇒ **沒有歸零** ⇒ 遊商階層還在（blueprint 的目標校準）
# ★★★fp：before 4b080cea8aa5f8ce97e7ad9ef6822c58 → after cb5d92447913daf0ccba6af0dbcda1dc ⇒ **變了（裁定接受）**
# ★>2 秒幀數：before 321／43200 → after 518／43200 ⇒ ★★**變差了，要單獨追**（同機無其他長跑；但它與終線那條線相衝）
#
