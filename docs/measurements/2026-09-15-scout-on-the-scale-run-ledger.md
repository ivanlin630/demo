## 這五輪【真的】產出了什麼（★不是零）

1. **每日成本不是常數**：360s→day 8（≈45 s/日）、2700s→day 21（≈128 s/日）；
   邊際 `(2700−360)/(21−8) = 180 s/日`。★兩點擬合 `total ≈ 11.25·d²/2` ⇒ 預測 day 30 ≈ 5000 s。
   ★★**標【兩點擬合，待驗】** —— 它的價值在於**會被證偽**：真跑完若顯著超過 5000 s，模型就錯。
2. **「當下可用記憶體」是一個變因**（#2 vs #3 同樹同 seed，死點不同）
   ⇒ 已照裁把 `[HOST] start FreeMB=… TotalMB=…` 寫進輸出第一行。
3. **指認到吃記憶體的鍵**：`poll.eventwake`／`poll.outcome`／`t0.emit_ctx`（cap **40000**）、
   `tier.fire`（cap 6000）。靜音前三族後：day 3 `samples_inst` 44372 → **19368（−56%）**、
   `static_mem` 110.3 → **95.1 MB（−14%）**。
   ★★★**而這【解釋不了 OOM】**：百 MB 級撐不爆 32 GB 機器 ⇒ **真因仍未找到**，本項只是拿掉一個可指認的純負擔。
4. **`bump_pt` 不是交叉積**（`probe_stats.gd:89-93`）：`event+day_suffix` 與 `event+".team."+id`
   **兩個獨立鍵** ⇒ 鍵數 ≈ 71×天數 **＋** 71×隊數。
5. **儀器缺口兩個，都是實跑照出來的**（不是讀 code 想到的）：
   - `recon.dispatch.*` 只裝在 `unified` ⇒ 差額長得像「贏了卻沒派出去」，其實是**三個沒接電的迴圈**；
   - `solo`／`subteam`／`survival` 的 `try_set` **沒傳 `opt`** ⇒ `arbiter.deny.*.opt.*` 對偵查恆空。

## ★★★閘跟長跑的【判讀規矩】（復工第一天買來的，2026-09-16）

```
事實：從 PowerShell 叫 `bash .claude/hooks/merge-gates.sh`
      ⇒ **PowerShell 的 PATH 上沒有 `bash`** ⇒ runner **從未啟動** ⇒ 零輸出
      ⇒ ★而背景任務回報 **exit code 0** ⇒ **「沒跑」長得跟「跑完了、綠」一模一樣。**
```

★★**runner 裡其實早就有守衛**（「實跑 N 支；N==0 ⇒ 紅」）—— ★★★**而它在這裡結構上無效**：
**它住在 runner 裡面，而失敗發生在 runner 【被啟動之前】。**

> ★★★**通則：一支守衛偵測不了「它自己沒有被執行」。**
> ⇒ 這一族只能靠**外部的、內容性的證據**，不能靠回傳碼。

**判讀規矩**（寫死在這，因為這件事沒有任何東西擋它 ⇒ **它會再發生**）：

```
①閘跟床一律用 **Bash 工具**跑（PowerShell 裡沒有 `bash`；
   若一定要從 PowerShell，用完整路徑 `& "C:\Program Files\Gitinash.exe" …`）
②判「有沒有跑」**看結尾橫幅**（`註冊表 N 支｜總時 …s`），**不看 exit code**
   ★回傳碼答的是「那個 shell 有沒有活著」，**不是「那 55 支有沒有跑」**。
③長跑同理：看輸出裡的結束標記，**不看任務狀態**。
```

★**而這一次沒有損失**：票乙的 55 支在 `476bd0401` 已經跑過，之後 `scripts/` 零改動
⇒ ★★**那一輪本來就不必跑** —— **「它沒跑」只是照出了工具的洞。**
