> ★**為什麼需要這個檔**：`docs/measurements/` 有 **1426** 個檔，而其中一大半的數字
> 是在一個**有一整層行為沒在跑**的世界裡量的。
> ★★而舊數字**看起來跟新數字一模一樣** —— 沒有這個檔，它們會在下週被當成基線引用。

## ★★★兩個【不同的軸】：世代（code）與硬體（machine）

```
★世代邊界（既有）＝【世界的行為變了】⇒ 連【邏輯量】都不可跨代引用（分布、頻率、到場率…）
★★硬體邊界（本節新增，用戶令 2026-09-21）＝【世界沒變，機器變了】
   ⇒ 只有【時間量】不可跨機引用；★邏輯量（fp、圈數、呼叫次數、母體）跨機【仍然有效】
⇒ ★★★兩個軸要分開問：「這個數字是【秒】還是【次】？」
```

### ★哪些【不】受硬體邊界影響（★不要過度作廢）

```
・fp 指紋／逐 tick 行為軌跡（同 seed 同 code ⇒ 換機器【不該】變，★而「不該變」本身就是一條可驗的守衛）
・圈數、呼叫次數、母體大小、比值（score_n 的半數、p=10.3%…）
・所有「次數／有沒有發生」類的判準（到場點名、寫世界 0 次、RNG 抽取序列）
⇒ ★★把它們一起作廢是【過度】—— 而過度作廢的代價是：下一個人以為什麼都不能引用，於是什麼都重量一次
```

### ★★★什麼樣的 merge 才開新世代（判準，免得下一個人憑感覺）

```
★**開**：一個 merge 讓**某一類行為的發生率跨了一個量級**
  （例：2.5% → 75%｜静音 → 常態｜0 → 非 0）
  ⇒ 因為**舊數字的母體本身變了**，不是只有數值變了。
★★**不開**：純觀測（tap）／效能／修 bug／參數微調／只改工具與文件
  ⇒ ★★★**每次 merge 都開一代 ＝ 世代這個概念失效** —— 它的價值在於【少】。
★開了之後要做的只有一件：**在本檔加一段**（sha ＋ 理由 ＋ 受影響的分布）。
```

### ★★★「67 支全綠」**不等於**「世界沒變」（★這一句要留在這裡，否則下一個人會讀錯）

```

⇒ 它們驗的是【決定論】，不是【與某個釘死基線相同】
⇒ ★所以世界變了它們也不會紅 —— 上面那兩組新舊 fp【不是】由它們證明的，
   是由 `world_fp_snapshot_bed` 證明的
⇒ ★★而這也解釋了「全庫釘住 fp 字串的床只有 1 支」為什麼是【對的】而不是碰巧
```
