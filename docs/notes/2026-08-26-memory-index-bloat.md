## §3 同一個病，第五個地方

```
檔層      docs/process/status/*.status.md   整檔是紀錄
段層      game-design.md                    整段是盤點/診斷
★段內     invariants.md                     規則 2 行 + 佐證 29 行
★★索引層  MEMORY.md                         索引行變成內容摘要
```

規則同一條（見 `9e3816f9`）：
> **每一段只能是「規則/概念」或「證據/紀錄」之一。證據不與規則同居，只留一行指標。**

索引層是它的極端形式：**索引行本身就該只是指標**，現在卻塞進了整段證據。

### ★ 副作用：索引詳細到不用開檔

索引寫得夠完整 → **recall 時看索引就夠了，不會打開檔案**
→ 檔案變成**死庫存**（沒人讀，但佔著）
→ 而索引繼續膨脹（因為它是唯一被讀的地方）

⇒ 這解釋了為什麼索引會長成這樣：**它在替檔案做檔案的工作。**

| | 刪檔（`186ebad5`） | **索引瘦身（本篇）** |
|---|---|---|

⇒ **索引瘦身是純機械、零風險、省得多。** 刪檔可以慢慢來。

## §6 建議做法

**① 立一條上限**：索引行 **≤ 60 字**（規格本來就是「hook」）。

**② 搬，不是刪**：超出的部分**移進該檔的正文**（大多數本來就已經在檔裡了，是重複）。
⇒ 動手前先確認：**索引裡的內容，檔案裡有沒有？** 有 → 純刪索引那段；沒有 → 先搬進檔案再刪。

**③ 從最長的 19 條（>200 字）開始**，那 19 條就佔了不成比例的量。

**④ 上限要能自動查**：
```bash
awk 'length($0)>60 && /^- \[/ {print FILENAME":"NR"  "length($0)"字"}' MEMORY.md
```
一行指令，寫進 memory 規格旁邊即可。**不需要新機制。**
