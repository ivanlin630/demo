## §1a 消滅：為什麼玩家打不死 NPC 隊（用戶 2026-10-13：「全殲滅跟戰鬥逃跑是兩回事，NPC 隊無法被消滅」）

三個漏，全在玩家遭遇戰這一邊；世界側（NPC 對 NPC）沒這病。修法＝把玩家戰場的**結算**接到世界側已有的帳，不改戰鬥本身：

| 漏 | 修 | 用什麼 |
|---|---|---|
| 失能者滿血回家 | 結算時失能未死的匿名**寫進 `team.wounded`**、記名走 HealthSystem 傷勢；傷兵占人口但不上場、不出工、要吃，照既有恢復速度好 | `TeamData.wounded`（npc_combat 已讀）、HealthSystem |
| 戰後沒收尾 | 加一步**「場上傷兵的命運」**：勝方對失能的敵人選殺／俘／放。NPC 勝方走人格（殘忍→殺、貪婪或缺人→俘、義氣→放）；**玩家勝方＝一個動詞，你按**（C1）。俘＝走 `capture_routed_as_captive` 進 `captive_groups`（§4 接帳同一條路） | 既有 manpower 俘虜帳；社交層「處置」同型 |
| 居民處置替你決定 | `_process_occupied_residents` 攻方是玩家時**停下來問**（屠／放棄／強佔三選），NPC 照舊讀人格 | 既有三支函式，只加一個玩家分岔 |

- 追擊：玩家要不要追、追到砍幾個——可選的第二步，掛同一張票尾巴（NPC 版在 `_apply_pursuit`，上限 3）。
- 效果：連勝幾場的隊真的會變小、傷兵拖累它、最後被 `_on_team_extinct` 收掉——**不是改殲滅線，是讓傷亡算進帳**。殲滅稀（07-10 定案）不動：死戰才殲滅，但打輸會流血。
- 結算寫 wounded 那一行是最小修，先做；殺俘放那步跟 §4 接帳同票。

## §1b 潰退：三個主詞三把尺（用戶裁：讀領袖膽量當全隊的「怪」⇒ 拆）

**原則**：膽量只管一個人——領袖本人。兵讀士氣，士氣讀供養與耗損。勇將帶餓兵照樣崩；懦夫帶飽兵撐到他自己先跑。

| 主詞 | 撤不撤讀什麼 | 既有來源 |
|---|---|---|
| **匿名** | 士氣：供養夠不夠（雙層薪資裁「匿名靠供養」）、`readiness`（npc_combat 已在戰鬥中耗損）、本場失能比例 | `readiness`、匿名供養狀態、UnrestBank |
| **領袖抓不抓得住人** | 門檻抬高量＝**統領**技能 | `skills["統領"]`（立國閘讀的同一個） |
| **領袖自己** | 他的膽量（好戰／求生欲／慎重）決定**他**跑不跑 | 現有 `_courage_of` 只用在這 |
| **記名** | 自己的求生欲＋對領袖的忠誠／恩義（留下陪他血戰或先走） | LoyaltyBank、relation edges |

- **連鎖**：領袖跑了或倒了 ⇒ 統領項歸零 ⇒ 匿名士氣崩 ⇒ 整隊散（將倒兵潰）。
- **一把秤兩個戰場**：遭遇戰（`encounter_system`）新加團級判斷，每回合一次；`npc_combat` 那把同樣拆成三主詞（它現在也拿領袖膽量當全隊的，同一個怪）。
- **退場的常數**：`RETREAT_TEAM_RATIO 0.7`、`FLEE_SURVIVAL_VALUE 0.7`、`FLEE_TEAM_RATIO 0.5`、`FLEE_CHANCE 0.3`——工作被秤接走（照妖鏡同型）。
- **玩家零特例**（用戶裁「玩家永不被跑」）：你附身的人跑不跑是你按的（C1 零自動）；**你的兵不是你**——匿名讀士氣、記名讀忠誠，該走就走，不問你。你站到最後可能孤身一人 ⇒ 被圍／被俘／被殺 ⇒ 走既有繼位／附身下一人。跑是你的選擇，代價是你的。
- 配套：①撤退動詞要在遭遇戰選單確認玩家按得到；②兵潰散那一刻要有事件打到玩家臉上（「你的匿名兵開始潰散」「某某離開戰場」），列推進停點。
- tap：`enc.rout.n_高／中／低`（照 `mortal_flee` 三桶），驗「士氣低桶多」。
- 結束不用改：一隊跑光＝現有「沒活人在場」結算自動成立。
- 供養制在戰場上有了讀者（B2「帳要有讀者」）。

## §2 顧問：讀 belief、走情報管線（零新系統）

| 段 | 做法 | 用什麼 |
|---|---|---|
| 讀 | 顧問只讀**玩家的 belief store**，永不讀真值。評敵→`best_estimate`＋`uncertainty`；外交→名聲與恩怨邊；資源→自家庫存＋糧流感官（自知合法）；戰略→已知威脅；讀情報→claims 可信度 | `BeliefSystem` 現有函式 |
| 算 | 準不準**不擲骰**：顧問估計＝玩家 belief 加一層 `observation_noise(…, 他的技能)`，技能高雜訊小。人格偏頗＝**數字上的系統偏移**（好戰高估己方勝算、慎重反之），句子從偏移後的數字生成 | `observation_noise` 現有 |
| 出 | 一則玩家事件走 `world_events.emit`，kind＝`advice`，subjects＝[顧問, 對象]，info 帶依據（哪筆情報、幾天前、親見或傳聞）。進事件流＋情報面板（10-13 #10 票那頁）。來源血統寫明 ⇒ 講錯了之後的事件會打臉他 | #10 情報面板同一列 |

- 講錯代價＝玩家照做的後果，不另罰。`trust[顧問]` 數字先不長（面板上「依三天前傳聞」已夠判）；要加同軍票 trust 形。
- 排：#10 情報面板之後、玩家可見批收斂後（它寫的就是那張面板的列）。

### §2a 顧問文本怎麼做（用戶問「要做多少文本」）

現況 `text_bank.gd` 顧問組 31 行、6 鍵，寫法＝**一種結果一句**（`accurate_strong`／`wrong_underestimate`／`biased_attack`…）。兩個病：句子自己知道自己錯（玩家久了從語氣認對錯）；情境×對錯×偏頗×語氣組合爆炸。

**改法＝數字管對錯、句型管聲音，沒有「錯的文本」**：

| 層 | 每情境 | 例 |
|---|---|---|
| 事實句 | 1 | 「{對象}約 {人數} 人，{武裝}成帶兵器——{來源}，{幾天}前。」數字＝顧問偏移後估計；來源／時間＝belief 血統 |
| 判斷句 | 3（優／均／劣） | 哪句出來＝偏移後估計 vs 自家實力落哪帶；好戰者偏移往上⇒多講「佔上風」，不另寫鷹派句 |
| 語氣尾 | 4，全情境共用 | 直率／拘謹／刻薄／預設 |
| 不知道 | 1，共用 | 「這我不清楚，沒人去看過。」`uncertainty` 高或無 belief 就講——**顧問能說不知道** |

數量：5 情境×4＋4 語氣＋1 不知道＋3 來源詞（親見／聽說／打聽）≈ **28 行**，比現在少，五情境全蓋，錯時不露餡。現有 3 組主動警報（缺糧／敵近／盟友背叛）照留。加一情境＝4 行。砍：全部 `wrong_*`、`biased_*`。

### §2b 所有文本外置（用戶裁 2026-10-14「當然是所有文本」）

**量**（`text_bank.gd` 以外含中文字串的行，2,501）：

| 桶 | ≈行 | 處置 |
|---|---|---|
| 識別字：八軸人格鍵、技能鍵、tag、task／option／tier 名（`TASK_ATTACK := "攻擊"`、`values.get("好戰")`、`["軍隊","商隊"…]`） | ~900 | **不動**。引擎拿它比對，改名是另一個決定，動了就破正典 |
| 診斷：`print`／`push_warning`／`Probe`／`_enc_log`／`invariant_audit` | ~340 | 留 code |
| **玩家文本**：動作結果句、面板標籤、事件人話、UI 版面字 | **~1,300** | 外置。六檔占絕大多數：`text_ui_main` ~540、`player_command_system` ~310、`player_api_mapper` ~290、`encounter_view` ~115、`world_events` ~35、`observer_event_text` ~32 |

`text_bank.gd` 現 75 條＝玩家文本只外置了約 5%。

**形狀**：一域一檔 TSV（`data/text/advisor.tsv`、`actions.tsv`、`events.tsv`、`ui.tsv`、`encounter.tsv`），一行＝`鍵 ⟶ 變體 ⟶ 句`；code 只留鍵，`TextBank.fmt(鍵, 變體, params)` 介面不變改從檔讀。TSV 不 JSON：直接開 Excel／記事本改、diff 一行一句、simp-lint 照掃。啟動讀一次，幾十 KB。

**兩支守衛，缺一＝外置後靜默壞**：①鍵對帳——code 引用的鍵檔裡必有、檔裡的鍵 code 必有人用，少一邊紅（否則打錯鍵只印預設句沒人知道）；②槽對帳——句裡每個 `{槽}` 呼叫端必給、多給少給都紅。

**順序**：顧問那 31 行當試點（本來就要重寫）→ `player_command_system`／`player_api_mapper`（動作結果句，玩家天天看）→ `world_events`／`observer_event_text`（事件人話）→ `text_ui_main`／`encounter_view`（版面字，最多最雜，最後）。每檔一票，搬完跑兩支守衛。識別字桶的分類是用 regex 粗分的，搬每檔時逐行再判一次——「它是鍵還是句」看呼叫端不看字面。HOW 歸 systems。

## §3 通商：綁兩個既有機制，違約有價

- **通商＝兩個承諾**：①**互不勒索**（勒索選項對有約對象 util 多扣三筆，見下）②**板單互轉**（對方市場板的單走 relay 給你＝情報效果）。兩個消費者都在，util 算得出（省下被勒索的期望損失＋情報值）。
- **約＝一筆記名雙邊紀錄** `{甲, 乙, 起日}` 兩邊各存（賒帳那條帳的形狀，先用在這）。
- **不保證**（用戶問「怎保證」）：保證＝硬閘，違憲。違約做得到，代價三層全是既有帳：

| 層 | 寫什麼 | 誰讀 |
|---|---|---|
| 對方 | `betrayal` 邊（`form_feud`）＋雙邊信譽掉＋約作廢 | 對方的秤：不賒、不盟、可能報復 |
| 第三方 | 「甲對有約的乙動手」走 message＝傳聞 | 別人的秤：跟甲簽約 util 打折——**背約者簽不到下一份** |
| 自己 | 信義高 ⇒ util 直接負 | 自己的秤 |

- **解約 vs 背約**：先告知再動手＝解約（只掉一點信譽）；不告知直接勒索＝背約（三層全吃）。差別＝有沒有先寄那封信。
- 湧現：守約者越簽越多、背約者被孤立。沒有全局分數。
- 玩家：團頁列「與誰有約」；背約進事件流帶對象。
- 文案：`interaction_system.gd:510`「收過路費」改「勒索」（systems 順手）。真過路費（領土通行費）歸直轄／據點維護那批，現在沒有。
